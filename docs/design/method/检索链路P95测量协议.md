# 检索链路 P95 测量协议（v1.0 · 固化口径）

> 固化日期：2026-11-10 ｜ 关联：`§4 P0-3` 的 `P95<3s` 硬闸、`P-021`、`D-029`、`D-030`
> 性质：**测量口径文档**，不是验收结论。本文件不改变任何硬闸、不放宽达标线、不实施优化。
> 🔴 后续所有涉及 `P95<3s` 的验收、复采、对照，**必须逐字采用本协议**；不同协议的数字不可合并、不可比较、不可互相替代。

---

## 1. 适用范围与目的

`§4 P0-3` 规定检索链路 `P95<3s`。D-028 曾以 10 次采样得出 3705ms，并因「复采回落」初判冷启动；P-021 以 80 次采样修正为稳态长尾。两次结论分歧的根源之一是**没有把测量协议写死**。

本协议把「query 集合、样本量、冷/热定义、P95 算法、环境记录、零写入核」固定下来，使不同时段的复采可比、可复核，杜绝用「换 query 集合 / 只报暖机后 / 换 P95 算法 / 只取更快子集」的方式凑达标。

## 2. 协议表（v1.0）

| 项 | 固化值 |
|---|---|
| 协议版本 | `v1.0`（2026-11-10） |
| 端点 | `GET {GK_API_BASE}/netdisk/search?q=<encodeURIComponent>` |
| `GK_API_BASE` | `http://127.0.0.1:3000/api`（**直连后端**） |
| 鉴权 | 自签 `X-Auth-Token` = `v1.<largest_qo_user>.<exp>.<HMAC-SHA256(前 40)>`，`exp = now + 3600` |
| 身份 | `question_objects` 中行数最多的 `user_id`（L3 现为 `cc6d7b10…`）；不传 `referenceMode`、不传 `deep` |
| query 集合 | **5 条构造题，顺序固定**：`geo-raw` / `geo-fixed` / `eng-page` / `eng-fixed` / `eng-short`（逐字见 `.tmp/gk-p021-p95-probe.mjs` 的 `CASES`） |
| 轮次 | `ROUNDS=8`，每轮 5 题 ⇒ **40 次/轮**；题间 `GAP_MS=250`；全程串行 |
| 优先级 | `nice -n19`；不与 soffice / 批量转换任务并行 |
| 客户端计时 | `Date.now()` 包住 `fetch` + `r.text()` + `JSON.parse`，**单次一个样本** |
| 服务端计时 | 响应 `data.tookMs`（服务端内部，从 `started` 到 return）；**必须同时记录** |
| **P95 算法** | **最近秩法**：`sorted[ceil(n × 0.95) − 1]`。n=40 ⇒ 取排序后第 **38** 个值（1-based） |
| 冷 / 热定义 | `round = 1` 记「首轮」；`round ≥ 3` 记 `warm`。🔴 **warm 只是分层观察，不是达标口径**；报达标只用全量 40 次 |
| 必报指标 | 全量 `min / P50 / P90 / P95 / P99 / max`、首轮 P95、warm P95、`>3s` 明细（轮次 + tag）、`exact` / 非 JSON / 错误数 |
| 环境记录 | 每轮前后记录 `MemAvailable`、`/proc/loadavg` 的 load1、`gk-api` 状态、孤儿 soffice；复采另以 ≥5s 间隔连续采样到独立日志 |
| 基线记录 | `question_objects` 总行数、`netdisk_files.text_status='ok'` 行数、`CACHE_VERSION`、判定层文件 sha256 |
| 零写入核 | 采样后复核 `question_objects` / `answer_cache` / `question_inline_figures` 行数不变；`/api/health=200` |
| 复现物 | `.tmp/gk-p021-p95-probe.mjs`（临时诊断脚本，**不进 `server/scripts/` 真相源目录**） |

🔴 **为什么必须直连 3000**：`127.0.0.1:8080` 是 Caddy IP 站点块，对 `/api/netdisk/search` 与 `/api/health` 都返回 **200 空 body**（无 `content-type`）。只测 `%{http_code}` 会漏掉这类空响应；必须校验 JSON 可解析（`nonJson = 0` 才算有效样本）。

## 3. 三轮基线（同一协议 v1.0）

| 轮次 | 时段（2026-11-10） | n | 全量 P95 | warm P95 | `>3s` | 环境 |
|---|---|---|---|---|---|---|
| 1 | 上午（D-029） | 40 | **3443 ms** | 3498 ms | 5（全 `geo-fixed`） | `qo=656650` |
| 2 | 上午（D-029） | 40 | **3457 ms** | 3462 ms | 5（全 `geo-fixed`） | `qo=656650` |
| 3 | **17:19（跨时段复采，D-030）** | 40 | **3488 ms** | 3488 ms | 5（全 `geo-fixed`） | `MemAvailable 2.65–2.91 GB`、load1 ≤0.53、soffice 0 |

三轮全量 P95 均 ≥3s，`>3s` 次数恒为 5 且全落在 `geo-fixed`；`exact=0/120`、非 JSON 0、错误 0。跨时段复采未回落到 <3s ⇒ **falsifier #1「本轮偶发负载」被否证**；但按 P-021 §2 ⑥ **不宣称达标、不归因切题、不触发回滚**。

🔴 三轮的「首轮 P95」并不一致（2405 / 2312 / **4069** ms）⇒ 首轮不是稳定的快/慢档，**不得**用「首轮」或「warm」任一子集替代全量 40 次作为达标判据。

## 5. 禁止事项（等同放宽硬闸）

1. 只报暖机后数据、剔除 `geo-fixed`、剔除 `>3s` 样本、改用 P90 / 均值 / 最小值代替 P95。
2. 改 P95 算法（如插值法）、改样本量后再与本协议数字并列比较。
3. 为了让数字达标而改 `MAX_DEEP_FILES`、8s 预算、判定层、缓存版本或预热服务。
4. 把「观察到稳态长尾」表述为「已定位根因 / 修复有效 / P95 达标 / 命中提升 / 误判归零」。
5. 用本协议 5 条构造题外推真实用户 query 分布、计算召回率或学习结果指标（`0021 review_events` 仍 **0 行**）。

## 6. 修订规则

协议变更须：①新版本号 + 独立 D 号；②在 `P-021` 或新提案中写明变更理由与影响的红线；③旧协议数据**保留但不与新数据合并**；④`method:check` / `verify:gate` 全绿。任何以「让 P95 数字达标」为目的的修订一律不受理。
