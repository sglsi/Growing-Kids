## 2. 六栏（GK-OPS-22 §3.1）

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——不新增学习行为，只保护「参考例题的题干能不能被看懂」这一呈现前提。** 与 P-018 / P-020 同口径：图插错位置会让题干与图对不上，修的是**呈现正确性**，不改善 L1/L2/L3 任一条效果量，也不进入 `0021` 分组。

若评审认为归因不足，按 P-008 / P-019 / P-020 写法：**当作「不涉及判据的索引与呈现工程」，直接走 ⑥ 的显式不宣称**，本提案证据强度不依赖判据归属成立。

**L1（本提案，仅评估）**：产出 F4 与 Q5 的放行前置链、代价与红线、逐题确认清单。
**L2（不做）**：改 `netdisk-inline-build.mjs` 候选 SQL、写 `question_inline_figures`、产图落盘、升 M42 v3、`w:object` 转 LaTeX、公式识别、向量召回 / Reranker、`question-match.ts` 改动、P0 六闸调整、`strict=1`、第二层准入。
**L3（不做）**：复习排程、隐私口径、`0021` 分组、身份治理、正式版发布 10 项前提。

### ② 归因（不变量 / 约束 / 准则）

- **不变量 A（判定层零改动）**：`shared/question-match.ts` 一行不动，sha256 与 M35–M42 钉住值一致；**库变大 ≠ 放行变宽**。
- **不变量 B（定位不到不入库不下发）**：沿用 P-018 铁律；F0 哈希不符、F2 无唯一最近、F3 未定性 OLE、`offset_zero` 语义不正 ⇒ **一律不产出该图**，绝不拿相邻题 / 占位图顶替。
- **不变量 C（同源）**：重转产物 `sha256(extract_docx 流 stripNul+slice(0,200000))` 必须等于 `doc_convert_done.text_sha256`（F0）；同源只钉文字流，不得用文件哈希。
- **不变量 D（只写白名单表 / 列）**：只写 `question_inline_figures` + `question_inline_done` + 内容寻址 `figures/<2>/<sha>.webp`；**绝不改** `netdisk_files` / `question_objects` / `question_figures` / `text_content`。
- **不变量 E（隔离与幂等）**：唯一键 `(user_id, source_type, source_id, object_index)`；无 RLS ⇒ 查询必带 `.eq('user_id', …)`；`question_inline_done` 记账保证断点续跑。
- **约束**：C-资源（L3 4C/3.7G、≤2 worker、cgroup、`nice19` / `ionice -c3`、独立 LO profile、`MemAvailable<700MB` 等待）、C-正确性（图与题干对应）、C-呈现（RichText 行内混排）、C-口径（测量协议 v1.0 不可换口径比较）。
- **准则**：`GK-SRS-20a M10`（宣称不超能力）/ `M11`（如实告知不是拦截）/ `M8`（不进 `0021` 分组）；`GK-OPS-22 §4` 举证责任倒置。

### ③ 证据（20b 条目 + 级别）

| 条目 | 级别 | 量级 | 边界 |
|---|---|---|---|
| **20b 无对应条目** | — | 「老格式转换产物的图能否插回题干」不是学习干预 | Q1/Q2 不适用；Q3 **不可测**（`0021 review_events` 仍 **0 行**）⇒ `OPS-22 §3.2` 判 **D（降维）**：只做正确性工程，不做指标、不做宣称 |
| P-018 docx 原件全量 | 项目实测 | 7,286 份 / 273,037 张 / 越界 0 | 该链路在**原件 docx** 上全量验证过；不复用其「可抽率」到 `.doc` |
| P-020 阶段 1（28 份） | 生产样本 | `ok=25 / f0_reject=1 / no_marks=2`、F2 纠正 3、越界 0 | 首批 30 份试点，不外推 |

参照系是「`char_offset` 是否落在正确题干内、插入点上下文是否为题目文字、越界是否为 0、判定层 sha256 是否漂移」，**不是学习结果、不是命中率、不是召回率**。

### ④ 算子（T / D / X）

- **T 移植**：若将来批准，原样复用 P-018 的 `parse_docx` → PDF bbox 裁切 → `grab_figure` → `save_webp` → `question_inline_figures` → 前端 `RichText` 行内混排；前端与共享契约一行不改。
- **D 降维**：接受「`.doc` 必须重转」且只保证文字流同源；接受 OLE 性质未定 ⇒ 未定性前不入库；接受多重匹配无唯一最近时丢图；接受 `offset_zero` 语义不正时丢图。对外宣称降级为「这批老格式资料的部分题目可能带图」。
- **X 禁止**：改判定层或放宽任一硬闸；跳过 F0；把 `w:object` 直接当公式；拿相邻题 / 占位图顶替；在批准前扩 `inline-build` 候选 SQL；把「覆盖率 14.5%」说成「全量通过」；计算召回率；宣称命中提升 / 修复有效 / 误判归零 / 题题有图 / 所有用户已可用。

### ⑤ falsifier（产品内可采集，写明复核时点）

| # | 若判断错了，会先看到什么 | 复核时点 |
|---|---|---|
| 1 | `.doc` 来源 `char_offset` 越界 > 0 或插到题干之外 | 每批结束 SQL 全扫；上线前全库一次 |
| 2 | 多重匹配题的图出现在答案卷 / 重复段落（串题） | F2 后抽样 ≥30 条人工核对上下文 |
| 3 | `U+FFFD` 文档被误放行 | 每批统计 `text_sha256` 不符并跳过数 |
| 4 | `w:object` 被当公式裁出错误图片 | F3 定性前，`.doc` 来源 `kind='formula'` 必须为 0 |
| 5 | 重转图对象数与 `doc_convert_done` 记账不一致 | 每批对账，差异即停 |
| 6 | `offset_zero` / 数字残串处的图被下发 | **新增**：每批统计 `char_offset=0` 且上下文非题目文字的条数，须为 0 |
| 7 | `question-match.ts` sha256 漂移、`CACHE_VERSION` 被顺手 bump、`answer` 非空或 `verified=true` | 部署前后各一次，M35–M42 |
| 8 | 批次期间 `health` 非 200 / 内存 <700MB / 孤儿 soffice | 每批前查，长跑全程轮询 |
| 9 | 文案写成「题题有图 / 看懂图形 / 命中提升」 | 提案、台账、日志、前端文案四处逐字复核 |

### ⑥ 验收断言（显式不宣称 + 静态门）
