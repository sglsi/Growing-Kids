## 1. 触发：D-025 的结论被复判推翻

`D-025` 用「`parse_docx` 的 `plain` 流与 `text_content` 流**逐字同源**」判定阶段 3 不通过（14/24 错位）。但 P-018 抠图主链路用的是 `norm()` 去空白后的锚点重定位（`ns.find(ns_stem)` + `offset_in_stem`），**从不依赖逐字对齐**；D-025 自己记录的差异也全部是空白折叠。

独立实证（详见 `docs/reports/P-019-阶段3-坐标系复判与定位链路实证报告.md`）：生产 28 份 `.doc`、1,250 个真实 `question_objects`，直接 import 两个真相源跑完整定位链路 ⇒ document 正文非空白流 **28/28 一致**、13 份页眉页脚差异 **13/13 是严格前缀追加**、`stemInHeaderFooter=0`、stem 命中 **1,160**、`offset` 越界 **0**。

⇒ 真实结论不是「坐标系坏了」，而是「判据选错参照系」。但复判同时暴露 4 个真问题，必须闸门化后才能谈放行：

| # | 真问题 | 实证 |
|---|---|---|
| 1 | 1 份写入流把「知」写成 2 个 `U+FFFD` | 双次转换一致、`db_matches_recorded=true` ⇒ 写入 CLI 编码瑕疵，非转换非确定性 |
| 2 | 65 个 stem 全文多重匹配，`ns.find()` 取首次 | 消歧实证 244 对象中**抓到 3 处会选错** |
| 3 | 28 个 `w:object` 被标 `formula`，性质未定 | 可能是 MathType / 嵌入表 / 其它 OLE |
| 4 | `inline-build` 候选 SQL 写死 `ext='docx'` | `.doc` 不在链路内；阶段 1 docx 产物用完即删，必须重转 |

🔴 按 `GK-OPS-22`，扩展 `question_inline_figures` 写入范围属 **L1 索引/呈现工程**且触碰 P-018 现网链路，必须独立提案 + 台账 D 号 + 二次评审，**不得塞进 P-019 收尾**。

## 2. 六栏（GK-OPS-22 §3.1）

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——不新增学习行为，只保护「参考例题的题干能不能被看懂」这一呈现前提。** 与 P-018 同口径：图若插错位置，孩子看到的题干与图对不上，这份资料就失去参考意义；修的是**呈现正确性**，不是学习机制，也不改善 L1/L2/L3 任一条效果量。

若评审认为该归因不足，按 P-008 / P-019 写法：**当作「不涉及判据的索引与呈现工程」，直接走 ⑥ 的显式不宣称**，本提案证据强度不依赖判据归属成立。

**L1（本提案）**：在 P-018 链路上为 `.doc` 转换产物增加 F0–F4 五道闸门，使 `question_inline_figures` 能安全覆盖 `.doc`；判定层、前端、`CACHE_VERSION` 均不动。
**L2（不做）**：`w:object` 转 LaTeX、公式识别、版面还原、向量召回、Reranker、`question-match.ts` 改动、P0 六条硬闸调整、`strict=1`、第二层上线准入。
**L3（不做）**：复习排程、隐私口径、`0021` 分组、身份治理、正式版发布与 10 项前提。

### ② 归因（不变量 / 约束 / 准则）

- **不变量 A（判定层零改动）**：`shared/question-match.ts` 一行不动，sha256 与 M35–M40 钉住值一致。**库变大 ≠ 放行变宽**：P0 六条硬闸串联否决，本提案不碰。
- **不变量 B（定位不到不入库不下发）**：沿用 P-018 铁律。F2 无唯一最近匹配、F0 哈希不符、F3 未定性 OLE、图 bbox 挑不到 ⇒ 一律**不产出该图**，绝不拿相邻题/相邻行顶替。
- **不变量 C（同源）**：重转产物的 `sha256(extract_docx 流)` 必须等于 `doc_convert_done.text_sha256`（F0）。同源只钉**文字流**：D-024 已证 docx 二进制 12/12 全不同，不得用文件哈希。
- **不变量 D（只写白名单表/列）**：只写 `question_inline_figures` + `question_inline_done` + 内容寻址的 `figures/<2>/<sha>.webp`；**绝不改** `netdisk_files` / `question_objects` / `question_figures` / `text_content`。
- **不变量 E（隔离与幂等）**：唯一键 `(user_id, source_type, source_id, object_index)`；无 RLS ⇒ 查询必带 `.eq('user_id', …)`；`question_inline_done` 记账保证断点续跑。
- **约束**：C-资源（4C/3.7G、与 `gk-p019-stage1` 全量并存、`gk-api` 全程可用；长任务守 ≤2 worker / cgroup / `nice19` / `ionice -c3` / 独立 profile）；`GK-SRS-20a M10`（宣称不超能力）、`M11`（如实告知不是拦截）、`M8`（不进 `0021` 分组）；个人主体 ⇒ 只做私有自用索引。
- **归因**：C-正确性（图与题干对应）＋ C-呈现（延续 P-018 的 RichText 行内混排）＋ C-资源（重转 + PDF 渲染开销）。

### ④ 算子（T / D / X）

- **T 移植**：原样复用 P-018 的 `parse_docx` → PDF bbox 裁切 → `grab_figure` → `save_webp` → `question_inline_figures` → 前端 `RichText` 行内混排；前端与共享契约**一行不改**。
- **D 降维**：接受「`.doc` 必须重转」且重转只保证文字流同源（F0 兜住编码瑕疵）；接受 OLE 公式性质未定 ⇒ 未定性前不入库；接受多重匹配时无法唯一消歧的题直接丢图。对外宣称降级为「这批老格式资料的部分题目可能带图」，不得说成「题题有图」。
- **X 禁止**：改判定层或放宽任一硬闸；跳过 F0 同源校验；把 `w:object` 直接当公式；把「逐字同源」重新写成硬门；拿相邻题/占位图顶替；在未批准前扩 `inline-build` 候选 SQL；把 `norm()` 链路可用说成「命中提升 / 修复有效 / 误判归零」；计算召回率；未发正式版前说「所有用户已可用」。
