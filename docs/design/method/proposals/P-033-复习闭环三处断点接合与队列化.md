# P-033 · 复习闭环三处断点接合与队列化（学习行为类 · L1）

> 提案号：P-033 ｜ 状态：已批准（语义与范围经思傅 2026-11-18 逐题确认）｜ 日期：2026-11-18 ｜ 关联决策：D-095（待建）｜ 关联缺口：**C1 掌握梯度**（M7/M15 的落地形态；本提案不新增判据，只把已判定结果接到界面）与 **C4 复习排程的执行率**（不涉 C5 交错、不涉 C2 信心、不涉 C3 错因）
> 🔴 需求原文：思傅 2026-11-18「我们先把我们的工作做好，即先将科学学习方法的流程打通，比如家长先录入错题…在一段时间内进行复习/背记…标记已掌握，移出当前列表或复习本，未移出的和新加入的一起继续复习…其在使用的过程中，知识的录入、标记及相关内容的移出本身就是一个流程的反馈…即将方法论和便捷性操作相结合，而不是机械地执行流程」。

> 本提案改的是**学习行为**（掌握判定、入本默认、复习作答路径），按 OPS-22 §2 属 **L1 功能级**：需六栏 + 比对 M1–M11 + 至少一条断言。

## 1. 触发与现状（实测代码，不是推测）

思傅设想的闭环是「录入 → 隔段时间复习 → 再复习 → 标记掌握 → 移出 → 未移出的与新加入继续」。逐环核对代码，**七环里四环已通、三处断开**：

| 环节 | 代码实况 | 判定 |
|---|---|---|
| ① 录入 | `create`/`createBatch` 建题走表默认值 `in_review_book default false`（`migrations/0010_review_book.sql:16`、`0002_fresh_schema.sql:71`）；`recognize` 页全文无「加入复习本」字样 | ❌ **断**：录完不进本，需另到首页/详情手动加入 |
| ② 到期复习 | `timeline/review.ts` 五档 1/3/7/14/28；`addToReviewBook` 给未排程条目补第一档（`timeline.service.ts:965-980`） | ✅ 通 |
| ③ 再复习 | `advanceReview` 做对推进、**做错 `review_count` 归零**并回第 1 档（`review.ts` wrong 分支） | ✅ 通 |
| ④ 标记掌握 | `mastered` 只写 `mastered/mastered_at`（`timeline.service.ts:845-847`），语义是「汇总导出默认不纳入」（`summary/index.tsx:86`）；与复习本无任何联动 | ⚠️ **语义错位** |
| ⑤ 移出 | `removeFromReviewBook` 置 `in_review_book=false`（`timeline.service.ts:993-1008`），入口在详情「★已加入复习本」与列表「…→移出」 | ❌ **断**：标掌握不触发出本，两个动作两个位置 |
| ⑥ 未移出+新增继续 | 复习列表只 `.eq('in_review_book', true)`（`timeline.service.ts:286`；到期统计 `:1180-1182`），**不看 mastered** | ❌ **断**：标了「已掌握」仍占待办位 |
| ⑦ 反馈 | `review()` 内直接 `insert review_events`（`timeline.service.ts:1054-1075`；失败只记日志不阻断作答） | ✅ 通，且正是思傅所说「流程本身即反馈」 |

**决定性事实（本提案的支点）**：`advanceReview` 的 `wrong` 分支返回 `review_count: 0`，故「五档走完」严格等价于**连续 5 次成功提取**——这正是 20a M15「毕业：连续 5 次做对」的定义、也是 M7「做成的次数 > 夸奖」的落地形态。但毕业时只置 `next_review_at=null`，`in_review_book` 仍为 true，`detail:1104` 文案甚至明写「五档都做对了，这题已经稳了（仍留在复习本）」。**机制已经实现，结果却没有界面后果**。

**第二处实测**：复习作答按钮只存在于单题详情（`detail:1138`「做错了」/ `:1143`「做对了」）；列表卡片 `review-item-card.tsx` 只有徽标、无作答入口。故一次复习的实际操作是：进复习本 → 点开一题 → 滚动到复习区 → 点按钮 → 返回列表 → 下一题。复习本页已有「今天该复习 N 题」横幅（`subject/index.tsx:751`）却没有「开始复习」的连续入口。

**第三处实测**：系统内并存三个互不联动的「完成」状态——`mastered`（只管导出）、`in_review_book`（管待办）、五档毕业（停排程但不出本）。家长要自行维护三套状态，这是「机械执行感」的结构来源，不是意志力问题。

## 2. 落地口径

| 编号 | 改动 | 具体口径 |
|---|---|---|
| **A** 录入即入本 | `create`/`createBatch` 落库时 `in_review_book=true` + `added_to_review_at=now` + `next_review_at=首档（+1 天）` | 录入错题这一动作本身即为「我要掌握它」的声明，不再追问第二次。误录兜底＝移出（可见噪音），优于此前的漏加入（静默失败） |
| **B** mastered 降级为导出口径 | 详情页「已掌握」改名「不进入导出」并加说明；明确「是否继续复习由五档自动判定」；**不删字段、不改导出默认** | 存量 `mastered=true` 且仍在本的题不自动改（不代猜用户意图），仅在详情页提示「已标为不进导出，仍在复习本中」 |
| **C** 毕业自动出本 | `review()` 中当 `adv.review_count >= REVIEW_STAGES` 时同一事务内同时置 `in_review_book=false`、`added_to_review_at=null`；保留 `review_count/review_lapses` | 新增迁移一次性处理存量「`review_count>=5` 且 `in_review_book=true`」的题；详情页毕业文案改为「已自动移出复习本，可在复习本找回」 |
| **D** 复习队列 | 复习本「今天该复习 N 题」旁加「开始复习」→ 队列视图：一次一题、卡上直接「做对了/做错了」、作答后自动下一题、全部完成后给一句总结 | 队列顺序＝到期升序（逾期在前），不做智能排序/难度加权（M8 明确不实现自适应）；作答复用 `markReviewed` → `review()`，不新增写入路径 |
| 断言 | 新增 `server/scripts/verify/modules/73-review-loop-closure.mjs` | 锁定 A/B/C/D 四条与边界（见 ⑥） |
| 边界 | 不改五档数值、不改 M7/M15 判据、不动 `question-match.ts`、不动 `review_events` 口径、不改导出默认 | — |

## 3. 六栏（归因门硬结构）

### ① 判据（L1 / L2 / L3）

- **L1（事实·延迟/无提示的提取是否真的发生）**：A 决定机制是否**开始**（不入本则永不到期，`review_events` 永无该题的行）；C 决定机制是否**收尾**（毕业不出本则「已掌握」在界面上不存在，家长只能自己记）；D 决定机制是否**会被执行**（逐题进详情把一次复习拆成 5 步，是执行率的结构性杀手）。三者共同决定「到期首次作答」这一唯一够格指标能否积累出样本。
- **L2（无提示/工程判断）**：队列作答页**只显示题干，不显示答案与解析**，作答后再进详情看解析——这是 M10/L2 的物理保证：答案不在同一屏，就没有「看着答案点做对了」的路径。B 项把 `mastered` 从「掌握判定」降级为「导出偏好」，是为了让系统成为掌握的唯一判定者（M7/M15），避免与家长自我判断形成两套权威。
- **L3（迁移/不宣称）**：**不宣称**本改动提高学习成绩或提高记忆保持；**不宣称**移出率、掌握率、复习次数可作效果证据（它们只属 GK-SRS-24 §2.5 的 F-1/F-2 采纳度层，永不得升格为 F-3）；**不宣称**真机已验证或已面客。

### ② 归因（不变量 / 约束 / 准则）

- **不变量**：`REVIEW_INTERVALS = [1,3,7,14,28]` 与 `REVIEW_STAGES` 一字不动（M8）；`advanceReview` 的「做错归零」语义不动；`server/src/shared/question-match.ts` 一行未改；`review_events` 的六列写入口径不动（`0021` 迁移）；`mastered` 字段与其导出默认行为保留（B 只改界面语义与文案，不删列、不改默认）。
- **约束**：① 复习列表的 `in_review_book=true` 过滤在 `timeline.service.ts:286`（列表）、`:1180-1182`（到期统计）两处，C 项出本后两处必须同时正确——否则「待办数字」与「列表条数」打架；② 毕业出本**必须保留** `review_count/review_lapses`（`removeFromReviewBook` 现有注释即按此约定：再次加入从原档位继续，不白费之前的复习）；③ 队列作答必须走既有 `markReviewed` 端点，不得新开写入路径（否则埋点分叉）；④ 队列模式必须在作答复用同一事务语义，中断（杀小程序）后重进不重复计数。
- **准则**：M7（提升做成过的次数，而非夸出来的信心感）——C 项即其机制化；M15（毕业＝连续 5 次做对）——C 项是其界面化，不是新判据；M3（不得只显示「已复习 N 次」，必须显示下次/今天/逾期）——队列卡沿用该口径；M10（不可测则诚实降级）；M11（不做激励门槛、不施压）——队列完成页只陈述「今天 N 题完成」，不做连续天数、不打分、不排名。

### ③ 证据（20b 条目 + 级别）

- **代码级**：`server/src/timeline/timeline.service.ts`（create/createBatch 入本、review 毕业出本）、`server/src/timeline/review.ts`（`advanceReview` 归零分支，作为「五档＝连续 5 次」的依据）、`migrations/0010_review_book.sql:16`（默认 false 的来处）、`src/pages/detail/index.tsx`（945 开关、1095-1150 复习区）、`src/pages/subject/index.tsx`（740-790 待复习横幅与列表）、`src/components/review-item-card.tsx`、`src/services/api.ts`（`markReviewed`）。
- **守卫级**：新增 `73-review-loop-closure.mjs`；既有 `M15`（间隔表硬断言）、`M71`、`M72` 与 `M12/13/16/18` 门禁不得回退。
- **实证级**：`GK-SRS-24` §2.3 的三条代码实测（C3 展示位已在、C6 天然延迟、C1 可降维）；`D-044` 实测 `review_events` 生产 0 行；20b `A5`「掌握只有一级台阶」与 `A6`（C4 已落地）的现状描述。
- **证据级别说明**：本提案**不引入新文献主张**，全部机制沿用 20b 已有条目（M7 引 Sitzmann & Yeo 2013 / Byars-Winston 2017 / Robbins 2004，ρ=.496；掌握学习 d=0.52；分散 0.85 / 提取 0.74）。新增的只是「同一机制如何少两次操作」的工程判断，按 L2 处理，不冒充证据。

### ④ 算子（T / D / X）

- **T（移植）**：把已存在的四段能力（建题、入本排程、五档判定、出本）接成一条连续路径，机制本身零新增。
- **D（降维）**：队列化只做「到期升序顺序推进」，不做智能排序、难度加权、动态调参；`mastered` 不删除只降级；C 项不引入「掌握度分数」这类不可测中间量。
- **X（明确不做）**：不做自适应算法 SM-2/FSRS（20b 已证 Latimier 2021 递增 vs 均匀 g=0.034, p=.59）；不做连续打卡/成长值/排名（M3 挤出效应、M11 边界）；不做订阅消息推送（项目零订阅能力 + M11 只许陈述事实，见 GK-SRS-24 §2.5）；不做 AI 推断掌握或错因、不做生成同类题（个人主体下 K1 硬约束）；不改判定层。
- **宣称同步降级**：对外只能说「复习少两步、不用自己记什么时候该复习」，不得写成「提高记忆效果 / 提分 / 让孩子更爱学」。

### ⑤ falsifier

- 若改后仍需手动「加入复习本」才能复习新录的题 → A 未生效（可能 `create` 走的是另一条落库路径，或 `default` 覆盖了显式赋值）。
- 若五档毕业的题仍出现在复习本列表或仍计入「今天该复习 N 题」 → C 未生效，或 `:286` 与 `:1180` 两处过滤未同步（此时数字与列表会互相矛盾）。
- 若队列模式下作答后 `review_events` 无新增行 → D 走错了写入路径（绕过了 `review()`），须立即回退。
- 若导出默认口径发生变化（纳入范围变多/变少、含答案默认翻转）→ B 越界，回滚。
- 若队列中途退出再进入出现重复计数或进度错乱 → D 的状态管理有缺陷，退回列表逐个进入模式（列表模式必须始终保留为可用兜底）。
- 若出本后家长无法「找回」已掌握题（在复习本里看不到、也没法恢复）→ C 造成数据不可逆的可感知损失，须补回恢复入口或撤回自动出本。

### ⑥ 验收断言

- 静态：`73` 模块 ≥6/6（A 入本默认 / C 毕业出本且保留计数 / 两处过滤同步 / D 走 `markReviewed` 且队列卡不含答案 / B 不删列不改导出默认 / `review.ts` 五档与归零分支未动）；`M15`、`M71`、`M72` 不回退；`method-gates` H1/H2/H3 三绿；`verify:ci` 全绿。
- 构建：`nest build` RC=0；前端 `tsc --noEmit` RC=0；`build:weapp` 通过。
- 显式**不宣称**：效果提升、掌握率可信、真机已验证、已面客；放行前实证项见 §4。
