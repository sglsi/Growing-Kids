## 1. 触发与现状（实测代码，不是推测）

- `src/pages/library/index.tsx` 的合成排序页：D-064 落地的是「长按激活 → 拖到目标格 → 松手落位」，但 `touchmove` **只挂在 `ScrollView` 上**，格子矩形只在 `onLongPress` 回调里异步量一次；手势起点在格子（子节点）上，`scrollY={!dragging}` 一翻转就打断手势序列 ⇒ 思傅实测「长按已激活（选中条出现）但拖不动」。
- 同页全屏预览层只有 `Swiper + <Image mode="aspectFit">`，**没有任何编辑能力**；左右滑动看不同图是 D-064 唯一能力。
- 项目已有成熟 `src/components/image-editor.tsx`（裁剪／四角透视／高清／**只有右转 90°**），但 `library/index.tsx` 从未引用它；`handleOpen()` 图片资料走 `Taro.previewMedia` 直接看，不进编辑器。
- `library_docs` 无文件夹字段，全仓无目录树实现；`load()` 的缓存 key 只带 `keyword/subjectId/grade/pageSize`。

## 2. 四项拍板与实施口径

| # | 问题 | 结论 |
|---|---|---|
| Q1 | 拖动 | **缺陷修复**：保留长按激活，但必须真能拖动；不得改成 `movable-view` 自由拖拽（P-029 已排除） |
| Q2 | 预览编辑写回口径 | 放大＝只查看、**不写回**；旋转／裁剪＝写回 `composeItems[i].path`，**参与最终 PDF** |
| Q3 | 左转 90° | 通用编辑器 + 合成页预览**两处都加**；左转 = 顺时针 270°，复用既有 270° 分支 |
| Q4 | 文件夹层级 | **无限层级树**（`parent_id` 自引用）；删除文件夹＝软删 + 内容提升到父级，**绝不删资料** |

### ① 判据（L1 / L2 / L3）

- **L1（事实）**：微信触摸事件同时给 `clientX/clientY` 与 `pageX/pageY`，`boundingClientRect()` 是视口口径；`canvasToTempFilePath` 的 CSS／缓冲口径歧义已在 `image-editor.tsx` 用「CSS == 缓冲 1:1 + 原点全区域导出 + 显式 destWidth/destHeight」解决；本库**无 RLS**，所有 `.from()` 链必须带 `.eq('user_id', …)`；PG text 不收 U+0000；`uploadFile`／`request` 超时硬顶 60s。
- **L2（工程判断）**：① 手势必须收在**稳定的根 `View`**（而非会随 `scrollY` 重建的 `ScrollView`）并在 `touchstart` 提前量矩形，多个祖先同时收事件就必须用 ref 给 `endDrag` 去重复，否则一次松手会移两次；② 只做 CSS `rotate` 不会进成品，因为合成上传的是本地文件 `path`，必须用离屏 Canvas **烘焙成新临时文件**；③ 新前端必须能打旧后端（`0033` 未执行时 `library_docs.folder_id` 不存在），因此先探测 `/api/library/folders` 再决定是否传 `folder_id`，且后端只在**显式传了**该字段时才碰新列；④ 文件夹名是用户主动输入的短文本 ⇒ 过 `UgcTextGuard`。
- **L3（不宣称）**：不宣称真机手势已验证（静态守卫与离线实证只证明纯函数与编译产物）；不宣称 Canvas 旋转在真机一定出图；不宣称文件夹已可面客；不宣称无损编辑；不宣称「所有用户可用」。

### ② 归因（不变量 / 约束 / 准则）

- **不变量**：`shared/question-match.ts` 六条 P0 硬闸与判定层**一行未动**；`CACHE_VERSION` 保持 **v17**（不改召回源、不改 `note`/result 结构）；一图一页、keys 顺序即页序、只建 1 条 `library_docs`、上限 20、`purpose='temp'` 全部不变；M51 A1–A9 与 D-064 的 `确定／开始合成` 两段、暂存框、`-N-` 页码、Swiper 全保留；r11 政策、`urlCheck`／`__usePrivacyCheck__` 两门不动。
- **约束**：`0033` 只加表与列，**不在本轮执行到任何库**；文件夹路由独立挂 `/api/library/folders`（避免被 `@Patch(':id')` 吃掉），4 个端点全 `requireUserId()`，不进 `PUBLIC_ROUTES`；文件夹查询链全带 `user_id`；移动文件夹沿 parent 链查环（`MAX_DEPTH=32`）；软删把资料与子文件夹提升到父级；空串／`'root'` 归一为 NULL，不当外键写；合成与上传只在能力探测成功时透传 `folder_id`。
- **准则**：同一能力只留一份实现（裁剪复用 `ImageEditor`，旋转坐标口径复用其已验证方案）；纯函数可离线执行（`folderPathOf` / `subtreeIds` / `folderTreeRows` / `hitCellIndex`）；best-effort 分支必须打全错；删除必须可撤销／不丢文件；改动可回滚、可由静态守卫与离线实证复验。

### ④ 算子（T / D / X）

- **T（转换）**：
  - 拖动：`touchstart`（提前 `measureCells()`）→ `onLongPress` 激活 → `touchmove` 收在根 `View`／`ScrollView`／网格 `View` → `hitCellIndex(rects,x,y)` 命中或最近格子兜底 → 跟手浮层 + 目标格绿框 → `touchend` 用 `dragActiveRef` 去重复后 `moveCompose(from,to)`。
  - 预览编辑：`放大` → `Taro.previewImage`（不写回）；`左转/右转 90°` → `rotateImageFile()` 离屏 Canvas 烘焙 → `setComposeImage(idx,out)`；`裁剪` → 关预览 → `ImageEditor(cropOnly)` → `onConfirm` → `setComposeImage(idx,path)` → 重开预览。复核态里编辑会退回调整态重新「确定」。
  - 文件夹：`fetchLibraryFolders()` 能力探测 → 面包屑／当前层子目录 → 新建·改名·移动·软删 → `fetchLibrary({folderId})` 只列当前层 → 上传／合成透传 `folder_id` → 资料卡「⋯」可移动到任意层级。
- **D（判定）**：文件夹写入前 `assertFolder()` 校验归属；名字过 `UgcTextGuard`；移动沿 parent 链查环；`normalizeName()` trim + 去 NUL + ≤60 字；落点距所有格子 >1.6 格宽返回 -1；探测失败 ⇒ `folderSupportedRef=false` ⇒ 不传 `folder_id`，列表退回全量旧口径。
- **X（排除）**：不上 `movable-view` 自由拖拽；不用 CSS rotate 冒充写回；不把放大结果写回；不把文件夹做成免登录；不硬删任何资料或行；不递归删子树；不递归查 UI 树（32 层硬闸）；不改判定层、不加向量召回／Reranker／LLM 兜底；不在本轮执行 migration 或发货。

### ⑤ falsifier

- 若 `onTouchMove` 仍只挂 `ScrollView`、或矩形只在长按回调里量 ⇒ 拖动缺陷未修，判失败。
- 若多个祖先 `touchend` 导致一次拖拽移动两位 ⇒ 去重失效，判失败。
- 若旋转只改 CSS 而不产出新临时文件、或预览放大结果写回 `path` ⇒ 写回口径被破坏，判失败。
- 若通用编辑器与合成页只在一处有左转 90° ⇒ Q3 未落地，判失败。
- 若 `0033` 未执行时新前端把 `folder_id` 传到旧库导致资料库打不开 ⇒ fail-safe 失效，判失败。
- 若任何文件夹查询缺 `.eq('user_id', …)`、或删除文件夹会删资料／递归删子树 ⇒ 隔离与安全口径失效，判失败。
- 若文件夹层级被写死为 1 或 2 层，或移动时可把文件夹放进自己的子目录 ⇒ 无限层级／防成环失效，判失败。
- 若 M51 / D-064 任一既有断言被改掉以「让新代码通过」 ⇒ 判失败（红线：不得靠改断言放行）。
