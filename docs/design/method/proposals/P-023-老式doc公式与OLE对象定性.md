## 1. 触发：F5 解决「图插在哪」，解决不了「题干有没有字」

D-032 §4② 在 40 条分层清单里发现老 `.doc` 的**题干文字本身不完整**，肉眼可见：

| 清单条目 | 实际入库题干片段 | 期望内容 |
|---|---|---|
| #3 / #4 / #17–#20 | `如图，在锐角中，是边上不同的两点，使得设和的外心` | `在锐角△ABC 中，P、Q 是边 BC 上不同的两点…设△ABC 和…的外心` |
| #10 | `在 中，已知，,则的值为.` | `在△ABC 中，已知 a, b, C，则 c 的值为…` |
| §4① 第 2/3 条 | `上任取一点（，，），记，的内心分别为，，` | 点名、坐标、∠ 等符号整块消失 |

窄正则下界统计：**F5 放行的 1,354 条候选里 15 条（1.1%）有明显字符丢失痕迹**，且这是保守下界（只数了最显眼的形态）。

⚠️ 这与 P-018 在 **docx 侧**已修复的问题不是同一件事：docx 侧靠 `w:drawing` / `w:object` 原位重建把图/公式**插回**题干；`.doc` 侧连**文字流里该有的字母、点名、坐标**都没有，插图位置再准也读不懂题。

**根因假设（待证伪）**：`ocr-engine/pdf_tool.py::extract_docx()` 用 zip + 正则剥标签生成入库文字流，对 `m:oMath` / `m:oMathPara`（OMML 公式）与 `w:object`（OLE / MathType / VML 公式对象）只保留可见 `<w:t>`，公式内部的 `m:t`、点名、上下标被整块丢弃。P-020 阶段 3 已实证 `w:object` 有 **236 个**（F3 全跳过），但**从未定性这些对象里到底是什么**。

## 2. 六栏（GK-OPS-22 §3.1）

### ① 判据（L1 / L2 / L3）

- **L1**：`.doc` 题干「看得懂」的充分条件不只是图放对，还要求文字流里**该有的符号在**。本提案先定性，不预设修复方案。
- **L2**：`m:oMath` / `w:object` 在重转 docx 中的**标签构成、出现频次、可恢复文本形态**；`extract_docx` 对它们的丢弃行为；丢失字符的形态分类；以及「修复是否触碰已入库坐标系」的二元结论。
- **L3**：不新增学习行为缺口。这是**索引/呈现工程**，与 20a §5.1 三问一致：不改判定层、不改学习规则、不改前端契约。

### ② 归因（不变量 / 约束 / 准则）

| 不变量 | 说明 |
|---|---|
| F0 同源铁律 | `doc_convert_done.text_sha256` 钉住的是**当前入库文字流**；任何文字流变更都会让 10,147 份正文与 **656,898** 个 `question_objects` 的 `char_start` / `stem_text` 坐标失效，必须全量重跑并重新验收 |
| 真相源唯一 | 入库文字流来自 `pdf_tool.py::extract_docx`，**不是 LibreOffice 的文字提取**（P-018 已证：LO 只做 docx→PDF 底图）；换 Word/WPS/COM 不会改变剥标签行为 |
| 公式走 PDF 位图 | P-018 §5.3/§5.4：公式必须 PDF 渲染成 IMAGE 位图，**不做识别**，因此不会「把 ≤ 认成 £」；真实风险是 Symbol 别名丢失让 `≠`/`<`/`−` 静默消失（`assertSymbolFont()`） |
| 定位不到不入库不下发 | 拿不到可靠文字/图就丢，绝不拿相邻题顶替 |
| `w:object` 未定性 | 236 个对象性质未明 ⇒ F3 全跳过是等价保护，但**不能据此声称「已覆盖」** |

### ③ 证据（20b 条目 + 级别）

- D-032 §4② 的 40 条分层清单（方向性证据，**不得计算召回率**、**不外推** 10,147 份全库）。
- P-020 阶段 3 报告：`w:object` 236 个、OLE 全跳过、`offset_zero` 16 处、抽查覆盖 14.5%→100%（F5 后）。
- P-018 §5.3：Symbol 字体别名的静默降质实证。
- 仍为 **0 行** 的 `0021 review_events`：唯一够格的结果指标仍未出数。

### ④ 算子（T / D / X）

只读定性，**T = 抽样重转 docx 的 `word/document.xml`**（不下载全库、不写文件到生产 storage）：

1. **T1 标签普查**：在 D-032 的 200 份分层样本（同 `seed=p020-stage3-v1`）里，统计 `w:object` / `v:shape` / `o:OLEObject` / `m:oMath` / `m:oMathPara` / `m:t` / `w:drawing` 的标签数与共现关系。
2. **T2 对象解剖**：对全部 `w:object` 逐个记录其子节点类型（OLE / VML / 图片 / 公式）、是否含 `w:t` / `m:t` 文本、指向的 `word/embeddings/*` 类型。
3. **T3 丢弃复现**：用 `extract_docx` 对同一份重转 docx 跑一遍，逐字符对比「XML 里存在的 `m:t` 文本」与「入库文字流」，量化被丢弃的字符形态（希腊字母 / 点名 / 坐标 / 运算符 / 上下标 / 数字）。
4. **T4 边界关联**：把 T3 的丢失位置与 D-032 的 15 条疑似残缺候选、142 份 `U+FFFD` 文档做交叉，判断是**同一现象**还是**两类独立问题**。
5. **D 判定**：给出二元结论 ——「修复是否需要重建 `text_content` / `text_sha256` / `question_objects` 坐标系」。
6. **X 不做**：不改 `pdf_tool.py`、不改 `netdisk-inline-crop.py`、不改 `netdisk-inline-build.mjs`、不写任何表、不产图、不发版。

### ⑤ falsifier（产品内可采集，写明复核时点）

| 假设 | 证伪条件 | 复核时点 |
|---|---|---|
| 「缺字主要是 OMML 公式被剥掉」 | T1 显示 `m:oMath` 频次为 0，或 T3 显示 `m:t` 文本并未被丢弃 | T1/T3 出数时 |
| 「缺字主要是 OLE 公式对象」 | T2 显示 `w:object` 里绝大多数是纯图片 / 空 OLE，无可恢复文本 | T2 出数时 |
| 「不动坐标系即可修复」 | T3 显示任何可恢复文本都落在现有文字流**中间**（插入会改变后续所有 `char_start`） | T3 + D 判定时 |
| 「F3 全跳过已等价覆盖」 | T2 发现 `w:object` 内含**可下发的题干文字**（不是图） | T2 出数时 |

任一证伪成立 ⇒ 结论改写，**不得跳过定性直接提修复方案**。

### ⑥ 验收断言（显式不宣称 + 静态门）

- ✅ T1–T4 全部出数，200 份样本逐份可回放；`w:object` 分类覆盖 **100%**（不是抽样外推）。
- ✅ 真相源 `pdf_tool.py` / `netdisk-inline-crop.py` / `question-match.ts` sha **前后一致**；`CACHE_VERSION` 仍 **v14**。
- ✅ 零写入：`question_inline_figures` 的 `.doc` 来源 **0 行**、`qo_total` 仍 **656,898**、`doc_ok` 仍 **10,147**、`health=200`。
- ✅ D 判定为明确的「需要 / 不需要重建坐标系」二元结论，并列出若需要重建的**全量代价**（重跑切题 + 重新验收 + 缓存失效）。
- 🔴 **不宣称**：题干已读懂 / 公式已恢复 / 误判归零 / 图形全覆盖 / 命中提升 / 修复有效 / 所有用户可用；**不计算召回率**；200 份样本**不外推**。
