# P-005 年级属性与按年级检索

> 提案号：P-005 ｜ 状态：已批准 ｜ 日期：2026-11-04 ｜ 关联决策：D-008 ｜ 关联缺口：无（检索归类工程，不新增学习行为缺口）
> 流程依据：`GK-OPS-22` §3.1（六栏）｜ 方法论依据：`GK-SRS-20a` M8 / M10 / M11 ｜ 证据来源：`GK-SRS-20b`（**无对应条目**，见 ③）
> 分档：**L1（功能级）**——改了题目召回的默认行为，对标 §2 判定示例「复习本加按错因筛选」。**不改准则**，故不走 L2，不升 20a 主版本、不补 20b 条目。
> 拍板记录：2026-11-04 思傅「按推荐开始实施」，八项设计决策全取推荐档（见文末）。

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——本提案不新增学习行为，它保护 L1 的「可执行性」。**

诚实说明：按年级检索**不直接改善** L1（隔 N 天还能做对）、L2（无提示）、L3（迁移）中的任何一条。它改善的是「找到该做的那道题」的成本。之所以仍要归到 L1 名下，是因为二者有因果关系：

> 检索把同年级题与跨年级题混在一起 → 用户在结果里逐个辨认「这题是不是我们年级的」 → 辨认成本高到一定程度就放弃检索 → 那道到期该复习的题没有被打开 → **L1 的测量前提（题被做了）根本不发生**。

因此本提案的定位是**保护性**的：不给学习结果加分，只避免「有排程却复习不到」这一执行断点。这也决定了它的宣称必须同步降级（见 ④）：只陈述「优先找同年级的题目」，**不得**说成「提升学习效果」。

> ⚠️ 若评审认为「保护性归因」不足以支撑 L1，可降为「不涉及判据的检索工程」并**直接按 ⑥ 的显式不宣称处理**——本提案的证据强度不依赖判据归属成立。

---

### ② 归因（不变量 / 约束 / 准则）

- **不变量**：无直接不变量。I1 提取 / I2 修正 / I3 间隔均不涉及「检索归类」——**本提案不在学习机制层，在信息组织层**。这一点必须写明，否则会被误读成「按年级出题 = 难度适配」。
- **约束**：**C-资源**（工作记忆与注意力有限）。跨年级混杂的结果集要求用户对每一条做「年级判断」这一与学习无关的加工，属于外在认知负荷（extraneous load），直接挤占本可用于学习的注意力。
- **相关准则**：
  - `GK-SRS-20a M10`：不得宣称能测量 ZPD / 智能水平 —— 年级是**用户自报的静态标签**，不是系统推断的能力水平，二者前提不同；但正因为形似，宣称必须显式降级。
  - `GK-SRS-20a M11`：连续天数 / 停留时长只作引导性展示 —— 本条的外推：未选年级的提醒只能是**引导**，不得成为检索门槛。
  - `GK-SRS-20a M8`：排程用分段常数即——年级**不得**进入复习间隔表或排程计算，两者严格隔离。
- **一句话**：年级是一张**书架标签**，用来让题先被找到；它不是一把**尺子**，不用来量孩子。

### ③ 证据（20b 条目 + 级别）

| 条目 | 级别 | 量级 | 边界 |
|---|---|---|---|
| **20b 无对应条目** | —— | —— | 20b 覆盖提取（I1）、修正（I2）、间隔（I3）、交错、动机、元认知，**不含「按年级检索」这类信息检索工程** |
| 检索范围与结论 | —— | 定性 | 已检索 20b §2–§5 全部条目与 §7 参考文献主题分布：无一条涉及「题目按年级归类」或「年级筛选对学习结果的影响」。**故本提案不引用任何效应量** |

**结论**：无 ≥ B 级证据支撑「按年级检索能提升学习成绩」，因此**不做该宣称**。本提案按 `GK-OPS-22` §3.3 第三关走「**显式不宣称**」——这是该条明文允许的合法选项，不是逃避。

> ⚠️ 反过来说：**不能因为「没有证据表明有效」就否定它**。它是一个可用性问题（找得到 / 找不到），不是学习干预问题（有效 / 无效）。把可用性需求硬塞进效应量框架，才是真正的跨层跳跃。

### ④ 算子（T / D / X）

- **结论：D（降维）**。保留「按年级归类 + 相邻年级兜底」这个机制方向，放弃一切「智能匹配 / 难度适配 / 精准推荐」的精度与宣称。

| 约束 | 内容 | 理由 |
|---|---|---|
| **① 年级只由用户自报** | 不根据做题记录、正确率、题目难度反推年级 | 反推即等于宣称能测量能力水平（`GK-SRS-20a M10`） |
| **② 扩散有硬上限** | 本年级 0 命中才扩散，±1 → ±2 最多两级，去重，结果标注来源年级 | 无上限扩散会退化为「全库召回」，等于没筛 |
| **③ 老题兜底可见** | 存量 `grade is null` 题目在按年级检索时仍然可见 | 现网有存量题目，排除 NULL 会让老题凭空消失（最坏后果是内容看起来丢失） |
| **④ 不碰排程与指标** | 不进 `REVIEW_INTERVALS`、不进「到期首次作答正确率按档位」的分组 | `GK-SRS-20a M8`；结果指标口径唯一，不得被新维度稀释 |

- **边界（不适用条件）**：
  - 只覆盖**本地**题目与资料库检索。`answer-search` / `search-solve` 是**把题面发到外部联网搜**，本地没有年级可过滤，年级只能作为查询词附加、效果不可控 ⇒ **明确不在本次范围**。
  - 不覆盖「按年级出卷 / 按年级推荐题目」——那是另一个提案。
- **明确不做**：年级排行榜、年级对比、班级/学校维度、按年级自动调难度、AI 推断年级、把年级写进任何用户可见的「水平评价」。
- **若为 D，对外宣称同步降级为**：只说「**勾选年级后，优先找同年级的题目**」。禁止「智能匹配」「精准推荐」「适合你的水平」「自适应难度」——这些词目前不在 H2 词表内，但按其依据（M10）的精神同样禁止。

### ⑤ falsifier

若判断错了，会先在产品数据里看到（全部可采集，不需要新埋点之外的推断）：

1. **勾选年级后「检索 → 进入详情」的转化率，与未勾选用户无差异**（差值 < 5 个百分点）。⇒ 年级筛选没有帮到「找到题」，只是加了一步操作。
2. **相邻年级扩散的结果被点开的比例，显著低于本年级命中**。⇒ 扩散在给噪声，应收窄到 ±1 或不扩散。
3. **家长侧「搜不到我们年级的题」反馈占比上升**。⇒ 年级标签本身错得多（录入时默认值用错、升学没跟上），应回退为「不强绑年级」。

配套口径：
- 只做**同一用户前后对比**；跨用户横向比较不做（`20a §5.5`：内部纵向优先）。
- 样本 < 30 次检索时只看趋势，不做显著性表述。
- 复核时点：上线后第 **8 周**（写进台账 D-008）。

### ⑥ 验收断言

| 断言 | 落在哪 | 说明 |
|---|---|---|
| 相邻序列与扩散上限**逐字锁定** | `verify/modules/26-grade.mjs` 新用例 | `grade=3` ⇒ `[3,2,4,1,5]`；`6` 的下一个是 `7`、`9` 的下一个是 `10`（允许跨学段）；`1` 只有`[1,2,3]`、`12` 只有`[12,11,10]`（不越界）；最多 2 级 |
| 本年级有结果时**不扩散** | 同上 | 返回结果的 `grade` 全部等于本年级；混入相邻年级即失败 |
| 未选年级**不拦截** | 同上 | `grade=null` 时请求照常 200、全年级返回；**不得**出现 4xx 或空列表 |
| 老题兜底 | 同上 | `grade is null` 的题目在本年级检索中仍可见 |
| 跨用户隔离 | `check:isolation`（现有门禁） | 新列不改变「查询必须 `.eq('user_id', userId)`」 |
| 文案不含门槛话术 | H2 口径门 | 「勾选年级后，优先找同年级的题目」通过；不得出现「必须勾选才能搜索」 |

> 📌 **三处必须同时改，缺一即静默失败**（C4 与 C3 都踩过同款）：
> **迁移列** → 后端 `SELECT_COLS` / 更新白名单 → 前端类型与渲染。
> 漏一处的表现是「存进去了但读出来是空」，且**不报错**。

## 附：八项设计决策（2026-11-04 拍板，全取推荐档）

| # | 决策 | 取值 |

| 1 | 年级字典 | 12 档，小学 1–6 / 初中 7–9 / 高中 10–12，连续编号 |
