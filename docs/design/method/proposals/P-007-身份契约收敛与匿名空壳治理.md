# P-007 身份契约收敛与匿名空壳治理（D + A + C1）

> 提案号：P-007 ｜ 状态：已批准 ｜ 日期：2026-11-05 ｜ 关联决策：D-010 ｜ 关联缺口：无（身份建号链路、平台隐私申报与「我的」页文案，不新增学习行为缺口）
> 流程依据：`GK-OPS-22` §3.1（六栏）/ §3.2（三问决策）/ §2（L1 分档）｜ 方法论依据：`GK-SRS-20a` M8 / M10 / M11 ｜ 证据来源：`GK-SRS-20b`（**无对应条目**，见 ③）
> 分档：**L1（功能级）**——改了 `/api/auth/anonymous` 的默认建号行为（陌生设备标识不再无条件落一行 `users`），对标 §2 判定示例「导出默认值由『含答案』改为『不含答案』」。**不改 20a 准则**，故不走 L2、不升主版本、不补 20b 条目。
> 拍板记录：2026-11-05 思傅原话「**勾第 7 项并填『允许你在图片预览中保存题目图片到手机相册』；那按签名令牌和 openid 来进行实施；其他先 A、C1**」。即选 **D（补勾第 7 项）+ A（治 197 空壳）+ C1（换手机前登录引导）+ 身份契约（签名令牌 + openid）**；**明确不做** B（换随机算法）、C2（数据迁移码）、C3（自建账号体系）。

---

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——本提案不新增学习行为，它保护「到期复习拿得到自己的题」这一前提。**

诚实说明：改建号时机、补勾一项平台隐私声明、在「我的」页加一行提示，都不改善 L1（隔 N 天还能做对）、L2（无提示）、L3（迁移）中的任何一条。它损害的是更靠前的一环：

> 陌生 `X-Device-Id` 被无脑建成匿名号 → 现网 197 个 users 行里绝大多数是零数据空壳 → 空壳因「滑动续期」永不过期 → 运维无法分辨哪些是真用户、哪些是测试噪声 → 一旦误清理，有题的匿名号（29 个 / 528 道题）被连带删掉 ⇒ **用户到期复习时拿不到自己的题，L1 的测量基准直接消失**。

因此本提案是**保护性**的：不给学习结果加分，只避免「身份层噪声污染数据层」这一执行断点。这也决定了宣称必须同步降级（见 ④）：只陈述「换设备登录同一微信账号即可找回」，**不得**说成「数据永不丢失」「自动同步所有内容」。

> ⚠️ 若评审认为「保护性归因」不足以支撑 L1，可降为「不涉及判据的身份工程 + 合规申报」并**直接按 ⑥ 的显式不宣称处理**——本提案的证据强度不依赖判据归属成立（同 P-005 / P-006 的写法）。

---

### ② 归因（不变量 / 约束 / 准则）

- **不变量**：无直接不变量。I1 提取 / I2 修正 / I3 间隔均不涉及「怎么建 users 行」——**本提案在身份与信息呈现层，不在学习机制层**。
- **约束**：**C-资源**（工作记忆与注意力有限）。换手机后要逐条翻找「我的题去哪了」、运维要在 197 行里逐行分辨空壳，都是与学习无关的外在负荷；把「引导登录」做成强制门槛则会直接挤出正常使用，故只能做成**事实陈述**。
- **相关准则**：
  - `GK-SRS-20a M10`：不得宣称超出能力——「数据会自动同步」**只在已登录（有 openid）时成立**，纯匿名用户换机找不回，必须如实写明，不能包装成「永不丢失」。
  - `GK-SRS-20a M11`：连续天数 / 停留时长只作引导性展示，不得作判定标准——外推到本条：C1 的换机提示是**引导与如实告知**，不是拦截、不是门槛、不逼用户去登录。
  - `GK-SRS-20a M8`：排程用分段常数即可——**明确隔离**：本提案不碰 `REVIEW_INTERVALS`、不碰 `timeline/review.ts`、不进「到期首次作答正确率」分组。
- **一句话**：身份是**装数据的容器**，不是学习功能；把容器修干净，是为了别把孩子做过的题弄丢，不是为了让他多做题。

### ③ 证据（20b 条目 + 级别）

| 条目 | 级别 | 量级 | 边界 |
|---|---|---|---|
| **20b 无对应条目** | —— | —— | 20b 覆盖提取（I1）、修正（I2）、间隔（I3）、交错、动机、元认知，**不含「匿名建号时机」「平台隐私申报」这类身份工程与合规操作** |
| 检索范围与结论 | —— | 定性 | 20b §2–§5 无一条涉及「device_id 生成策略」「users 行数量」或「隐私清单项数」对学习结果的影响。**故本提案不引用任何效应量** |

**结论**：无 ≥ B 级证据支撑「改身份链路能提升学习成绩」，因此**不做该宣称**。本提案按 `GK-OPS-22` §3.3 第三关走「**显式不宣称**」。

**三问决策器（20a §5.1）走一遍，留痕**：
- **Q1 量级**：不适用——没有学习干预，谈不上效应量，不能拿 0.3 门槛硬套（跨层跳跃）。
- **Q2 覆盖**：不适用——同上。
- **Q3 可测**：**不可测**（无产品内指标能把「空壳变少」映射成学习结果）⇒ 按 §3.2 边界情形「Q3 不可测但机制清楚 ⇒ **D**：只做启发式，不做指标、不做宣称」。
- 三问结论：**D（降维）**，与 `GK-OPS-22` §3.3「显式不宣称是合法选项」一致。

> ⚠️ 不能因为「没有证据表明有效」就否定它。这是**数据安全与如实告知**问题（题会不会丢、话有没有说满），不是学习干预问题（有没有用）。

### ④ 算子（T / D / X）

- **结论：D（降维）**。保留「匿名可先用、登录可迁移」这个机制方向，放弃「任何陌生标识都立刻落库」的精度，并放弃「数据自动同步」的全域宣称。

| 约束 | 内容 | 理由 |
|---|---|---|
| **① 信任根不改动** | `X-Auth-Token`（服务端 HMAC 签名）是业务请求唯一被采信的身份；`openid`（`code2session` 服务端返回、跨设备稳定）是唯一身份依据；`device_id` 降级为**登录前临时锚点**，只用于 bootstrap 换令牌与登录时合并匿名数据 | 思傅拍板「按签名令牌和 openid 来进行实施」；改信任根等于重开 `R-技术-09` |
| **② 只增不减、现有用户零影响** | 限流**只拦「新建匿名行」**，绝不影响已存在 `device_id` 的查找、续期、签令牌；清理**只删零数据空壳**，保留 29 个有题匿名号 | 最坏情况只能是「没建成新空壳」，不能是「用户数据分家」（工程教训录 L27） |
| **③ 完全 lazy 建号本轮不做** | 不改令牌格式、不在 bootstrap 阶段取消 `users` 行 | 见下方「明确不做」——令牌 `v1.<userId>.<exp>.<sig>` 绑定真实 `users` 行，物化前无法签票；改成设备票据会动信任根，最坏是数据分家 |
| **④ 第 7 项用途如实填** | 勾「相册（仅写入）」，短句固定为「允许你在图片预览中保存题目图片到手机相册」 | 思傅真机实测点图可保存；保存由 `previewImage` 原生预览器完成，小程序未调用 `saveImageToPhotosAlbum`，属官方「开发者可自主勾选其他项目」，不是接口必填 |
| **⑤ 不碰排程与指标** | 不进 `REVIEW_INTERVALS`、不进结果指标分组 | `GK-SRS-20a M8` 的隔离精神 |

- **边界（不适用条件）**：
  - 只覆盖 `/api/auth/anonymous` 引导建号、`users` 表匿名行、平台隐私指引清单、「我的」页文案；**不覆盖**登录后的业务读写、不改 `auth/login` 迁移逻辑。
  - 限流是**单机进程内**闸门（本项目 L3 单实例）；若将来多实例部署，须换成共享计数，否则每实例各算各的。
  - 清理脚本默认 **dry-run**，必须由人在 L3 上带 `--apply` 执行；本提案**不自动删生产数据**。
- **明确不做**：
  - **完全 lazy 建号**（bootstrap 阶段不落 `users` 行）——令牌契约绑定真实 user id，需改 `signAuthToken` / `verifyAuthToken` / `loadUser` / 前端重放全链路，属 **L2**；按 L27「改到第三版先建复现模型」与「最坏是内容丢失就先改到最坏只是烦恼依旧」的纪律，本轮不做，留待另立提案 + D 号。
  - **B 替换随机算法**（`crypto.randomUUID` / 后端下发 device id）——思傅未选；且随机串碰撞只会让 197 变少，不是空壳成因。
  - **C2 数据迁移码 / C3 自建账号体系**——思傅未选。
  - **AI 解题**、改隐私政策「不做 AI 生成」口径、动 `AI_PUBLIC_ENTRY`——属 L2（同 D-009 边界）。
- **若为 D，对外宣称同步降级为**：只说「**换设备后用同一微信账号登录即可找回**」「**未登录时的匿名内容换机后无法找回**」「**允许你在图片预览中保存题目图片到手机相册**」。禁止「数据永不丢失」「自动同步所有内容」「智能识别设备」「精准找回」——按 M10 精神同样禁止。

### ⑤ falsifier

若判断错了，会先在产品数据里看到（全部可采集，不需要推断）：

1. **闸门没挡住增量**：上线后 `users` 表新建匿名行数在 4 周内仍维持高位（与测试脚本量级相当）⇒ 限流阈值或格式校验太松，需收紧或补按来源 IP 计数。
2. **闸门误伤真实用户**：出现「换手机 / 重装后题目不见了」反馈，且可追到该 `device_id` 被闸门拒绝 ⇒ 限流方向错了，立即回滚闸门（不动数据）。这是**最坏情况**，出现即按 OPS-22 §3.4 改实现。
3. **清理误删**：清理后 30 天内出现「到期复习里少了题」反馈，且能追到被删的匿名号 ⇒ 零数据判定漏了某张表，立即从备份恢复并补断言。
4. **第 7 项被审核质疑**：提审因「相册（仅写入）用途与接口不符」被驳回 ⇒ 按后台实际显示回退为 6 项，或改填更贴用途的短句（**以后台实际显示为准**）。
5. **诚实化被当成倒退**：用户反馈「以前换手机数据还在，现在说找不回」占比上升 ⇒ 说明 C1 文案版本没讲清「仅限已登录」，应改文案，不得退回含糊宣称。

配套口径：只做**同一用户前后对比**；样本 < 30 时只看趋势；复核时点：上线后第 **4 周**（写进台账 D-010），第 4 项在**提审结果出来时**即复核。

### ⑥ 验收断言

| 断言 | 落在哪 | 说明 |
|---|---|---|
| `device_id` 格式校验：合法 `dev_` 串通过、超长/非法字符/空串拒绝 | `verify/modules/28-identity-gate.mjs` | 纯函数单编；**必须含现存格式回归样本**，防止把老用户的 `gk_device_id` 判成非法 |
| 新建闸门：窗口内累计新建超阈值 ⇒ 拒绝；**已有 `device_id` 不受闸门影响** | 同上 | 纯函数 + 源码静态断言：`findOrCreateByDeviceId()` 的 insert 分支前必须过闸门，find 分支不得过 |
| 清理脚本默认 dry-run、带 `--apply` 才删、删前逐表查零数据、`.select('id')` 校行数 | 同上（静态源码断言） | 防「脚本一跑就删生产」；断言含 `--apply` 与 `dryRun` 两个关键串 |
| 身份契约三处一致 | 静态源码断言 | `user-context.ts` / `users.service.ts` / `auth-bootstrap.ts` 头注释均写明「令牌唯一信任根 + openid 唯一身份 + device_id 临时锚点」 |
| C1 文案在「我的」页且不含门槛话术 | 静态源码断言 + H2 口径门 | 含「换手机前」「无法找回」；禁止「必须登录才能用」「解锁」 |
| 隐私清单全篇 7 项、第 7 项用途短句逐字一致 | 静态文档断言 | `GK-QA-16` / 验收记录 / L3 方案 / `7.1` 清单均不得残留「6 项」口径（历史变更记录除外） |
| 跨用户隔离 | `check:isolation`（现有门禁） | 新增查 `users` / 业务表的查询须 `.eq('user_id', userId)` 或按主键 |
| 文案不含禁用宣称词 | H2 口径门 | 「找回」「如实告知」通过；「永不丢失」「智能识别设备」不通过 |

> 📌 **四处必须同时改，缺一即静默失败**：
> **闸门真相源** → `findOrCreateByDeviceId()` insert 分支 → 清理脚本 → 文档/契约注释与验证断言。
> 漏闸门的表现是「197 继续涨」；漏契约注释的表现是「下一个人又把 device_id 当成唯一身份」；漏文档同步的表现是「提审时按 6 项填，第 7 项没勾」。
