## 六栏（GK-OPS-22 §3.1）

### ① 判据（L1 / L2 / L3）

- **L1**：`.doc` 侧下发的首要充分条件不是「图插得准」，而是**不下发错图**；宁可不给图，也不给插在化学式中间、把水印当配图、插在答案区的图。
- **L2**：候选对象的**显示尺寸、像素内容、节点类型、媒体引用、浮动/行内属性**；插点题干的完整性；以及「文字邻域规则能否达到签核标准」的二元结论。
- **L3**：不新增学习行为缺口。这是**索引/呈现工程**，与 20a §5.1 三问一致：不改判定层、不改学习规则、不改前端契约（路线 ③ 若涉及前端形态，须另案）。

### ② 归因（不变量 / 约束 / 准则）

| 不变量 | 说明 |
|---|---|
| F0 同源铁律 | `doc_convert_done.text_sha256` 钉住当前入库文字流；任何清洗 / 重映射都会让 10,147 份正文与 **656,898** 个 `question_objects` 的坐标失效 ⇒ **只判对象，不碰文字流** |
| 真相源唯一 | 入库文字流来自 `pdf_tool.py::extract_docx`（zip + 正则剥标签），**不是 LibreOffice 文字提取**；LO 只做 `.doc → docx → PDF` 底图重转 |
| 「图标记」≠「题目配图」 | `parse_docx()` 把每个 `<w:drawing>` / `<w:object>` 都打成标记；老 `.doc` 重转后排版占位符被实体化，F0/F1 只保证文字流同源，**不保证对象语义** |
| 定位不到不入库不下发 | 拿不到可靠对象就丢图，绝不拿相邻题顶替 |
| 错图比没图更糟 | 给家长/孩子看 `(NH4\|)2SO4` 中间插图，比明确提示「原文含图，暂不支持显示」危害更大 |
| 判定层不动 | `question-match.ts` 六道 P0 硬闸、`CACHE_VERSION` v14、第二层准入、`0021 review_events`（0 行）全部不碰 |

### ③ 证据（20b 条目 + 级别）

## 3. 目标与非目标

**目标**

1. 保证**不下发错图**：宁可不给图，也不给插在化学式中间／把水印当配图／插在答案区的图。
2. 把观测点从「题干文字邻域」前移到「对象自身属性」，并保留 F0 同源铁律。
3. 为 `.doc` 侧选一条最终呈现形态，使「题干缺字、公式丢失、渲染器差异」不再成为 blockers。

**非目标（明确不做）**

- ⛔ 不追加 F5c 之类**文字邻域规则**（已在 D-034 记为证伪路线）。
- ⛔ 不清洗 `text_content`、不重映射 `char_offset`、不改 `text_sha256`（会破坏 10,147 份正文与 656,898 个题目对象的坐标）。
- ⛔ 不碰 `netdisk-inline-build.mjs`（docx 侧 273,037 行零回归基线）。
- ⛔ 不动判定层 `question-match.ts`、六道 P0 硬闸、`CACHE_VERSION`（仍 v14）。
- ⛔ 不上向量库 / Reranker / LLM 兜底 / VLM 版面分割（项目红线 + L3 4C/3.7G）。
- ⛔ 本轮不执行 `--apply`、不升 M42 v4、不部署、不发版、不 push。

## 3. 四条路线

### 路线 ① 对象级准入（F6，止血）

在**候选生成处**按对象自身属性判定，命中即丢图；判定发生在写 `candidate_details` 之前，因此下游 F2/F5/F5b 全部不变。

| 层 | 判据 | 状态 |
|---|---|---|
| A | `min(w_cm, h_cm) < 0.30` | 本提案拟实现 |
| B | `h_cm < 0.60 且 w_cm/h_cm > 2` | 本提案拟实现 |
| C | 渲染后非透明像素占比、纯色判空、整页水印尺寸/位置、`wp:anchor` 浮动、`w:object` OLE 分类 | **另案**，需独立提案 + 资源压测 |

技术要点：

- 复用 `netdisk-inline-crop.py::parse_docx()` 的 `marks` 元数据，扩展其字段但**不改文字流生成逻辑**；
- 尺寸取 `wp:extent`（EMU→cm），无 `wp:extent` 时取 VML `style` 的 width/height，**取不到一律丢图**（fail-closed）；
- 🔴 **`media bytes` / `no_media` 不得作为判据**：本轮探测脚本的 rels 属性顺序假设已导致漏解析，且 OLE 公式对象天然可能无 `r:embed`。C 层若要用内容判空，必须走「渲染后像素」而非「有无 media」。

### 路线 ② 整题级污染闸

把 F5 的扫描范围从插点邻域扩到**整条 stem**：命中 `U+FFFD`、换行+长数字残串、答案/解析区特征 ⇒ **整题不下图**（不是只丢这一张）。用于覆盖 03/04/31 的题干尾部残串与「答案：D」区插点。仍属 fail-closed，不清洗原文。

### 路线 ③ 整题渲染快照（P-017 兜底思路，**推荐最终形态**）

不做插点、不解析对象：`soffice → PDF → pypdfium2` 按题区间裁切，直接把原题渲染图作为题目内容下发。

- **一次性绕开**：题干缺字、公式/上下标丢失、图错位、水印误判、WPS/网盘渲染器差异——因为不再依赖「对象识别」与「文字流坐标」；
- 复用 P-018 已压测的 PDF 渲染链路与 `assertSymbolFont()` 字体闸门；
- 代价：文字不可选/不可搜索、体积与带宽、需裁掉答案区、需 PDF 渲染/裁切/产图/写库资源压测、前端 `RichText` 形态要改；
- 🔴 与 P0 硬闸「来源唯一」「举证责任倒置」不冲突：快照只替换**呈现**，不替换**判定依据**。

#### 🔴 D-035 补记：这条路**不是从零新建**，架构已预埋

思傅 2026-11-11 提「比对用当前题库已收录内容、展示用从 PDF 裁切的整题」。只读核查（`docs/reports/P-024-比对文字展示整题双轨方案只读核查报告.md`）确认：

- 判定层 `question-match.ts` 本就只读 `stem_text`；`question-reference.ts` 的 **`figureUrl` 就是整题块级快照**（`question_figures` / `0028`），前端 `answer-editor.tsx` 已在渲染。⇒ **复用现有字段即前后端契约零改动、不必 bump `CACHE_VERSION` v14**。
- 🔴 **但 `.doc` 快照 0 张**：`netdisk-figure-build.mjs::pendingSources()` 写死 `nf.ext='docx'`；整题快照只铺了 **620/3,705 份 docx（16.7%）／31,685 张**、全 `fig-v1`、11-08 单日；`.doc` 有 3,700 份含解析来源、42,619 个 stem≥10 字但无快照。docx 定位率 95.6% **不可外推 `.doc`**。
- 🔴 **新增风险**：`netdisk-figure-crop.py::locate()` 靠 `stem[:28/20/14/10]` 文字锚点，且有「全篇任意位置」兜底；`.doc` 文字是**静默缺字**（对象级 `U+FFFD` 仅 174 个）⇒ 可能给出**相邻题的整题错图**，比插错一张小图更严重。⇒ 实施前必须补「图文同源复核闸」并收紧兜底，在独立盲测样本上验。
- 🔴 **边界**：比对层用的正是那份残缺 `stem_text` ⇒ 双轨只解决「**显对**」，不改善「**给对**」（`review_events` 仍 0 行、P95 仍 3.4s 量级）。不得宣称检索变准。
- 展示形态、`.doc` 是否禁用 `inlineFigures`、是否补跑 docx 剩余 3,085 份 ⇒ 见 **§5.1 C1–C3**。

## 4. 验收口径（先定，再写实现）

🔴 **本轮最重要的教训**：D-033 的 F5b 是在同一批 200 份样本上调阈值、同批验收；随后的 40 条人工复核仍判 18 条不通过。⇒ **禁止再用「同一样本调阈值 + 同一样本验收」**。

实施前必须先固化：

1. **样本分离**：阈值只能在「调参样本」上选；「盲测样本」独立抽取、不参与任何阈值决策，且不得复用本轮 40 条 / 20 份。
2. **分层抽样**：按文档、学科、对象尺寸分档，每档 ≥30 条；`offset_zero`、宽扁条、公式碎片、真实配图各设必含反例。
3. **人工签核**：盲测由思傅按 `P-020-40条人工复核操作指引.md` 口径逐条判 A位置 / B题干 / 结论；AI 不代签。
4. **通过线**：不通过 0 且存疑 ≤2；**并单独统计「题目是否可解」**，不得用「文字读得懂」代替。
5. **对照前后**：同 seed 重跑，报候选数、放行/丢弃数、真相源 sha、生产 `health`、docx 侧 14 项数据门零漂移。
6. **不宣称**：不计算召回率/准确率，不外推全库，不宣称误判归零、修复有效、图形全覆盖。
7. **一键下线**：沿用 `doc-inline-rollback.sql` 口径，写前备份（`NODE_OPTIONS=--max-old-space-size=2560`）、先演练再写。
