在 L3 上把 5 份 50 KB 级 `.doc` 下载到 `/tmp/gk-doc-probe/`，用独立 LO profile 串行做 `.doc → docx`，再用 `zipfile + re.sub` 剥标签看文字层。结果：

**结论（严格限定为这 5 份）**：① 5/5 是真 OLE 复合文档（`d0cf11e0a1b11ae1`）、未加密，不是 docx/RTF/HTML 伪装；② `soffice --convert-to docx` 5/5 成功，小文件 1.4–1.8 s；③ 转后文字层完好（1,101–3,577 有意义字符），远超 `MIN_MEANINGFUL_CHARS=50` 的扫描版判据；④ 3/5 含 `w:drawing`，说明 **P-018 的 `w:drawing` 抠图路径在转换产物上理论可用**；⑤ 5/5 `w:object=0 / m:oMath=0`，**样本里没有 MathType/OMML 公式，公式路径完全未被验证**，不得外推。

**2026-11-09 阶段 0 压测补记（保留上文 5 份探测原结论不涂改）**：100 份实测把「公式路径完全未验证」推进为「**OLE 对象确实存在但性质未定**」——`w:object` 在 **9/100 份、合计 135 个**（单份最多 94 个），`m:oMath` 仍全 0；`w:drawing` **92/100 份、合计 6,945 个**。⚠️ `w:object` 可能是 MathType 公式、嵌入表格或其它 OLE，**不得直接当作公式**，阶段 3 仍需专项抽样定性。详见 `docs/reports/P-019-阶段0-100份压测报告.md` §4.3。

### 1.5 三条硬结论

1. **顺序只能是「转换 → 抽正文 → 切题入库 → 才谈图」**，不能跳过前两步直接搬 P-018。
2. 🔴 **同源铁律（本提案特有的新风险）**：`text_content` 与 `char_start` 必须来自**同一次转换产生的同一份 docx 文字流**。docx 原件时代 P-018 直接读用户文件、坐标系天然同源；`.doc` 是转换产物，若「抽正文转一次、抠图再转一次」，两次转换可能给出不同字符流 ⇒ `char_offset` 静默错位。这是 P-018 不变量 E 在老格式上的延伸，必须用产物复用 + 哈希钉死。
3. 转换是**离线一次性工程**：中间 docx 只作抽取输入，不入库、不进 `blob_objects`，否则 7.2 GB 会再翻倍。

## 2. 六栏（GK-OPS-22 §3.1）

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——不新增学习行为，只保护「检索时这道题有没有机会进候选池」这一前提。** 与 P-008 ① 同口径：`.doc` 的题干关键词不出现在 `text_content`（因为它为空），这份资料**永远进不了候选池**，正文匹配再准也没机会用上。它不改善 L1/L2/L3 任一条效果量，修的是**候选可得性**而非学习机制。

若评审认为该归因不足，按 P-008 的写法：**当作「不涉及判据的检索索引工程」，直接走 ⑥ 的显式不宣称**，本提案的证据强度不依赖判据归属成立。

**L1（本轮）**：把 `.doc` 纳入离线正文抽取 → 落 `text_content` → 走既有 `question-objects-build.mjs` 切题入 `question_objects`；新增记账表防 0 文本文档反复重试。
**L2（不做）**：版面还原（MinerU / PP-StructureV3）、公式转 LaTeX、向量召回、Reranker、知识点图谱、`question-match.ts` 改动、P0 六条硬闸调整、`strict=1`、第二层上线准入。理由：L3 4 核 3.7 G 无 GPU；且判定层准入另案，各需独立提案。
**L3（不做）**：复习排程、隐私口径、结果指标 `0021` 分组、4 组身份治理、正式版发布。

### ② 归因（不变量 / 约束 / 准则）

- **不变量 A（判定层零改动）**：`shared/question-match.ts` 一行不动（零依赖单文件、不得加 import），sha256 与 M35–M38 钉住值一致。**库变大 ≠ 放行变宽**：11-09 实测全量 docx 后同一验证脚本命中从 3 条变 2 条，P0 六条硬闸照旧拒配对。
- **不变量 B（缺失就如实缺失）**：转换失败 / 加密 / 损坏 / 无文字层 ⇒ 记账标 `failed` 或 `none`，**绝不拿别处文本顶替**；不得把「转换成功」等同于「抽到正文」。
- **不变量 C（同源）**：见 §1.5 第 2 条；产物单次生成、文字流哈希钉死、`char_start` 越界一律丢弃。
- **不变量 D（只写白名单表/列）**：写 `netdisk_files.text_content / text_status / text_updated_at` 三列 + 新增记账表 + `question_objects`（upsert）；**绝不改** `name / path / size_bytes / mtime / synced_at`，绝不写 `question_inline_figures` / `question_figures`。
- **不变量 E（隔离与幂等）**：唯一键 `(user_id, source_type, source_id, object_index)`；`objectFingerprintInput()` 含 `source_id`；PG `text` 不收 U+0000 ⇒ `stripNul()`；无 RLS ⇒ 每个查询必带 `.eq('user_id', …)`；删除加 `.select('id')` 校行数。
- **约束**：C-资源（4C/3.7G、7.2 GB 下载量、`gk-api` 必须全程可用）；`GK-SRS-20a M10`（宣称不超能力）、`M11`（如实告知不是拦截）、`M8`（不碰 `REVIEW_INTERVALS`、不进 `0021` 分组）；个人主体 ⇒ 只做私有自用索引，不做共享题库/UGC。
- **归因**：C-正确性（候选可得性）＋ C-呈现（后续才谈图）＋ C-资源（离线构建、断点续跑、内容寻址不重复落盘）。

### ③ 证据（20b 条目 + 级别）

| 条目 | 级别 | 量级 | 边界 |
|---|---|---|---|
| **20b 无对应条目** | — | 「老格式是否可抽」不是学习干预，是索引完整性问题 | Q1/Q2 不适用；Q3 **不可测**（M8 隔离，`0021 review_events` 仍 **0 行**）⇒ `OPS-22 §3.2` 判 **D（降维）**：只做正确性工程，**不做指标、不做宣称** |

### ④ 算子（T / D / X）

- **T 移植**：把 P-008 的「离线正文预抽」与 P-010 的「题目级结构化切分」原样扩到 `.doc`；坐标映射沿用 P-018 的 `char_start` 不变量，但增加「单次转换产物复用」约束。

## 3. 转换路线三选一（**已拍板 A**，2026-11-09）

| 选项 | 做法 | 已证实的优点 | 真实代价 / 风险 |
|---|---|---|---|
| **A** | **soffice `.doc → docx` 后复用既有全链路**（`pdf_tool.py::extract_docx()` + `question-objects-build.mjs`，后续可接 P-018 抠图） | 工具已装、Symbol 别名已配；5/5 实证成功；文字流与 docx 侧**同一口径**，`char_start` 可直接沿用；后续图能力可复用 | 每份要起一次 soffice（本次 1.4–1.8 s，但大文件/长跑未测）；P-018 已证实的**两类卡死**（profile 退化 ~1,000 份、极少数文档 LO 死循环）会原样出现；LO 重写排版可能丢 OLE 公式 |
| **B** | 装 `antiword` / `catdoc` 直接抽纯文本，不产 docx | 轻、无 soffice 进程、资源最省、无 LO 死循环风险 | **拿不到 `w:drawing` / `w:object`，阶段 3 的图能力彻底断掉**；纯文本无字符坐标，与 `char_start` 体系不兼容；需新增工具与新的文字流口径 |
| **C** | A 为正文主线 + B 作交叉校验（双路抽，文字不一致则标 `conflict` 不入库） | 能主动发现 LO 转换失真，证据最硬 | 两套口径、双倍下载/转换、实现与运维复杂度最高；`conflict` 率未知 |

**我的倾向（供参考，不是决定）**：**A**，理由是它与 docx 侧共用同一套文字流与 `char_start` 口径，是唯一不破坏 §1.5 同源铁律、且能保留阶段 3 图能力的选项；代价（LO 长跑治理）已在 P-018 全量阶段摸清并有现成护栏可移植。但 **B 的「资源最省」在 4C/3.7G 上是真优势**，若思傅判断阶段 3 的图不重要，B 更稳。
