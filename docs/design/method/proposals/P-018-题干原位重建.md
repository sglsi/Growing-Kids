## 1. 触发

1. 裁切尺寸是否符合要求；

第 3 问点中了 `P-017` 的真实边界：**它是「整页一条横带」贴在题干文字下方，从没插进文字流**。而库内题干本身是残的——`extract_docx` 只做 `re.sub(r"<[^>]+>", "", xml)`，`<w:object>` 整块被当标签剥掉，所以「关于x的一元二次方程␠␠有两个相等的实数根」中间空一段。

## 4. 关键判断

- 公式位置**不需要**靠 PDF 版式推断——`char_start` 与 docx 文字流同一坐标系，可直接给出插入点。
- 几何图**必须**从 docx 原图抠（png/jpeg 无损），不走 PDF 渲染。
- 公式图像**不能**用 `wmf2svg`（装字体后仍失真，见 §5）。**必须让 LibreOffice 渲染**：docx→PDF 后公式是 `IMAGE` 对象，`get_bounds()` 给出精确 bbox。
- 只用「前后锚点算间隙」不够稳：左锚点常以标点结尾（字框仅 1.6pt），会被误判跨行，且公式字号大于正文时会带进上一行。**正解＝锚点定大致区间 + 在该页 `IMAGE` 对象里按 x 重叠度挑 bbox**。
- `v:shape` 的 `width/height`(pt) 是文档声明的显示尺寸，可作**裁切校验器**（`|bbox_w − shape_w|` 超阈值即拒绝）；本轮先记账，不入准入。

## 5. 已证伪 / 已排除的路径

| 路径 | 结果 |
|---|---|
| `wmf2svg` + `rsvg-convert`（未装字体） | ❌ 矢量还原失真（`√4` 渲成灰边粗线框、上下被切）；10 个样本里 8 个 rsvg 直接解析失败（libwmf 输出非 UTF-8） |
| `wmf2svg` + **装 Symbol/Times 字体别名后** + latin-1→UTF-8 修编码 | ⚠️ 10 个样本 **9 个能渲染**、根号与分式完整；但仍有**字符级错乱**：`(x≤300)` 渲成 `(x£ 300¼)`、`S_{△EOF}` 渲成 `S_D̂ΔEÖF`、多元素公式互相重叠 ⇒ **不能作为入库来源** |
| GBK 优先解码救符号 | ❌ 实测这些字节是真实 latin-1（0xA3 / 0xBC），不是 GBK 双字节，改解码无效 |
| `wmf2gd` 直出 PNG | ❌ 只输出到 stdout、低分辨率（宽中位 96px） |
| `soffice --convert-to png x.wmf` | ❌ `source file could not be loaded` |
| `soffice --convert-to html` | ❌ 公式导出为 1x GIF，放大即糊；300dpi 选项不生效 |
| 纯锚点间隙裁切 | ⚠️ 可用但会在标点/大字公式上出错，仅作 bbox 匹配失败时的兜底 |

### 5.1 字符级错乱的根因（字节级实证）

「Word 里字符编码唯一」只成立于 `word/document.xml` 的 `<w:t>` 文本层（XML/UTF-8，每字符一个 Unicode 码位）。MathType 公式不是文本，是 `<w:object>` 里嵌的 **WMF 矢量图元文件**：`strings` 可见 `MathType` / `Symbol` / `Design Science, Inc.` / `WinAllBasicCodePages`；内容是一串 GDI 绘图指令（"用 Symbol 字体在 (x,y) 画字节 0xA3"），**不存在 Unicode 字符这一层**。0xA3 不是字符编码，而是 Symbol 字体的**私有码位（字形索引）**：在 Symbol 私有码表里是 `≤`，在 Latin-1 里是 `£`——唯一性由字体提供，字节本身不携带。

Linux 无微软原版 Symbol 字体，`libwmf 0.2.13` 也未实现 SYMBOL_CHARSET → Unicode 映射表，退化成**逐字节恒等映射**（`b` → `U+00B`）。对全部测试 WMF 的 `META_EXTTEXTOUT` 字节与 SVG `<text>` 字符做全量计数对照：

| WMF 字节 | 次数 | SVG 中的字符 | 次数 | Symbol 字体里本应是 |
|---|---|---|---|---|
| `0xA3` | 6 | `£` U+00A3 | 6 | `≤` |
| `0xB4` | 10 | `´` U+00B4 | 10 | `×` |
| `0xBC` | 1 | `¼` U+00BC | 1 | 省略号类符号 |
| `0xD0` / `0xCE` / `0xD2` / `0xF5` | 3 / 3 / 2 / 2 | `Ð` / `Î` / `Ò` / `õ` | 3 / 3 / 2 / 2 | 数学关系符（非拉丁字母） |
| `0xEF` / `0xEC` / `0xED` / `0xEE` | 10 / 3 / 3 / 3 | `ï` / `ì` / `í` / `î` | 10 / 3 / 3 / 3 | 大括号、根号的拉伸构件 |

每一对次数**完全一致、无例外** ⇒ 这是恒等映射，错在**字节→Unicode 的转换步**，不是后续字体替换。SVG 里 `font-family:Symbol` 只是 CSS 声明，落到 `Standard Symbols PS`（URW 替代品，按 Unicode cmap 工作）自然画不出 `≤`。`0x44` 在 Symbol 大写希腊字母区是 `Δ`，直译成 `D` 后与相邻构件叠在一起，可解释肉眼观测到的 `D̂`。

另有独立一层：MathType 把每个字符的 x 坐标与 Dx 间距按**原版 Symbol 字体的字形宽度**写进 WMF，替代字体度量不同 ⇒ 上下标、分式错位/重叠。因此装字体只解决「找不到字体」，解决不了「码位解释错」与「度量不一致」。

**推论**：把「字节→字形」交给完整实现 WMF 语义的 LibreOffice，PDF 里公式已定型为字形/矢量路径，本项目只按 bbox 裁图、全程不再解释字节 ⇒ 从根上绕开。换任何多字节解码（含 GBK）只会把若干私有单字节错并成别的字符。

1. 新增迁移 `0029_question_inline_figures.sql`：只存「图 ↔ 题目对象 ↔ 插入点」映射，**不动任何既有表**。

5. 前端用 `RichText` 按 `charOffset` 切段内联渲染：公式图按行高缩放内联，几何图独占一行。
6. `CACHE_VERSION v13 → v14` + 旧断言同步 + 新增 `M40`。
7. `P-017` 的整块快照**保留**作为兜底（不删表、不退库），两套并存。
