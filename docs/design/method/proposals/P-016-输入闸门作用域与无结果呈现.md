## 0. 一句话

**服务没坏，是闸门短路后前端把提示吞了；而按 D-018 的口径，闸门本就不该把「参考例题层」一起关掉。**

## 1. 报障取证（2026-11-08 10:42–10:50，L3 现网，全部只读）

| 检查项 | 实测 |
|---|---|
| `/api/health` / `gk-api` | 200 / 0.25s / `active` / 0 ERROR |
| 干净单题 `GET /api/netdisk/search` | 200 / **2.4s** / `hits=8` / `exact=0` / **`refs=3`** ⇒ P-015 链路完好 |
| 用户原题（243 字，10-29 录入「问题探究：1）…2）…3）…」） | 200 / **0.065s** / `hits=0` / `refs=0` / `keys=[]` + 闸门提示 ⇒ **公共资料库检索根本没跑** |
| `answer_cache` 10:42:17 `mode=kb` result | `{"source":"none","match_level":"none","answer":"","refs":[],"note":"这段内容像是整页试卷或多道小题连在一起，请把要查的那道小题单独录入后再搜答案"}` |
| L3 日志 10:42:17 | ima 兜底 0 条（另有 1 库报 `220030` 订阅知识库权限错误），非本次主因 |

**三层根因**：
1. `answer-search.service.ts:396` 要求 `inputGuard.ok` 才调 `netdiskSearch.search()`，`:525` 再把结果整体覆盖为 `source:'none'` ⇒ 闸门作用域从「不送判定」扩大成「不检索」。
2. `answer-editor.tsx:555` 条件 `candidate.source !== 'none' || hasRefs` 为假 ⇒ **结果卡片整块不渲染**，卡片内 `:694` 的 `note` 跟着看不到。
3. `:335` 唯一提示是 `Taro.showToast`，`finally` 紧接 `hideLoading()`；微信下 toast 与 loading 共用实例，提示极短甚至被抢关 ⇒ 用户观感＝「点了什么都没有」。

## 2. 作用域修正（本提案的核心，不是新功能）

`D-018` 已批准「参考例题层」与「原题答案层」**并列**：`exact` 六条硬闸、`answer`、`verified`、`canAdopt` 是答案层的门；`references` 是**同源配对 + 事先声明 + 禁采纳**的独立第二层。当前实现把 P-014 闸门放在 `netdiskSearch.search()` 最前面，等于用「答案层的门」把「第二层」也锁了，与 `D-018 §设计思想修正` 直接冲突。

**修正口径（写死）**：
- 闸门继续拦**判定层**：不合格输入绝不送 `judgeWithStore()` / `judgeObjects()`，绝不产出 `exact`，绝不进 `answer`；
- 闸门**不拦参考例题层**：不合格输入仍可做一次**只读召回**，只收集 `references`，不输出任何 `hits`、不输出 `keys`、不扩大召回面；
- 两次都是**一次检索、一次深挖预算**，不自动切题、不逐题多次检索、不改写原文任何一个字符；
- `question-match.ts` **一行不动**，六条硬闸、`strict=1`、第二层上线准入全部原样。

## 3. 六栏

### ① 判据（L1 / L2 / L3）

**L1（本轮）**：① 后端新增「仅参考例题」读模式 `referenceMode:'examples'`，由 `answer-search` 在闸门不合格时调用；② `answer-search` 的如实告知改为**合并式**（保留 `references` / `reference_disclaimer`，不再整体覆盖清空）；③ 前端 `source:'none'` 时把 `note` 常驻显示，并修 `showToast` / `hideLoading` 时序；④ `CACHE_VERSION v11→v12`（用户可见 `note` 与 result 结构变了）＋旧断言同步＋新增 M38。
**L2（不做）**：向量召回 / Reranker / 知识点图谱 / 自动切题 / OCR 纠错字典 / 逐题检索 / 大模型改写讲解。理由见 §1 对照（现有 trgm + 长锚点已能在 2.4s 内给出 3 道例题），且 `P95<3s`、L3 单机、第二层准入仍锁。
**L3（不做）**：改 20a 学习准则、改复习排程、改隐私政策口径、动身份治理 4 组文件、改 `question-match.ts`。

### ② 归因（不变量 / 约束 / 准则）

- **不变量 A（零放宽）**：`answer` 只能来自 `exact`；参考例题永不进 `answer`、永不置 `verified=true`、永不提供「采纳」；`examples` 模式 `hits=[]` / `exactCount=0`。
- **不变量 B（同源配对）**：`stem` 与 `solution` 仍来自同一个 `question_objects` 行，`collectReferences()` 一行不改，声明仍在所有内容之前且每条例题重复。
- **不变量 C（不送判定）**：不合格输入在 `examples` 模式下**不调用** `judgeWithStore()` / `judgeObjects()`；`/api/netdisk/search` 直连仍按 P-014 短路（防绕过双入口）。
- **约束**：`GK-SRS-20a M10`（宣称不超能力）、`M11`（如实告知不是拦截）、`M8`（不碰间隔表与结果指标）；《双减意见》§15 ⇒ 只有 `exact` 才放解析，本轮不放行任何 `exact`。
- **归因**：C-正确性（不合格输入仍不得产出本题答案）＋ C-资源（单次检索、深挖上限与预算不大于合格输入）＋ C-呈现（如实告知必须看得见）。

### ③ 证据（20b 条目 + 级别）

**20b 无对应条目**——输入合格性、结果呈现与读路径作用域都不是学习干预；Q1/Q2 不适用、Q3 **不可测**（M8 隔离，`0021 review_events` 当前 0 行）⇒ `OPS-22 §3.2` 判 **D（降维）**：只做正确性与呈现工程，**不做指标、不做宣称**。参照系是同一批输入在改动前后的 `hits` / `refs` / `answer` / `verified` / `tookMs` 与 `question-match.ts` sha256，不是学习结果。

### ④ 算子（T / D / X + 边界 + 不做什么）

**D 降维**：把 `D-018` 已批准的「并列第二层」落到读路径上，但**不追求整页输入的例题质量与召回率**——整页文本的长锚点混杂，例题可能不如干净单题贴切，如实说明「请把小题单独录入可得到更贴合的例题」。**X 禁止**：自动切题、逐题检索、放宽六条硬闸、把 `references` 提为答案、把 `source:'none'` 伪装成命中。**T 移植**：仅 `M11` 已落地的「如实告知」做成常驻可见（属 bug 修复，不是新干预）。

### ⑤ falsifier（产品内可采集）

1. 任一不合格输入产出 `exact` / 非空 `answer` / `verified=true` / 出现「采纳」按钮 ⇒ 作用域失守，停下、回滚、登记；
2. `/api/netdisk/search` 直连对不合格输入返回 `hits.length>0` ⇒ P-014 双入口被绕过；
3. `examples` 模式出现「题干 A + 别人解析」（同源配对被破坏）或声明缺席/在内容之后；
4. `question-match.ts` sha256 与 M35/M36/M37 钉住值不同；
5. 单次请求出现 >1 次检索调用、深挖份数 > 合格输入、或 `tookMs` 超硬兜底 18s；
6. `CACHE_VERSION` 未 bump 或旧缓存仍吐「有内容、无声明 / 无提示」；
7. `check:isolation` 越权、`topic` 非空答案、`exact` 缺 `source_location`；
8. 出现「提升命中 / 修复有效 / 误判归零 / 所有用户已可用 / 精准定位到题」等宣称。任一出现即按 `OPS-22 §3.4` 停下、回滚、登记。

### ⑥ 验收断言

- **M38**（新增）：判定层 sha256 未变、`examples` 模式不送判定、直连仍短路、合并式告知保留 references、`answer` 空 / `verified=false` / 禁采纳、声明先于内容、`CACHE_VERSION v12` 且 8 个旧模块断言同步、前端 `source:'none'` 常驻提示且 toast 时序已修、`input-guard.ts` 前端镜像逐字一致。
- **生产对照**：干净单题仍 `refs≥1`；用户原题 `refs≥1` 且 `answer=''` / `verified=false` / 无采纳；不合格输入的 `hits=0` / `exact=0`；`tookMs` < 18s；`answer_cache` 新行带 `references` 与声明。
- **不宣称**：本轮只消除「点了什么都没有」并让第二层在闸门不合格时可用；**不计算召回率、不宣称命中提升**，样本仅方向性证据；唯一够格指标仍是 `0021 review_events`（当前 0 行）。

## 5. 实现方案（执行期偏差须回填本节）

**后端**：`netdiskSearch.search(question, { referenceMode:'examples' })` —— 只在闸门不合格分支调用；`examples` 模式不短路闸门、跳过 `judgeWithStore()` 与 `snippetFor()`、深挖上限与预算取更保守值、`hits=[]` / `keys=[]` / `exactCount=0`、专属 `note`；`answer-search` 的 `!inputGuard.ok && !settled` 改为合并式覆盖（只换 `note` 前缀，保留 `references`）。`/api/netdisk/search` 直连不传该参数 ⇒ 行为不变。

**前端**：`candidate` 存在即渲染结果卡片（含 `source:'none'`）；`source:'none'` 时标题为「这次没有可用结果」并常驻显示 `note`；`showToast` 统一移到 `hideLoading()` 之后，且 `source:'none'` 不再依赖 toast（卡片已常驻）；`canAdopt` 继续排除 `topic` / `none` / `refs`。

**缓存**：`CACHE_VERSION v11→v12`，`qHash` 仍带版本号；M27/M31/M32/M33/M34/M35/M36/M37 八处旧断言同步。
