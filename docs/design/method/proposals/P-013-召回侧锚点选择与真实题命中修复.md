## 0. 一句话，以及一次必要的自我订正

**要修的不是「用户录入的 OCR / 切题质量」，而是「检索召回侧的粗筛关键词选择」：原题文件就在库里，但从来没被送进判定池。**

🔴 **订正上一轮（2026-11-07 20:xx）的结论**：当时我据 6 条真实题 `exact=0` 归因于「整页 OCR 文本没切成单题 + 错字」，建议 P0 先修上游切题/OCR。**该归因经本轮实测被证伪**：

| 当时的说法 | 本轮实测 |
|---|---|
| 题干质量是瓶颈 | 把几何题人工切成单小问、连错字都修好 ⇒ **仍 `exact=0`**（8 hit 全 `topic`）；几何修错字版甚至触发「设问冲突」 |
| 题库可能没有这些题 | L3 只读查 `question_objects`：`BMDN` **4 行**（`has_solution=true` / `link_status=ok` / 解析段 1053 字）、`ABC=60` 类 **33 行**、`black hole` **2 行**、`modern technology` **21 行**、`tsunami` **1 行**；`netdisk_files.text_flat ilike '%BMDN%'` **47 份** |
| 判定层可能过严 | 判定层工作正常：`store.total=49 / usable=49`，`rejectReason` 为「对象内锚点共现不足 1/17（要求 ≥0.55）」——拒绝的是**别的题**，判定正确 |

**真实断点**：`netdisk-search.service.ts` 的正文粗筛词 `textAnchors` 取 `extractDistinctive().keys` 的前 `TEXT_RECALL_KEYS=4` 个；而 `extractDistinctive()` 的 `keys` 被 12 个 6 字滑窗占满并截断，前 4 个是 `DABC60 / C60AB3 / AB3BC5 / BC5MN分` 这类**归一化后拼出来的题干开头碎片**，教辅正文里几乎不存在。含判别性 `BMDN` 的片段排在 `keys` 第 12 位之外，进不了 `ilike` ⇒ 47 份含原题的文件一份都进不了深挖 8 份。英文题干更糟：`extractKeys()` 的 4 字滑窗把 `tsunami swept through` 切成 `tsun / unam / swep / thro / roug / vill`，召回全是英文绘本。

⚠️ **上游 OCR / 切题质量确实也是问题**（6 条里有 1 条 17,035 字整张试卷、多条多题连排＋错字），但它是**独立的 P1 项**，不是本轮 `exact=0` 的原因；修它不会提升命中，故本提案不把它列进 P0。

## 3. 六栏

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——不新增学习行为，只保护「到期复习时拿到的答案确实是这道题的答案」这一前提能被兑现。** 与 P-012 ① 同口径。不改善 L1/L2/L3 任一条效果量，修的是更靠前的**候选可得性**：原题在库、判定能认，却因粗筛词选错而根本没被送进判定池。若评审认为该归因不足，按 P-012 同样写法当作「不涉及判据的检索正确性工程」，直接走 ⑥ 显式不宣称。

### ② 归因（不变量 / 约束 / 准则）

- **不变量**：无。I1 提取 / I2 修正 / I3 间隔均不涉及「粗筛词怎么选」。
- **约束**：**C-正确性**（候选池没有原题 ⇒ 再严的判定也产不出正确答案）；**C-资源**（不增加深挖份数与在线抽取，4 核 4G 不额外承压）。
- **准则**：`M10` 宣称不得超出能力、`M11` 如实告知「找到 / 没找到」、`M8` 不碰间隔表与结果指标。
- **外部合规**：《双减意见》§15 ⇒ `exact` 才放解析、`topic` 答案必须为 `''`；本提案不改答案呈现形态，不构成拍照搜题。
- **性能**：保持 P95 < 3s；`TEXT_RECALL_KEYS` 若上调必须给出 `ilike` OR 数与耗时实测。
- **既有边界（D-014/D-015 延续）**：判定层六条硬闸一行不动、举证责任仍是「未达标不放行」、`strict=1` 继续锁、`NETDISK_TEXT_RECALL=0` / `NETDISK_ONLINE_EXTRACT=1` 双回退保留。

### ③ 证据（20b 条目 + 级别）

**20b 无对应条目**——SQL 粗筛词选择不是学习干预，无效应量可引。三问决策器（20a §5.1）：Q1/Q2 不适用、Q3 **不可测**（M8 隔离）⇒ 按 `GK-OPS-22` §3.2 判 **D（降维）**：只做正确性工程，不做指标、不做宣称。工程证据为 §1 的八层实测（内部实测，非学习证据）。

### ④ 算子（T / D / X + 边界 + 不做什么）

**D 降维**：把「判定层已能认出原题」这一能力，降维到「先让原题文件进得了判定池」；**宣称同步降级**——修完仍只说「在公共资料正文里找到 / 没找到」，不得说「都能搜到」「精准定位到题」。

**明确不做**：
- ⛔ 不放宽六条硬闸、不把 `topic` 给答案、不去掉 `source_location`、不开 `QUESTION_OBJECTS_STRICT=1`
- ⛔ 不改 `MAX_DEEP_FILES=8` / 8s 预算 / 18s 兜底、不启在线抽取
- ⛔ 不改 `question-match.ts` 的 `anchors` / `longAnchors` / `judge*` 任何判定逻辑
- ⛔ 不改 result 结构、不做自动跳题、不新增答案内容
- ⛔ 本轮不修上游 OCR / 切题质量（另立 P1，理由见 §0）
- ⛔ 不写成「误判归零 / 所有用户已可用 / 已解决张冠李戴」

### ⑤ falsifier（产品内可采集）

1. 修复前后同一批「真实录入题 + 手工单题」对照，`exact` 数**没有上升**，或 `tookMs` P95 ≥ 3s ⇒ 判断错了，改实现。
2. `question-match.ts` 的 `longAnchors` 输出与修复前**逐字不同** ⇒ 判定层被动过，立即回滚（M31/M32 断言红）。
3. `check:isolation` 出现任何越权、`topic` 出现非空答案、`exact` 缺 `source_location` ⇒ 违反 D-009/D-012，停下。
4. 出现「题干 A + 别人解析」被判 `exact` ⇒ 第二层上线准入仍不达标，`strict=1` 继续锁。
5. `CACHE_VERSION` 未 bump 导致旧缓存继续返回 `topic` ⇒ 按 M-缓存红线判失败。
6. 文案出现禁用宣称词（H2 门）⇒ 退回。

### ⑥ 验收断言

- **新增 M35**（`server/scripts/verify/modules/35-kb-recall-anchors.mjs`），至少钉住：
  - `extractDistinctive('…BMDN…').keys` **包含** `BMDN` 或等价判别性符号锚点；英文题干 `keys` 不含 `tsun/unam/swep` 类 4 字碎片
  - 同一批题干的 `longAnchors` 与修复前**逐字一致**（判定层未动）
  - `judge*` / 六条硬闸常量 `MATCH_*` 与 D-012 钉住值一致
  - `CACHE_VERSION === 'v9'`（或拍板后的实际值）
  - 深挖上限 8 / 预算 8s / 默认禁在线抽取 未被改动
- **回归**：M27–M34 全绿、`verify:gate` 全绿、`check:isolation` 150/150、`method:check` H1/H2/H3。
- **实测对照**：修复前后各跑一次 `kb-hit-diagnose.mjs`，把 `exact` 数、`keys`、正文召回份数、`tookMs` 并列写进 QA-16。
- **显式不宣称**：样本仅 6 条真实题 + 5 个手工单题，**不得据此计算召回率**，唯一够格指标仍是 `0021 review_events` 到期首次作答正确率（当前 0 行）。
