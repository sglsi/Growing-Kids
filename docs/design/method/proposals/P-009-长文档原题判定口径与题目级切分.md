# P-009 长文档原题判定口径与题目级切分

> 提案号：P-009 ｜ 状态：已实施 ｜ 日期：2026-11-06 ｜ 关联决策：D-012 ｜ 关联缺口：无（检索正确性工程，不新增学习行为缺口）
> 流程依据：`GK-OPS-22` §3.1（六栏）｜ 方法论依据：`GK-SRS-20a` M8 / M10 / M11 ｜ 证据来源：`GK-SRS-20b`（**无对应条目**，见 ③）
> 分档：**L1（功能级）**——把原题判定的单元从「整份文件」收敛到「一道题一个对象」。**不改准则**，故不走 L2，不升 20a 主版本、不补 20b 条目。
> 拍板记录：2026-11-06 思傅「**按照一题一对象 + 来源位置；多因子校验（锚点共现 + 设问一致 + 相邻解析段）思路进行修改完善**」——批准**仅 P0 判定层**落代码。**P1 / P2 / P3 全部未批准**（见 ④ 与 ⑤）。
> 实施范围：`status: 已实施` 仅指 P0 判定口径已落本地代码；**未部署、未写生产数据、未 push**。
> 评审依据：`docs/reports/资料库正文召回-检索侧四步方案评审.md` §0 / §3 / §4 / §7 / **§8**（§8 是「未达标不放行」的思想与判据正式稿）。

### ① 判据（L1 / L2 / L3）

**保护性归因：L1 延迟——本提案不新增学习行为，它保护「到期复习时拿到的答案确实是这道题的答案」这一前提。**

诚实说明：把判定单元从整份文件换成题目对象，不改善 L1（隔 N 天还能做对）、L2（无提示）、L3（迁移）中的任何一条。它修的是更靠前的一环：

> `D-009` 的硬闸在**单题片段**上成立，但现网正文里一份 docx 常是整本教辅（L3 实测 3.5 万字 / 76 道题 / 303 个【答案】标记）。此时「全文锚点共现」会把散落在不同题目里的条件片段凑够 3 个，而「文中有任意【解析】段」几乎必然成立 ⇒ 实测 1 道真题判出 **3 个 `exact`，逐条核对全是别的题的解析（0/3）**。答案一旦被采纳进题库，到期复习时家长照着讲，错了还不知道。

这不是「判得更聪明」，而是**让 `D-009` 的硬闸在真实语料上重新成立**。因此宣称必须同步降级（见 ④）：只说「在资料正文里找到 / 没找到」，**不得**说成「都能搜到」「精准定位到题」「一搜即得」。

> ⚠️ 同 P-005 / P-006 / P-008 的写法：若评审认为「保护性归因」不足以支撑 L1，可当作「不涉及判据的检索正确性工程」，**直接按 ⑥ 的显式不宣称处理**——本提案的证据强度不依赖判据归属成立。

---

### ② 归因（不变量 / 约束 / 准则）

- **不变量**：无直接不变量。I1 提取 / I2 修正 / I3 间隔均不涉及「检索时怎么认定同一道题」——**本提案在信息检索与结果可信度层，不在学习机制层**。
- **约束**：**C-资源**（工作记忆与注意力有限）。家长要在几十道连排的题目里自己分辨「这段解析到底是哪道题的」，属与学习无关的外在负荷；分辨错了还会把错误讲解带进复习。
- **相关准则**：
  - `GK-SRS-20a M10`：宣称不得超出能力 —— 纯文本无法证明「解析段归属」时，不得说成已精准定位；`exact` 必须带可复核的来源位置。
  - `GK-SRS-20a M11`：「找到 / 没找到」是**如实告知**，不是拦截，也不是逼用户去开 AI 开关。
  - `GK-SRS-20a M8`：明确隔离 —— 不碰 `REVIEW_INTERVALS`、不进「到期首次作答正确率」分组；判定口径与复习排程、结果指标无任何耦合。
- **合规约束（外部、不可放宽）**：《双减意见》§15 与 2021-12-13 教育部通知（详见评审 §7.6）⇒ `exact` 才放解析、`topic` 答案必须为 `''`，**既是正确性红线也是合规红线**。

4. **关系信号 ROC 实测**（评审 §8.4）：40 正例 / 40 负例上，符号指纹与答案提示词的任何组合都做不到「误判归零 + 正例召回够高」⇒ **纯文本无法证明解析段归属**，这是本提案划定边界的直接证据。

### ④ 算子（T / D / X）

本提案主体是 **D（降维）+ X（明确不做）**。`GK-OPS-22` §3.2 的三问决策器（20a §5.1）留痕：

| 问 | 结论 |
|---|---|
| Q1 量级 | 不适用（不是学习干预，不产生新的学习行为） |
| Q2 覆盖 | 不适用（同上） |
| Q3 可测 | **不可测**——「判定精确率」不在现有结果指标里（只测到期作答正确率） ⇒ 按 §3.2 边界情形判 **D（降维）**：只做正确性工程，不做指标、不做宣称 |

| 约束 | 内容 | 理由 |
|---|---|---|
| **① 只做 P0 判定层** | `question-match.ts` 新增题目级切分 + 多因子闸门；两个正文调用方接入 `judgeObjects()` | 评审 §4 的 P0；P1/P2/P3 未批准 |
| **② 零依赖单文件** | 不新增任何 import、不建表、不写库、不下载、不改迁移 | M27 用 tsc 单编后 require，加 import 即破契约 |
| **③ 一题一对象 + 来源位置** | `splitQuestionObjects()` 按题号 /【例 N】/ 问题 N / 演练 N 切分；`SourceLocation` 带 sourceId、objectIndex、label、字符区间 | 对应业界 `question_id` + 父子 ID + 位置；无题号的单题片段**退化为 1 个对象**，保证 P-006 老行为不回退 |
| **④ 因子串联否决，不加权求和** | 锚点共现（限对象题干内）、设问一致、相邻有效解析段、来源唯一，逐条布尔 | 改成加权打分就退化回旧的「主题相似」打分，F1 原地复活 |
| **⑤ 未达标一律降级** | `topic` 保持 `answer:''` / `verified:false`，**不带** `source_location`、不给 `solution` | D-009 硬约束 + 双减合规红线 |
| **⑥ 软信号不得当硬闸** | `solutionLink()` 只影响 `confidence` 与呈现层「请核对」提示 | ROC 实测已证伪；硬凑阈值只会把「看起来达标」写进文档 |
| **⑦ 缓存必须失效** | `CACHE_VERSION` v4 → **v5** | 改了 result 结构（新增 `source_location`）与 exact 口径；旧 `answer_cache` 存着全文级假 `exact`，命中原样返回 |
| **⑧ 前后端契约同步** | `answer-search.types.ts` / `src/services/api.ts` 同步 `source_location?` | D-009 教训：只换后端时旧前端会把 `answer:''` 也采纳 |
| **⑨ 不改学习行为** | 不进 `REVIEW_INTERVALS`、不进结果指标分组 | `GK-SRS-20a M8` 的隔离精神 |
| **⑩ 明确不做** | 向量库 / Reranker / LLM 兜底 / 亿级公共题库 | 4 核 4G、`ai_enabled` 默认 false、个人主体 `AI_PUBLIC_ENTRY=false`；且题干是用户自录原题而非拍照 OCR，无语义变式需求（评审 §7.5） |

**P1 / P2 / P3 明确未批准**：`0026` 重定义为归一化列 + 题目级切分入库 + 索引、`text_flat` 预计算、`searchLocal()` 双通道正文召回、`keyHits` / 锚点共现统一打分、`MAX_DEEP_FILES` 3→20~30、删除 `coverage<0.2` 闸门、呈现层来源可追溯 + 家长可见前置 —— **一项都不做**。理由见 ⑤：上线准入闸门未全绿。

### ⑤ falsifier

| # | 触发条件 | 处置 |
|---|---|---|
| 1 | **验收集出现任何 1 个假 `exact`**（真原题在长文档里被判中别的题解析） | 立即停止，回滚到「一律 `topic`」；误判零容忍，一票否决 |
| 2 | **正例召回跌破 90%**（真实题目自匹配被大量降级） | 停下查切分规则，不得以「降低误判」为由把功能做成永远判不出 |
| 3 | **来源定位错对象**：`source_location.objectIndex` 与实际题目不符 | 立即停止；定位错了，解析照样张冠李戴 |
| 4 | **P-006 老行为回退**：单题片段 / 无解析段 / 同专题不同题三条 M27 断言任一失效 | 回滚本提案；`judge()` 契约不得破 |
| 5 | **因子被改成加权求和**，或 `topic` 出现非空 `answer` / 带上 `source_location` | 视为硬闸失守，按 `GK-OPS-22` §3.4 处置 |
| 6 | **解析段归属误判被证实存在于生产**：家长反馈「答案讲的是另一道题」且能追到 `source_location` | ⚠️ **已知残余风险，尚未消除**（见下）⇒ 立即把该来源降级为永不 `exact`，并启动 P1 结构化切分；在此之前**不得**放宽召回 |
| 7 | **纯文本被宣称成「已证明解析归属」**（文档或文案出现「精准定位到题」「一搜即得」） | 按 M10 立即订正；这是诚实化红线 |
| 8 | `CACHE_VERSION` 未 bump 或 bump 后未参与 `qHash` | 立即修；老缓存会继续吐全文级假 `exact` |

**复核时点**：每次 `pnpm verify:ci` 复核 ①②③④⑤⑧（M31 + M27 自动）；⑥ 在**部署后第 4 周**及每次家长反馈时复核；⑦ 随每次文档改动。

**🔴 已登记的残余风险（falsifier ⑥ 的前置状态）**：合成「题干 A + 别人的解析段」当前实现**仍会放行**。40/40 ROC 实测（评审 §8.4）证明纯文本无版面坐标 / 父子 ID 时无法证明「紧邻解析段就是本题解析」，`link>=2 AND cue` 在拦住 67% 负例的同时误杀 30% 正例。⇒ **第二层上线准入闸门未全绿**，据此 P1/P2/P3 全部不放行；消除路径只有「入库时预切分并给每个对象稳定 ID / 来源坐标 / 内容指纹」，属 P1 前置条件。**期间 `exact` 必带 `source_location` 供家长回原文复核，这是兜底不是免责。**
