## 1. 为什么立项

D-028 在切题后做了 10 次只读 GET 采样，合并 P95 **3705ms ≥ 3s**，越过 `§4 P0-3`；当时据「复采回落」初判为冷启动效应，并明确「不归因、不宣称达标、不触发回滚」，列 P1 独立评估。

本轮按思傅「冷启动 P95 进行立项评估」的指令，做了两轮共 **80 次**同条件只读采样，结论**修正了初判**：

- **不是冷启动**。第 3 轮起（warm）P95 仍 **3498 / 3462 ms**；`geo-fixed` 这条 query 在第 3–8 轮稳定落在 **3.43–3.83s**，是**稳态长尾**而非首轮尖峰。
- **不能归因于切题**。库已写入，无法在不破坏生产数据的前提下回到 32.7 万行状态做同条件前后对照；且 `EXPLAIN ANALYZE` 显示检索候选池走的是 `netdisk_files.text_flat`（490ms）与 `question_objects` 按 `source_id` 索引（4.3ms），**后者并未随行数翻倍而变慢**。
- 因此 D-028 的「复采回落指向冷启动」应作为**历史行保留不涂改**，本条以更大样本给出更保守的观察，不推翻其「不归因、不宣称、不回滚」的处置。

立项目的不是"修好 P95"，而是把**「P95<3s 硬闸到底有没有被越过、由什么构成、该怎么测」**变成可复核的工程事实，避免在证据不足时顺手改判定层或放宽硬闸。
