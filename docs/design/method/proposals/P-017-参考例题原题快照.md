## 0. 一句话

**库里一直有图，只是抽文本时被丢掉了；解析残缺不是「题难」，是公式（OLE/WMF 位图）和几何图一起被`text_only`吞了 —— 所以要把原题那一块原样截回来给出来。**

## 1. 报障取证（L3 只读，2026-11-08）

| 检查项 | 实测 |
|---|---|
| `question_objects` 字段 | **没有任何图片类字段**（只有 `stem_text` / `solution_text` / 坐标与定位列）⇒ 图从来没进过结构化表 |
| `pdf_tool.py` | 抽取走 `text_only=True`，**明确不保留图**；PDF 来源的图全丢 |
| docx 内的公式 | 是 `o:OLEObject` 引用，落地为 **WMF 位图**；成都二诊文档 3,205 个 `wmf` 中 **2,761 个是公式对象** |
| 库内残缺实际长什么样 | 「抛物线中，当时，；当时，或3」—— 该有公式的位置全空，纯文本抽取把公式一起吞了 |
| 来源分布（带解析对象 92,357） | docx **3,705 份 / 89,523 对象（97%）**；PDF 440 份 / 2,805 对象 |
| 图片能否匿名读 | 既有 `GET /api/storage/files/*` 在 `PUBLIC_ROUTES` 内，`LOCAL_HTTP=200 / PUBLIC_HTTP=200 / image/webp` ⇒ **不用新开端点** |

**结论**：这不是召回问题，也不是判定问题，而是**取数管线在第一步就把「非文本」扔了**。任何在 `question-match.ts` 或打分侧做的改动都救不回来。

## 2. 主流设计思想复检（选型依据）

| 方案 | 能力 | 为什么本轮不选 |
|---|---|---|
| **MinerU / PP-StructureV3**（版面分析 + bbox + 公式识别） | 文档级版面还原，能出 markdown + 图 + 公式 LaTeX | 需较大算力（GPU 或大内存），L3 只有 **4 核 / 3.7G / 无 GPU**，且要跑 3,705 份；更关键的是它输出「整页的图与文本块」，**不等于「这道题对应哪块图」**——我们要的是题级映射 |
| Mathpix 类商用 OCR | 公式转 LaTeX 质量最好 | 收费 + 外部上传整份教辅，涉第三方与版权面扩大，且同样不解决题级映射 |
| 重跑切题 / 改 OCR 纠错 | — | `D-017` 已实测纯规则切题 `exact` 1/8 且唯一命中是假 exact，此路**已证伪**，不重走 |
| **docx → PDF → 文本锚点定位 → 裁切原题块**（本轮采用） | 一次拿到**图形 + 公式 + 排版**三样；题级对应直接由题干锚点算出；纯 CPU、可断点续跑、内容寻址 | 依赖 LibreOffice 转换保真度；扫描版 PDF 无文本层时不适用（PDF 440 份本轮不在范围） |

**为什么这条对**：`D-018` 的目标已经重锚为「检索到正确解答**思路和过程**」。孩子看到「抛物线中，当时，」这种残串根本读不懂题，更谈不上借鉴思路。**原题快照不是装饰，它是「读懂题」的前提**。而 docx 占 97%，转 PDF 后原样裁切，图形与公式同时回位，改动面最小、可回滚。

## 3. 六栏

### ① 判据（L1 / L2 / L3）

**L1（本轮）**：① 迁移 `0028_question_figures.sql` 新增「图↔题目对象」映射表（只存 key，不存二进制）；② 离线构建脚本 `netdisk-figure-build.mjs` + `netdisk-figure-crop.py`（docx→PDF→锚点定位→裁切→WebP→内容寻址入库）；③ `ReferenceExample` 增 `figureUrl` / `figureWidth` / `figureHeight` / `figurePage`，由 `netdisk-search.service.ts` 在 `mergeReferences()` 之后一次性批量挂载；④ 前端参考例题卡片内嵌缩略图 + `previewImage` 放大；⑤ `CACHE_VERSION v12→v13` + 9 处旧断言同步 + **M39**。
**L2（不做）**：MinerU / PP-StructureV3 版面还原、公式转 LaTeX、向量召回、Reranker、知识点图谱、变式题生成。理由见 §2 与 `P-015 §1`；各需独立提案与更强算力。
**L3（不做）**：改 `question-match.ts`、六条硬闸、`strict=1`、第二层上线准入、复习排程、隐私政策口径、4 组身份治理。

### ② 归因（不变量 / 约束 / 准则）

- **不变量 A（判定层零改动）**：`question-match.ts` **一行不动**，sha256 仍为 `84f998ff…`；图只挂在 `references` 上，`answer` 仍只能来自 `exact`。
- **不变量 B（缺失就如实缺失）**：定位不到 / 题干过短 / 转换失败 ⇒ **不入库、不下发**，前端无图就不渲染图片区（**绝不拿相邻题或占位图顶替**）。
- **不变量 C（只读挂载）**：`attachFigures()` 只做一次 `select ... in (source_ids)`，不参与召回、不参与打分、不改 note、不改 `match_level`。
- **不变量 D（顺序）**：事先声明仍在所有参考内容之前，图上不得插到声明之上（`D-018`）。
- **约束**：`GK-SRS-20a M10`（宣称不超能力）、`M11`（如实告知不是拦截）、`M8`（不碰间隔表与结果指标）；《双减意见》§15 ⇒ 仍只有 `exact` 才放解析，图是「参考资料原文截取」，不是解析放行。
- **归因**：C-正确性（不改变答案层准入）＋ C-资源（离线构建、单机可跑、断点续跑、内容寻址去重）＋ C-呈现（题必须连图一起看得懂）。

### ③ 证据（20b 条目 + 级别）

**20b 无对应条目**——「参考例题是否带图」不是学习干预，是呈现完整性问题；Q1/Q2 不适用、Q3 **不可测**（M8 隔离，`0021 review_events` 当前 0 行）⇒ `OPS-22 §3.2` 判 **D（降维）**：只做正确性与呈现工程，**不做指标、不做宣称**。
参照系是同一批检索结果在改动前后的 `references[].figureUrl` 有无、图与原题是否同一块区域、以及 `question-match.ts` sha256 是否漂移 —— **不是学习结果**。

### ④ 算子（T / D / X + 边界 + 不做什么）

- **T 移植**：`D-018` 已批准的并列第二层「原样呈现」——把已批准的第二层补上它本该有的视觉部分（属缺陷补全，不是新干预）。
- **D 降维**：接受「快照是近似呈现」——裁切块可能带上相邻题的行距、页眉页脚已在 ±3% 边界裁掉但可能残留，**如实标注「上图是资料库原题的原样截取（含图形与公式）」并给出原文档页码**，不承诺像素级精准。
- **X 禁止**：拿相邻题的图顶替；构造占位图；把图当成本题答案或解析；新开需登录的图片端点；把「有图」说成「题看懂了」；承诺全覆盖。
- **边界**：扫描版 PDF（440 份）、`.doc` 10,503 份、超大 PDF 不在本轮；`engine_version='fig-v1'` 只对 docx 来源生效。

### ⑤ falsifier（产品内可采集）

1. 任一 `references[]` 的 `figureUrl` 指向的图**不是该题所在区域**（拿相邻题顶替）⇒ 立即停、回滚、登记；
2. 图片端点需要登录头 / 不在 `PUBLIC_ROUTES` 内 / 小程序 `<Image>` 拿不到图（`LOCAL_HTTP` 或 `PUBLIC_HTTP` 非 200）；
3. 无图时前端出现占位图或「图加载失败」框 ⇒ 违反不变量 B；
4. 图被渲染在 `reference_disclaimer` 之前 ⇒ 违反 `D-018` 声明先行；
5. `question-match.ts` sha256 与 M35–M38 钉住值不同，或 `answer` 非空 / `verified=true` / 出现「采纳」；
6. 构建脚本写入了 `question_figures` 之外的表，或对 `question_objects` / `netdisk_files` 做任何写操作；
7. `CACHE_VERSION` 未 bump，或旧缓存仍吐「有图字段但无图」的错位结构；
8. 出现「每道题都带图」「图形全覆盖」「看得懂图形」「精准到这道题」/「提升命中 / 修复有效 / 误判归零 / 所有用户已可用」等宣称。

任一出现即按 `OPS-22 §3.4` 停下、回滚、登记。

### ⑥ 验收断言

- **M39**（新增，10 组）：判定层 sha256 未变；`0028` 表结构 / 唯一键 / 版本列齐全；构建脚本只写本表；短题干跳过且不留顶替；挂载只读、无占位；`CACHE_VERSION v13` 且 9 个旧模块断言同步；前端按 `figureUrl` 条件渲染 + `previewImage` + 「原样截取」如实说明；声明先于图；走既有公开读路由、不新开端点；文档六栏 + 台账 + 不宣称词。
- **生产对照**：干净几何单题 `references` 带 `figureUrl` 且 `PUBLIC_HTTP=200 / image/webp`；整页 `mode=kb` 同样带图；`/api/netdisk/search` 直连行为不变；`answer` 恒空、`verified` 恒 false。
- **不宣称**：本轮只让**已经召回出来的参考例题**连图一起可见；**不计算召回率、不宣称命中提升、不宣称题都看得懂**；样本仅方向性证据；唯一够格指标仍是 `0021 review_events`（当前 0 行）。

## 5. 实现方案（执行期偏差须回填本节）

**落库**：`migrations/0028_question_figures.sql` —— `(user_id, source_type, source_id, object_index)` 唯一键；只存 `storage_key / width / height / size_bytes / page_index / source_revision / engine_version / built_at`，**不存二进制**。

**取数**：`netdisk-figure-build.mjs` 从 `question_objects` 取「有解析且题干够长」的对象，按 `source_id` 断言来源，docx 下载到工作目录 → 批量交 python 段；`--shard i/n` 按 `source_id` 哈希分片（幂等、断点重启不留空洞），`--apply` 才写库，默认 dry-run。

**定位**：`netdisk-figure-crop.py` —— `soffice --headless` 批量转 PDF；`pypdfium2` 取字符框；三重兜底：① 按 `char_start/正文总长` 折算预期页 ±3 页窗口；② 锚点长度 28→20→14→10 字逐级缩短；③ 全篇单调向后 → 全篇任意。裁掉页眉页脚（±3%），余白 40px，`SCALE=2.0`、`MAX_H=2200`、`WEBP_Q=78`。题干 <10 字直接跳过并计数（「1.C」这类答案片段不是题）。

**存储**：内容寻址 `figures/<sha前2位>/<sha>.webp`，同一块图天然去重。

**下发**：`question-reference.ts` 增 `figureUrlFor(key)`（拼 `STORAGE_PUBLIC_BASE_URL` + `/api/storage/files/<key>`）；`netdisk-search.service.ts` 在 `mergeReferences()` 之后 `attachFigures()`，一次 `in (source_ids)` 查询；无图则不设字段。

**呈现**：`answer-editor.tsx` 参考例题卡片内 `{r.figureUrl ? (<Image mode="widthFix" onClick={previewImage}/>) : null}` + 「上图是资料库原题的原样截取（含图形与公式），点一下可放大 · 原文档第 N 页」。

**缓存**：`CACHE_VERSION v12→v13`（`references[]` 结构变了，旧缓存会「有内容、无图」）。
