## 1. 文档目的与适用范围

本文约束所有页面与组件的交互与视觉实现。新增页面/组件必须符合本文；与本文冲突的实现视为缺陷。

- 与 `design_guidelines.md` / `DESIGN.md` 的关系：二者已标注"已并入"，气质与配色口径以本文为准；
- 令牌的**实施细则**（设计依据、量化诊断、实施批次）见**附录 C《视觉美学设计方案》**；
- 平台坑的实现细节见 DD-08 第 12 章。

### 1.1 设计前提：主要用户是家长（2026-10-24 定稿，上游 SRS-01 第 2 章）

本文所有交互与视觉取舍，均以「**家长在碎片时间里用手机单手操作**」为第一前提：

| 前提 | 落到规范上的硬约束 |
| --- | --- |
| 家长是整理者与督导者，孩子只做「做—订正—巩固」 | 录入链路步数最少（拍 → 裁剪 → 入题，尽量不打字）；孩子侧界面克制、不打扰、单次题量可承受 |
| 碎片时间、单手、常被打断 | 关键操作一步可达；写操作后必须保持滚动位置（不得跳回列表顶部）；支持随时中断后继续 |
| 家长要「能打印、能改」 | 导出物同时提供 PDF（拼页省纸，直接打印）与 Word（可编辑、加批注后再打印）——同一入口、用户选格式 |
| 家长也要看得清、看得久 | 视觉基线遵循本文第 9 章令牌体系（纸底 + 墨字 + 松绿强调）：正文对比度 ≥ 4.5:1、字号下限 12px、触控目标 ≥ 44px |

> 📌 反例：任何"为了视觉精致而增加操作步骤""把关键入口藏进二级菜单"的改动，都违背本文前提，评审时应直接驳回。

## 2. 信息架构

### 2.1 TabBar（5 个）

| Tab | 页面 | 用途 |
|---|---|---|
| 首页 | `pages/index` | 最近录入（收件箱全量流 + 筛选 + 批量） |
| 复习本 | `pages/subject` | 复习本条目（学科/标签/时间筛选，合成 PDF/Word） |
| 文档 | `pages/document` | 生成 + 文档库两页签，导出与查看 |
| 记忆 | `pages/memory` | 成长记忆列表 |
| 我的 | `pages/profile` | 登录、资料、配额与统计 |

TabBar 视觉：`color #9A948A`、`selectedColor #2E6F4E`（品牌色）、背景 `#ffffff`、`borderStyle white`。

### 2.2 页面树（13 个）

**一级（Tab）**：index、subject、document、memory、profile
**二级（从列表/我的进入）**：detail（题目详情）、recognize（识别导入）、library（资料库）、chat（智能客服）、chat/admin（知识库管理）、memory/edit、memory/detail、scan-login（H5 扫码登录落地页）

### 2.3 跳转关系

```
首页 ──┬─▶ 详情（编辑/填答案/图片编辑）
       ├─▶ 识别导入（拍照录入）
       └─▶ 图片编辑器（cropOnly 裁剪入题）
复习本 ─┬─▶ 详情
        └─▶ 合成 PDF/WORD → 文档页产物
文档 ───▶ 生成 / 文档库（打开、改名、删除）
记忆 ───▶ 记忆详情 / 记忆编辑
我的 ───▶ 登录、资料库、客服、知识库管理
```

### 2.4 页面参数约定

- 条目 id 用路由 query 传递（如 `/pages/detail/index?id=xxx`）；
- 从列表进详情时，列表侧保存 `restoreItemId`，返回时按 **id** 锚回（不是像素偏移）；
- 来源标记（如裁剪目标题标签 `cropTargetLabel`）用显式参数，不用隐式全局。

## 3. 导航与返回

**核心规则：返回必须回到原位置，不得回到顶部。**

1. 列表 → 详情：进入前记录当前滚动偏移与条目 id；
2. 详情 → 列表：先恢复偏移，再归位到该条目（双帧 + 强制触发滚动，Taro 下需"先偏移再归位"才生效）；
3. 物理返回键与左上角返回行为一致；
4. 弹层关闭：遮罩点击 / 关闭按钮 / 返回键三者一致；多弹层叠加时按栈后进先出关闭。

## 4. 列表页交互

| 项 | 规则 |
|---|---|
| 进入选择态 | 长按条目或点"批量"按钮 |
| 底部批量条 | `selection-bar`：加入/移出复习本、合成、删除；退出用取消/Esc 区 |
| 单条「⋯」菜单 | **各列表页保持一致**：图片 AI 动作 / 编辑 / 修改分类 / 加入或移出复习本 / 删除 |
| 筛选 | 控件固定在列表头部（`filter-header`），变更即请求后端（不做前端过滤），首屏/筛选切换才显示骨架屏 |
| 分页 | 触底加载，`PAGE_SIZE=20`，到底显示"没有更多" |
| **写操作** | **静默刷新**：不置 loading、不显示骨架屏、不重置滚动位置 |

> 静默刷新的原因：置 loading 会让列表内容塌缩 → ScrollView 高度骤变 → 滚动位置被钳回顶部（思傅三次反馈点）。

---

## 5. 图片交互规则

1. **点图片 = 打开并可编辑；点列表其它区域 = 进详情**；
2. 编辑结果**原位替换**（同时更新 `file_key` 与 `thumb_key`），绝不新建条目；
3. 图片可删除（详情页题面图 / 答案图 / 图片条目），只解引用不删文件；
4. 支持大图预览与多图切换；
5. 上传附件一律 `purpose=attach`（用 `save` 会重复建条目）——详见 ADD-06 第 6 章；
6. 开发者工具返回的 `http://tmp/...` 是伪 URL，必须用 `isRemoteImageUrl()` 判定后再决定是否上传。

## 6. 弹层与层级

| 层级 | z-index | 用途 |
|---|---|---|
| 页面内容 | 0（文档流） | 列表、卡片 |
| 固定头部 / 底部保存条 | 100 | 筛选头、批量条、悬浮保存条 |
| 弹层与遮罩 | 200+ | 底部抽屉、居中对话框、全屏编辑器、Toast |

- ⚠️ **任何 fixed 浮层必须 > 100**，否则会被底部保存条盖住（历史事故）；
- 弹层类型：底部抽屉（筛选、批量操作）、居中对话框（重命名、确认删除、格式选择）、全屏编辑器（图片编辑）、Toast（结果反馈）；
- Toast 由 `app.tsx` 的全局 `<Toaster />` 宿主承载，页面内不自建。

---

## 7. 表单与编辑

- 编辑态与展示态切换：点「编辑」进入，「完成」退出；
- 数学输入：`math-symbol-bar` 四页签（常用符号 / 希腊字母 / 公式模板 / 常用序号），网格三行限高可滑动，按光标位置插入**可读形式**；
- ⚠️ **编辑态绝不显示 LaTeX 源码**（如显示 `1/2`、`√3`、`x²`，不显示 `\frac{1}{2}`）；
- 公式渲染：`math-text` 无公式行走 `Text`、含公式行走 rich-text；解析失败回退显示源码（仅兜底）；
- 保存为局部合并语义（未传字段不清空）；
- 重命名类弹层：条件渲染 + 挂载取初值，避免渲染相位 setState 被丢弃导致空白。

## 8. 反馈机制

| 类型 | 规范 |
|---|---|
| Toast | 明确动作结果（「已移出复习本」「已保存」），不用"操作成功"这类空话 |
| Loading | 首屏与筛选切换用骨架屏；按钮级操作用按钮 loading；**写操作后禁用骨架屏** |
| 空态 | `EmptyCard` 给出引导动作（如"去拍照录入"） |
| 错误态 | 必须给可重试的显式入口；配额/限流类错误直译后端文案（如"知识库今日调用次数已达上限"） |
| 超时 | 下载类显式 30s 超时并给"复制链接"兜底；请求连接类错误自动唤醒后端并重放一次（用户无感） |

## 9. 视觉基线（令牌与数值）

> 令牌单一出口：`src/app.css`（CSS 变量 + `@theme inline`）与 `src/lib/theme.ts`（JS 侧常量）。两处必须同步；能用 Tailwind 类名的一律用类名（`text-brand` / `bg-brand-soft` / `border-brand-line`）。

### 9.1 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--brand` | `#2E6F4E`（松绿） | 强调色：主按钮、选中态、Tab 选中、进度 |
| `--brand-soft` | `rgba(46,111,78,0.08)` | 淡底：芯片、标签、选中背景 |
| `--brand-line` | `rgba(46,111,78,0.25)` | 描边：强调态边框 |
| `--brand-foreground` | `#FFFFFF` | 品牌底上的文字 |
| `--destructive` | `#A8321F` | 危险语义（删除）；与品牌色拉开明度差 |
| `--background` | `#FAF8F3`（纸） | 页面底 |
| `--foreground` | `#2A2825`（墨） | 主文字 |
| `--muted-foreground` | `#6F685C` | 次要文字（纸底 5.16:1，满足 WCAG AA） |
| `--muted` / `--secondary` / `--accent` | `#F1EDE4` | 卡片内浅底、次要按钮 |
| `--border` / `--input` | `#E4DED1` | 分隔线与输入框描边 |
| `--ring` | `#2E6F4E` | 聚焦环 |
| `--card` / `--popover` | `#FFFFFF` | 卡片与浮层 |
| `INK_FAINT` | `#9A948A` | 占位符、禁用图标 |

- ⚠️ **强调色只允许三档派生**（`-soft` / `-line` / 实色），禁止散落其它透明度（历史上曾有 15 种）；
- ⚠️ **删除类动作必须「图标 + 文案」共现**，不靠颜色单独表达；
- 品牌色历史：朱砂 `#BE3E2D` → 松绿 `#2E6F4E`（2026-10-24 改，因红色在家长督导场景提升生理唤醒；松绿白字对比度 6.03:1）。附录 C 若仍写朱砂，以本文为准。

### 9.2 字阶与字号

- **字号下限 12px**：所有可点击功能键与正文不低于此值；装饰性角标/提示徽标为例外（代码现存 8~11px 徽标属既有例外，新增不得再降）；
- 层级靠**尺寸而非颜色**建立（如统计数字 24px、标签 12px）；
- 常用类：`text-xs`（标签/次要）、`text-sm`（正文）、`text-lg`（强调符号）。

### 9.3 尺寸与结构

| 项 | 值 / 规则 |
|---|---|
| 触控目标 | ≥ 44px（小程序规范；图标按钮靠 padding 撑够） |
| 圆角 | 沿用组件库既有圆角令牌（卡片 > 芯片 > 徽标） |
| 间距栅格 | 8pt 栅格（4/8/12/16/24） |
| 列表卡片结构 | 标题区 → 摘要/题干 → 图片区（缩略图）→ 操作区（⋯、选择态） |
| 设计宽度 | 750（Taro `designWidth`，`rem2rpx` 转换） |

### 9.4 学科色

`SUBJECT_COLOR_MAP`（12 主色 + 3 兼容旧值），每色含 `badge/bar/dot/soft/text` 五档；缺省回退 `gray-500`。新增学科色必须先登记令牌。

## 10. 平台差异与已知限制

| # | 限制 | 应对 |
|---|---|---|
| 1 | Taro 4.1.9 `<Text>` 不绑点击事件 | 交互元素一律 `<View onClick>`；已在 `app.tsx` 补 `pure-text` 别名修复事件移除 |
| 2 | 渲染相位 setState 会被丢弃 | 副作用进 `useEffect` + `cancelled` 守卫；弹层条件渲染后再取初值 |
| 3 | 首帧数据可能为 null | 子组件延迟挂载（`{item && <Child/>}`） |
| 4 | 字号下限 12px | 见 9.2 |
| 5 | 开发者工具伪 URL（`http://tmp/...`） | 用 `isRemoteImageUrl()` 判定；否则后端 `ENOTFOUND tmp` |
| 6 | 小程序无相对路径 / 域名校验 | baseURL 由编译期 `PROJECT_DOMAIN` 注入；真机需同 Wi-Fi 且端口放行 |
| 7 | iOS / 安卓差异 | 滚动回弹、图片解码、字体渲染差异需两端分别验收 |
| 8 | 微信请求默认 60s 超时 | 长任务（chat 130s 等）显式设 timeout；下载显式 30s |

## 附录 A · 交互检查清单

新增/修改页面时自检（开发自测与 AI 自检通用）：

1. 层级：fixed 浮层 z-index > 100？
2. 字号：正文与可点元素 ≥ 12px？触控目标 ≥ 44px？
3. 颜色：强调色只用三档派生？删除动作"图标 + 文案"共现？品牌色取自令牌而非硬编码？
4. 返回：从详情返回是否按 id 锚回原位？
5. 写操作：是否 silent 刷新（无骨架屏、不重置滚动）？是否 `invalidateAfter` 清了对应缓存域？
6. 图片：点图进编辑、点其它区进详情？编辑是否原位替换且同步 thumb_key？附件上传用 `attach`？
7. 交互元素是否都用 `<View onClick>`（不用 `<Text>`）？首帧 null 是否守卫？
8. 反馈：Toast 文案是否说明动作结果？错误是否有可重试入口？
9. 列表：菜单项与其它列表页是否一致？分页到底是否有"没有更多"？
10. 空态：是否有引导动作？
