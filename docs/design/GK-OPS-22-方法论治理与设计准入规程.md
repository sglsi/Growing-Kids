# GK-OPS-22 方法论治理与设计准入规程

> 编号：GK-OPS-22 ｜ 版本：v1.0 ｜ 日期：2026-10-28 ｜ 状态：**正文完成 · 三条硬门已接入套件与 CI · C3 样板已出**
> 读者：产品决策者 / 设计与研发 / 任何提出「加个功能」的人 ｜ 上游：**GK-SRS-20a（宪法：判据、三问、算子、准则）**、GK-SRS-20b（证据台账）｜ 下游：SRS-01 §10（不做清单）、OPS-18 §3.x（缺口状态）、QA-17（交付自检）、QA-21（套件与报告）、`server/scripts/method-gates.mjs`
>
> 📌 **本文解决什么问题**
> `GK-SRS-20a` 说清了「什么算学会、什么样的功能有依据」，但它**不会自己生效**——宪法没有程序就是参考文献。本文只做一件事：**把 20a 的三个产出（七栏准则 / 三问决策器 / T-D-X 三算子）装进流程，让绕过去比遵守更难。**
>
> 📌 **本文不重复 20a 的内容**
> 判据、证据、准则正文一律以 20a/20b 为准；本文只规定**谁在什么时候必须交什么、机器验什么、失败怎么办**。两处若冲突，方法论以 20a 为准，流程以本文为准。

---

## 0. 一句话

**四道门（提案单 → 三问 → 落地三关 → 复核）+ 三条硬门（归因 / 口径 / 同步）+ 一本台账（决策记录）。**

门要少，少到不遵守很明显；台账要真，真到能挡住同一个提案被反复提。

---

## 1. 为什么需要这一层（三个真实失效场景）

不是假想。这三件事在本项目都出现过或差点发生：

| 失效场景 | 具体形态 | 20a 里本来就有答案，为什么还是发生 |
|---|---|---|
| **文档写完没人读** | 20a 附录 B 有 8 步操作清单，但它是「读的时候照做」，不是「不照做就过不去」 | 缺少触发点：没有哪一步会因为你没填而停 |
| **降维后仍在宣传** | D 算子的定义明确要求「降维必须同时降级对外表述」，但没有任何地方检查文案 | 缺少检查面：文案与准则分属两个仓库区域，没人对照 |
| **参数与断言漂移** | 间隔表改一处、断言没改，套件仍然全绿（断言锁的是旧值，只是没人改它） | 缺少镜像：文档、代码、断言三处各写一遍，靠自觉同步 |

三条对应的解法就是本文的三条硬门：**给触发点、给检查面、给镜像**。

## 2. 谁在什么时候用（三档分级）

分档依据是**是否触碰学习行为**，不是代码量。改 800 行样式仍然可以是 L0；加一个 20 行的字段可能是 L1。

| 档 | 判定条件 | 必须做的事 | 谁做 | 典型耗时 |
|---|---|---|---|---|
| **L0 微改** | 不动机制：文案措辞、样式、修 bug、重构（行为不变） | 无提案单；照 QA-17 §9.4 自检 | 开发者 | 0 |
| **L1 功能级** | 新增或改动**一个学习行为**：题型、反馈时机与内容、排程、掌握判定、导出默认口径、复习排序 | 提案单六栏 + 比对 M1–M10 + 至少一条断言（或明确「不宣称」） | 提案人写，决策者批 | 半小时 |
| **L2 机制级** | 改准则 / 加准则 / 改判据 L1–L3 / 改不变量 / 改结果指标口径 | 20a 升**主版本** + 20b 补条目 + 全仓引用同步 + 断言 + 台账记 D 号 | 文档所有者 + 一轮评审 | 半天 |

**判定示例**（用真实提案，避免分级靠感觉）：

| 提案 | 档 | 理由 |
|---|---|---|
| 把导出按钮文案从「导出 Word」改为「打印练习卷」 | L0 | 只改措辞，不改默认行为 |
| 导出默认值由「含答案」改为「不含答案」 | **L1** | 改了默认学习行为（孩子拿到的卷子变不变） |
| 复习本加「按错因筛选」 | L1 | 新增一种学习行为入口 |
| 把间隔表 1→3→7→14→28 改成 1→2→5→10→21 | **L2** | 动的是 M8 的具体数值，20a/20b/注释/断言四处联动 |
| 给复习条目加 `confidence` 自评 | L1 | 新字段 + 新交互，但不动准则 |
| 决定「做一个 ZPD 测量功能」 | L2（且大概率 X） | 直接冲 M10 |

> ⚠️ **不要给 L0 也套表单。** 一个 30 行的表单套在改错别字上，两周之内所有人都会绕过它——这是流程最常见的死法。

## 3. 四道门

### 3.1 第一道：提案单（六栏，缺一栏退回）

提案单是本规程唯一的输入工件，落 `docs/design/method/proposals/P-NNN-<短名>.md`。**只留六栏**，因为再多就没人填。

| 栏 | 填什么 | 合格判据 | 常见不合格 |
|---|---|---|---|
| ① **判据** | 这个改动改善 L1 延迟 / L2 无提示 / L3 迁移 中的哪一条 | 必须点名一条；写「体验更好」不合格 | 「让孩子更爱学」（不是判据，是期望） |
| ② **归因** | 指回哪条不变量（I1 提取 / I2 修正 / I3 间隔）或哪条约束（C-资源 / C-动机 / C-元认知），以及相关准则号 | 至少一条不变量或约束；**指不回去即退回**（20a R2） | 「属于学习闭环」（不变量不是这个意思） |
| ③ **证据** | 20b 条目号 + 级别 + 量级；20b 里没有则说明检索范围与结论 | 级别 ≥ B 才可「做」；C/D 只能用于**否决** | 「很多研究都说」（无条目、无级别） |
| ④ **算子** | T 移植 / D 降维 / X 禁止，并写出边界（不适用条件）与「不做什么」 | 必须选一个；选 D 必须写清**宣称同步降级什么** | 只写 T 不写边界（等于假设全域有效） |
| ⑤ **falsifier** | 若这条判断错了，产品里会先看到什么数据 | 必须是产品内可采集的量，不是「再查文献」 | 「如果效果不好」（不可观测量） |
| ⑥ **验收断言** | 用什么用例/静态门锁住；没有则写「不宣称」并说明 | 二选一：一条可执行断言，或显式声明不对外宣称 | 「人工验收」（不是断言，是承诺） |

> 📌 **六栏的因果顺序不是随手排的**：①定方向 → ②定归属 → ③定依据 → ④定形态 → ⑤定退路 → ⑥定证据。跳过②直接写④，就是 20a 说的「跨层跳跃」。

### 3.2 第二道：三问决策（产出 T / D / X）

三问与算子定义见 20a §5.1 / §5.2，本文只补**边界情形怎么裁**——实际评审中 90% 的分歧都在这些缝里：

| 情形 | 处置 | 理由 |
|---|---|---|
| Q1 量级不够，但实现成本近零 | **仍然 X** | 成本低不是理由，注意力位是稀缺资源（20a §5.3） |
| Q1 过，Q2 边界只覆盖部分用户 | **D**，并在文案上限定适用面 | 部分有效的事实必须显式说出来，否则等于全域宣称 |
| Q2 边界内为**负效应** | **X**，不做降维 | 降维的前提是「方向对、精度降」，方向错了没有可降的东西 |
| Q3 不可测但机制清楚 | **D**：只做启发式，**不做指标、不做宣称** | 20a M10 的直接推论 |
| 三个问题都过，但与某条 M 冲突 | 走 20a §7.4 张力裁决 | 冲突不是否决，是要求写明让位关系 |
| 已被否决过的提案再次提出 | 先查台账（§5）；无新证据则**直接引用旧 D 号驳回** | 台账的主要用途之一 |

### 3.3 第三道：落地三关（20a §5.6 的强制化）

| 关 | 强制要求 | 谁来保证 |
|---|---|---|
| ① 文档 | 20a/20b 对应条目已更新；或写明「本次不动准则」 | 人工（评审时看） |
| ② 代码注释 | 实现处引用 `GK-SRS-20a M<n>` 与 20b 章节号 | 人工（review 时看） |
| ③ 断言 | 三选一：**硬断言**（行为锁死）/ **镜像断言**（与代码常量逐字一致）/ **显式不宣称** | 机器（H3）+ 人工 |

> ⚠️ **「显式不宣称」是合法选项，不是逃避。** 有些机制（如辅助强度随掌握梯度变化）现阶段只能做启发式，写清「我们不宣称它有效」比硬凑一条假断言更诚实。

### 3.4 第四道：复核（falsifier 触发）

falsifier 一旦在产品数据里出现，**动作是改准则或改实现，不是解释数据**。处置三选一，且必须留痕：

1. **改实现**（判断没错，实现偏了）；
2. **改准则**（判断错了，20a 升主版本，走 §7 变更程序）；
3. **记录例外**（数据噪声/样本太小，写明复核时点）。

## 4. 三条硬门

硬门是**机器能判定的那部分**，不是全部。把不能判定的也做成门，只会逼人写假证据。

| 门 | 机器验什么 | 人判什么 | 失败处理 |
|---|---|---|---|
| **H1 归因门** | 提案单存在、六栏齐备且非占位、引用的 `M<n>` 与 `20b 文献 <n>` 真实存在 | 归因**是否成立**、边界写得对不对 | 退回补栏，不进入评审 |
| **H2 口径门** | 用户可见面（`src/**`、SRS-03 手册）不含**禁用宣称词** | 宣称与实现是否匹配 | 改文案或降级宣称；词表误伤可提 PR 改词表 |
| **H3 同步门** | **镜像参数**逐字一致（见 §4.3） | 三关是否真的都过了 | 红，不允许「先合后补」 |

### 4.1 H1 归因门

机器部分只验**结构**与**引用可解析**，因为它验不了语义——「指回 I1」这句话对不对，只有人知道。但结构这一半恰恰最容易被跳过，所以值得机器守。

### 4.2 H2 口径门

禁用词表（出现在用户可见文案即失败）：`ZPD`、`最近发展区`、`智能水平`、`智商`、`天赋`、`学习风格`、`左右脑`、`提分`、`保证提分`、`过目不忘`。
观察词表（不失败，仅提示人工确认）：`打卡`、`排行榜`、`成就`、`勋章`、`段位`。

> ⚠️ **词表只扫用户可见面**，不扫 `20a`/`20b`/`OPS-22`——那些文档必须能讨论「为什么不做 ZPD」。
> ⚠️ **禁用词表不是内容审查**：它的依据是 M10（不得宣称能测量）与 20b §5.3（明确不做），不是文风偏好。

### 4.3 H3 同步门（镜像参数表）

「改一处忘另一处」是这类项目最典型的静默缺陷。做法：把**同一事实的多处副本**登记成镜像，逐字比对。

| 镜像 | 代码位置 | 断言位置 | 文档位置 |
|---|---|---|---|
| 复习间隔表 | `server/src/timeline/review.ts` 的 `REVIEW_INTERVALS` | `verify/modules/15-review-schedule.mjs` 的期望串 | 20b §5.2.1「1→3→7→14→28 天」 |
| 导出默认口径 | `server/src/document/document.service.ts` 的 `include_answers === true` | `verify/modules/10-ocr-pdf-export.mjs` 的三条口径用例 | 20b §4.3 / SRS-01 导出条目 |

新增镜像的条件：**同一个数值/判据在三处以上出现，且任一处漂移都会导致错误行为**。不满足就别登记——镜像太多会变成维护负担。

## 5. 决策台账

`docs/design/method/decision-log.md`。凡走过三问的提案，无论结论是 T/D/X，**都要记一条**。

| 字段 | 说明 |
|---|---|
| 编号 | `D-NNN`，只增不改 |
| 对应提案 | `P-NNN`（L1 以上才有） |
| 结论 | T / D / X |
| 一句话理由 | 含关键量级（如 `g = 0.034`），让后人不必重查 |
| 参照系 | 这个量级是相对什么比较的（防「0.3」被当成普适阈值） |
| 复核时点 | falsifier 触发或定期体检的时点 |

**与既有文档的关系（避免三处真相源）**：

- 20b §5.3「明确不做」= **结论清单**（人读的摘要）；
- 台账 = **数据源**（含理由、量级、复核时点）；
- SRS-01 §10「本期不做」= 台账的**产品口播版**，只放用户能感知的条目。

新增 X 时：先记账台，再决定是否升级到 20b §5.3 与 SRS-01 §10（**不是每条都升**，否则这两处会被噪声淹没）。

## 6. 度量与体检

| | 代理指标 | 结果指标 |
|---|---|---|
| 本项目可采集 | 录入数、复习次数、连续天数、停留时长 | **到期首次作答正确率（按档位分组）** |
| 用途 | 只用于发现异常（如录入骤降），不作成功证据 | 唯一够格判断「机制是否奏效」的量 |

结果指标不需要新建埋点：`timeline_items` 已有 `review_count` / `last_reviewed_at` / `next_review_at`，到期时那一次作答的结果就天然满足 **L1（隔了 N 天）+ L2（无提示）**。按档位（1/3/7/14/28 天）分组看正确率随档位的变化，就是 20a 要的那条曲线。

**季度体检清单**（每季度一次，半小时）：

1. 逐条看 falsifier 是否被触发（20a §5.4 的 10 条）；
2. 台账里 D 号是否有需要复核的（含 falsifier 触发的、到期未复核的）；
3. 镜像参数表是否与代码一致（H3 已自动验，人工只需看趋势）；
4. 断言覆盖率：附录 A 三向索引里还有几格是 `——`（只报不拦）。

## 7. 变更程序（改准则时）

20a §6.4 已规定谁能改、改要什么。本文补**改完怎么不留下半截**：

```text
1. 改 20a 正文（纪律：编号不重排、不复用；废弃保留编号并标注）
2. 补 20b 证据条目（含级别与量级；边界写进「纠正」栏）
3. 改代码实现与注释（注释引新准则号）
4. 改断言（H3 覆盖的镜像参数必须逐字同步）
5. 全仓搜引用：grep -rn "GK-SRS-20a M<n>" docs/ server/src src/
6. 台账补一条 D 号（改准则本身也是一次决策）
7. GK-00 变更记录追加，20a 升主版本
```

## 8. 反模式（写下来是为了能指认）

| 反模式 | 长什么样 | 后果 |
|---|---|---|
| **表单空转** | 六栏都填了，但②写「学习闭环」、⑤写「效果不好」 | 比不填更糟：留下了「已评审」的假证据 |
| **门禁膨胀** | 从三条加到八条，每条都要豁免流程 | 三周内所有人学会绕过；门禁变成仪式 |
| **假断言凑数** | 为了覆盖率写「函数存在」「字段非空」这类永真断言 | 覆盖率好看，行为无保护——比没有更危险 |
| **指标反噬** | 把「复习次数」做成 KPI 或成长值 | 行为向代理指标优化，学习不变（20a §5.5 明确禁止） |
| **判决失忆** | 同一个提案半年内被评三次 | 台账存在的意义就是消灭这个 |

## 9. 落地路线与「怎么知道它生效了」

| 阶段 | 内容 | 验收判据（可观测） |
|---|---|---|
| **P0**（已完成） | 本文 + 决策台账（回填 6 条历史裁决）+ C3 样板提案单 | 台账有 6 条带量级的记录；C3 提案单可通过 H1 |
| **P1**（已完成） | `method-gates.mjs` 三条硬门 + 套件 M16 + CI `gate` 接入 | `pnpm method:check` 退出 0；故意破坏任一条能使它退出 1 |
| **P2**（持续） | 按本文走 L1/L2；季度体检；结果指标首次出数 | 每个 L1 提案有 P 号；体检记录落台账 |

判断「是否真的在指导设计」不看填了几张表，看三件事：

1. 有没有提案**被退回**（全通过的流程等于没有流程）；
2. 有没有提案因台账里已有 X 而被**直接驳回**；
3. 结果指标曲线有没有被真的拿出来看过一次。

## 附录 B 三条硬门速查

```bash

pnpm method:check

# 只跑某一条
node server/scripts/method-gates.mjs --only=h1
node server/scripts/method-gates.mjs --only=h2
node server/scripts/method-gates.mjs --only=h3
```

退出码：`0` 全过 ｜ `1` 有硬门失败 ｜ `2` 环境异常（文件找不到等，区别于「内容不合格」）。
