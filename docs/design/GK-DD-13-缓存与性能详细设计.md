## 2. 前端缓存（SWR）

**要写**：
- 存储与 key 结构：`gkc:{userId}:{域}`（**账号隔离**，登出/切身份必须 clearAllCache）；
- SWR 流程：页面进入先同步读缓存渲染首帧（0 等待）→ 后台请求刷新 → 静默更新并回写；
- 域与 TTL：列表 5min / 详情 10min / 学科 30min；详情域 LRU 30 条；
- 缓存安全前提：图片 URL 来自 public 桶 `getPublicUrl`，**永久有效非签名**，所以缓存久了不会图裂；
- 缓存读取失败、缓存过期、缓存不存在的三种分支行为。
**素材**：`src/services/cache.ts`

## 3. 写后失效收口

**要写**（本设计的核心纪律）：
- 所有写函数在 `src/services/api.ts` 用 `invalidateAfter(p, ...domains)` 包裹，**成功后**才失效对应域（失败不清——缓存仍反映服务端现状）；
- 域：`tl`（题目）/ `subj`（学科）/ `lib`（资料库）/ `doc`（文档）/ `mem`（记忆）；
- `uploadFile` 按 purpose 判域（save → tl+lib；memory → mem；temp/attach 不清）；
- **新增写接口必须包 invalidateAfter**，否则缓存 5~10min 不刷新（这是最容易漏的地方，要写成自查项）；
- auth 三个身份切换点（login / applyLoginUser / logout）必须 clearAllCache。
**素材**：`src/services/api.ts`、`src/services/auth.ts`

## 4. 后端缓存（mem-cache）

**要写**：
- 实现：`Map + TTL(30s) + 前缀失效`，定时清理且 `unref()` 避免阻止进程退出；
- 接入点：`timeline.service` 的 list / findOne / overview（key 带 userId）；所有写方法成功后 `invalidateUserTimeline(userId)`；
- **用户对象缓存 60s**：`UserContextMiddleware` 每个请求都查 users 表，是隐藏的最大瓶颈；只缓存非 null（防"登录建号前瞬间查空"被缓存成幽灵用户）；只消费 id / is_anonymous / expire_at；
- 新增读接口如何照此模式接入。
**素材**：`server/src/shared/mem-cache.ts`、timeline.service.ts、用户上下文中间件

## 5. 静默刷新（silent）

**要写**（本项目最痛的一个问题，必须写清前因后果）：
- **现象**：列表内任何写操作（加入/移出复习本、删除、改分类、上传、导出）后，页面跳回第 1 题；
- **根因**：写操作 → `invalidateAfter` 清缓存 → `load()` 走 `setLoading(true)` → 整页骨架屏替换列表 → ScrollView 内容高度塌缩 → 原生滚动位置被钳到 0；
- **修法**：五页（首页 / 复习本 / 资料库 / 成长记忆 / 文档导出）的 load 增加 `silent` 选项——不置 loading、不显骨架，旧列表留屏、后台拉新数据静默替换；
- **适用范围**：所有列表内写操作一律 silent；筛选切换 / 分页追加 / 首屏加载仍走骨架路径；
- 与「详情返回按 id 锚回」的分工（前者治列表内操作，后者治跨页返回）。
**素材**：五页 load 实现、项目记忆
