# GK-QA-15 测试策略与用例设计

> 编号：GK-QA-15 ｜ 版本：v0.0（提纲） ｜ 日期：2026-10-24 ｜ 状态：提纲待审
> 读者：测试 / 全体 ｜ 上游：全部设计文档 ｜ 下游：QA-16
> 定位：在**没有自动化测试框架**的前提下，用最小成本建立可重复验证的能力。务实优先，不追求覆盖率数字。

---

## 1. 测试目标与分层

**要写**：
- 现状：无 CI、无测试框架、单人 + AI 协作 ⇒ 策略必须"轻量、可回归、能防住历史坑"；
- 分层与定位：
| 层 | 手段 | 覆盖什么 | 是否门禁 |
|---|---|---|---|
| 单元 | 纯函数单编 + node 跑用例 | 算法与转换逻辑（latex 双向转换、探针策略、文件名解码） | 是 |
| 接口 | curl / 脚本 e2e | 端点可用性、鉴权、参数清洗、错误码 | 是（关键链路） |
| 算法 | 动态探针 + GT 数据集 | 识别与擦除指标 | 是（G16 等） |
| 前端 | 手工用例 + 特征串校验 | 渲染、交互、缓存、滚动位置 | 部分 |
| 真机 UAT | 清单勾选 | 端到端可用性 | 发布门禁 |
- **回归优先原则**：优先把"历史踩过的坑"变成用例，而非追求全面覆盖。

## 2. 可测试性基建

**要写**（这是能跑起测试的前提）：
- **纯函数单编技巧**：保持被测文件零 import（如 `src/utils/latex.ts`）⇒ `npx tsc <file> --outDir tmp --module commonjs` ⇒ node 直接跑用例；
- **动态探针**：脚本放在 `server/dynamic-tests/`，**必须在 `server/` 目录下运行**（依赖与路径要求）；
- **接口 mock**：统一 mock 层覆盖 `globalThis.fetch`，**每个用例结束后必须恢复**（历史上未恢复污染了后续用例）；
- **假凭据打真端点**：用假 API Key 请求真实外部端点，验证请求构造正确（应返回 401 而非 200）；
- 测试数据：必须使用真实 user UUID（否则每次新建匿名号导致 404）。

## 3. 单元测试用例

**要写**：逐组列出（组 / 覆盖函数 / 用例数 / 断言要点）：
- `latex.ts` 双向转换往返测试（含历史三个 bug 的回归用例：`\frac{x^2}{y_1}` 回转、分数分母吞上下标、`→` 生成空参 `\vec{}`）；
- ima provider 的 `buildQueryFallbacks` 探针链生成；
- 上传文件名解码（percent 解码 + latin1→utf8）；
- 查询参数清洗（undefined、非法日期）。

## 4. 接口测试用例

**要写**：按 ADD-06 的端点分组，逐条给「请求 / 前置数据 / 期望 / 校验点」。重点：
- 鉴权缺失、UUID 非法的表现；
- 参数污染（`undefined` 字符串）是否被清洗；
- 写操作后缓存是否失效；
- 删除越权是否被拦截（返回 200 但 0 行是 bug）；
- 上传 purpose 四种取值的落库差异；
- 三模式搜题缓存互不串味（`mode` 前缀）。
**待确认**：接口测试是否需要固化为可执行脚本（当前为手工 curl 集）。

## 5. 算法测试用例

**要写**：GT 数据集构成（五场景）、指标口径（G13 / G15 / G16，G16 口径 M ≤ 2.0%）、探针运行命令、回归门禁阈值、失败时的定位路径。指向 DD-10 第 10 章。

## 6. 前端用例

**要写**：手工用例清单，逐条给「前置 / 操作 / 期望」。重点覆盖历史坑：
- 缓存：写操作后刷新、切身份后清空；
- 滚动位置：列表内操作后不跳顶、详情返回锚回；
- 弹层：不被悬浮保存条遮挡（z-index）；
- 首帧：慢网络下不崩（null 守卫）；
- 公式：编辑态不显示源码、渲染失败回退；
- 符号栏：三行限高可滑动、插入位置正确；
- 图片：原位替换不新建条目、删除只解引用。

## 7. 真机验收清单

**要写**：发布前逐条勾选的清单（iOS / 安卓分列），覆盖：登录、拍照录入、识别、复习本、导出、三模式搜题、资料库、成长记忆；以及阻断项（不通过不发版）。

## 8. 回归门禁

**要写**：明确哪些是**合并前必须跑**的（单元用例全绿、关键接口 e2e、算法指标达标、tsc 无错、build 通过 + dist 特征串校验），以及当前的自动化程度缺口（登记 OPS-18）。

## 9. 缺陷管理
