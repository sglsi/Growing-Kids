> 定位：在**没有自动化测试框架**的前提下，用最小成本建立可重复验证的能力。**务实优先，不追求覆盖率数字。**

## 1. 测试目标与分层

### 1.1 现状约束

无 CI、无测试框架、单人 + AI 协作 ⇒ 策略必须"**轻量、可回归、能防住历史坑**"。

### 1.2 分层

| 层 | 手段 | 覆盖什么 | 是否门禁 |
|---|---|---|---|
| **单元** | 纯函数单编 + node 跑用例 | 算法与转换逻辑（latex 双向转换、探针策略、文件名解码、查询清洗） | ✅ 是 |
| **接口** | curl / 脚本 e2e | 端点可用性、鉴权、参数清洗、错误码 | ✅ 是（关键链路） |
| **算法** | 动态探针 + GT 数据集 | 识别与擦除指标 | ✅ 是（G16） |
| **前端** | 手工用例 + 特征串校验 | 渲染、交互、缓存、滚动位置 | 部分 |
| **真机 UAT** | 清单勾选 | 端到端可用性 | ✅ 发布门禁 |

### 1.3 🔴 回归优先原则

**优先把"历史踩过的坑"变成用例**，而非追求全面覆盖。本文所有重点用例都对应一次真实事故。

## 2. 可测试性基建（能跑起测试的前提）

### 2.1 纯函数单编技巧

保持被测文件**零 import**（如 `src/utils/latex.ts`）⇒ 单编后直接用 node 跑：

```bash
npx tsc <file> --outDir tmp --module commonjs
node tmp/<file>.js   # 或直接 require 后跑断言
```

### 2.2 动态探针

脚本放 `server/dynamic-tests/`，⚠️ **必须在 `server/` 目录下运行**（依赖与相对路径要求）。

| 脚本 | 用途 |
|---|---|
| `probe-erase-chain.ts` | 擦除链路五场景验收 |
| `probe-verdict.ts` | 红笔判错 A1/A2/A3/B/C/D 五组 |
| `eval-real-erase.ts` | 真实图评估（`--img/--dir/--out`，输出 `report.json`） |

### 2.3 接口 mock

统一 mock 层覆盖 `globalThis.fetch`——⚠️ **每个用例结束后必须恢复**（历史上未恢复，污染了后续用例）。

### 2.4 假凭据打真端点

用假 API Key 请求真实外部端点，验证请求构造正确 ⇒ **应返回 401 而非 200**。这是验证"请求真的发出去了、头部构造对了"的最省钱手段。

### 2.5 测试数据

⚠️ **必须使用真实 user UUID**（用 `X-Device-Id` 建立身份后取回），否则每次新建匿名号 ⇒ 404。

## 3. 单元测试用例

| 组 | 覆盖函数 | 断言要点 |
|---|---|---|
| **latex 双向转换** | `latexToReadable` / `readableToLatex` | ① 往返一致性；② ⚠️ **`\frac{x^2}{y_1}` 回转**（`takeLastAtom` 必须认 `^{}` / `_{}`）；③ **分数分母吞紧随的上下标**；④ ⚠️ **`→` 后跟非字母原子时原样保留**（曾生成空参 `\vec{}`） |
| **ima 探针链** | `buildQueryFallbacks` | 探针链生成顺序与降级（关键词串 → 前 4 词 → 前 2 词 → tokens[0] 去停用词 → 书名号 → 4 字窗）；`IMA_PROBE_MAX` 截断生效 |
| **文件名解码** | `original_name` 处理 | percent 解码 + latin1 → utf8 回转（中文名不乱码） |
| **查询清洗** | `cleanStr` / `cleanDate` / `cleanInt` | `undefined` 不被拼进 query；非法日期回退 |

## 4. 接口测试用例

按 ADD-06 的端点分组，逐条给「请求 / 前置数据 / 期望 / 校验点」。重点：

### 4.1 鉴权与隔离

| 用例 | 期望 |
|---|---|
| 缺失身份头 | 自动建匿名号，`X-User-Id` 回传 |
| 🔴 **带他人 `session_id` 查聊天历史** | 返回空（必须 `.eq('user_id')`）——历史越权读缺陷的回归 |
| 🔴 **删除他人条目** | 返回 200 但**删 0 行**；调用方必须 `.select('id')` 校验 |
| 伪造 `X-User-Id`（已启用令牌） | 后端 warn 并以 `X-Auth-Token` 为准 |
| 全局知识库写（非 `admin` 角色，含无任何 admin 的部署） | **403**（fail-closed，不再是放行 + warn） |

### 4.2 参数与缓存

| 用例 | 期望 |
|---|---|
| query 传 `undefined` | 被清洗，不出现字符串 "undefined" |
| `subject_id=none` | 转为 `.is('subject_id', null)` |
| 写操作后读列表 | 返回新数据（缓存已失效） |
| 🔴 **三模式搜题缓存互不串味** | 同题换 `mode` 必须返回不同 `source`（key 含 mode 前缀） |

### 4.3 上传 purpose 四档

| purpose | 落库期望 |
|---|---|
| `save` | 建业务条目（图片 → `timeline(kind=image)`；文档 → `library`） |
| `temp` | 不建条目，`ref_count = 0` |
| `memory` | 不建条目，持久化 |
| 🔴 **`attach`** | 不建条目，持久化——**误用 `save` 会重复建条目**（首页两行） |

### 4.4 常用 curl

⚠️ **本机 shell 必须带 `--noproxy '*'`**：

```bash
curl --noproxy '*' http://127.0.0.1:3001/api/health
curl --noproxy '*' -H "X-Device-Id: dev_test_1" http://127.0.0.1:3001/api/timeline?page=1
```

⚠️ 测试一律用 `X-Device-Id`；裸 `X-User-Id` 传不存在的 id 会**每次新建匿名用户**。

**待确认**：接口测试是否固化为可执行脚本（当前为手工 curl 集）。

## 6. 前端用例（手工清单，逐条给「前置 / 操作 / 期望」）

每条都对应一次历史事故：

| # | 场景 | 前置 | 操作 | 期望 |
|---|---|---|---|---|
| 1 | **缓存刷新** | 列表已加载 | 执行任意写操作（加复习本/删除/改分类） | 内容更新且**滚动位置不变**（silent） |
| 2 | **切身份清缓存** | A 账号有数据 | 登出 → B 账号登录 | 看到 B 的数据，**不串号** |
| 3 | **详情返回锚回** | 列表滚到第 N 条 | 点进详情 → 返回 | 仍停在第 N 条附近 |
| 4 | **弹层不被遮挡** | 页面有悬浮保存条 | 打开学科选择弹层 | 弹层完整可见（z-index > 100） |
| 5 | **首帧 null 守卫** | 慢网络 | 打开详情页 | 不崩（骨架屏 → 数据） |
| 6 | **公式编辑态** | 题目含 LaTeX | 进入编辑 | **不显示源码**，显示可读形式 |
| 7 | **公式渲染回退** | 不支持的公式 | 渲染 | 整行回退源码，不崩 |
| 8 | **符号栏** | 编辑态 | 打开符号条 | 三行限高可上下滑动；插入位置**跟随光标** |
| 9 | **光标不跳末尾** | 长文本中间 | 组词/回车/程序化插入 | 光标停在预期位置（`use-caret`） |
| 10 | **长文本不截断** | 输入 > 140 字 | 保存 | 完整保存（textarea 默认 maxlength -1） |
| 11 | **图片原位替换** | 题目有图 | 编辑并保存 | **不新建条目**（首页仍是一行） |
| 12 | **删除图片** | 题目有多图 | 删一张 | 只解引用，题干不清空（局部合并） |

## 8. 回归门禁（合并前必须跑）

```bash
# 1) 前端类型
npx tsc --noEmit --skipLibCheck

# 2) 前端 lint + tsc 并行
pnpm validate

# 3) 前端构建 + dist 特征串校验
pnpm build:weapp
grep -c "特征串" dist/pages/<页>/index.js

# 4) 后端类型
cd server && npx tsc --noEmit --skipLibCheck -p tsconfig.json

# 5) 隔离门禁
pnpm --filter server check:isolation

# 6) 算法探针（改动算法时）
cd server && npx ts-node dynamic-tests/probe-erase-chain.ts   # G16 必须达标

# 7) 关键接口拨测
node server/scripts/health-probe.mjs
```

**当前自动化程度缺口**（登记 OPS-18）：

- ⬜ 无 CI，全部靠手工执行；
- ⬜ 接口测试未固化为脚本；
- ⬜ 前端无自动化测试；
- ⬜ G13 / G15 无数值门禁。

## 9. 缺陷管理

### 9.1 记录格式（四段式复盘）

```
现象：用户看到什么（含截图/日志）
最小复现：最短步骤
根因：为什么会发生（写到代码行）
修复：改了什么
验证：怎么证明修好了（命令 + 输出）
防复发：① 加了什么检查/用例 ② 更新了哪份文档
```

### 9.2 与 OPS-18 的联动

| 触发 | 动作 |
|---|---|
| 缺陷**重复出现**（≥2 次） | 升级为 OPS-18 风险项 |
| 修复需要**改架构 / 破坏性变更** | 登记为技术债，排期 |
| 修复只是**绕过**（未根治） | 必须写明"绕过了什么"并登记 |
| 缺陷暴露**文档与代码不一致** | 同步回写文档（代码为准） |
