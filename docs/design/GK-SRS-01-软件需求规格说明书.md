## 2. 产品定位与目标用户

> ✅ 本章已按思傅 2026-10-24 的产品定位口述落地（含此前「待确认」的裁决：不区分学生/家长身份）。

### 2.1 一句话定位

面向**家长**的 K12 错题「收集—整理—巩固—导出」工具：由家长帮孩子把日常作业与考试中的错题沉淀下来，组织复习、导出纸面练习，并逐步把「一道题」上升为「一类题的方法」。

### 2.2 目标用户画像

**主要用户：家长（P0）——整理者与督导者**

| 维度 | 说明 |
| --- | --- |
| 典型动作 | 拍照/导入错题、裁剪成题、归学科与打标签、加入复习本、导出 PDF/Word、安排复习节奏 |
| 使用场景 | 碎片时间（批改后、接送间隙），手机单手操作 |
| 核心诉求 | ① 快：少打字，拍一下就能进库；② 准：按学科/时间/标签找得到；③ 省事：一键导出可打印的练习；④ 有数：看得见薄弱点与进步 |
| 失败容忍度 | 低。录入链路每多一步，家长就少用一次 |

**次要用户：孩子 / 学生（P1）——使用者与被督导者**

- **为什么是次要目标**：学业紧张（可支配时间极少）+ 自制力不足（难以自主坚持录入与复习）⇒ 不能把「孩子主动录入、自主复习」设计成主路径。
- **产品对策**：由家长代为收集整理，孩子只需在家长督导下完成「再做一遍 → 订正 → 巩固」。
- **对孩子的体验要求**：界面克制、不打扰；题干与解析看得懂；单次复习量可承受（不做无限滚动的题海）。

**关于「是否区分学生 / 家长两种身份与权限」——本期裁决：不区分**

| 决策 | 口径 |
| --- | --- |
| 账号语义 | 一个账号 = 一个孩子的数据空间；登录者即该空间的管理者 |
| 不拆身份的理由 | 家长与孩子操作的是**同一份数据**（同一个孩子的错题集）。拆成两种身份会立刻引出「同一道题归属谁」「孩子账号删了家长的记录怎么办」的权限矩阵复杂度，当前阶段收益不抵成本 |
| 后续演进路径 | 需要时**不拆账号**，改为引入「数据空间 + 成员 + 角色（owner / guardian / child）」的**共享授权关系**来表达（见 2.4） |

### 2.3 核心价值：三层递进

1. **收得进（基础）**：拍照 / 导入 → 裁剪 → OCR → 入题，尽量少打字；识别不准也能「只存图不存字」。
2. **复习得起来（进阶）**：复习本 + 学科 / 时间 / 标签三维检索 + 掌握状态流转。
3. **举一反三（最高目标）**：不止给答案，而是从**方法论层面**引导——错因归类（概念不清 / 计算失误 / 审题偏差 / 方法未掌握）→ 同类题推荐 → 提炼解题通法，让孩子从「会做这一道」到「会做这一类」。

> 第 3 层是产品的差异化所在，也是后续 AI 能力（错因分析、同类题推荐、方法卡片）的投入方向；前两层是它的地基——数据进不来、找不到，方法论就无从谈起。

> 📚 **本章的方法论依据见 `GK-SRS-20a`《科学学习方法论指引》**（规范层：统一框架、研究方法、M1–M10 准则与元准则），证据与效应量原文见 `GK-SRS-20b`（证据层，58 条参考文献）。三层价值与机制的对应关系见 **20a §7.1**（① 收得进 = 降低外在认知负荷；② 复习得起来 = **提取练习 0.74 + 分散练习 0.85**；③ 举一反三 = 自我解释 0.54 + 交错练习 0.47，且收益集中在概念理解与迁移）。当前缺位状态见 20a §7.2 / 20b §5.2（C4 已关闭，**C3 错因是下一个阻塞项**）。
> **新增或改动涉及「学习行为」的功能时，须先按 20a §5.1 的三问决策器判出 T/D/X，再逐条比对 20a §6.2 的 M1–M10，并写明 falsifier。**

### 2.4 数据共享：家长 / 孩子 / 朋友之间按权限共享

- **需求原文**：家长、孩子、朋友之间，可在授权范围内共享与使用本人名下的数据信息。
- **本期口径**：**暂不实现共享**。数据一律「一人一库、全量按 `user_id` 隔离」（见第 3 章）。
- **预留设计（不实现，登记为待办）**：
  - 共享 = 在 `user_id` 之外引入「数据空间 + 成员 + 角色」的授权关系；共享**不复制数据**，只增加授权行；
  - 角色最小集：只读（查看/导出）/ 可编辑（增删改）/ 可管理（改成员与权限）；
  - 对外共享默认只读，随时可撤回，关键操作留痕可审计；
  - 导出物（PDF/Word）属于数据副本，出系统后不受授权约束 ⇒ 导出需显式确认，敏感项（姓名、学校、班级）默认不写入导出物。
- **详见**：ADD-07 安全与隐私设计说明书（共享授权模型一节）。

### 2.5 典型使用场景

| # | 场景 | 主路径 |
| --- | --- | --- |
| 1 | 作业批改后录入 | 家长拍下错题 → 裁剪成题 → OCR 识别（或只存图）→ 存入错题库 |
| 2 | 周末巩固 | 按学科 + 近两周筛复习本 → 合成 PDF/Word → 打印给孩子重做 |
| 3 | 考前专项 | 按标签（如「一元二次方程」「几何辅助线」）导出专项练习 |
| 4 | 错题复盘 | 详情页补错因标签与解题通法；下次同类题出现时给出提示 |

> 「合成 PDF / Word」为同一入口的两种目标格式：PDF = 多图智能拼页、省纸，直接打印；Word = 图片顺排、可编辑，家长加批注后再打印。

## 3. 角色与身份分层

> 📌 **本节不涉及「学生 / 家长」角色拆分**：按第 2.2 节裁决，本期只有一种业务身份（数据空间管理者），学生/家长差异不进权限模型。

| 身份 | 建立方式 | 标识 | 有效期 | 数据 |
|---|---|---|---|---|
| 微信用户 | `wx.login` → 后端 `code2session`，可取 `open_id` | `users.open_id` | 长期 | 跨设备可用，登录后匿名数据可迁移（`migrated`） |
| 设备用户（匿名） | 首次请求自动建号，锚定 `X-Device-Id` | `users.device_id` | 30 天（命中请求滑动续期） | 一人一库，按 `user_id` 隔离 |
| 扫码登录（H5） | 票据一次性（`expires_in=300`），手机端授权 | 票据 token | 5 分钟 | 用于电脑端 H5 登录同一账号 |

**分层规则**：

1. 未登录也能完整使用（匿名降级），**登录失败不得阻塞使用**；
2. `/api/auth/*`、`/api/health` 不触发建号，避免每次登录产生垃圾账号；
3. 匿名转微信用户时按 `anonymous_id` 迁移数据，返回 `migrated`；
4. 身份切换（登录成功 / 应用已登录用户 / 登出）必须清本地缓存与令牌，并重置后端唤醒状态。

**功能边界与配额档位**（`quota/quota-policy.ts` 实测）：

| 档位 | 容量 | 图片张数 | 月增量 | 触发表现 |
|---|---|---|---|---|
| anonymous | 20 MB | 10 | 50 MB | 超限 `413 QUOTA_BYTES` / `QUOTA_COUNT` |
| free（默认） | 500 MB | 300 | 200 MB | 同上 |
| member | 10 GB | 5000 | 2 GB | — |
| family | 50 GB | 不限 | 10 GB | — |

> ⚠️ **待确认（思傅）**：临时（匿名）用户是否额外限制高成本功能（AI 解题 / 联网搜题 / 超分）。当前实现只做了容量与张数限制，应用层另有 `ANSWER_SEARCH_DAILY_LIMIT`（默认 20 次/用户/天，不区分身份）。

### 5.1 首页收件箱（M1）

| 编号 | 功能点 | 说明 | P | 状态 |
|---|---|---|---|---|
| F1.1 | 最近列表 | 按 `created_at desc` 分页（20/页），图/题混排卡片 | P0 | 已上线 |
| F1.2 | 筛选 | 学科、标签、关键词、时间范围（后端筛选，非前端过滤） | P0 | 已上线 |
| F1.3 | 批量选择 | 加入/移出复习本、批量删除 | P0 | 已上线 |
| F1.4 | 单条「⋯」菜单 | 加入或移出复习本、修改分类、图片编辑与 AI 动作、删除 | P0 | 已上线 |
| F1.5 | 首帧缓存 | 本地缓存铺首帧 → 后台静默刷新 | P0 | 已上线 |
| F1.6 | 包版本角标 | 展示构建元信息（`BUILD_META`），便于确认真机包新旧 | P2 | 已上线 |

**关键流程**：进入 → 读本地缓存铺屏 → 请求 `/api/timeline`（带筛选） → 回写缓存并替换 → 用户操作（写操作）→ `invalidateAfter` 清域 → **silent 刷新**。

**异常与边界**：
- 写操作必须保持当前滚动位置（思傅三次反馈点）⇒ silent 刷新，不显示骨架屏；
- 从详情返回按条目 **id** 锚回原题（不是像素偏移）；
- 后端不可达时自动唤醒 + 重放一次（仅连接类错误）。

**验收标准**：① 断网进入仍有内容（缓存）；② 删除一条后列表不跳回顶部；③ 筛选条件在返回列表后保持；④ 真机包版本角标与最新 commit 一致。

### 5.5 题目答案服务（三模式，M5）

| 编号 | 功能点 | 说明 | P | 状态 |
|---|---|---|---|---|
| F5.1 | 联网搜题 `search` | **只检索**，给来源摘要 + 链接，无结果如实说明 | P0 | 已上线 |
| F5.2 | 知识库 `kb` | ima 自建知识库检索，只检索不推理 | P1 | 已上线（受配额与自建库限制） |
| F5.3 | AI 解题 `ai` | 只推理，明确标注「未联网核实」 | P0 | 已上线 |
| F5.4 | 结果展示 | 来源徽标、引用链接、答案渲染态；**采纳才入库** | P0 | 已上线 |
| F5.5 | 结果缓存 | 题面 hash + mode 持久化缓存（命中返回 `cached=true`） | P1 | 已上线 |

**异常与边界**：
- 三种模式结果缓存 key 必须带 `mode`（否则检索结果会冒充 AI 结果）；
- `mode` 走 **body**（写 query 会静默变 `search`）；
- ima 日配额耗尽给专属文案并引导改用其它模式；LLM 全链路失败给出配置/重试提示，**绝不伪造答案**。

**验收标准**：① 同一题切换模式不会串结果；② 零结果时三模式各有明确文案；③ 同一题第二次请求命中缓存（秒回且标记 cached）。

## 6. 非功能需求

> 每条给**可测量指标**，不写"快速""稳定"这类空话。

| 类别 | 指标 | 目标 / 现状 |

| 性能·首帧 | 列表首屏 | 本地缓存命中时 0 网络等待（SWR）；未命中走一次列表接口 |

| 次数 | 应用日限额 | 搜题默认 20 次/用户/天；ima 受供应商日配额约束（靠持久化缓存摊薄） |
| 兼容 | 平台 | 微信小程序（Taro 4.1.9）、微信/字节/H5 同源码；iOS 与安卓真机分别验收 |
| 兼容·显示 | 字号 | 正文不小于 12px（徽标类小字为例外，见 SRS-02） |

## 8. 约束、假设与依赖

- **平台约束**：微信小程序（包体积、域名白名单、UA 限制）；生产形态与备案强相关。
- **第三方依赖**：Supabase（DB+Storage，跨境 RTT 与 IP 封锁）、ima 知识库（日配额 + 订阅库不可 API 检索）、LLM 供应商（扣子/DeepSeek/混元额度）、百度网盘（可选归档）。
- **运行约束**：OCR 依赖本机 Python venv 与模型缓存（生产需打进镜像或走云托管改造）。
- **假设**：单人维护 + AI 协作；无自动化测试门禁；RLS 未启用（隔离靠代码层 + 静态门禁）。

> ⚠️ 以上约束均为**当前环境的观测口径，会随平台政策与环境变化**。完整清单与"失效条件 / 复核方式"见 **ADD-04 第 2.3 节**（约束快照）；外部依赖的配额与降级矩阵见 ADD-04 第 9 章。

## 9. 验收与发布标准

**每次发布前必测（不通过即不发版）**：

1. 登录/匿名可用（含登录失败不阻塞）；
2. 录入链路：拍照 → 切块 → 入题（含只存图路径）；
3. 列表：筛选、批量、删除后滚动位置保持；
4. 复习本：加入/移出、合成 PDF 与 Word 并可打开；
5. 搜题三模式：各有结果或明确文案，不串味；
6. 资料库：中文名、打开文档、删除；
7. 导出：产物在文档页可见且图片不损坏。

**分平台验证**：iOS 与安卓真机各跑一遍第 1~7 项；需重新生成二维码扫码（旧码连旧会话）。

**构建校验**：后端 `npx nest build` 零错 + 前端 `pnpm build:weapp` 通过 + dist 特性串在位（详见 QA-16）。

### A.3 文件与存储

| 标准术语 | 英文/代码 | 含义 |
|---|---|---|
| file_key | `blob_objects.file_key` | 对象在存储中的唯一键。**一律写 `file_key`，不翻译** |
| 对象记录 | `blob_objects` 一行 | 物理文件与其引用计数；非业务条目 |
| 引用计数 | `ref_count` | 对象被多少处引用；归零即"孤儿" |
| 孤儿对象 | orphan | `ref_count = 0` 的对象，由定时 GC 回收（临时对象 24h） |
| 签名 URL | signed URL | 后端为私有对象生成的临时访问 URL（有有效期） |
| 上传意图 | `purpose` | `/api/upload` 的分流参数，见下方 A.3.1 |
| 访问代理 | `GET /api/storage/files/{file_key}` | 手机端访问文件的统一代理通道（跨境段由服务端承担） |

#### A.3.1 上传意图（purpose）语义表

| purpose | 存储位置 | 是否建业务条目 | 典型用途 |
|---|---|---|---|
| `save` / `1` / `true` | 正式区（引用计数 +1） | **建**（图片→图片条目；文档→资料库条目） | 「存进收件箱」「导入资料库」 |
| `temp` | 临时区（`ref_count=0`） | 不建 | 24h 后 GC 回收的中间产物 |
| `memory` | 正式区 | 不建（由 `memory_media` 关联） | 成长记忆附图 |
| `attach`（及其他未知值） | 正式区 | **不建** | 附件（如题目的题面图，key 由条目 `content` 引用） |

> ⚠️ **"要持久化" ≠ "用 save"**：附件必须用 `attach`。用 `save` 会额外建一条条目，导致同一内容在首页出现两行。
