# GK-QA-23 小程序功能测试与缺陷修复报告

> 编号：GK-QA-23 ｜ 版本：v1.0 ｜ 日期：2026-10-29 ｜ 状态：**用例集完成 + 首轮执行完毕（发现 15 项缺陷，已修 15 项，新增源码红线门禁 M18）**
> 读者：开发 / 测试 / 发布责任人 ｜ 上游：GK-00、GK-QA-15、GK-QA-17、GK-QA-21 ｜ 下游：GK-OPS-18
> 定位：补上「**前端功能面**」这一块空白——GK-QA-21 的 193 条用例几乎全部打后端接口，
> 而用户日常遇到的是「点了没反应 / 列表空白 / 保存后没变」，这些**接口测试一条都测不到**。

---

## 1. 为什么补这一套

| 事实 | 说明 |
|---|---|
| 后端已有 193 条用例 | `server/scripts/verify/` 17 个模块，覆盖鉴权、隔离、缓存、OCR、AI 闸门 |
| 前端自动化**接近 0** | 只有 M12（纯函数）+ M13（tsc / lint / 隔离门禁），**没有任何一条断言前端行为** |
| 用户反馈的问题集中在前端 | 「点了没反应」「列表一片空白」「改了保存还是旧的」——全部落在渲染与交互层 |
| 前端没有测试框架 | 不引 jest/vitest（为跑一次验证装半个 npm 宇宙不划算）⇒ 采用**源码红线 + 手工用例**双轨 |

**结论**：把能自动化的（源码特征、契约、红线）做成可执行门禁；把只能人看的（真机交互、隐私弹窗、录音）
写成 AAA 手工用例清单，发版前逐条勾。

## 3. 怎么跑

```bash
# ① 前端源码红线（秒级，不需要后端）——发版前必跑
cd server && node scripts/verify/run.mjs M18

# ② 后端接口核心（约 16 分钟，需后端在跑）
cd server && node scripts/verify/run.mjs M01 M02 M03 M04 M05 M06 M07 M08 M15

# ③ 纯函数 + 工程门禁（M12 在 verify 内；单独跑 lint/tsc）
pnpm validate
```

| 命令 | 退出码 | 门禁含义 |
|---|---|---|
| `run.mjs M18` | 0/1 | **新增**：前端红线不过不许发版（本次首跑即抓出 5 项真实缺陷） |
| `run.mjs M12 M13 M18` | 0/1 | 建议并入 CI 的 `gate` 作业（都不需要数据库与外部密钥） |
| `run.mjs M01–M08 M15` | 0/1 | 现有 `api-core` 作业不变 |
