## 2. 架构目标与约束

**要写**：
- 业务目标：拍得快、找得到、复习得起来；
- 技术目标：首帧快（缓存优先）、识别准、弱网可用、单人可维护；
- **硬约束清单**（这些决定了后面所有选型）：
  1. 微信小程序平台（包体积、域名白名单、UA、无备案域名不可作 API 后端）；
  2. 无备案域名 ⇒ 生产 API 只能走微信云托管 `wx.cloud.callContainer`；
  3. 云托管不支持 Compose ⇒ NestJS 与 Python OCR 侧车必须打进同一镜像；
  4. callContainer 文本 ≤100KiB、超时 15s ⇒ 图片传输走 `wx.cloud.uploadFile` 换 fileID；
  5. 数据库在 Supabase 新加坡 ⇒ 单次 RTT 高，必须靠缓存与查询合并；
  6. 单人维护 + AI 协作 ⇒ 架构必须易理解、易回归。
**素材**：`docs/后端托管与小程序发布-调研纪要.md`、`迁移到腾讯云-方案与步骤.md`、项目记忆

## 4. 容器视图

**要写**：逐容器表（名称 / 技术栈 / 职责 / 端口 / 通信协议 / 关键依赖）：

## 7. 技术选型与理由

**要写**：主选型表（技术 / 用途 / 选择理由）+
**被否决方案表**（方案 / 试图解决什么 / 为什么否决）——这条极有价值，防止后人重复踩坑：
- katex / temml（公式渲染）：rich-text 环境无 svg、无伪元素、无字体 ⇒ 自研零依赖渲染
- 扣子 SDK 直连：只认平台运行时注入 JWT，平台外不可用 ⇒ 改标准 OpenAPI
- WorkBuddy 云服务（cloud-service）：无容器运行时，跑不了 NestJS + Python
- `*.app.workbuddy.host` 当 API 后端：边缘网关拦 MicroMessenger UA + 无 ICP 备案
- Supabase 静态 IP 池：已证伪 ⇒ 改 dns-pin 动态优选
- 全局状态管理库（Redux 等）：项目规模下得不偿失，局部 state + 服务层缓存足够
**素材**：项目记忆各决策点

## 9. 外部依赖与集成（原 ADD-09）

**要写**：依赖总表（系统 / 用途 / 协议 / 凭据位置 / 失败影响），再逐项展开：

## 10. 跨层约定

**要写**（这些是"全项目必须遵守"的契约，写在此处，各 DD 引用不重复）：
- 全局 `/api` 前缀（v2 起为 `/api/v2`，URI 版本化方案见 ADD-06 第 8 章）；前端禁止漏写、禁止各 service 手写版本段
- 数据隔离：所有查询 `.eq('user_id', userId)`（RLS 未启用，这是唯一手段）
- 存储只存 `file_key`，不存 URL；URL 由 `withUrls` 富化
- 前端不直连第三方 LLM 与 Supabase，一律后端代理
- 查询参数必须清洗（禁止 undefined 进 query）
- 删除必须校验实际删除行数
- 写操作后必须失效缓存
**素材**：项目记忆接口与安全章节
