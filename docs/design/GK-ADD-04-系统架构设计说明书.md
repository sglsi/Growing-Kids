## 2. 架构目标与约束

### 2.1 业务目标（来自 SRS-01）

拍得快（一次拍照即入库）、找得到（三维检索）、复习得起来（复习本 + 艾宾浩斯）、**举一反三**（错因归类 → 同类题 → 方法通法，最高目标）。

### 2.2 技术目标

| 目标 | 衡量方式 |
|---|---|
| 首帧快 | 列表优先读本地缓存再静默刷新（SWR），见 DD-13 |
| 识别准 | 双 OCR 引擎分工 + 人工框选兜底，见 DD-10 |
| 弱网可用 | 请求失败仅连接类错误触发后端唤醒 + 重放一次；业务错误不重试 |
| 单人可维护 | 模块按业务域划分；AI 协作为主，架构必须"读得懂、改得动、可回归" |

### 2.3 ⚠️ 约束快照（当前环境的实测口径，**不是永久铁律**）

> **这一节的性质**：以下是 2026-10 前后在本项目实际环境中**观测到的约束**，它们决定了当时的选型与实现形态。
> **平台规则、托管能力、网络条件、第三方配额都会变**——例如域名备案补齐、云托管支持多容器、Supabase 换区、配额提升，都会让某条约束失效。
> 因此本文**不把它们当作"必须照此执行"的硬规定**，而是作为"当时为什么这么做"的依据。
> **复核方法**：变更部署形态或引入新外部依赖前，重新实测下表"复核方式"一列；结论变化即回写本表并在第 11 章记 ADR。

| # | 约束（观测时点） | 当时的依据 / 影响 | 失效条件与复核方式 |
|---|---|---|---|
| C1 | 终端是微信小程序（包体积、域名白名单、UA 限制） | 决定前端走 Taro 跨端、请求域名必须白名单、不能用无备案域名 | 若新增 H5/App 端需重新评估；复核 `src/app.config.ts` 与微信后台域名配置 |
| C2 | 生产 API 需可备案域名；未备案 ⇒ 只能走微信云托管 `wx.cloud.callContainer` | 决定生产部署形态候选 | 备案完成后直连自有域名即可；复核方式：确认域名备案状态 |
| C3 | 云托管单容器（不支持 Compose）⇒ NestJS 与 Python OCR 需打进同一镜像 | 影响镜像构建方式 | 平台若支持多容器/边车则解绑；复核云平台最新能力说明 |
| C4 | `callContainer` 文本响应 ≤100KiB、超时 15s ⇒ 图片不能走文本通道 | 大图改走 `wx.cloud.uploadFile` 换 fileID | 平台放宽即失效；复核官方文档上限值 |
| C5 | 数据库在 Supabase（新加坡区）⇒ 单次 RTT 高，且 CF IP 间歇被封 | 决定了缓存优先、查询合并、`supabase-dns-pin` 动态优选 | 换区/换供应商后 RTT 与封锁表现都变；复核 `supabase-dns-pin.ts` 探测日志 |
| C6 | 单人维护 + AI 协作 ⇒ 架构必须易理解、易回归 | 决定"少抽象、显式 `user_id`、写操作收口"等约定 | 团队规模变化后重新权衡 |
| C7 | OCR 依赖仓库外 venv 与模型缓存（本机 `D:/AI/gk-ocr-env`） | venv 与缓存必须在仓库外，否则开发者工具文件监听耗尽句柄（EMFILE） | 迁移到容器部署后由镜像承载；复核 `OCR_VENV_DIR` 指向 |
| C8 | 第三方配额有限（ima 日配额按调用计数、零命中也扣；LLM 各有额度） | 决定持久化答案缓存 + 单题调用次数压缩 | 配额提升或改自建检索后失效；复核接口返回码与供应商后台 |

> 相关：被约束逼出来的具体决策见第 7.2 节"被否决方案"与第 11 章 ADR。

|---|---|---|---|---|---|
| 小程序前端 | Taro 4.1.9 + React 18 + Tailwind 4（weapp-tailwindcss）+ 本地 shadcn 风格组件（46 个） | 5 Tab / 13 页面；拍照、编辑、复习、导出 | — | HTTPS `/api` | `PROJECT_DOMAIN` 编译期常量 |
| 后端 | NestJS 10（Express 适配器），20 controller / 70 处理器 | 业务编排、身份、存储、OCR 调度、AI 编排 | 3001（`0.0.0.0`） | HTTP JSON + multipart | Supabase、OCR、LLM |

| 唤醒服务 | Node ESM 脚本（`scripts/wake-server.mjs`） | 后端未运行时按需拉起；`/status` `/wake` `/wait-ready` | 3002 | HTTP | Node、OCR 环境变量 |

| 对象存储 | Supabase Storage（public `media` 桶）/ 本地盘（回退） | 图片、文档、导出产物 | — | HTTPS / 本地文件 | `STORAGE_DRIVER` |
| 百度网盘（可选） | OpenAPI | 资料库归档副本 | — | HTTPS | AppKey/Secret/refresh_token |

**子进程与窗口纪律**（本机开发态）：所有 Python 派生一律走 `pythonw.exe`（`ocr/python-gui.ts` 的 `toGuiPython()`）+ `windowsHide`，避免控制台窗口弹出；唤醒服务**不得派生任何子进程**（探活用 `process.kill(pid,0)` 与 TCP）。详见 QA-16 与项目记忆。

## 5. 部署视图

| 环境 | 前端 | 后端 | 存储 | 关键前提 / 备注 |
|---|---|---|---|---|
| 本地联调 | 微信开发者工具（真机需同 Wi-Fi） | `http://192.168.3.242:3001`（`PROJECT_DOMAIN`）+ 唤醒服务 3002 | Supabase（或 local 驱动） | 防火墙放行 3001/3002；`urlCheck:false`；真机改构建需重新扫码 |
| 体验版 | 同本地联调地址 | 同上 | Supabase | 每次新构建需重新生成二维码 |
| 生产（规划） | 微信云托管 | `wx.cloud.callContainer` | Supabase | 改造点：单镜像内含 NestJS + Python OCR；图片走 `uploadFile`；见第 12 章 |

**配置差异要点**：

- `PROJECT_DOMAIN`：编译期注入（`config/index.ts`），H5 端强制空串走 devServer 代理；小程序端取 `process.env.PROJECT_DOMAIN`，缺省 `http://127.0.0.1:3001`。
- `STORAGE_DRIVER=local|supabase`：默认 `local`（断网可跑），生产显式设 `supabase`。
- 本机 OCR 与唤醒服务：`OCR_VENV_DIR`、`PADDLE_PDX_CACHE_HOME`、`XDG_CACHE_HOME` 三项必须在仓库外；由唤醒服务拉起后端时注入。
- 密钥：`.env.secrets` → `encrypt-env.mjs` 加密为 `.env.secrets.enc` 后随部署包上传，启动时解密（见 ADD-07）。

## 6. 运行时视图（关键链路时序）

> 只画链路与责任边界，不展开实现（实现见对应 DD）。

### 6.1 上传与存储

```
小程序 chooseImage → /api/upload (multipart: file + purpose + original_name)
  → 配额预检（413 QUOTA_*）
  → 压缩/缩略图 → 内容 hash 去重（命中则复用，不重复占空间）
  → 落对象存储（key 内容寻址）
  → purpose 分流：save → 建条目（图片→timeline / 文档→library；archive_to=library 时图片也进资料库）
                  temp  → 24h GC；memory/attach → 持久化不建条目
  → 资料库条目：异步归档百度网盘（best-effort，失败不影响保存）
  → 返回 { key, url, thumb_key, thumb_url, timeline_id?, library_id? }
```

### 6.2 图像编辑与保存替换

`/api/image/process`（auto|enhance|erase|erase_v2）→ 本地管线（纠偏/黑白/超分/去手写；超分走并发闸与排队）→ `save=true` 时替换原图并**同步换 thumb_key**；限流类错误（429/503）不回退、原样抛出。

### 6.3 OCR 识别

```
快速（默认）：ocr-tool 工具式调用常驻 pythonw（RapidOCR）
精准（版面/公式/整卷）：HTTP 9301 侧车（按需启动、空闲回收、健康自愈）
     └ 侧车不可用 → 返回 null → OcrService 降级 VLM，绝不阻断主链路
环境缺失：启动后 3s 全量自检（import 8 个大件）；
         ⚠️ 超时或「一次性失败但逐包全过」均判定为资源竞争，不触发重装
```

### 6.4 搜题三模式（互不混淆）

| mode | 走哪些外部系统 | 结果语义 |
|---|---|---|
| `search` | 博查联网检索 | 来源摘要 + 链接，用户自行核对 |
| `kb` | ima 知识库（仅自建库可用） | 知识库片段，标注未做 AI 整理 |
| `ai` | LLM 降级链（扣子→DeepSeek→混元） | 模型推理，明确标注未联网核实 |

三者都经 `answer_cache`（题面 hash + mode）持久化缓存，命中即不再消耗外部配额；`force=true` 绕过缓存重算并覆盖。

### 6.5 导出与下载代理

`/api/pdf/combine`（图→PDF/DOCX）、`/api/document/export`（题目汇总→docx）→ 写入 `documents` **并落对象存储**。手机端打开一律走 `GET /api/storage/files/{file_key}` 代理（避免手机直连跨境对象存储超时）。

### 6.6 登录与身份

`X-Auth-Token`（HMAC 验签，优先）→ `X-User-Id`（兼容期）→ `X-Open-Id` → `X-Device-Id` → 匿名建号（30 天 TTL，`/api/auth/*` 与 `/api/health` 免建号）。每次响应回写并续签令牌；前端登录/登出两个切换点必须清本地缓存与令牌。

### 6.7 后端未运行时的自救

```
小程序请求 → 连接类错误（超时/拒绝）→ 判定 isConnError
          → POST 唤醒服务 :3002/wake → 拉起后端（带 OCR 环境变量）
          → /wait-ready 长轮询 → 自动重放原请求一次（单 flight + 30s 缓存 + 60s 冷却）
```

## 7. 技术选型与理由

### 7.1 主选型表

| 技术 | 用途 | 选择理由 |
|---|---|---|
| Taro 4.1.9 + React 18 | 跨端小程序 | 一套代码覆盖微信/字节/H5；vite 编译链快 |
| Tailwind 4 + 本地 shadcn 组件 | 样式 | 无第三方组件库依赖（小程序兼容成本低），令牌集中在 `app.css` |
| NestJS 10 | 后端框架 | 模块/依赖注入清晰，中间件-守卫-拦截器-过滤器分层明确，适合"读得懂" |
| PostgreSQL（Supabase） | 业务库 | 托管免运维；JSONB 承载 `content` 灵活结构 |
| Supabase Storage / 本地盘双驱动 | 对象存储 | 断网可开发（local），生产切 supabase 不改调用方 |
| RapidOCR + PaddleOCR(PP-StructureV3) | OCR 双引擎 | 快速引擎秒级、精准引擎版面强，互补；失败可降级 VLM |
| 内容寻址（sha256）+ 引用计数 | 存储去重 | 同一份内容天然只占一份，删除靠 ref_count 释放 |
| 自研 LaTeX 渲染（`src/utils/latex.ts`） | 公式显示 | 零依赖，绕开 rich-text 环境限制（见下） |
| 明文 SQL 迁移（`migrations/*.sql` + `migrate.mjs`） | 数据库演进 | 可版本化、可重复执行、可回滚到单文件事务 |

### 7.2 被否决方案表（防止后人重复踩坑）

| 方案 | 试图解决 | 否决原因 |
|---|---|---|
| katex / temml 渲染公式 | 数学公式显示 | rich-text 环境无 svg、无伪元素、无自定义字体 ⇒ 改为自研零依赖渲染 |
| 扣子 SDK 直连 | 快速接入 Bot | 只认平台运行时注入的 JWT，平台外不可用 ⇒ 改标准 OpenAPI |
| WorkBuddy 云服务（cloud-service）托管后端 | 免运维部署 | 无容器运行时，跑不了 NestJS + Python |
| `*.app.workbuddy.host` 当 API 后端 | 免备案域名 | 边缘网关拦 MicroMessenger UA + 无 ICP 备案 |
| Supabase 静态 IP 池 | 规避 CF IP 封锁 | 已证伪（IP 池会变）⇒ 改 dns-pin 动态优选 + 5min 自愈重探 |
| 全局状态管理库（Redux/Zustand） | 跨页状态共享 | 项目规模下得不偿失；`zustand` 已装但零引用，实际用页面局部 state + 服务层缓存 |
| 看门狗定时拉起后端 | 后端保活 | 每分钟的进程窗口严重干扰用户 ⇒ 改前端驱动的唤醒服务 |
| WorkBuddy 百度网盘连接器做资料库归档 | 资料同步到网盘 | 只能传文本/URL 转存，传不了 PDF/图片二进制；凭据客户端加密后端拿不到 ⇒ 改后端直连 OpenAPI |

## 8. 质量属性策略

| 属性 | 目标 | 手段 | 验证方式 |
|---|---|---|---|
| 性能 | 列表首帧快 | 前端 SWR（本地缓存铺首帧）+ 后端 mem-cache（30s + 前缀失效）+ 用户对象 60s 缓存 + 缩略图 | `docs/reports/` RTT 实测；真机首帧观感 |
| 可用性 | 单点故障不致命 | LLM 降级链、Supabase IP 封锁自愈、OCR 侧车自愈 + 降级 VLM、后端唤醒 + 请求重放、匿名身份降级 | 断依赖演练（见 QA-16 故障剧本） |
| 可维护性 | 改一处知道影响面 | 模块按业务域划分；写操作缓存失效收口在 `api.ts` 的 `invalidateAfter`；跨层约定集中在本文第 10 章 | 新接口按 ADD-06 第 10 章清单执行 |
| 安全性 | 一人一库不越权 | RLS 未启用 ⇒ 所有查询显式 `.eq('user_id')`；令牌 HMAC 验签；密钥加密部署（详见 ADD-07） | `pnpm --filter server check:isolation` 静态门禁 |
| 可测试性 | 可单编、可 curl | 纯函数可单编（如 `latex.ts`）；`server/dynamic-tests/` 动态探针；接口可 curl | QA-15 |
| 成本 | 第三方配额可控 | 持久化答案缓存（同题不重复消耗）、ima 单题调用压缩、超分并发闸与用户配额、存储引用计数与孤儿 GC | 配额日志与 `/api/quota/usage` |

## 9. 外部依赖与集成（原 ADD-09）

### 9.1 依赖总表

| 系统 | 用途 | 协议 | 凭据位置 | 失败影响 |
|---|---|---|---|---|
| Supabase | DB + Storage | HTTPS | `.env`（URL）+ `.env.secrets`（Key） | 核心不可用；靠 dns-pin 自愈 |
| 微信开放平台 | 登录、上传下载、云托管 | HTTPS | `WX_APPID` / `WX_SECRET` | 登录失败；已登录用户不受影响 |
| 扣子 Coze | LLM（首选） | HTTPS OpenAPI | `COZE_API_TOKEN` / `COZE_BOT_ID` | 降级 DeepSeek |
| DeepSeek | LLM（次选） | HTTPS | `DEEPSEEK_API_KEY` | 降级混元 |
| 腾讯混元 | LLM（兜底） | HTTPS | `HUNYUAN_API_KEY` | 全部失败则 AI 功能明确报错 |
| 博查搜索 | 联网检索 | HTTPS | `BOCHA_API_KEY` | `mode=search` 空结果，提示改用其他模式 |
| ima 知识库 | 知识库检索 | HTTPS（自定义头） | `IMA_CLIENT_ID` / `IMA_API_KEY` / `IMA_KB_ID` | `mode=kb` 不可用，提示改用其他模式 |
| 百度网盘 | 资料库归档（可选） | HTTPS OpenAPI | `BAIDU_*` | 归档跳过，资料库本身不受影响 |
| OCR Python | 识别 | 子进程 / HTTP | 无需凭据（本机 venv） | 失败降级 VLM |
| 本地 VLM / SBERT（可选） | 增强识别与判定 | HTTP | 未配则禁用 | 回退规则判定 |

### 9.2 Supabase：跨境 RTT 与 IP 封锁

- `supabase-dns-pin.ts`：33 个候选 IP 的 TLS 探测优选，5min 自愈重探；**仅 GET 重试一次**（写请求重试可能造成重复写入）。
- 对象读取一律经后端代理 `/api/storage/files/*`，避免手机直连。

### 9.3 ima 知识库：三条红线与当前结论

| 红线 | 表现 | 应对 |
|---|---|---|
| 全词 AND 语义 | 自然语句题干必零命中 | 探针式查询链：关键词串 → 主题短语（≤2 级） |
| 日配额 `220021` | 按调用计数、**零命中也扣**、不可退避 | 单题最坏 4 次（`IMA_PROBE_MAX=2`、`IMA_FALLBACK_KB_MAX=2`）+ 持久化答案缓存 |
| QPS `200001` | HTTP 403，可退避 | 库间 250ms、轮间 600ms、单库退避 900ms 重试一次 |

**当前结论（2026-10-24 实测）**：官方基础配额 500 次/天（按账号档位有差异）；更关键的是**订阅知识库不能通过 API 检索**（`220030：没有权限通过 skill 获取订阅知识库的文件`），只有自己上传文件的自建库可用。因此 ima 在本项目已降级为"可选补充"，后续方向是把教辅资料切片自建检索（pgvector），ima 作兜底或不引用——决策记录见 ADR-009。

### 9.4 LLM 降级链

扣子 → DeepSeek → 混元；上一级无 Key 或调用失败自动降级下一级；429/5xx 退避 1.2s 重试一次。图生图兜底路径已知混元开放接口不支持图生图，会明确报错（不静默）。

### 9.5 OCR 引擎生命周期

- 常驻 fast：工具式 `--loop` 调用（pythonw，无窗口）。
- 侧车 precise（9301）：按需启动 → `/healthz` 轮询就绪（30s）→ 空闲回收（默认 15min，资源紧张 2min）→ 连续 3 次健康失败自愈重启并告警 → 请求进行中绝不回收。
- 任何失败返回 `null`，由 `OcrService` 降级，**不阻断主链路**。

### 9.6 配额限流总表（观测值，随供应商政策变化）

| 系统 | 配额/限流 | 触发表现 | 可退避 | 用户可见文案 |
|---|---|---|---|---|
| ima 知识库 | 日配额约 500 次/天（按调用计） | `220021` | ❌ | 「知识库今日调用次数已达上限，请明天再试」 |
| ima 知识库 | 账号 QPS | `200001` / 403 | ✅ | 自动退避重试，用户无感 |
| 超分（SR） | 全局并发闸 + 用户级 | `429 SR_RATE_LIMIT` / `SR_USER_BUSY` / `503 SR_QUEUE_TIMEOUT` | ✅（排队/降级 x2） | 「排队中/请稍后重试」 |
| 上传配额 | 容量/张数（档位制） | `413 QUOTA_BYTES` / `QUOTA_COUNT` | — | 「存储已满，清理后再传」 |
| 应用日限额 | `ANSWER_SEARCH_DAILY_LIMIT`（默认 20/用户/天） | 业务提示 | — | 「今日搜题次数已用完」 |

### 9.7 降级与熔断矩阵

| 依赖挂掉 | 系统表现 | 类型 |
|---|---|---|
| Supabase 主库 | 请求失败并提示；dns-pin 自愈重探 | fail-closed（数据不可伪造） |
| OCR 侧车 | 降级 VLM / 快速引擎 | fail-open（能力降级不阻断） |
| 任一 LLM | 降级下一级；全失败则明确报错 | fail-closed（不伪造答案） |
| ima / 博查 | 该模式返回空并提示改用其他模式 | fail-closed |
| 百度网盘 | 静默跳过归档，资料库照常保存 | fail-open |
| 后端进程不在 | 前端唤醒 + 重放 | 自愈 |

### 9.8 凭据轮换步骤

改 `.env.secrets` → `node server/scripts/encrypt-env.mjs` → 重启后端（本机：杀 3001 进程后 `POST :3002/wake`）→ 验证。正式版发布前必须轮换 `WX_SECRET`（历史曾随部署包明文上传）。完整清单见 ADD-07。

## 10. 跨层约定（全项目必须遵守，各 DD 引用不重复）

1. **全局 `/api` 前缀**：后端 `setGlobalPrefix('api')`；前端禁止漏写、禁止各 service 手写版本段（v2 方案见 ADD-06 第 8 章）。
2. **数据隔离**：RLS 未启用 ⇒ 所有查询必须显式 `.eq('user_id', userId)`；删除必须 `.select('id')` 校验实际行数。
3. **只存 `file_key` 不存 URL**：URL 由 `withUrls` 富化；手机打开一律走 `/api/storage/files/*` 代理。
4. **前端不直连第三方**：LLM、Supabase、网盘一律后端代理。
5. **查询参数必须清洗**：前端禁止把 `undefined` 拼进 query（会变字符串 `'undefined'`，日期比较直接 500）；后端用 `shared/query-param.ts` 兜底。
6. **写操作后必须失效缓存**：收口在 `api.ts` 的 `invalidateAfter`；列表写操作必须 **silent 刷新**（置 loading 会让列表塌缩、滚动位置被钳回顶部）。
7. **上传 purpose 语义**：见 ADD-06 第 6 章；附件类必须 `attach`，误用 `save` 会重复建条目。
8. **子进程纪律（本机）**：Python 一律 `pythonw` + `windowsHide`；唤醒服务与常驻进程不得派生 shell/解释器子进程（会造成窗口闪烁）。
9. **best-effort 的 catch 必须 `console.error` 打全错**：静默吞错是本项目反复踩过的坑。
10. **品牌色单一出口**：`--brand`（`app.css`）+ `lib/theme.ts` 的 `BRAND`；强调色只允许三档派生。

## 11. 架构决策记录（ADR）

| 编号 | 决策 | 背景 / 理由 | 后果 | 状态 |
|---|---|---|---|---|
| ADR-001 | 存储只存 `file_key`，不存 URL | URL 会过期/换域名；存储可换驱动 | 读取必须过 `withUrls` 富化 | 生效 |
| ADR-002 | 前端 SWR + 后端 mem-cache 双层缓存 | 跨境 RTT 高、首帧要快 | 写操作必须显式失效缓存 | 生效 |
| ADR-003 | 三模式搜题彻底拆开，缓存 key 带 mode | 曾出现「联网搜题结果冒充 AI 结果」 | 三种模式各自独立入口与文案 | 生效 |
| ADR-004 | OCR 双引擎（常驻 fast + 侧车 precise） | 速度与版面精度不可兼得 | 侧车生命周期管理复杂度 | 生效 |
| ADR-005 | 部署包密钥加密（AES-256-GCM） | 部署包会随包上传 | 改密钥必须重跑 encrypt-env | 生效 |
| ADR-006 | 生产走微信云托管 | 无备案域名 | 单镜像需含 Python OCR | 规划 |
| ADR-007 | 不启用 RLS，隔离靠代码层 | 历史库与 service_role 形态 | 每个查询都要记得 `.eq('user_id')`；有静态门禁 | 生效 |
| ADR-008 | 公式渲染自研零依赖 | rich-text 环境限制 | 复杂公式支持有限 | 生效 |
| ADR-009 | ima 知识库降级为可选补充 | 订阅库不可 API 检索 + 日配额紧 | 后续方向：教辅切片自建检索（pgvector）；期间用持久化答案缓存兜底 | 生效（2026-10-24） |
| ADR-010 | 资料库归档百度网盘用后端直连 OpenAPI | 连接器传不了二进制、凭据拿不到 | 需自建应用 OAuth；同步 best-effort，主存储不变 | 生效（2026-10-24） |
| ADR-011 | 后端保活改前端驱动唤醒（取消看门狗） | 看门狗每分钟进程窗口干扰用户 | 依赖唤醒服务常驻（本机由启动项 + 计划任务保障） | 生效（2026-10-24） |
| ADR-012 | 答案结果持久化（题面 hash + mode） | ima/LLM/检索配额都按次计费，内存缓存重启即丢 | 新增 `answer_cache` 表；成功结果默认永久、零命中短期记忆 | 生效（2026-10-24） |

## 12. 演进路线与遗留问题

**遗留（已知，登记于 OPS-18）**：

- `questions` / `materials` 模块已接线但前端不调用（v3 遗留表）；
- RLS 未启用，隔离靠代码层 + 静态门禁；
- 无 CI/CD，构建与发布靠手动脚本（见 QA-16）；

- `requireUserId` 抛普通 Error ⇒ 身份缺失表现为 500 而非 401；
- `chat/knowledge` 为全局表（无 `user_id`），依赖管理员白名单，未配置时放行；

3. RLS 启用与身份体系收敛（彻底弃用裸 `X-User-Id`）；
4. 自动化测试门禁与构建产物校验；
