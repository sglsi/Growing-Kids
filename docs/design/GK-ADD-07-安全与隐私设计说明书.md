## 1. 安全目标与威胁模型

**要写**：
- 受保护资产：儿童学习数据（作业照片、错题、成长记录）、用户身份、第三方凭据、对象存储文件；
- 威胁清单与评级：越权读取他人数据、密钥随部署包泄露、小程序包反编译、第三方数据传输、配额滥用（成本攻击）、临时用户数据滞留；
- 安全目标（机密性/完整性/可用性/可审计）在本项目中的具体含义。
**素材**：`安全与隐私设计方案.md`

## 2. 身份分层与认证

**要写**：
- 三态：授权用户（微信登录，长期）/ 匿名（自动创建）/ 临时（24h 清理）；
- 微信登录链路：`code2session` → 建立/绑定 user → 返回身份；失败时**降级为匿名而非阻塞**；
- 扫码登录票据（`login_tickets`）：一次性、短时效、绑定设备；
- 身份切换后前端必须清空缓存（缓存按 userId 隔离，否则串号）。
**素材**：`server/src/auth/`、`src/pages/scan-login/`

## 3. 授权与数据隔离

**要写**：
- ⚠️ **RLS 未启用**（0002 中全为注释），后端以 service_role 访问 ⇒ 代码层 `.eq('user_id', userId)` 是唯一隔离手段；
- 强制规范逐条列出（含代码评审自查项）：所有查询带 user_id、所有删除带 user_id 且 `.select('id')` 校验行数、所有写操作带 user_id；
- 文件访问：对象存储桶为 public（URL 永久有效、无签名过期），**安全性依靠 key 不可猜 + 不在前端暴露列表**；评估是否改为私有桶 + 签名 URL（登记 OPS-18）；
- 后端代理下载（`/api/storage/files/{key}`）同样必须校验归属；
- **数据共享授权模型（预留，本期不实现）**：需求为「家长 / 孩子 / 朋友在授权范围内共享本人名下数据」。口径见 SRS-01 第 2.4 节：本期一人一库、不拆学生/家长身份，共享一律不实现。预留设计要点——
  - 共享 = 引入「数据空间 + 成员 + 角色」授权行，**不复制数据**；
  - 角色最小集：只读（查看/导出）/ 可编辑（增删改）/ 可管理（改成员与权限），对外共享默认只读；
  - 随时可撤回、关键操作留痕可审计；
  - ⚠️ 导出物（PDF/Word）出系统后不再受授权约束 ⇒ 导出需显式确认，姓名/学校/班级等身份信息默认不写入导出物；
  - ⚠️ 一旦实现共享，现有「`.eq('user_id')` 是唯一隔离手段」的前提即被打破 ⇒ 届时必须同步改造为「数据空间可见性」判定，并重新评估 RLS 是否启用（与第 3 章首条强耦合，改动面大，登记 OPS-18）。
**素材**：ADD-05 第 8 章、项目记忆、SRS-01 第 2.4 节

### 3.1 RLS 重新评估（2026-10-24，结论：**不启用**，改用静态门禁兜底）

**现状**：`migrations/0002_fresh_schema.sql` 138~153 行预留了 4 条策略（timeline_items / subjects / library_docs / documents），**全部处于注释状态**；其余 11 张表没有策略。

**为什么不启用（四条理由，逐条可验证）**：

| # | 理由 |
|---|---|
| 1 | **生效前提不成立**：RLS 只对「anon key + 用户 JWT 走 PostgREST」的路径自动生效。本项目所有查询走后端 NestJS + service_role，而 **service_role 一律绕过 RLS** ⇒ 启用后不拦截任何现有查询，纯装饰 |
| 2 | **策略写不出来**：策略谓词依赖 `auth.uid()`，但本项目登录体系是自定义的（微信 code2session + 内存 `login_tickets`），**没有 Supabase Auth JWT** ⇒ `auth.uid()` 恒为空，只能写出 `using (false)`（全拒）或全放 |
| 3 | **覆盖面不增反减**：预留策略只覆盖 4/15 张表。补全需逐表写策略、新表必须同步补，漏一张就是一个洞——维护负担与代码层 `.eq('user_id')` 完全相同，却多一层"看起来安全"的错觉 |
| 4 | **与共享模型冲突**：一旦实施共享（见上节），可见性 = 「本人数据空间 ∪ 被授权空间」，策略要 join 授权表判断，可读性与查询性能都差；把该判定放在应用层**一个收口函数**里更可控、可测试、可灰度 |

**替代方案（已落地）：静态门禁 `server/scripts/check-isolation.mjs`**

- 扫描 `server/src` 全部 `.from()` 调用点，检查是否带 `.eq('user_id')`；有意不带的分四类豁免：**表级白名单**（全局表 / 内容寻址 / 身份表 / 运维表）、**文件级白名单**（cron、容量统计）、**insert 链**（隔离靠 payload.user_id 后端强制写入）、**通用出口** `supabase-db.provider.ts`（where 由调用方传入）。
- 源码级豁免用 `// check-isolation-ignore: 理由`，**理由必须写清**，防止"为了过检而关检查"。
- 跑法：`pnpm --filter server check:isolation`（建议提交前 + CI 各跑一次；当前 93 处调用点全通过）。
- ⚠️ 它是**启发式告警门禁**（向后看 12 行 + 常量表名还原），报出的点需人工确认；发现漏报先改脚本，不要删检查。

**本次同步修掉的两个授权缺口（Explore 全量扫描发现）**：

1. **越权读（已修）**：`chat.service.ts` `sendMessage` 取会话历史只按**客户端可控的 `session_id`** 过滤 ⇒ 传入他人 session_id 即可读走该会话全部历史，并作为多轮上下文注入 LLM（数据外泄面）。已补 `.eq('user_id', userId)`。
2. **全局表零鉴权（已加固）**：`knowledge_articles` 是无 `user_id` 的全局表，其内容直接拼进 system prompt，而 `/chat/knowledge` 四个 CRUD 端点此前无任何身份校验 ⇒ 任意请求可操纵所有用户的助手人设。已加固：列表需登录；写操作走 `requireAdmin()`——配置 `CHAT_ADMIN_IDS`（`.env.secrets`，逗号分隔 user id）后仅白名单可写，未配置时放行并每次 warn。彻底方案（`users` 加 role 列 + 管理员体系）登记 **GK-OPS-18**。

**仍存的根因级风险（登记 GK-OPS-18，本期不处理）**：`X-User-Id` 请求头无签名校验 ⇒ `.eq('user_id', userId)` 可被伪造 header 绕过。当前的"数据隔离"**防误操作与 IDOR，不防伪装身份**。中期二选一：① 身份头签名（HMAC + 服务端密钥，改动小）；② 全面切 Supabase Auth JWT（可与 RLS 方案合并评估）。

## 5. 部署包加密方案

**要写**：
- 背景：平台 sites 部署打包 `server/` 全目录且排除名单不含 `.env`，平台无 env 注入 ⇒ 敏感项必须脱离明文；
- 方案：敏感项拆到 `server/.env.secrets`（`DATABASE_URL` 另拆 `.env.migrate` 仅供本地迁移）→ `scripts/encrypt-env.mjs`（AES-256-GCM，scrypt 派生自小程序 AppID）→ 产出 `.env.secrets.enc` 只传密文 → 部署 `startCmd` 覆盖为 `node scripts/decrypt-env.mjs && npm run start` 在容器内还原；`deploy-pack.mjs pack|restore|status` 负责打包前后把敏感文件挪到 `<项目根>/.deploy-staging/`；
- **纪律：改了 `.env.secrets` 必须重跑 `encrypt-env.mjs`**；
- 边界声明：防包泄露与扫描器，**防不住平台运维与定向攻击**（派生因子 AppID 是公开的）。
**素材**：`server/scripts/encrypt-env.mjs`、`deploy-pack.mjs`、《安全与隐私设计方案.md》4.8.1

## 6. 前端与客户端安全

**要写**：
- 小程序包内**不含任何密钥**（不直连 Supabase、不直连第三方 LLM，一律后端代理）——已核实；
- 上传/下载超时与失败兜底（不泄露内部地址）；
- 域名白名单与 `urlCheck` 仅开发环境关闭；
- 日志不打印敏感字段（file_key 可打、URL 与 token 不打）。

## 7. 儿童隐私与内容合规

**要写**：
- 数据最小化：只收集实现功能必需的数据；
- 留存周期：授权用户长期、临时用户 24h、删除后不可恢复（用户手册同步口径）；
- 用户权利：查看、导出、删除；
- 第三方数据传输说明：哪些内容会送到 ima / LLM 供应商（题干文本、图片），传输目的与最小化措施；
- 内容合规：AI 输出标注"未经核实"、不允许冒充官方答案。
**待确认**：是否需要正式《隐私政策》文本并在小程序中展示（微信平台通常要求）— 若需要，登记为合规待办。
