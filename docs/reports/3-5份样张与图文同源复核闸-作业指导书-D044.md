## 0. 这道闸到底在防什么

`P-024 Q3②` 把 `.doc` 最终形态定为**整题 PDF 快照**（`figureUrl` 双轨：判定层仍只读 `stem_text`，快照只替换呈现，契约零改动、不 bump `CACHE_VERSION v14`）。但 D-035 只读核查发现三件事：

| 事实 | 数字 / 来源 |
|---|---|
| `.doc` 整题快照 **0 张** | `netdisk-figure-build.mjs::pendingSources()` 写死 `nf.ext='docx'` |
| 既有 docx 快照只铺了 **620 / 3,705 份（16.7%）／31,685 张** | `question_figures`（`0028`），全 `fig-v1`、11-08 单日 |
| `.doc` 有 **3,700 份**带解析来源、**42,619 个** `stem ≥10` 字对象无快照 | D-035 实测 |

🔴 **真正的风险不是「没图」，是「错图」**：`netdisk-figure-crop.py::locate()` 靠 `stem[:28/20/14/10]` 文字锚点定位，且第 ③ 级兜底是**全篇任意位置**；而 `.doc` 的文字是**静默缺字**（对象级 `U+FFFD` 仅 174 个）⇒ 长锚点大面积失配、退化到全篇兜底后，可能把**相邻题的整题图**配给本题。按 D-034「**错图比没图更糟**」「**读得懂 ≠ 题目可解**」，这道闸必须在任何 `.doc` 快照下发前由人逐份看样张签核。

## 2. 样张选谁（3–5 份，含必含反例）

候选池：生产库**只读**查 `.doc` 来源、`has_solution`、该题 `stem ≥10` 字、尚无快照。禁止挑「看起来最干净」的（举证责任倒置）。

| 层 | 必含形态 | 为什么 |
|---|---|---|
| S-a | 含 **OLE/VML 公式**（D-042 实测 362 个 `w:object` 全是 `ole_with_vml_image`、零内部文字） | 验证公式在快照里是否完整、是否被当成空白 |
| S-b | 含**几何配图 / 插图** | 验证图形与题目是否同一道 |
| S-c | **纯文字长题**（≥200 字） | 验证裁切是否把答案区、下一题一起裁进来 |
| S-d | **短题干 / 高失配风险**（归一后 10–20 字、含 `U+FFFD` 或缺字形态） | **必含反例**：专门逼 `locate()` 走全篇兜底 |
| S-e（可选，凑 5 份） | **跨页题**（`char_start` 折算页与实际页不一致） | 验证 `WINDOW=3` 预期页窗口是否够 |

抽样：`ORDER BY md5(source_id || ':' || object_index)` 确定性排序，每层取第 1 条；登记 `source_id` 清单 + sha256 + 抽样 SQL 全文，供复跑。**改配额或换层须重抽、重算 sha、另建 D 号。**

## 3. 每份样张交付什么（材料包 7 项）

对每一份，产出一个目录 `sample-0N/`，含：

| # | 内容 | 用途 |
|---|---|---|
| 1 | `snapshot.webp`（整题快照，含 `page_index`、裁切 bbox、`width/height/size_bytes`） | 主材料：看「显对」 |
| 2 | `full-page.png`（**同页整页渲染图**） | 人工核对「是不是相邻题的图」——没有整页图无法判同源 |
| 3 | `stem.txt`（该题入库 `stem_text` 原文，标注 `U+FFFD`、缺字位置、`stem_len`、`char_start`） | 对照「库里那道题」与「图上那道题」 |
| 4 | `locate-log.json`（**决策日志**）：`ANCHOR_LENS` 逐级命中情况、`expect` 预期页、命中页、偏移、是否走第 ③ 级全篇兜底、`totalLen` | 图文同源闸的核心证据 |
| 5 | `convert-log.json`：soffice 退出码、`fc-match Symbol` 输出、耗时、profile 路径、`MemAvailable` 前后 | 排除「Symbol 别名丢失让 `≠`/`<`/`−` 静默消失」与环境坑 |
| 6 | `answer-leak.txt`：裁切区是否包含解析/答案段的机器标注（**只是提示，不是结论**） | 防止把答案一起裁给用户 |
| 7 | `README.txt`：该题 `source_id` / `object_index` / 文档名 / 抽样层 / 生成时间 / 引擎版本 | 可回放、可追溯 |

🔴 **`locate-log.json` 第 4 项是关键**：`locate()` 现有实现在 `netdisk-figure-crop.py:113-145`，三级兜底；样张阶段**不改真相源**，只在独立驱动里把「是否走全篇兜底」记下来，并在复核表里直接标「存疑」。

## 4. 步骤（S0–S9，逐步可执行）

### S0 · 建档与只读声明
另建 D 号，写明：样张数量与分层、候选池 SQL、材料包清单、签核表模板、通过线、零写入边界。**未建档不启动。**

### S1 · 候选池只读查询（纯 `SELECT`）
在 L3 按 §2 口径出 3–5 条候选 + 分层依据 + sha。输出不落题干原文到仓库（只落 `source_id` / 长度 / 层标）。
```sql
-- 示意（正式 SQL 在 S0 建档时固化，前后同口径）
select q.source_id, q.object_index, q.char_start, length(q.stem_text) as stem_len,
       q.has_solution, nf.ext
from question_objects q
join netdisk_files nf on nf.id = q.source_id and nf.user_id = q.user_id
where nf.ext = 'doc' and q.has_solution
  and length(q.stem_text) >= 10
  and q.source_id not in ( /* D-034 的 20 个 source_id */ )
order by md5(q.source_id || ':' || q.object_index)
limit 5;
```
> ⚠️ 上面 `join` 的键以 `migrations/0026` 实证为准（S1 执行前先回查 `question_objects.source_id` 与 `netdisk_files` 的真实对应关系），**不许猜列名/外键**。

### S2 · 环境预检
- `free -m`：`MemAvailable` **< 700 MB 就等**，绝不与生产 API 抢资源；
- `fc-match Symbol` 输出必须含 `symbol`（不区分大小写），否则**停止**（`assertSymbolFont()` 口径，M40 B9）；
- `soffice --version`；**每个 worker 独立 LO profile**（`lo_profile_arg()`）；
- 🔴 cwd：驱动启动前 `cd /tmp/gk-sample-*/work`（D-042 踩过的坑——ssh 落在 `/home/ubuntu`，`gk` 进不去，`/usr/bin/soffice` 包装脚本末尾 `cd "$sd_cwd"` 会直接 `exit 2`）；
- `/tmp` 脚本与目录 `chown -R gk:gk`（否则 EACCES）。

### S3 · 转换（soffice → PDF）
每批 ≤2 份、`ionice -c3 nice -n19`、单批超时 ≤8 min；长跑一律：
```bash
sudo -n systemd-run --wait --collect --unit=gk-sample-fig --uid=gk \
  -p MemoryMax=1800M -p CPUQuota=150% -p RuntimeMaxSec=1800 \
  bash /tmp/gk-sample-*/run-sample.sh
```
`systemd-run` 不继承 dotenvx ⇒ unit 内 `set -a; . .env.secrets; . .env.migrate; set +a`；远端日志另开 ssh 轮询，不依赖后台通知。

### S4 · 定位与裁切（**不改 `netdisk-figure-crop.py`**）
用独立只读驱动按 `manifest.json` 结构（`fsId / userId / sourceId / name / docx / totalLen / objects[{index,stem,rev,start}]`）调用既有 python 段，产出 `result.json`；同时在驱动里记录 `locate()` 的三级命中路径。
- `SCALE=2.0`、`MARGIN=40`、`MAX_H=2200`、`ANCHOR_LENS=(28,20,14,10)`、`ANCHOR_MIN=10`、`WINDOW=3`、`HEADER_CUT=0.03/FOOTER_CUT=0.97` 全部**沿用现状**，不调阈值；
- 🔴 **图文同源闸（样张阶段的收紧口径）**：凡第 ③ 级「全篇任意位置」兜底才命中的，材料包标 `fallback_hit=true`，复核表**直接记「存疑」**，不自动采用、不下发；
- 定位不到 ⇒ `status='empty'`，**绝不拿相邻题顶替**；
- 产物只写 `/tmp/gk-sample-*`，不进 `question_figures`。

### S5 · 生成材料包与自检
按 §3 出 7 项文件；机器自检只做**完整性检查**（文件齐、bbox 在页内、webp 可解码、sha 登记），**不做通过判定**。

### S6 · 回传本地并交付
`scp` / `sudo cat` 回传 `.tmp/sample-pack/`，用文件卡片交给思傅；同时给一份「每份样张一页」的复核表（模板见 §5）。

### S7 · 思傅逐份人工签核（**只能本人做**）
按 §5 六列逐份判，**每份约 2–3 分钟**，建议一次看 2 份、中途休息（D-034 教训：疲劳会把「存疑」误判成「通过」）。AI 不代签、不提示倾向。

### S8 · 判定与收口
- **通过线**（`P-024 §4` 第 4 条）：**不通过 0 且存疑 ≤2**，且**单独统计「题目是否可解」**；
- 同 seed 重跑一次，报候选数 / 定位数 / 兜底命中数 / 真相源 sha / 生产 `/api/health` / docx 侧 14 项数据门零漂移；
- **通过** ⇒ 另建 D 号，才谈「是否补跑 docx 剩余 3,085 份」与 F6 实现；**不通过或存疑超线** ⇒ 保持 `.doc` 0 张、收紧 `locate()` 兜底另立提案，**不得靠调阈值在本批样张上自证**；
- 不计算召回率/准确率、不外推 3,700 份 `.doc`、不宣称图形全覆盖／修复有效／误判归零。

### S9 · 清理与零写入复核
删远端 `/tmp/gk-sample-*`（逐文件、小批量、先备份清单）；回查 `question_figures` / `question_inline_figures` 行数与 `engine_version` 分布**与 S1 前一致**；确认 `git status` 只多出文档与探针 SQL。
