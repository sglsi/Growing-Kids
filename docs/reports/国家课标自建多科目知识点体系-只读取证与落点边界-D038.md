## 0. 结论摘要（通俗版）

思傅给的思路是：**既然那个第三方图谱有 CC BY-NC 许可限制，就别用它的数据了，直接照国家课标自己做一套，别的科目也一起做，写进库里。** 这个方向成立，而且比原方案更干净——但有三件事必须先说清楚，否则容易做成「换了个名字的复制」：

1. **「按国标」的取数源只能是教育部官方文本，不能是那个仓库里的课标文件。** 我实测了它的 `cn-curriculum-standards.json`：803 条条文里 **646 条标着 `verbatim=false`（转述）、157 条空值、逐字原文 0 条**，编号还是作者自编的，文件自己写着「库存去掉了例 1、例 2、例 3」。**它是作者对课标的转述，是受 CC BY-NC 覆盖的原创表达，不是课标原文**。把它改名导入，许可绕不过去，内容准不准也没保证。
2. **「其他科目」不能靠那个仓库凑齐。** 它覆盖 10 个学科、3,474 个知识点；而 2022 版义务教育课标是 **16 门**，缺日语、俄语、信息科技、体育与健康、艺术、劳动 6 门。我们现有的 `TOPIC_TERMS` **55 个词全是数学**（面积、勾股、二次函数、方差…），一个其他学科的词都没有 ⇒ 多科目是**净新增工作**，不是词表增补。
3. **「写入当前库中」目前没有现成的地方可写。** `migrations/0026_question_objects.sql` 里 `question_objects` 表**没有任何知识点 / 学科 / 学段 / 题型 / 难度字段**（本轮 grep 0 命中）。要写就得新建表或加字段 ⇒ 那是实现代码 + 数据库迁移，属于独立实施提案，不是本轮能顺手做的事。建议建**独立知识点维度表**，跟 65.7 万行的题目表解耦，避免全量回填和判定层契约被牵动。

**另外核实了一条好消息**：思傅引的《义务教育数学课程标准（2022年版2025年修订）》**版本名称属实**，是教育部「教材〔2025〕1号」日常修订版的正式叫法，不是第三方自造的（详见 §2）。

### 3.2 由此得到的硬判据

| | 结论 |
|---|---|
| ✅ **可用作自建依据** | 教育部官方课标文本中的**事实性内容**：知识点名称、领域/主题划分、学段划分、内容要求条目。国家机关规范性文件的事实性内容可作为自建参考（**工程判断，非法律结论**） |
| ❌ **不得作数据源** | `cn-curriculum-standards.json` 的 `items[].text`（转述、`verbatim=false`、删例题、自编编号）、`topics.json` 节点取值、`dependencies.json` 先修边、`mastery_criteria`、`diagnostic_question`、`questions.json` 题库 |
| 🔴 **唯一合法取数源** | **教育部官方 PDF / 通知附件原文**。第三方仓库仅可作①**数据结构参考**（两表本体、先修图、可测单元、独立盲解协议）②**交叉校验线索**（用它提示「该去官方哪一章找」），**不得复制其表达** |
| 🔴 **法务边界** | CC BY-NC 4.0 判据是「是否主要指向商业利益或金钱报酬」（`LICENSE:116`），且 `LICENSE:281` 明确**提取部分内容也在使用范围内** ⇒ 只导词表 / 只导条文片段同样受约束。本报告**不代做法务结论**；面客集成前建议保留「来源标注 + 逐科官方文本核对 + 法务复核」三道 |
| 🔴 **不解除项** | D-038 解除的是「按国标自建的体系不得集成」这条**合规禁令**；对 **`cn-math-taxonomy` 数据本身**的「不进代码/生产」禁令**继续有效**（`P-026` F9 精确化、F12 新增） |
