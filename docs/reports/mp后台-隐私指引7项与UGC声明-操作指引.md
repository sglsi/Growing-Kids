## 2. 用户隐私保护指引：7 项逐屏步骤

### 2.1 先选入口（选错不会报错，只会白等 1–2 天）

微信有**两个**入口，改的不是同一份协议（官方 2026-11 口径）：

| 入口 | 路径 | 改的是 | 生效条件 |
|---|---|---|---|
| **入口1** | 左下角头像 → **账号设置 → 服务内容声明 → 用户隐私保护指引 → 去完善** | 现网版本协议 | 审核通过即生效；**小程序没有线上版本时，审核通过也不生效、页面空白** |
| **入口2** | **管理 → 版本管理 → 开发版本那一行右侧「提交审核」 → 信息填写页底部「用户隐私保护指引设置」** | 本次提审版本协议 | 随本次代码审核通过 **+ 发布上线** 一起生效 |

**本项目走入口2**：至今没有线上正式版（本期未发正式版）。托管解除后入口2 正常可用。
> 后台菜单会改版，认准「**服务内容声明**」「**用户隐私保护指引**」这两个词；找不到就用后台顶部搜索框。点「去完善」没反应通常是浏览器拦了弹窗，放行即可。

### 2.2 逐屏操作（照做，每步给判据）

| 步 | 操作 | 通过判据 / 注意 |
|---|---|---|
| 1 | 开发者工具上传代码 → 后台「管理 → 版本管理」找到该开发版本 → 点该行右侧绿色 **「提交审核」** | 后台没有叫「提交代码审核」的菜单；按钮就在开发版本那一行，旁边下拉是「选为体验版本 / 删除」。**不用真提交**，进信息页就能配 |
| 2 | 信息填写页底部找到 **「用户隐私保护指引设置」** → 进入指引页 | 若被拦截提示「隐私接口调用情况与协议内容有出入」，就在**当前入口2** 更新，别跑回入口1 |
| 3 | 二选一页：**必须选第二项**「本小程序处理了用户信息，将如实填写并及时更新用户信息处理情况」（提审页对应选 **「采集用户隐私」**） | 🔴 绝不能选第一项「未以任何方式处理用户的任何信息」：一旦声明未处理，隐私接口**申请入口会被关闭**，恢复要重走「改声明 + 完善协议 + 审核」；提审页选「未采集用户隐私」会直接驳回（2026-11-14 实测截图即误选此项，见 §2.4.1） |
| 4 | 在「处理的信息」清单里**只勾 7 项**（见 §2.3） | 多勾位置/通讯录/微信运动/手机号/日历/设备信息/发布内容 = 虚假声明，反而增加驳回风险 |
| 5 | 给 7 项逐行填「为了 ___」，**照抄 §2.3 短句** | 写长句会截断；别写「优化服务」「保存图片」这类泛词 |
| 6 | 填「信息保存期限」：粘贴 §2.4 文本 | ⚠️ 不能写「永久」，不能填 0 天；数字须与 r11 第七节一致 |
| 7 | 「再次告知 / 采集变动通知方式」选 **弹窗** | 项目用 `privacy-gate` 在首次调用隐私接口前弹窗，不是站内公告 |
| 8 | 展开「第三方信息共享」，按 §2.5 逐条添加（**r11 后 5 条；第 5 条微信须同时写登录 + 内容安全检测**） | 少一条 = 漏报；多填一条已不存在的服务商 = 与实际行为不符 |
| 9 | 手机号 / 邮箱填**真实可达**的（个人开发者填自己的），两栏都必填 | 这是法律文本第十节「联系方式」落地的唯一依靠 |
| 10 | 点「提交」→ 等审核（通常 1–2 工作日，首次更久）→ 审核通过后**发布上线**才算生效 | 提交后状态「审核中」时**不要重复提交**；只审核不发布 = 没生效 |

### 2.3 七项勾选 + 用途短句（逐字照抄）

| # | 勾选项 | 「为了 ___」填这句（短句） | 代码依据 | 漏勾后果 |
|---|---|---|---|---|
| 1 | **用户信息（微信昵称、头像）** | `设置并展示你在「我的」页的昵称与头像` | `openType="chooseAvatar"` + `type="nickname"`（`profile/index.tsx`） | 点头像报 `chooseAvatar:fail api scope is not declared` |
| 2 | **收集你选中的照片或视频信息** | `识别您选择上传的题目照片，生成错题记录` | `chooseMedia` / `chooseImage`（识题、记忆页选视频） | 选图静默失败 `errno 112` |
| 3 | **访问你的摄像头** | `拍摄纸质作业或试卷，识别题目文字` | `sourceType: ['camera', ...]` | 拍照点了没反应 |
| 4 | **访问你的麦克风** | `录制语音备忘，与您的成长记忆一起保存` | `getRecorderManager().start()`（记忆页录音，最长 60s，mp3） | 录音点了没反应 |
| 5 | **收集你选中的文件** | `从聊天中选取图片或PDF，导入资料库识别` | `chooseMessageFile()`（资料库 / 答案附件） | 选文件页报错 |
| 6 | **剪切板** | `复制识别结果或图片链接，方便您粘贴使用` | `setClipboardData()`（复制 OCR 文本 / 图片链接） | `setClipboardData:fail api scope is not declared`；**只写也必须勾**，官方按「有没有调接口」判 |
| 7 | **相册（仅写入）** | `允许你在图片预览中保存题目图片到手机相册` | 三个保存接口零调用；真机由 `Taro.previewImage` 微信原生预览器提供 | 不是接口必填（不会 `errno 112`），但审核员真机测到「能存图」却查无声明，可能被质疑未如实申报 |

> 第 7 项是官方「开发者可自主勾选其他项目」，2026-11-05 思傅已拍板补勾，短句**不要临场改写**。
> 若提审时该项被质疑「用途与接口不符」，按后台提示调整短句或回退为 6 项，并回来同步 `GK-QA-16` 4.5.4.2 与本指引。
> ⚠️ **以后台实际显示为准**：若平台把「设备信息」列为必填（说明它检测到了它认定的接口），就勾上并如实填「适配不同屏幕尺寸的界面布局」，别硬扛。

### 2.4 信息保存期限（粘贴这段）

```
登录账号保存至注销；未登录匿名身份连续 30 天不使用即过期清理；答案缓存与识别结果缓存
按内容寻址长期保留，升级识别引擎后自然失效；服务端运行日志保留 7 天且不含题目内容；
数据库整体加密备份本地与异地各保留最近 14 份、按天滚动覆盖，注销后数据可能在备份中
留存不超过 14 天。
```

> 依据 r11 第七节。关键数字（30 天 / 7 天 / 14 份 / 14 天）一个都不能改，平台会与应用内政策比对。

### 2.4.1 提审信息页 &「开发者对信息的存储 / 信息的使用规则」逐项填法（2026-11-14 截图核对）

## 3. UGC 信息安全声明：逐字段步骤

### 3.1 入口与表单字段

**路径**：`mp.weixin.qq.com` → **设置 → 功能设置 → 用户生成内容场景声明 → 详情 / 编辑**。

### 3.4 ✅ 方案 A 已实施：内容安全 API 已有用户可达调用（`D-059`）

**2026-11-14 思傅拍板「按 A 实施」后落地**。`D-058` 时全仓 `checkText()` 只有 `chat.service.ts` 一处调用且前端不可达；本轮新增统一闸门 `server/src/security/ugc-text-guard.service.ts`，在**五条用户可达的文本写入口**接入：

| # | 落点 | 送检字段 | scene |
|---|---|---|---|
| 1 | `auth/auth.service.ts`（`PATCH /api/auth/profile` 与登录带 profile） | 昵称 | 1 资料 |
| 2 | `timeline/timeline.service.ts`（create / batch / update） | 题目名称、题干、答案、解题过程、错答、父题干、题号标签、标签 | 2 评论 |
| 3 | `questions/questions.service.ts`（旧表，create / update） | 题干、答案、解题过程、错答、来源 | 2 评论 |
| 4 | `memory/memory.service.ts`（create / update） | 成长记忆标题、正文、心情、标签 | 4 社交日志 |
| 5 | `subjects/subjects.service.ts`（create / update 改名称时） | 学科名称 | 1 资料 |

命中 `reject` / `risky` ⇒ 抛 400「内容包含不适宜的文字，请修改后再保存」，**整条不入库**；只送用户主动编辑的文本，不送 OCR 全文、文件正文、图片 key、URL；批量保存合并为一次调用；两次微信外网 fetch 带 3s 超时。隐私政策随之升 r10 补披露（本轮 `D-060` 再升 r11）。

**`method=1` 现在成立**，用 §3.3 的正式版 `audit_desc`。本地实证（不连微信、不连库）：

```

cd server && node scripts/verify/run.mjs M50   # 静态守卫
```

🔴 **但填 `method=1` 前必须先完成后端发货**：`D-059` 目前只改了本地代码与 `server/dist`，**生产 `gk-api` 跑的仍是 D-056 的旧 dist**（无检测）。线上代码没换就去勾 1，等于「声明有、代码没有」，比填 4 更糟。顺序见 §4 第 0 步，换 dist 需思傅单独授权（备份 + sha256 集合比对 + 重启 + `:3000` 真健康探针）。

**诚实边界（写在这里，别把「接入」说成「全覆盖」）**：

| 边界 | 实情 |
|---|---|
| best-effort | 凭据缺失 / 微信接口异常 / 匿名账号无 openid 时底层**放行**，不阻断保存。生产 `users` 中匿名账号占多数，这部分实际不会送检 |
| 图片 / 视频 / 音频 | **未接** `imgSecCheck` / `mediaCheckAsync`（需公网可访问 URL，现有文件在私有存储）；五类 UGC 里只有文本过了检 |
| 机器生成文本 | OCR 全文、资料库正文、AI 历史产物不送检（设计上只管用户主动编辑的短文本） |
| 旧数据 | 只对**新写入 / 新修改**生效，历史数据不回溯检测 |

> 若审核意见是「小程序功能存在信息安全风险，请完善内容机制」，优先补的是**图片检测**与**匿名态 openid 获取**（前端保存前确保 `wx.login` 已换正式身份），而不是把文本检测再铺一遍。这两项需另开 D 号，本轮未做。
