## 3. 判定推导

### 3.1 T0 的准确定义（`P-026 §4` 第 117 行）

> **T0（硬门）＝ 度量闭环**：独立盲测样本固化（与调参样本物理分离、禁复用 D-034 的 40 条 / 20 份）＋ 前后对照协议 v1.0 必跑（指标 / 判据 / 样本 / falsifier 实施前写死，同一份 `measure-baseline.sql`）｜ 未过 T0 不得启动 A0/B0 以下任何算子。

按定义逐项对表：

| 定义要件 | 实测 | 判定 |
|---|---|---|
| 独立盲测样本固化、与调参样本分离 | 200 条 sha 复现、排除 D-034 的 20 个 `source_id`、声明「只验收永不调参」 | ✅ 完成 |
| 指标 / 判据 / 样本 / falsifier 实施前写死 | `P-025 §3` 七条纪律、§⑤ F1–F7、配套报告 §2 协议矩阵、D-040 样本登记 | ✅ 完成 |
| 同一份 `measure-baseline.sql` | 源码一字未改；本轮 8 项加总与 D-036 零漂移 | ✅ 完成 |
| **前后对照「必跑」** | 无任何获批实施落地（0032 未上生产、无新引擎、无「后」值）⇒ **「后」采集无对象** | ❌ 未完整实跑 |
| **结果指标出数** | `review_events` 0 行 | ❌ 未出数 |

⇒ **状态判定：未过**（A）。但两项 ❌ 的性质完全不同：

- 「后」采集无对象 ⇒ **逻辑上的循环依赖**：`P-025 Q2①` 把协议设为任一借鉴项实施的必跑前置，而「后」值只能在实施之后产生。若把「必跑前置」读成「实施前必须已经跑完前后配对差分」，则永远无法实施、永远无法 T0 通过 —— 这是**记账口径错误**，不是质量门。
- 「结果指标 0 行」 ⇒ **发布后外部条件**，受正式版发布与真实使用约束，不是任何工程动作能交付的东西。

### 3.2 循环依赖的正确解法（C，**不放宽任何门**）

协议 v1.0 的七条纪律里，P1 同口径 / P2 事前注册 / P3 配对差分 / P5 样本分离 / P7 零回归都是**流程约束**，可以在实施前全部满足；只有「后」值采集必须在实施后。⇒ 把 `Q2①` 的「必跑前置」按协议原文解释为：

| 阶段 | 必跑内容 | 是否可前置 |
|---|---|---|
| 实施**前** | 复测「前」基线（同一份 `measure-baseline.sql`）、复核数据门 14 项与契约 sha、确认指标/判据/样本/falsifier 已注册、样本分离 | ✅ 可、且**必须** |
| 实施**中** | 按已注册口径执行，禁改阈值/SQL/seed/环境 | ✅ 必须 |
| 实施**后同轮** | 用同一份 SQL 采「后」值、配对差分、逐条过 F1–F7、D 二元判定 | ⛔ 逻辑上不可能前置 |

🔴 这不改变 `P-025 Q2①` 的「必跑」性质、**不豁免任何一项**、不把「未过」改写成「已过」；只是把一盏混装红灯拆成「工程前置物（已完成）」「验收门（实施后同轮）」「外部条件（发布后）」三本账。**任何实施解锁仍须另立 D 号逐项拍板**（F）。
