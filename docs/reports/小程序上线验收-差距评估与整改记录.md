## 0. 一句话结论

**工程底子比预期扎实**——隐私保护指引、监护人同意、内容安全检测、密钥轮换、备份演练、发布清单都已落地，不是"从零开始补"。

但站在验收官角度仍有 **5 个只在上线后才会暴露**的缺口，本次已修 4 个、登记 1 个；另有 **6 项属于 mp 后台 / 资质侧，代码改不了**，需按第 3 章逐项人工办。

最关键的一条认知：**这个项目一直在吃「开发态豁免」**——`urlCheck:false` 让域名校验在开发期完全不生效，局域网直连让网络永远可达，开发者工具让隐私弹窗与版本更新都不触发。豁免消失的那一天，暴露的全是这类"本地永远正常"的问题。

## 2. P0 事故级缺口（本次已修）

| # | 缺口 | 为什么上线才暴露 | 处置 |
|---|---|---|---|
| 1 | **无版本更新检测** | 小程序没有"刷新即生效"。旧包会一直用到微信决定更新为止，期间线上修了 bug、改了接口，用户看到的仍是旧行为，且无法热修复 | 新增 `checkAppUpdate()`：`getUpdateManager` → 新包就绪弹窗（立即重启 / 稍后）。**选"稍后"不强制**——用户在做题中途被强制重启会丢输入 |
| 2 | **线上错误黑盒** | 开发有 console、有后端日志；线上拿不到用户手机上的堆栈，出问题只能靠用户描述"点了没反应" | 新增 `installErrorMonitor()`：`onError` / `onUnhandledRejection` / `onPageNotFound` → 微信**实时日志**（mp 后台 → 运维中心 → 实时日志，按 openid 可查）。零后端改造 |
| 3 | **无网/弱网无提示** | 局域网调试时后端永远可达；真机断网时界面只表现为"转圈"，用户分不清是断网还是功能坏了 | 新增 `watchNetworkStatus()`：断网/恢复各提示一次（去重），并写实时日志 |
| 4 | **唤醒机制在云端不存在** | 唤醒服务（3002 端口拉起后端）是**本机开发态**的产物。迁云托管后没有它，每次连接失败会先白等最多 40s 才报错——用户看到的是"转圈半天然后失败" | 新增编译期常量 `WAKE_ENABLED`：**生产构建默认 0**，`wake.ts` 直接返回 false；本地/体验版构建默认 1，行为不变 |
| 5 | **AI 生成内容无显式标识** | 开发期 AI 默认关闭（`users.ai_enabled=false`），没人看到过 AI 输出，自然没人发现缺标识 | 聊天页 assistant 气泡下加「AI 生成内容，请核对后再给孩子讲」；AI 解题结果标题改为「AI 生成内容（未联网核实，请核对后再用）」。**标识办法要求的是"生成内容"这一法定表述**，原"AI 推理结果"不算 |

> 实现统一收在 `src/services/app-runtime.ts`，由 `App` 的 `useEffect` 一次性挂载。三条约束：**零新依赖、零后端接口、任一失败不阻塞启动**。
> ⚠️ 1、2 两项在**开发版与开发者工具里看不到效果**（基础库行为，非 bug），必须在**体验版或正式版**验证。

## 3. P0 合规项（mp 后台 / 资质，代码改不了）

| # | 项 | 现状 | 要做什么 |
|---|---|---|---|
| 6 | **服务器域名** | `.env.local` 是 `http://192.168.3.242:3001`（局域网 IP + http） | 必须换成 **https + 已完成 ICP 备案**的域名，并在 mp 后台配 **request / uploadFile / downloadFile** 三类白名单。⚠️ **downloadFile 最常漏**——导出文件走 `Taro.downloadFile` + `openDocument`，漏配的表现是"下载成功但打不开"。路线见 `GK-OPS-19` |
| 7 | **小程序 ICP 备案** | 未见 | 2023-09 起小程序上线需完成备案，与域名备案是两件事 |
| 8 | **服务类目与资质** | 未见 | 教育类目需确认主体类型能选（个人主体可选类目受限）。⚠️ 本项目**主体类型待核实**——若为个人主体，"在线教育"类可能需资质或不可选，需先在后台核对可选类目清单 |
| 9 | **用户隐私保护指引** | 代码侧已完备（`__usePrivacyCheck__` + 平台弹窗 + 监护人同意） | mp 后台需勾选 **4 项**：相册 / 摄像头 / 选中的文件 / **剪切板**，且必须**随本次版本一起提交**（未发布时入口不生效，QA-16 §4.5 已写明走提审页入口） |
| 10 | **生成式 AI 合规** | AI 默认关闭（有利事实）；标识本次已补 | 若对外提供 AI 生成内容：① 显式标识（已做）；② 服务提供者侧的算法/大模型备案与评估。**务实建议：首版保持 `ai_enabled` 默认关闭**，需要时按用户申请开通，把备案压力后置 |
| 11 | **用户协议入口** | 有《隐私政策》页，未见《用户协议》 | 提审材料里通常要求两者齐备；建议在「我的」页补入口 |

> 隐私接口与后台勾选项的对应关系（避免漏勾导致 `errno 112` 静默失败）：
> `chooseMedia`（相册+摄像头）／`chooseMessageFile`（选中的文件）／`chooseImage`（相册+摄像头）／`setClipboardData`（剪切板）。

## 4. P1 性能与体验

| # | 项 | 判据 | 现状 | 处置 |
|---|---|---|---|---|
| 12 | **网络超时天花板** | 微信 request / uploadFile 的**默认与最大超时都是 60s**（官方服务市场文档原文） | 代码里写 `timeout: 180000` / `130000`，**实际不会生效**。这是**假安全感**：比不写更危险，因为没人会再去查 | 注释已改正（不擅自改数值，避免改变既有行为）；长任务需后端异步化（先回 ticket 再轮询）→ 登记 `OPS-18 R-上线-01`。**precise 全链路实测 ~67s，在小程序端必然被掐断**，与网速无关 |

| 14 | **按需注入 `lazyCodeLoading`** | 微信官方推荐的启动优化 | 未开 | **本次未加**：收益与包体规模相关（当前包不大），且需真机回归验证（QA-16 §4.4 带 ★ 项）。建议体验版验证通过后再开 |
| 15 | **首屏体验** | 骨架屏 + 缓存 | 首页已有 `Skeleton` + 本地缓存 + 静默刷新 | 通过 |
| 16 | **图片上传** | 压缩 + 超时 | 已有 `compressForUpload`（按尺寸降采样）+ 显式 timeout | 通过 |
| 17 | **索引收录 `sitemap.json`** | 可选 | 未配 | 不配时微信默认全量索引，无功能损失；如未来某页不想被搜到再补 |

| 缺口 | 处置 |

| 发布清单靠人逐条看——提版本那天赶时间，最容易跳过的恰恰是"urlCheck 忘了开"这类**一步错全盘错、开发期完全无感**的项 | 新增 `scripts/release-check.mjs`（`pnpm release:check`），11 项自动验：dist 新鲜度 / 页面产物 / TabBar 图标 / 主包体积 / 隐私开关 / 明文密钥 / U+FFFD / 发布态配置 / 后端域名 / 版本角标 / 备份时效 |

## 6. 上线操作流程（按验收官顺序）

```
Step 0  域名与备案：备案域名 → 后端上云（OPS-19 路线 B2）→ https 证书
        ↓ 判据：浏览器直连 https 域名 /api/health 返回 200
Step 1  mp 后台：三类服务器域名白名单 + ICP 备案 + 服务类目 + 隐私指引 4 项 + 用户协议
        ↓ 判据：mp 后台各项状态为「已生效」
Step 2  构建与自动校验
        pnpm build:weapp && node scripts/release-check.mjs --prepare
        ↓ 判据：退出码 0，无阻断项
Step 3  上传体验版 → 真机回归（QA-16 §4.4 七项 + 本次新增：更新弹窗、断网提示、AI 标识）
        ⚠️ 体验版必须重新生成二维码并重新扫码
Step 4  提交审核：备好①测试账号（可登录的体验成员）②功能页面路径与说明③补充说明函
        （说明：面向家长的学习记录工具；AI 功能默认关闭，开启需用户显式授权；数据出境已告知）
Step 5  审核通过 → 发布 → 观察 24h（实时日志 + 后端 error 日志 + 健康拨测）
Step 6  回滚预案：mp 后台版本回退；数据库迁移不可逆时的应对见 QA-16 §8.1
```

## 7. 审核常见驳回点与本项目应对（预判）

| 驳回原因 | 本项目风险 | 应对 |
|---|---|---|
| 服务类目与实际功能不符 | 中（教育 + AI 双属性） | 类目按"教育信息服务"选；AI 部分若未备案，首版保持关闭 |
| 隐私指引未声明却调用了接口 | **低（已 4 项齐备）** | 但**必须随版本提交**，否则体验版/正式版报 `errno 112` |
| 涉及用户内容发布但无内容审核机制 | 低 | 后端已有 `ContentCheckService`（微信 msgSecCheck v2），聊天写库前拦截 |
| 未成年人信息无监护人同意 | **低（已有）** | `PolicyConsent` 要求勾选（非默认勾选），文案为监护人第一人称 |
| 功能不完整 / 存在明显 bug / 无法体验 | 中 | 提审前跑完 QA-16 §4.4 真机清单；提供测试账号 |
| 诱导分享 / 强制授权 | 低 | 未做分享与强制登录；未登录可匿名使用 |
| 实际界面与提审截图不一致 | 中 | 提审截图需在**体验版**上截取，别用开发版 |
