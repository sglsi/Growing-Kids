## 2. P0 事故级缺口（本次已修）

| # | 缺口 | 为什么上线才暴露 | 处置 |
|---|---|---|---|
| 1 | **无版本更新检测** | 小程序没有"刷新即生效"。旧包会一直用到微信决定更新为止，期间线上修了 bug、改了接口，用户看到的仍是旧行为，且无法热修复 | 新增 `checkAppUpdate()`：`getUpdateManager` → 新包就绪弹窗（立即重启 / 稍后）。**选"稍后"不强制**——用户在做题中途被强制重启会丢输入 |
| 2 | **线上错误黑盒** | 开发有 console、有后端日志；线上拿不到用户手机上的堆栈，出问题只能靠用户描述"点了没反应" | 新增 `installErrorMonitor()`：`onError` / `onUnhandledRejection` / `onPageNotFound` → 微信**实时日志**（mp 后台 → 运维中心 → 实时日志，按 openid 可查）。零后端改造 |
| 3 | **无网/弱网无提示** | 局域网调试时后端永远可达；真机断网时界面只表现为"转圈"，用户分不清是断网还是功能坏了 | 新增 `watchNetworkStatus()`：断网/恢复各提示一次（去重），并写实时日志 |
| 4 | **唤醒机制在云端不存在** | 唤醒服务（3002 端口拉起后端）是**本机开发态**的产物。迁云托管后没有它，每次连接失败会先白等最多 40s 才报错——用户看到的是"转圈半天然后失败" | 新增编译期常量 `WAKE_ENABLED`：**生产构建默认 0**，`wake.ts` 直接返回 false；本地/体验版构建默认 1，行为不变 |
| 5 | **AI 生成内容无显式标识** | 开发期 AI 默认关闭（`users.ai_enabled=false`），没人看到过 AI 输出，自然没人发现缺标识 | 聊天页 assistant 气泡下加「AI 生成内容，请核对后再给孩子讲」；AI 解题结果标题改为「AI 生成内容（未联网核实，请核对后再用）」。**标识办法要求的是"生成内容"这一法定表述**，原"AI 推理结果"不算 |

> 实现统一收在 `src/services/app-runtime.ts`，由 `App` 的 `useEffect` 一次性挂载。三条约束：**零新依赖、零后端接口、任一失败不阻塞启动**。

### 3.1 AI 首版口径：默认关闭 vs 开通（个人主体下的唯一可行解）

**这不是产品取舍，是主体资质决定的天花板。**

| 维度 | 首版 AI **关闭** | 首版 AI **开通** |
|---|---|---|
| 所需服务类目 | 无需「深度合成-AI 问答」 | **必须**补该类目 |
| 个人主体能否办 | — | ❌ **不能**。该类目仅向非个人主体开放；申请材料《互联网信息服务算法备案》要求备案主体为境内法人，自然人/个体工商户提交不了 |
| 审核结果 | 可按「教育信息服务」过 | 代码审核阶段即被认定类目不符，**驳回** |
| 法律定性 | 只是一个整理错题的本地工具 | 构成《生成式人工智能服务管理暂行办法》的**服务提供者**，对输出内容承担主体责任（调第三方大模型也不转移） |
| 数据处理 | 题目不出机（隐私政策卖点，未成年人数据风险最低） | 题干发往 ima / 大模型，需监护人二次同意（已有开关机制） |
| 功能损失 | 「联网搜题 / 知识库 / AI 解题 / 智能客服」不可用 | 四项可用 |
| 成本与稳定性 | 零 | 按调用计费 + 长链路（已异步化，precise 实测 86.8s）+ 失败率与投诉 |
| 补正路径 | — | ① 注册企业主体 → ② 小程序主体变更 → ③ 申请「深度合成-AI 问答」类目 + 算法备案（或走腾讯云代出材料）→ ④ 才能放开 |

**关键结论（与原建议的差别）**：原写「首版保持 `ai_enabled` 默认关闭」——这只挡住了**默认值**，没挡住**入口**。审核看的是「用户可访问的真实功能」，只要「我的」页还能自己把开关打开，就仍属对外提供 AI 服务。

⇒ 首版须做到 **三层同时收**：
1. 服务端 `users.ai_enabled` 默认 false（已实现，`0018`）；
2. **前端不渲染开关**（个人主体构建设置 `OPERATOR_TYPE === 'personal'` 时隐藏该 Card，改为一句话说明「AI 功能暂未开放」）；
3. 需要内部试用时走**管理员白名单**（`users.role`，已有 `requireAdmin`），不放给普通用户。

> 「AI 功能暂未开放」的文案不能写「即将上线 AI 解题」——那会被视为在提供/预告该类服务；写「当前版本仅在本机完成识别与整理」即可。

### 3.2 UGC 信息安全声明：必须填，本项目怎么选

**要不要填：要。** 官方口径（微信开放社区多帖一致）：小程序服务包含 UGC 功能场景，提审前须先在
**「设置 → 功能设置 → 用户生成内容场景信息安全声明」** 完成填写，否则审核直接驳回，提示语为
「请先在【设置-功能设置】完成对用户产生内容(ugc)申明填写，再提交代码」。

**填它是为了什么**：① 平台侧合规前置（不填就拦）；② 履行《网络安全法》《网络信息内容生态治理规定》
下的内容安全义务，把"谁对用户发的内容负责"写在纸面上；③ 它是**动态声明**——场景或机制变了要同步更新，
否则视为声明失实。

**本项目现状核账**（决定怎么勾）：

| 用户可产出的内容 | 本项目实际形态 | 是否本声明范围 |
|---|---|---|
| 用户资料 | 「我的」页昵称由用户**自行输入**（`updateProfile`）；未调用头像昵称组件 | ✅ 勾「用户资料」 |
| 图片 | 拍照/相册题目图、从聊天选文件（`chooseMedia` / `chooseImage` / `chooseMessageFile`），落库后**仅本人可见** | ✅ 勾「图片」 |
| 文本 | AI 助手提问（进库前已过 `msgSecCheck` v2）、答案与解题文本、错题名称（均仅本人可见） | ✅ 勾「文本」 |
| 视频 / 音频 / 其他 | 无 | ❌ 不勾 |

> 知识库文章（`knowledge_articles`）虽属文本 UGC，但**写入被 `requireAdmin` 锁死**，普通用户产不出，
> 因此不构成面向用户的 UGC 面。

**建议勾法（逐项）**：

| 字段 | 选择 | 理由 |
|---|---|---|
| 用户生成内容 | **包含** | 确实有图片与文本产出。选「不包含」= 声明失实，审核对照代码必挂 |
| UGC 场景 | **用户资料 + 图片 + 文本** | 视频/音频零调用，勾了反而要解释 |
| 内容安全机制 | **只勾「使用平台建议的内容安全API」** | 文本确实已接 `security.msgSecCheck`（v2）。另三个不勾：没接第三方审核产品、没人工审核团队、「未做审核把关」等于自认裸奔 |
| 审核机制说明（≤256 字） | 见下方可粘贴文案 | 声明必须"逐一、如实"，范围要写清，不能只说"已接入" |

**可直接粘贴的说明文案**：

> 本小程序无公开发布、评论、分享或他人可见入口，用户内容均为本人私密数据。①文本：用户向助手提问前调用微信 security.msgSecCheck(v2) 检测，命中违规直接拒绝入库；②图片：仅用于本人错题识别与存档，不对外展示、不进任何公开列表；③用户资料：昵称由用户自行填写，仅本人界面可见。未接入第三方审核产品，未设人工审核团队。

**诚实边界（必须知道，别当成已完全覆盖）**：

- 真正送检的只有**AI 助手提问**这一条文本链路。**答案/解题文本、错题名称没有送检**——它们只入本人库、
  无任何外显或被他人检索的路径，风险面极小，但严格说与"文本已全覆盖"不是一回事。
- **图片未送检**（`mediaCheckAsync` 未接入）。本项目图片是学习材料 + 仅在本人空间，且不上传公开展示。
- 若审核追问，两条补强路径（择一即可）：① 把答案/错题文本也接 `msgSecCheck`（复用现成 `ContentCheckService`，
  改动半天）；② 接 `mediaCheckAsync` 图片异步检测（需可公网访问的图片 URL，改动 1-2 天，本项目图片在 Supabase
  私有 bucket，需临时签名 URL，成本较高）。
- 已登记为可选技术债：`R-合规-03`（见 GK-OPS-18）。

| 2 | **设置 → 基本设置**里可编辑的对外展示信息（客服/联系信息一类字段，字段名随后台版本略有差异），填一个长期可用的邮箱或手机号。⚠️ 若该处也提示受托管限制，就只保留「你的权益」那一处（用户能在法律文本页看到它） |
| 3 | 真机 `··· → 更多资料` 页确认能看到（该页展示主体名称、服务类目、备案号、联系方式） |
| 4 | 隐私政策第 10 节与用户协议末尾都指向「更多资料」页 ⇒ 这里留空，两份法律文本就成了虚假指引 |

**⑤ 顺带一起做（同属「设置 → 功能设置」）**

- **UGC 信息安全声明**（§3.2）：本项目必须填，且和代码审核是两条独立前置，漏一条都会被驳回。
  入口在「**设置 → 功能设置**」，属设置区（非开发管理权限集），托管状态下通常仍可编辑；
  **若该入口同样被托管挡住**，则与隐私指引一并交托管方按 `setprivacysetting` 之外的管理接口代配，或临时走 `GK-QA-16` 4.5.12 取消授权再配。
- **订单中心 path**（本次新问）：本项目**无支付、无订单** ⇒ 不需要设置，弹窗直接关掉即可（依据见 §3.4）。

### 3.4 小程序订单中心 Path：本项目**不需要填**

**这是什么**：微信自 2022-12-31 起要求——**有「选购商品/服务 → 下单 → 支付」功能的小程序**，必须在小程序内设置订单中心页，并把该页 path 同步给平台（用户在微信「订单」入口能直接跳到你的订单列表）。设置位置两处：**设置 → 服务内容声明 → 小程序订单中心 path 设置**，或提审环节的信息填写页。

**本项目判定：不涉及。** 依据是本项目没有任何交易面——

| 判据 | 本项目 |
|---|---|
| 有下单/支付 | ❌ 无（无微信支付、无会员购买、无余额充值） |
| 有商品/服务售卖 | ❌ 无（用户协议明示「无课程、无付费、无直播」） |
| 开通实物电商发货管理 | ❌ 无 |

**所以**：弹窗直接关掉（点「取消」），不填路径。空着不影响提审——规则只对有交易的小程序生效。

⚠️ **别为了"把表单填满"而编一个路径**：网上教程给的兜底值 `/pages/order/index/index` 只是示例，前提是**该页面真实存在**。本项目没有订单页，填了会在审核时被判"页面不存在/路径无效"，比不填更糟。

**什么时候要回来填**：只有将来接微信支付、卖会员或课程时才需要。届时按官方口径——未开余额/会员填 `/pages/order/index/index`；开了则填账单中心路径并在「我的」页加「账单中心」入口。
