## 1. 结论摘要

1. **前后对照协议已固化为可复测算子**：`server/scripts/measure-baseline.sql`（纯 SELECT，3 行 JSON）。实施前后必须用**同一份文件、同一环境、同一口径**复测，否则对照作废。
2. **J1（题目归一/去重）有真实空间，但不能叫「30% 重复题」**：全库 656,898 行归一后仅 454,333 个不同题干，冗余 **202,564 行（30.84%）**；然而最大重复组是 `"10"`（1,273 行）、`"15"`（961）、`"2"`（951）等**纯题号数字**。排除短题干后，≥30 字的完整题干仍有 **124,088 / 502,145 = 24.71%** 冗余 ⇒ 确有空间，但成因（跨文档重复／同模板／切题把题号当题干）**未定性**。
3. **J2（反馈闭环）实证修正了上一轮口述建议**：埋点**早已实现**（`timeline.service.ts:1018`），生产 `dist` 也含该代码（构建 2026-11-04），近 7 天写入失败日志 **0 条**，`review_events` 仍 **0 行**。⇒ 缺的不是埋点，是**出数条件**；而 `timeline_items` 625 / `questions` 45 说明分母存在。测试期禁真登录、正式版未发 ⇒ **本提案不把「出数」写成可交付项**。
4. **J3 呈现降级、J4 图形表征为保持项**：契约 sha 前后一致即达标（不改动验证）；图形覆盖率沿用 D-035 实测（整题快照 31,685 张 / 620 份、内联图 273,037 张、`.doc` 侧 0）。
5. 🔴 **唯一够格的结果指标仍是 `0021 review_events` 的到期首次作答正确率（每档 ≥30 样本），当前 0 行**。本报告全部指标均为**代理/诊断指标**，按 20a §5.5 三条纪律**不得作为成功证据**。

## 2. 前后对照协议 v1.0（七条纪律）

| # | 纪律 | 具体约束 |
|---|---|---|
| **P1 同口径** | 同一份 `measure-baseline.sql`、同一 L3 环境、相近时间段、同一份 `gk-d033-baseline.sql` 数据门 | 禁换 SQL／seed／样本／时间段；`normalizeForMatch()` 镜像口径固定为「只保留 汉字 / A-Za-z / 0-9」 |
| **P2 事前注册** | 指标、判据、falsifier、样本在**实施前**写死 | 禁止事后改阈值再验收（D-034 同型错误） |
| **P3 配对差分** | 涉及量测对照时同题同轮配对 | 不用「中位数之差」（D-030 双峰下会算出负耗时） |
| **P4 指标分级** | 结果指标 / 代理指标 / 不变量严格分列 | 代理指标不得作成功证据；不计算召回率/准确率 |
| **P5 样本分离** | 调参样本与独立盲测样本物理分离 | 禁止复用 D-034 的 40 条／20 份样本既调阈值又验收 |
| **P6 不外推** | 方向性证据不外推全库 | 不宣称命中提升／误判归零／修复有效／所有用户可用 |
| **P7 零回归** | 判定层/契约 sha、`CACHE_VERSION=v14`、数据门 14 项、M42 v3 前后一致 | 任一漂移即判对照无效 |

**falsifier（逐条过，任一命中即作废）**：重复率下降但 `review_events` 仍 0 行却称「检索变准」；换了 SQL/seed/环境；同批样本调阈值又验收；埋点外发未成年人数据；把行业「命中率」当「误判归零」；改 `question-match.ts` 未先过三问＋M 系列准则＋建档；契约 sha 变化却称零改动。

### 3.2 分层敏感性（避免把短题干噪声读成「重复题」）

| 归一长度门槛 | 行数 | 不同题干 | 冗余行 | 冗余率 |
|---|---|---|---|---|
| 全部（`>0`） | 656,898 | 454,333 | 202,564 | **30.84%** |
| ≥10 字 | 589,746 | 439,580 | 150,166 | **25.46%** |
| ≥20 字 | 549,665 | 412,071 | 137,594 | **25.03%** |
| ≥30 字 | 502,145 | 378,057 | 124,088 | **24.71%** |

**Top 5 重复组**（全部是纯数字、长度 1–2）：`"10"`×1273、`"15"`×961、`"2"`×951、`"12"`×920、`"3"`×899 ⇒ **题号被切成了题干**，属切题链路质量缺口，不是「同一道题重复收录」。

🔴 **解读边界**：24.71% 是「≥30 字题干归一后字面相同」的比例，**不等于「24.71% 是重复题」**。成因可能是跨文档/跨匿名号重复收录、同模板题干、或切题错位；本轮**未定性**，也不删除任何行、不回写题干。`users` 80 行中 79 匿名＋1 正式，528 道题挂 29 个匿名号是联调数据（既有红线），重复率与之相关但不能据此归因。

## 5. 两处实证修正（相对上一轮口述）

1. **「补 `review_events` 埋点」→ 改为「定性 0 行成因」**：埋点代码与生产 `dist` 均已在、无写入失败日志 ⇒ 缺的是出数条件，不是代码。出数受真实使用与发布状态约束，**不是纯工程可交付项**。
2. **「库里 30% 重复」→ 改为「归一后字面相同 30.84%，含题号噪声」**：Top 组全是 1–2 位纯数字；排除短题干后仍 24.71%，有空间但成因未定性，**不宣称「重复题」、不计算去重收益**。

## 7. 边界与不宣称

- 「冗余」＝归一后字面相同，**不等于同一道题重复收录**；成因未定性，本轮不删除、不合并、不回写。
- `no_han 70,220` 是「纯英文/纯数字空 anchors」的**代理上界**，非 `extractDistinctive()` 精确判定结果。
- `login_tickets` 命中 query/log 正则属**名称误命中**，不计入日志表。
- 不计算召回率/准确率、不外推全库、不宣称命中提升／误判归零／修复有效／图形全覆盖／题题有图／所有用户可用。
- 行业公开数字（命中率 98%、32 亿题库等）为宣传口径且指标口径混乱，**不作精度证据**；三家排序特征、阈值、模型版本均不公开。
- 双减监管：提供「拍照搜题」的作业 App 2021 年被要求暂时下线、整改并经省级教育行政部门审核后恢复备案 ⇒ 产品形态不可照搬。
- 本轮**零生产写入**：两个 unit 纯 `SELECT`；`question-match.ts` / `question-reference.ts` / `answer-search.service.ts` / 任何 `doc-inline-*` / `netdisk-*` 脚本一行未动；M42 仍 v3；`CACHE_VERSION` 仍 v14；`health=200`、`gk-api active`。
