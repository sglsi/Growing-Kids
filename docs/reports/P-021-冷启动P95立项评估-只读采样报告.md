### 3.3 形态观察（不构成归因）

## 4. 只读 EXPLAIN（候选池耗时构成）

在生产 `gk` 库执行（只读），`user_id=cc6d7b10-…`（`question_objects` 全部 656,650 行归此号）：

| 查询 | 实测 | 计划要点 |
|---|---|---|
| 通道 B：`text_flat ilike '%平行四边形%' or '%面积最大值%'`，`text_status='ok'`，`limit 2000` | **490.136 ms** | `Bitmap Index Scan` 走 `netdisk_files_text_flat_trgm_idx`（2.3+4.3ms）→ `Bitmap Heap Scan` 回表 **488.8ms**、1133 行；`Buffers: shared hit=6514 read=553`；排序 489.9ms |
| 题对象按源：`question_objects where source_id=… order by object_index limit 100` | **4.343 ms** | `Index Scan using question_objects_src_idx`，0 行；`Buffers: shared hit=1137` |
| 索引清单 | — | `netdisk_files` 有 `text_flat_trgm_idx`；`question_objects` 有 `src_idx` / `src_obj_idx` / `fp_idx` / `engine_idx` / pkey |

**推论边界**：DB 两段合计约 0.5s，只解释了 3.4s 中的一小部分；其余约 2.9s 可能在 PostgREST 传输大字段、深挖 8 份的网盘下载、判定层扫描或附件装配 —— **本提案不猜**，列为阶段 B 分段计时的目标。另：题对象按源查询 4.3ms 说明**该路径未随行数翻倍而变慢**，因此「长尾＝切题造成」缺乏证据。
