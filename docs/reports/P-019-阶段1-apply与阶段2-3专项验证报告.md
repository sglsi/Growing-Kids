## 4. 🔴 阶段 3 文字流坐标系专项验证 — **不通过，抠图不放行**

### 4.1 验的是什么

`netdisk-inline-crop.py::parse_docx()` 在每张 `w:drawing`/`w:object` 前插入 `\x01F<n>\x02` 标记，切出 `plain` 文字流与 `pos`（即 `char_start` 偏移）；而 `text_content` 来自 `pdf_tool.py::extract_docx()`（含 `header*/footer*`）。若两者不是同一文字流，`char_offset` 打到 `text_content` 上会**静默错位**。本轮直接 import 两个真相源逐字比对（不做复刻、不做推断）。

### 4.2 实测（24 份全部成功出数，`probe_errors=0`）

| 指标 | 结果 |
|---|---|
| `identical`（A 与 B 逐字相同） | **3 / 24** |
| `a_startswith_b`（B 是 A 的前缀） | **10 / 24** |
| `all_offsets_safe`（全部 mark 偏移落在公共前缀内） | **10 / 24** |
| 其中**平凡假阳性**（`max_offset=0` 空文本流，判据恒真） | **2**（i=20/22，均为 scan 层，`b_len=0` 且上下文 100% 不符） |
| 有效非平凡样本（`max_offset>0`） | **22 份：safe 8 / unsafe 14** |
| 有效正文（`b_len≥200`） | **20 份：safe 8、identical 3** |
| 有页眉页脚 | 19 / 24；`marks_total=4782`；上下文比对不符 **42 处** |

### 4.3 根因（有逐字铁证，不是推测）

**`\x01F<n>\x02` 标记打断了连续空白/换行序列，使 `_finish()` 的折叠结果与 `extract_docx` 不同**，错位随图数量累积：

| 样本 | crop 流 `b`（char_start 坐标系） | `extract_docx` 流 `a`（= text_content） |
|---|---|---|
| i=0 | `·福建漳州中考）B\n\n\n（2015·山东` | `·福建漳州中考）B\n\n（2015·山东德` |
| i=5 | `A．A地 B．C地␣␣C．E地 D．B地` | `A．A地 B．C地␣C．E地 D．B地\n` |
| i=10 | `6课 北宋的政治\n\n\n一、知识与技能` | `6课 北宋的政治\n\n一、知识与技能` |
| i=13 | `…正确的是` + 9 个 `\n` + `11` | `…正确的是` + 2 个 `\n` + `114300108` |

- **第一类**：`re.sub(r"\n{3,}", "\n\n")` 与 `re.sub(r"[ \t\u3000]+", " ")` 在 crop 侧被标记隔开而少折叠 ⇒ `plain` 多出空白字符（i=0 的 `b_len=43717 > a_len=43630`）。
- **第二类**：`extract_docx` 把页眉页脚**追加在 document 之后**，本身安全（B 是 A 的前缀），但叠加第一类后公共前缀也会提前断掉（i=1 `common_prefix=569` / `b_len=13350`）。
- 这**不是 `.doc` 转换引起**，是 P-018 两个工具的固有实现差异；docx 原件上同样存在，P-018 靠「`norm()` 锚点重定位 + 定位不到不入库不下发 + 越界丢弃」护栏兜住，而非逐字流对齐。
- ⚠️ **判据漏洞**：`all_offsets_safe = common_prefix >= max_offset` 在 `max_offset=0` 时恒真 ⇒ 2 份空文本流被误记为「通过」，实际它们的 `char_start` 全部会落到页眉页脚文字上。

### 4.4 结论与处置

🔴 **阶段 3 硬门不通过**：24 份中最多 8 份（有效非平凡样本 8/22）坐标系可用，**14 份明确错位**。若直接复用 P-018 抠图链路把 `char_offset` 打到 `text_content`，会造成大范围静默错位 ⇒ **本轮不做任何阶段 3 抠图实现、不写 `question_inline_figures`、不下发图**。

可选的修法方向（**均需二次评审，本提案不预授权、不实现**）：
1. 阶段 3 改用 `parse_docx` 的 `plain` 流作为题目文本来源（改变文字流口径，需重评阶段 2 切题）；
2. 改 `parse_docx`：先在**不含标记**的 XML 上算出与 `extract_docx` 一致的流，再按图在 XML 中的位置换算偏移（不再靠标记占位）；
3. 沿用 P-018 的模糊锚点重定位，但须在 `.doc` 转换产物上重新实测定位成功率，并保持「定位不到不入库不下发」。
4. 坐标系判据须补 `b_len>0 && max_offset>0` 前置，排除平凡假阳性。
