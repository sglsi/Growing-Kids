## 2. 第二项：保持备案信息真实有效（必须）

这一项不是一次性动作，是持续义务。腾讯云/管局会做「专项核查」（截图里那个链接），核查不通过会被责令整改，严重的注销备案号。

### 2.1 四条硬约束（对本项目逐条对照）

| 约束 | 本项目现状 | 动作 |
|---|---|---|
| 域名必须解析到**腾讯云**服务器 | `deep-root.cn` / `www` → `42.192.36.120`（腾讯云轻量 L3）✅ | 别把域名解析改到别家 |
| 网站必须**可公开访问** | `http://deep-root.cn/` → **308 跳 https** → `https://deep-root.cn/` 200 ✅ | 别关 80/443 端口、别加访问口令。⚠️ 见下方「关于 308 跳转」 |
| 网站**名称**必须与备案填写的一致 | 首页 `<title>深度扎根</title>`（2026-11-05 统一） | ✅ **已核对**：备案「服务名称(网站)」= **深度扎根**。此前首页写「学习记录」，属站名不一致，已改（见 §1.4） |
| 网站**内容**必须与备案的服务内容一致 | 首页：「由人工智能协助创建的学习工具使用网站」（2026-11-12 调整主旨/副标题，站名与功能说明未变） | ✅ **已核对**：备案「服务内容」= **其他**，未涉前置审批类目 |

#### 关于 308 跳转（2026-11-04 启用 HTTPS 后新增）

11:11 起 `http://deep-root.cn/` 返回 **308 → `https://deep-root.cn/`**（Caddy 的自动 HTTP→HTTPS 跳转，浏览器/爬虫会自动跟随）。这是全行业通行做法，核查不受影响。

⚠️ **唯一例外**：若公安备案退回的理由写着「网站无法访问 / 未检测到备案号」，那就说明对方的抓取程序**不跟随跳转**。此时让 80 端口直接吐出 200 正文即可：

```caddyfile
# 在 Caddyfile 顶部全局块加一行（关闭自动跳转，http 与 https 并存）
{
	auto_https disable_redirects
}
```
```bash
sudo systemctl reload caddy
curl -sI http://deep-root.cn/ | head -3     # 期望变成 200，且仍能 grep 到备案号
```

改完记得把这条偏离写回本文档——**它会让站点同时开着明文 HTTP**，属于为过审做的临时让步，不要长期留着。

### 2.2 三个必须记住的红线

🔴 **L3 轻量服务器到期 ⇒ 备案失效。** 备案是绑在接入商（腾讯云）和这台服务器上的。到期不续费，腾讯云会取消接入，备案号随之被注销。续费提醒要提前设。

🔴 **备案信息变了必须 30 日内做变更备案。** 域名增减、主体信息变更、网站服务内容变更都算。不主动变更，被核查出来同样整改。

🔴 **首页文案禁出现「教育 / 培训 / 课程 / 辅导」。** 个人主体办不了前置审批（《互联网信息服务管理办法》第五条把教育列入前置审批范围），文案一旦被认定涉教育，不是慢，是备案会被撤。当前首页沿用「学习工具 / 学习内容整理」口径（2026-11-12 主旨改为「由人工智能协助创建的学习工具使用网站」后仍不涉前置审批类目），**以后改首页别破坏这条**。

## 5. 备案之后紧接着要做的两件事（不在本次备案范围，但会卡上线）

### 5.1 给 `deep-root.cn` 配 HTTPS

现状：Caddy 只有 `:80` 站点块，**443 未监听**，`https://deep-root.cn` 连不上（实测 `000`）。

为什么必须做：

- 微信小程序的「服务器域名」白名单**只收 https 域名**，`http://` 与 IP 都填不进去 ⇒ 正式版无法上线
- 备案核查走 http 没问题，但审核员/用户手动输 https 会打不开，观感差且可能被判「服务不可用」

做法（Caddy 自动签发，域名已备案 + 已解析，可直接申请）：

```caddyfile
deep-root.cn, www.deep-root.cn {
    encode gzip
    handle /api/* { reverse_proxy 127.0.0.1:3000 }
    handle { root * /srv/www
             file_server }
    header { X-Content-Type-Options nosniff
             X-Frame-Options SAMEORIGIN
             Referrer-Policy strict-origin-when-cross-origin }
}
```

## 7. 备案之后：能不能开放给别人用、加功能要付什么代价

> 2026-11-05 补。起因：思傅问「首页只有文字、没实现功能，为什么要限制成仅供个人及家人使用？是只有教育这样还是所有领域都这样？以后加注册/评论/社区/交易会有什么影响？」
> ⚠️ 本节是**决策依据**，不是法律意见；具体口径以工信部、属地通信管理局、属地公安网安部门与微信平台的最新公示为准。

### 7.1 一句话结论

**「限制」不是教育专属，是「个人主体」通用规则；教育只是在那之上再叠一道前置审批。**
个人备案 = 非经营性 = 不能收费、不能广告、不能做公开互动；想开放给不特定公众使用并承载互动/交易，**必须换主体**，不是改文案能绕过去的。

### 7.2 法律依据（《互联网信息服务管理办法》国务院令 292 号）

| 条款 | 原文要点 | 对本项目的含义 |
|---|---|---|
| 第三条、第四条 | 经营性=**有偿**提供信息/网页制作（许可制）；非经营性=**无偿**提供公开共享信息（备案制） | 个人主体只能走非经营性 ⇒ **不能收费、会员、广告、电商** |
| **第五条** | 新闻、出版、**教育**、医疗保健、药品和医疗器械等，须经有关主管部门审核同意 | 这类**前置审批**个人拿不到 ⇒ 个人做不了该类目信息服务 |
| **第九条** | 拟开办**电子公告服务**的，须专项申请或专项备案 | 论坛/评论/留言板这类，个人**无法**取得 ⇒ 对个人是关死的 |
| 第十一条 | **不得超出备案项目**提供服务；变更服务项目、网址等，应**提前 30 日**办理变更 | 加了功能不报备 = 超范围 |
| 第十二条 | 主页显著位置标明备案编号 | 已做（§1） |
| 第十四条 | 记录信息内容、时间、IP/域名，备份保存 **60 日** | 一旦有 UGC，这条就落到你头上 |
| 第十九条 | 超范围 ⇒ 责令限期改正，**拒不改正责令关闭网站** | |
| 第二十二条 | 未标明备案编号 ⇒ 改正，并处 **5000~5 万**罚款 | |
| 第十九条（经营性） | 无证经营性 ⇒ 没收违法所得，处违法所得 **3~5 倍**；无/不足 5 万 ⇒ **10 万~100 万**，情节严重关闭网站 | |

### 7.3 个人备案网站的「安全区」与「禁区」

| 可以（非经营性、个人性质） | 不可以 |
|---|---|
| 个人博客 / 技术笔记 / 作品集 / 简历 | 论坛、社区、评论、留言板、私信、用户互评 |
| 家庭相册 / 个人生活记录 | 电商、付费、会员、打赏、广告变现、平台撮合 |
| **纯工具**（记录、计算、查询、归档） | 新闻、出版、视听、游戏、医疗、金融等前置审批类目 |
| 单向展示，用户只看不互动 | 用户自行上传内容并**公开展示** |

### 7.4 功能变更要付什么代价（逐项对照）

| 想加的功能 | ICP 备案 | 公安联网备案 | 真正的拦路虎 |
|---|---|---|---|
| 开放注册（有账号体系） | 要变更（服务内容） | 要变更：**非交互式 → 交互式**，需**面审或实地检查** | 个人信息保护义务（PIPL）：告知同意、最小必要、泄露报告 |
| 评论 / 留言板 / 社区 / 论坛 | 要变更 | 同上（交互式 + 面审） | **电子公告专项审批**（292 号令第九条）+ 微信「社交-社区/论坛」类目，**个人 100% 不可** |
| 交易 / 付费 / 会员 / 充值 | 要变更（可能转经营性） | 要变更 | **经营性 ICP 许可证**（需企业主体）+ 微信支付（个人主体开不了） |
| 发布面向公众的内容 | 要变更 | 要变更 | 内容审核责任、日志留存 **60 日**、违法信息 **24 小时内**报告 |
| 仅加静态页面 / 文案 / 图片 | 一般不必 | 一般不必 | 只要不改「服务内容大类」即可（判据是**是否触及备案登记要素**） |

> 判据一句话：**看是否触及备案登记要素**（主体、服务内容大类、负责人、接入商、域名），而不是改了多少行文案。

### 7.5 微信小程序侧的边界（个人主体）

个人主体**不能选**的类目：社交-社区/论坛、社交-笔记（UGC 记录与分享）、电商、直播、游戏（需版号）、医疗、金融，以及教育下的**在线教育 / 培训机构 / 学校 / 在线视频课程**（微信官方指引对这几项标注「个人备案：不建议选择」）。

个人主体**可以选**的类目（2026 年口径，具体以平台最新公示为准）：
- **工具** → 备忘录 / 办公 / 计算器 / 信息查询 / 健康管理 / 预约报名 / 记账 / 日历
- **教育 → 教育信息展示**（免资质，只做内容展示；**不含**视频播放、直播、课程销售）

🔴 **交互边界（最容易误判的一条）**：
- ✅ **可以做**「单向反馈」：客服消息、仅管理员/开发者可见的反馈表单、只读自己数据的记录。
- ❌ **不能做**「双向公开互动」：公开评论区、留言板、问答社区、用户互评、点赞回复、私信、用户动态公开展示。

所以「意见与建议」这件事，**放小程序里合规、放网站上就不合规**：网站首页一旦出现提交表单，就从「非交互式」变成「交互式」，公安备案要走面审/实地检查。已于 2026-11-05 在小程序内以**原生客服**实现（见 §7.7 第 3 条），网站首页只写「通过小程序反馈」。

### 7.6 三条主体路径对比

| 路径 | 认证成本 | 微信支付 | 类目 | 适合 |
|---|---|---|---|---|
| **A 个人**（现状） | 0 / 30 元认证 | ❌ 开不了 | 工具、教育信息展示 | 免费工具、不收费、无社交 |
| **B 个体工商户** | 认证 **30 元/年** | ✅ 可开（费率约 0.6%） | 可到电商 / 餐饮 / 教育（**教育仍需资质**） | 想收费、想正经做服务，性价比最高 |
| **C 公司** | 高（记账报税、对公） | ✅ | 全类目（医疗 / 社交等仍需资质） | 团队化、复杂功能 |

### 7.7 本项目的当前口径与「以后免费开放」怎么做

**现状（2026-11-05）**：小程序**未提审、未发布正式版**；网站备案已通过（`-2`）。

**已定的方向（思傅 2026-11-05 确认）**：工具做好后可以让其他用户**免费使用**、**不做双向交互**、**只保留意见与建议**。

按这个方向，正确做法是：

1. **首页文案**已从「仅供本人及家人使用」改为「个人开发和维护的小工具，目前处于自用与内部测试阶段，尚未公开提供使用」，并保留「不设付费项目、不投放广告」。
   - 好处：现在真实（未发布），将来免费开放**不用再改口径**，也不会被认定为「面向公众提供经营性服务」。
2. **网站首页永远保持非交互式**：不加注册/登录、不加提交表单、不加统计脚本。意见与建议只写「请通过小程序内反馈入口提交」。⚠️ **2026-11-12 现状更新**：按思傅指示首页已去除小程序相关表述，**不再展示「意见与建议」段落**，首页也不出现任何反馈入口；非交互式约束本身不变。
3. **意见与建议落在小程序内**——**已于 2026-11-05 实现**：原生客服按钮（`open-type="contact"`，位置「我的 → 意见与建议」），消息承载在微信客服会话里、**不写入我们的数据库**，只有开发者能看到，不需要「社交-社区/论坛」类目。**刻意没做自建表单**：零后端改动、不新增第三方、不新增数据落库。⚠️ 两个前提：mp 后台「功能 → 客服」须配好客服人员；`contact` **只在真机生效**，开发者工具里点不动（别拿模拟器判故障）。详见 `GK-QA-16` §4.5.20。
4. **小程序类目**建议 `工具 → 备忘录`（主）+ 如审核要求再补 `教育 → 教育信息展示`；⛔ 不要选在线教育 / 培训机构 / 学校。
5. **一旦决定收费或做社区**，先换主体（个体户优先），**不要**先上线再补——个人主体下「先低调上线、以后再开放」这条路走不通，变更之后也批不下来。
