### 建议 2.1：形态学背景估计 —— SE 自适应 + 多尺度 + 边缘保护

**结论：⚠️ 修正后采纳。其中有一处**算子极性错误**、一处**尺寸基准错误**，必须纠正**

#### ❌ 硬伤 1：算子用反了

评审伪代码写的是：

```typescript
const background = morphOpen(image, disk(seRadius));  // ← 错误
```

对**暗字亮底**的文档（本项目全部场景：黑字白纸），估计背景必须用 **闭运算 closing**，不是开运算 opening：

- `opening`（先腐蚀后膨胀）→ 去除**亮**的小特征
- `closing`（先膨胀后腐蚀）→ 去除**暗**的小特征 → 才能把黑字填掉、得到背景

领域依据（Pandore 光照校正教程）明确：

> "Black top hat is used for **clear background**… `g = [f − closing(f)] + mean(closing(f))`"

即亮底暗字用 **closing** 估背景。若按评审的 `morphOpen`，背景估计里会残留文字，后续相减会把字一起削掉，适得其反。

> 📌 连带修正我原方案：原文档写"大结构元**开**运算滤掉文字"同样不严谨，一并改为**按极性选择**：暗字亮底 → closing；亮字暗底 → opening。

#### ❌ 硬伤 2：SE 尺寸基准错了

评审建议：`笔画宽度 ≈ 字符高度 / 8~12，SE 半径 = 笔画宽度 × 2~3`

**这会严重偏小，导致背景估计失败。** 闭运算要"填掉"一个字符，结构元必须**大于字符的整体尺寸（字高/词宽）**，而不是笔画宽度。

反例：字高 40px → 笔画宽约 4px → 评审公式给 SE 半径 8~12px（直径 16~24px）。一个 40px 高的字符**远高于** 24px 直径的结构元，闭运算根本填不满它 → 背景里残留字符轮廓 → 相减后文字被削薄、出现空洞。

**正确基准**：`SE 尺寸 ≈ 1.5~3 × 字符高度`（或与行高同量级，取 `max(字高×1.5, 行间距)`）。工程上用**大半径模糊/大核中值**近似背景是等价且更廉价的替代。

#### ❓ 不采纳：边缘 1px 膨胀保护

背景相减本身不会"吃边"，额外膨胀反而引入伪影与笔画粘连。不采纳。

#### ✅ 采纳：多尺度融合思路

"小字小 SE、大字大 SE 取 min" 的想法有价值，但应基于**字高**而非笔画宽度重构（`min` 保最细笔画，方向正确）。

### 建议 2.2：Sauvola —— 积分图加速 + 行感知窗口 + 软映射

**结论：✅ 采纳（这是本次评审最有价值的工程补充）**

| 子项 | 评估 |
|---|---|
| **积分图 O(1) 求局部均值/方差** | ✅ 强采纳。Sauvola 逐像素滑窗是 O(win²)，窗口 50 时在 Node 单线程下不可接受；积分图是标准解法 |
| 行感知窗口 `win = 行高 × 2~3` | ✅ 采纳（思路对）。注意区分**行高**（含行间距）与**字高**：建议以 `2~3 × 字高` 为准，用行高会偏大 |
| 软映射（sigmoid 拉伸）优先 | ✅ 与我原方案一致，评审的强调是对的 |

---

### 建议 2.3：超分升级用 TextSR + Real-ESRGAN 混合，复用 `handwriting-segmenter` 做文字 mask

**结论：❌ 不采纳（至少不按此路径优先推进）。四条理由：**

1. **成本严重错配**：`handwriting-segmenter` 的主入口是 `segmentByVlm()` —— **每张图要调用一次 VLM 视觉大模型**。拿它给超分做文字 mask，等于为一次增强额外付一次大模型推理 + 网络往返，完全不经济。
2. **语义不匹配**：它分割的是**手写**区域；我们要的是**印刷文字** mask。两者不是一回事（手写恰恰是常被"去手写"删掉的部分）。
3. **接缝伪影**：双模型分区域输出，mask 边界必然出现不连续的纹理/锐度跳变，必须做羽化或多尺度融合，工程复杂度显著上升。
4. **算力翻倍**：单核 CPU 虚机上跑两个超分模型，耗时翻倍，与已有的 `sr-gate` 限流直接冲突。

**替代方案**：P2 **只选一个模型**——文档/文字场景优先文本专用（TSRN / TATT）；若更看重通用性则 Real-ESRGAN-tiny。区域混合降级为"未来可选探索"，不作为 P2 目标。

> 📌 附带纠正：评审把 **TextZoom** 列为模型，TextZoom 是**数据集**（真实 LR-HR 文本对）；**TATT**（Text Attention，AAAI 2022）才是模型名。

### 建议 2.4：自适应锐化（sigma = 笔画宽度/2 + Canny 边缘保护 + 多尺度）

**结论：⚠️ 部分采纳**

| 子项 | 评估 |
|---|---|
| `sigma ≈ 笔画宽度 / 2` | ✅ 采纳。USM 的 sigma 应与待增强特征尺度相当，笔画宽度是合理锚点（可作为起点，实测微调） |
| Canny 边缘检测门控锐化 | ⚠️ 采纳**思路**，但 Canny 偏重。用**局部梯度幅值**做软门控更廉价、更平滑，也避免 Canny 双阈值调参 |
| 多尺度锐化（sigma 1px + 3px） | ⚠️ 谨慎采纳。有效但**光晕（halo）风险叠加**，需限制总 amount 并做 A/B 验证 |

### 建议 3.1：评估指标改用 NIQE / BRISQUE，边缘陡峭度作 OCR 代理

**结论：⚠️ 部分采纳，但 NIQE/BRISQUE 这条**不成立**，是本次评审最大的方法论问题**

#### ❌ NIQE / BRISQUE 不适用于文档图像

两者都是**自然场景统计（NSS）**无参考质量指标，训练/标定于**自然照片**（纹理丰富、色彩连续）。而文档图像是极端非自然的分布：**大片纯白背景 + 稀疏黑色笔画**。

后果：一张**完美的干净文档**（纯白底 + 清晰黑字）会被 NIQE 判为**低质量**（因为统计特性严重偏离自然图像）；反之加了噪声/纹理的图反而可能得分更高。**用它做筛选会系统性误导调参方向。**

> 文档领域的无参考/有参考指标另有体系：DIBCO 用 **F-measure / PSNR / NRM / DRD**；本项目更现实的抓手是下面这条。

#### ✅ 边缘陡峭度作 OCR 代理 —— 采纳

廉价、无需标注、且与"清晰"直觉一致。采纳为主观/自动化的快速指标。

#### ⭐ 更好的替代：项目**已有** OCR 一致性能力

评审说"OCR 准确率需要标注数据、成本高"——**在本项目里不成立**。

`server/src/image/image-quality.ts` 已实现 `compareRecognized()` 与 `OCR_CONSISTENCY_THRESHOLD = 0.75`，本就是拿识别结果做一致性比对。因此：

- 可用**增强前后 OCR 结果的一致性/置信度变化**作为任务指标（自比对，无需人工标注 GT）；
- 这比"建立标注样本集"便宜得多，且直接对应用户价值（看得清 = 认得出）。

→ 评估体系定为：**边缘陡峭度（快速筛选） + OCR 一致性（任务指标，复用现有能力） + 主观 A/B（终裁）**。人工标注样本集仍建议建，但仅用于 P3 与关键版本验收，不作为每轮迭代门槛。

### 建议 3.2：性能预算 —— 降采样 1024 + WebAssembly + tile 流式

**结论：⚠️ 修正后采纳。其中"整体降采样"与清晰度目标冲突，"WebAssembly"表述不实**

#### ❌ 不能整体降采样处理

"先降到 1024px → 处理 → 升回原尺寸"对**局部对比增强与锐化**是破坏性的——恰恰削掉了我们要增强的笔画高频细节，与"清晰度"目标直接冲突。

**修正为分阶段差异化**：

| 阶段 | 频率特性 | 是否可降采样 |
|---|---|---|
| 背景/光照归一化 | **低频** | ✅ **可以且应该**降采样（大幅提速，几乎无损） |
| 局部对比增强（Sauvola） | 高频（笔画级） | ❌ **必须原尺度** |
| 锐化 | 高频 | ❌ **必须原尺度** |

#### ⚠️ "WebAssembly 加速 sharp/libvips" 表述不实

sharp 的 libvips 后端是 **C/C++ 原生扩展（node-gyp addon）**，**不是 WebAssembly**。libvips 自身内部已有线程池与 tile 流式处理。表述需纠正，否则会误导技术选型（误以为要引入 WASM 方案）。

#### ✅ tile 流式 —— 采纳，但须注意接缝

分块处理利于控制内存峰值；但局部窗口算子分块必须**带重叠（halo）**，否则块边界出现统计不连续的接缝。这点要写进实现约束。

---

### 建议 4：优先级拆出 P0.5（自适应锐化）

**结论：✅ 采纳**

"锐化与对比增强正交（一个管灰阶间距、一个管边缘陡峭度），且锐化参数需匹配对比增强后的图像"——这个论证成立。接受 P0 → P0.5 → P1 → P2 → P3。

### 建议 5：对接点补充（handwriting-segmenter / image-deskew / image-perspective / sr-gate）

**结论：⚠️ 部分采纳**

| 补充项 | 评估 |
|---|---|
| `sr-gate` 复用控并发 | ✅ **强采纳**，且已核实存在 light/heavy lane。P2 换更重模型时应归 **heavy lane**，这是很实际的对接点 |
| `image-deskew` / `image-perspective` | ⚠️ 二者是几何校正，本就在增强管线的**上游**（自动调正已用）。不算新增对接点，但确认了"先几何、后增强"的顺序正确 |
| `handwriting-segmenter` 做文字 mask | ❌ 不采纳（见建议 2.3：VLM 成本 + 语义是手写） |

## 二、评估结论汇总

| # | 建议 | 结论 |
|---|---|---|
| 1 | 自适应参数（SE/窗口/sigma） | ✅ 采纳（需先扩展 `detectTextRows` 导出字高） |
| 2.1 | 形态学 SE 自适应 | ⚠️ 修正采纳：**closing 非 opening**；**SE 基准是字高非笔画宽** |

| 3.1 | NIQE/BRISQUE 指标 | ❌ **不采纳**（自然图像指标，文档场景失效）；改用**边缘陡峭度 + 已有 OCR 一致性** |

## 三、修订后的方案要点（同步更新至主方案文档）

### 3.1 修订后的优先级

| 优先级 | 内容 | 变更 |
|---|---|---|
| **P0** | 背景归一化（**closing** 闭运算，SE≈1.5~3×字高）+ Sauvola 软对比增强（**积分图加速**，窗口≈2~3×字高）+ 自适应窗口 | 修正算子与 SE 基准；加入积分图 |
| **P0.5** | 自适应锐化（sigma≈笔画宽/2，梯度软门控，防光晕） | 从 P0 拆出 |
| **P1** | 多模式输出（原图 / 增强软映射 / 黑白硬二值化） | 不变 |
| **P2** | 超分升级 —— **单模型**（文本专用 TSRN/TATT 优先），纳入 `sr-gate` 的 **heavy lane** | 去掉区域混合；明确限流对接 |
| **P3** | 场景化自动决策 | 不变 |

### 3.2 新增的前置改造项（落地前必须做）

1. **扩展 `detectTextRows`**（或新增 `estimateCharMetrics`）导出**字高 / 笔画宽度**——自适应参数的唯一数据来源，当前未导出。
2. **背景估计按极性选择算子**：暗字亮底 → `closing`；亮字暗底 → `opening`。

### 3.3 修订后的评估体系

| 层次 | 指标 | 说明 |
|---|---|---|
| 快速筛选 | **文字边缘陡峭度**、局部对比度 Δ（文字 vs 背景灰阶差） | 无需标注，每次迭代可跑 |
| 任务指标 | **OCR 一致性**（复用 `image-quality.ts` 已有的 `compareRecognized`） | ⭐ 无需额外标注，直接对应用户价值 |
| 终裁 | 主观 A/B（文字特写对比图） | 用户判定"像不像修过" |
| ❌ 不用 | NIQE / BRISQUE | 自然图像指标，文档场景失效 |

### 3.4 性能约束（修订）

- 背景/光照归一化阶段：**可降采样**（低频，提速显著）
- 对比增强 / 锐化阶段：**必须原尺度**（高频，降采样即破坏目标）
- 加速手段：**libvips 原生算子**（C/C++ 扩展，非 WASM）；局部统计用**积分图**
- 大图：**tile 分块 + 重叠 halo**，控内存峰值且避免接缝

## 四、仍需你确认的三件事

1. 是否按 **P0 → P0.5 → P1 → P2 → P3** 推进？（我建议先只做 **P0**，出 A/B 对比图确认观感达标后，再决定是否继续 P0.5）
2. "增强"默认强度：偏保守（保真优先）还是偏激进（可读优先）？——建议**默认中等 + 提供强度档位**，且**"黑白"模式单独提供**（避免硬二值化破坏图表/照片）
3. 是否建一个小规模真实样本集（试卷 / 印刷文档 / 手写笔记 × 清晰/模糊/有阴影）？——建议**建，10~20 张即可**，用于 P0 验收与后续回归；日常迭代靠边缘陡峭度 + OCR 一致性即可，不必每次标注
