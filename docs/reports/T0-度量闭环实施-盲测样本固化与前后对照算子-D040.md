## 4. T0-3 · `review_events` 0 行出数条件定性（本轮新证据）

D-036 已排除「缺代码」与「写入报错」：埋点在 `server/src/timeline/timeline.service.ts:1018`、生产 `dist` 含同一特征串（构建 2026-11-04）、近 7 天无写入失败日志。本轮只读实测把三假设往前推了一步：

| 假设 | 本轮读数 | 定性 |
|---|---|---|
| **H_b 路径未触达** | `timeline_items` 625 行／35 个用户有条目；`questions` 45 行／15 个用户；**`ti_ever_reviewed` = 88**（`review_count>0`）；`ti_in_review_book` = 187；`ti_with_due` = **167**、`ti_overdue_now` = **167** | **基本排除**：作答与到期路径是活的，不是「没人用过」 |
| **H_a 无真实到期作答（主因方向）** | `ti_last_reviewed_at` = **2026-10-30 08:37:35+08**；`review_events` 0 行、`review_events_last_event = null` | **部分成立**：最后一次累计作答停在 10-30，此后测试期禁真登录、正式版未发 ⇒ 埋点时间窗内没有新的到期作答进入。⚠️ 但无法区分「埋点在 10-30 前已上线 vs 之后才上线」，**不下定论** |
| **H_c 数据被清空** | `pg_stat_user_tables`：`n_tup_ins=2`、`n_tup_del=2`、`n_live_tup=0` | **仅保留旁证**：说明「见过写入与删除」，2 行更像联调测试；`pg_stat` 可 reset／轮转／被 autovacuum 改写，**不得据此断言人为清空** |
| 真实 query 日志 | `query_like_tables` = `["login_tickets", "review_events"]` | 与 D-036 一致：**仍无真实 query 日志表**（`login_tickets` 是名称误命中） |

🔴 **结论口径**：0 行仍是**出数条件**问题，不是代码缺陷；本轮把「路径未触达」基本排除、把「时间窗内无触发」列为主因方向、「数据清空」保留不可定论旁证。**不承诺出数、不新增 query 采集、不改埋点、不做真登录**；出数受真实使用与发布状态约束，另案拍板（`P-025 Q3①`）。

⚠️ 以上全部是**代理/诊断读数**，按 20a §5.5 不得作为机制有效或检索变准的证据；唯一够格结果指标仍是 `0021` 到期首次作答正确率（每档 ≥30 样本），**当前 0 行**。
