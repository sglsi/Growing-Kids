## 3. 根因分析（诊断模式坐实）

### 3.1 P0：混合词连坐（① ② ③ 三场景误擦的共同根因）

词级判别器假设「词同质」，但实际链路两个环节会把印刷与手写并进**同一个词**：

1. **行切分串行**：质心单链接的 `rowGap≈18-24px`，印刷行与手写行质心间隙仅 18px 时被并进同一行（组 0 / 组 2 差 1~7px 反而分开——切分结果依赖 jitter 的脆弱性本身即缺陷信号）；
2. **词切分拆不开**：手写笔画与文字 x 向交错，词间隙不存在。

后果：混合词特征偏手写 → state=1 → **整词 bbox 内印刷连坐被擦**。诊断 dump 证实：① 场景 mask 印刷命中 2976px 全部来自 1 个混合词；③ 场景 4096px。

### 3.2 P1：微型词噪声地板缺失（⑤ 场景误擦根因）

`nComp=1` 的退化连通域 heightCV 异常（|4−14|/14=0.71）+ 印刷抗锯齿 intensityStd≈0.17 达到 SEP 阈值 → 6px 的印刷抗锯齿碎片被判 state=1。实测最小真实手写词 69px（work 尺度 ~800 长边），印刷碎片 6~24px，之间存在一个数量级的可分空间。

## 4. 修复清单（2 项）

| # | 级别 | 修复 | 文件 | 判据 |
|---|---|---|---|---|
| Fix 1 | **P0** | state=1 词内「印刷字符序列」CC 整组豁免 | `word-level-discriminator.ts` | 单个 CC 满足：bh∈[0.85,1.15]×行字高 **且** bw≥1.9×行字高 **且** 底边贴行基线（\|y1−baseY1\|≤0.4×行字高）；同词内 ≥2 个生效即保护整组（仅从 mask 剔除，不新增，与疑罪从无以向） |
| Fix 2 | **P1** | 微型词噪声地板 | `word-level-discriminator.ts` | work 尺度墨量 `n < WORD_NOISE_N=12` → 直接落 UNCERTAIN（优先于分数门） |

判据出处说明：

- **Fix 1 的印刷字符序列签名**：小字号下相邻印刷字被 `closeInk3x3` 合并成宽 CC（宽而等高、贴基线）；手写 CC 窄或高度发散；纯手写词通不过宽度门。宽度 + 基线双门缺一不可——初版只加高度门时，高度恰等于行字高的宽手写块被误保（① ③ 残笔反升 16pp / 10pp），补基线邻近条件后 FP 消除、残笔回落到修复前水平。
- **Fix 2 的 12px**：实测最小真实手写词 69px vs 印刷碎片 6~24px，取对数区间中值以下。

配套改动：`WordRecord` 加 `compIdx`（组词 CC 序号）、`closeInk3x3` 改 export（探针复现行切分）、debug 加 `rowsDebug` 与 `mixedPrintProtected{words,px}`；`erase-mask-policy.ts` 补 1 行 debug 透传（原只挑特定字段）。

### 5.1 ① 剩余 38.27% 的构成（② 场景，非缺陷口径）

- **2784px 手写紧邻**：手写与印刷间距 ≤10px，属 G16 口径既定豁免（手写压住的印刷不计入误擦）；
- **2722px 纯连坐**：手写直接压在印刷文字上，两者并成**同一个连通域**（同色、笔画宽重叠）。T7 根因报告已实证「黑笔手写与手写体印刷字像素级不可分」，4 组实验证伪了粗细闸门 / print 占比 / 像素级保护（`protectPrintGeneric` 使 G15 擦净 33/44→13/44）；`structuralExtend` 只接线不重建文字。产品决策 T7-①「保持现状」——这是**架构性已知缺口**，阈值 42% 起回归看护作用（修复前 81.33% 的一半）。

### 5.2 ④ 残笔 77.4% 的认定（非缺陷口径）

小手写答案（4 字）自行成行成为行内自身参考（自一致），落在共识门之下 → 疑罪从无保留。这是 v21.5 G16 C2 标定的**既定取舍**（G15 冻结说明载明「宁留手写不误擦印刷」），非缺陷；阈值 85% 看护「不变得更差」。

¹ 阈值按「修复后实测 + 产品门禁口径」复标定，口径说明写入探针文件头。
² ③ ⑤ 同理为复标定期望值（⑤ 0.5% = 修复后实测 0.23% + 一倍余量，仍距 G16 天花板 2.0% 一个数量级）。
