## 0. 结论摘要

1. **它确实推翻了上一轮论证的一个前提，但没有推翻主结论。** 上一轮写「知识点图谱最重，因为要从零建本体 + 给 65.7 万对象打标」——**前半句被证伪**：这里有现成的中文 K12 数学本体（870 个知识点、1,459 条先修边、掌握标准、课标映射），阶段 4 的「建本体」成本应显著下修。**后半句仍成立**：它给不了「真实题目 → 知识点」的打标能力。
2. **推荐路线不变**：`度量先行 → 本地向量语义召回优先 → Reranker 条件性后续 → 知识图谱长期讲解层`。因为当前瓶颈是代码实证的「候选池只有 ≤8 份字面命中文档」（`netdisk-search.service.ts:634/682`），**图谱不是召回算法**，治不了「没看到」。上一轮 Q1–Q4 待拍板不变，本报告不代替。
3. **最有价值的可能不是数据，是它的质量工程方法**：独立盲解协议（解题者看不到 `answer`/`verify`/`explanation`）、自动核验与盲解分开留痕、以及「0 处不一致说明没有发现分歧，不是保证无错」这类诚实声明——与我们 `D-034` 事后拟合教训、`P-025` 独立盲测样本 / 事前注册协议**完全同构**，可直接借用为评估模板。
4. **能直接用的是「本体设计」和「词表」，不是「题库」和「诊断引擎」**。题库是 AI 生成的合成题：纯文字自包含、几乎无图（数学题带 `figure` 仅 73/3,627＝2.0%）、解析中位数 26 字、无证明题；与我们的 OCR 教辅 PDF（图形、公式、题号噪声、`U+FFFD`）分布差异极大，且方向是「知识点 → 生成题」而我们要的是「真实题 → 打标」。
5. **诊断引擎的产品形态不可照搬**：它的核心是「自适应前置诊断 → 找根因 → 学习路径推荐」，正好撞本项目 ⛔ 智能排程 / ZPD、`GK-SRS-20a M10`（不得宣称测量智能水平）与 §5.1 三问。可借数据结构与呈现，不可借算法与推荐。
6. 🔴 **许可为硬约束**：**CC BY-NC 4.0**（署名 + 非商业）。当前项目个人主体、免费、非经营性、未正式发版，大概率落在非商业范围；但「集成进面向家长的产品」与「个人学习/研究」不是一回事，且会锁死未来商业化路径。**是否采用需思傅做法务判断，并在集成前取得作者书面确认**；未确认前只做本地只读研究。
7. **新增一条极低成本过渡项**（供拍板，未实施）：把 870 个数学知识点名导成扩充词表，替换现有 `TOPIC_TERMS` 的 **55** 词。实测 55 词中 **50 词**能在知识点名中命中 ⇒ 语域一致、扩充风险低；但它仍是字面匹配，不解决 OCR 错字/改述，**不能替代向量召回**。

## 2. 主要设计思想

### 2.1 两张表就是一个本体：`topics` + `dependencies`

参考 [Marble os-taxonomy](https://github.com/withmarbleapp/os-taxonomy) 的 `topics` + `dependencies` 二元组，顶层是裸数组，无 `version` / `topicCount` 包装。稳定 id 带学段前缀（`cnm_p` 小学 / `cnm_j`→`cnm_001` 初中 / `cnm_h` 高中；`cne` 英语、`cnc` 语文、`cnp` 物理…）。

节点字段（实测 `topics[0]`）：`id / name / domain / grade / semester / chapter / type / description / mastery_criteria / diagnostic_question / external / standards / root_reason`。
`type` 五分类：`conceptual / procedural / reasoning / application / modeling`；数学 `domain` 四域：数与代数 / 图形与几何 / 统计与概率 / 综合与实践。

### 2.2 是「先修图」不是「分类树」

边格式：`{"topicId":"A","prerequisiteId":"B","strength":"hard|soft","reason":"一句中文理由"}`，语义是「学 A 之前需要 B」。

- `hard`＝不会 B 基本无法学 A；`soft`＝会 B 明显有帮助但非硬门槛。
- **传递约简**：`hard` 边仅在存在另一条全 hard 路径时才删；`soft` 边在存在任何其他路径时即删。⇒ 只留直接先修，避免冗余边。
- **跨学科隔离**：英语/物理/化学各自成图，不与数学连先修边；物理用到的数学写在 `mathLinks` 字段里，**不算先修边**。数学允许跨学段回溯（高中 → 初中 → 小学）。
- 图根唯一：数学 `cnm_p001`（1 到 5 各数的认识），只有根节点必填 `root_reason`。
- 引擎侧有环检测（`先修图存在环`）、拓扑排序、`hardAncestorSet` 与 `ancestorSet` 两种祖先集合（筛查模式只沿 hard 推断掌握，soft 不推断）。

### 2.3 知识点 = 一个「可测单元」

每个节点自带 2–3 条 `mastery_criteria`（掌握标准）、1 道 `diagnostic_question`（题干 + 答案）、以及 `standards` 课标映射（`{id, confidence, note?}`）。实测数学 **870/870** 都有掌握标准与诊断题，**868/870** 有课标映射。⇒ 知识点不是标签，而是「有判据、有样题、有出处」的最小可评估单元。

### 2.4 诊断引擎：答错就沿先修往回找根因

`diagnose/engine.js` 是纯静态、零依赖状态机：

- 状态 `mastered / shaky / weak / unknown`；确认题答对但基础题不稳 ⇒ `shaky`（**不向先修回溯**）；确认题也错 ⇒ `weak`，把其先修按 **hard 优先**压到出题栈顶回溯。
- 结果页拆成「根因 / 不稳 / 学习路径」，找 `roots`＝薄弱点中没有薄弱先修的那些；按年级从低到高 + 拓扑序生成路径。
- 🔴 **值得学的 fail-closed 表述**：「只答错一题就遇到题量上限的点按 weak 算」「先修里还没测到的，此时它未必是真正的根因」「筛查模式下范围之外的先修（不在本次范围内，没有检查）」——不把「没测到」写成「已掌握」，与我们 `answer:''` / `verified:false` / `source='none'` 也渲染卡片是同一类纪律。

### 2.5 质量工程（最值得借鉴的一条）

| 层 | 做法 |
|---|---|
| 格式校验 | `scripts/validate.py`：id 唯一且与 `topicId` 一致、`topicId` 存在、枚举合法、选项不重复、每知识点 ≥3 题且含 basic/standard |
| 自动核验 | `scripts/verify_questions.py`：受限 Python `ast` 白名单求值 `verify` 表达式，与 `answer` 精确/容差比对；输出 `auto_verified / mismatch / unverifiable` |
| **独立盲解** | `scripts/second_pass.py prepare`：把题去掉 `answer`/`explanation`/`verify`/`accept`，**只留题干和选项**分块给独立解题者；解题者只能读自己的块，作者核对过工具调用记录；`compare` 逐题比对，分歧用精确计算裁决。A 轮 19 个解题者 / 1,401 题，B 轮 16 个 / 752 题（风险题） |
| 留痕 | `data/verification_report.json`、`data/second_pass_log.json`、`data/_second_pass/`（原始答案与推导）、`CHANGELOG.md` 按日记录、Issue 纠错通道 |
| **诚实边界** | 原文：「**0 处答案错误说明没有发现分歧，不是保证无错**」「独立复核的解题者与出题者是同一模型家族，如果对某个知识点有共同的误解，这种错误两边都不会暴露」「高中题 `verify` 和答案来自同一条表达式，**不是另一遍独立解题**」 |

⇒ 这套「调参/出题 与 验收 物理分离 + 盲测 + 留痕 + 不宣称」的做法，正是 `P-025` 协议 v1.0 的 P2/P5 与 `D-034`（40 条复核 18 不通过、事后拟合教训）需要的模板。**比数据本身更可直接借用。**

**数据 schema 漂移（实测）**：
- `difficulty` 全库出现 **4 个值**：basic 6,909 / standard 5,415 / **`challenge` 1,364** / **`advanced` 355**；而 `docs/questions.md` 只定义 `basic/standard/advanced`，`challenge` 未在文档中登记。

- README 首页统计表与正文多处数字不一致（小学语文 493/494、初中英语 1,028/980），作者自己在 README 里标注了。

**与现有词表的关系（实测）**：`server/src/shared/question-reference.ts` 的 `TOPIC_TERMS` 共 **55** 个词（上一轮报告初稿写 58，已更正）；其中 **50 个**能在 870 个数学知识点名称中命中（高频：圆 38、三角形 31、方程 30、分数 20、概率 18、不等式 17、面积 15）。⇒ 两者语域高度同源，图谱词表是现有表的自然超集（更细粒度，如「三角形的三边关系」「圆周率」「组合图形的面积」）。

## 4. 可用性评估

| 维度 | 评价 |
|---|---|
| **结构完整性** | ✅ 高。纯 JSON、零外部依赖、字段自解释、有 `validate.py` 可复跑、活跃维护（2026-11-12 仍在提交）、提供 `CHANGELOG` 与纠错通道 |
| **本体质量** | ⚠️ 中。结构严谨（传递约简、跨学科隔离、环检测），但作者**反复声明**：「知识点的拆分粒度、掌握标准、诊断题答案，尤其是**先修关系（哪些是 hard、哪些是 soft，甚至某条边该不该存在）都需要一线教师审核**后才能用于教学、诊断或学习路径推荐」「hard/soft 区分是 AI 的主观判断，未经审核」；课标多处 `verbatim: false`（转述非原文）、`standards` 32% 为 `inferred` |
| **题库质量** | ⚠️ 低（对我们的用途）。题目与答案**全部 AI 生成、无教师审核**；高中题 `verify` 与 `answer` 同源，作者明确写「不是另一遍独立解题」；每知识点仅 4–5 题「不足以支撑严肃测评」；干扰项无真实学生数据校准、难度标注主观 |
| **与我们数据分布的匹配度** | 🔴 **差**。合成题是纯文字自包含、无图形题/作图题/证明题、带图 2.0%、解析 p50 26 字；我们的库是教辅 PDF 的 OCR 产物，含 `U+FFFD` 2,007 条、题号被切成题干（`"10"`×1273）、需 P-018 原位抠图与整题快照，`D-034` 刚定性过 0.079cm 透明占位图。**用它当训练集或讲解内容会系统性偏掉** |
| **方向是否对口** | 🔴 **反了**。它的 `topicId` 是**生成题目时绑定的**（知识点 → 合成题），不是对外部真实题目做分类标注。我们要的是给 656,898 个真实对象打知识点标签 ⇒ **它不是现成打标器**，最多作弱监督种子 / 术语词典 |
| **许可合规** | 🔴 见 §7，CC BY-NC 4.0 是采用前必须先解决的硬门 |

## 5. 对上一轮选型结论的影响（本轮核心）

### 5.1 需要修正的部分

上一轮报告 §3.2 写「图谱不是接一个算法，而是『建本体 + 给 65.7 万对象打标 + 持续维护』」，并据此把图谱列为最重、阶段 4。**「建本体」这一半被本项目证伪**：870 个数学知识点、1,459 条先修边、`mastery_criteria`、`diagnostic_question`、`standards`、`type/domain/grade/chapter` 全是现成的，且有校验脚本与活跃维护。⇒ 阶段 4 的**本体建设成本应显著下修**，从「从零建」改为「评估移植 + 本地化裁剪」。

### 5.2 不改变的部分（逐条）

| # | 上一轮判据 | 本项目是否改变 |
|---|---|---|
| 1 | 瓶颈是「参考例题只从 ≤8 份字面命中文档的 `rows` 里挑」 | ❌ 不变。图谱不产生候选，不是召回算法 |
| 2 | 题源不规范（8.05% `<6` 字、10.69% 无汉字、30.84% 字面冗余）需要语义召回 | ❌ 不变。图谱是字面标签体系，不解决 OCR 错字/改述 |
| 3 | 需要给 65.7 万真实对象打知识点标 | ❌ 不变（方向反 + 分布不匹配，见 §4） |
| 4 | `has_solution` 21.97% 是内容供给天花板 | ❌ 不变 |
| 5 | 度量闭环缺失（无 query 日志表、`review_events` 0 行） | ❌ 不变 |
| 6 | 判定层一行不动、第二层准入锁、四条不变量 | ❌ 不变 |
| 7 | 图谱阶段须过 20a §5.1 三问（若涉学习行为） | ❌ 不变，且本项目「自适应诊断 + 学习路径推荐」正面撞线（§6 C1） |

⇒ **「度量先行 → 本地向量语义召回优先 → Reranker 条件性后续 → 知识图谱长期讲解层」主线不变**；上一轮 Q1–Q4 待拍板不变，本报告不代替、不覆盖。

### 5.3 新增：一条极低成本的过渡项（供拍板，未实施）

把 870 个数学知识点名（可选 `description` 关键词）导出为词表，替换 `TOPIC_TERMS` 的 55 词：

- **优点**：纯召回层、零 L3 资源、零在线延迟、语域与现有表高度同源（50/55 命中）、可显著细化「为什么推荐这道」的共现信号；是 `P-015 §6` 那句「术语共现是行业里考点召回的最小可行实现」的自然延伸。
- **边界**：仍是**字面匹配**，不解决 OCR 错字/改述，**不能替代向量召回**；只改善「已看到之后怎么挑」，不改善「没看到」。
- **流程约束**：改 `question-reference.ts` 会打破 `P-025 T4`「J3 契约 sha 前后一致」的零改动口径，且需评估 `CACHE_VERSION`（result 结构不变但参考题内容变化 ⇒ 旧缓存留存旧 Top-3）、同步 M37 断言。⇒ **不能在 P-025 待拍板期间顺手做，须另立提案**。
