## 1. 一句话结论

**问题不在「图插在哪」，而在「被当成一个图的对象根本不是图」。**
F5/F5b 这类「看插入点邻域文字」的规则再怎么加，也看不到对象本身；本轮实证把观测点前移到对象侧后，40 条复核记录 **40/40 精确对齐**，18 条不通过**全部**命中的是「极小占位图 / 宽扁装饰条」，而通过集的对象尺寸与它们之间存在明显断层。

⇒ **「靠文字邻域规则达到放行标准」这条路线本轮被证伪**；F5/F5b 作为 fail-closed 兜底保留，但**不再追加 F5c 之类的同类规则**。
⇒ 思傅「doc 内容不规范」的判断方向正确，具体机制是：**老 `.doc` 经 LibreOffice 重转后，把排版占位符／装饰件转成了 `<w:drawing>`，而现链路把每一个 `<w:drawing>` 都当成题目配图。**

## 3. 第 26 题那个 `_|` 到底是什么（实证）

清单 #26：`docId 56774719-…` / `object_index 15` / `mark_offset 2112`，插点原文：

```text
……这一变化可将服装上残留的有毒物质含量大大【图插在这里】降低，新款干洗机的这一改进是利用了活性炭的______性。
```

L3 单份只读重转后 dump `word/document.xml` 与 `word/media/`：

| 项 | 实测值 |
|---|---|
| 节点 | `w:drawing`（`wp:inline`，非浮动 anchor） |
| 显示尺寸 `wp:extent` | **0.079 cm × 0.079 cm**（≈2.2pt） |
| 引用 | `word/media/image2.png`，**183 字节** |
| 像素尺寸 | **3 × 3 RGBA** |
| 像素内容 | 9 个像素中 **5 个 alpha=0 全透明**，其余 4 个为浅粉灰 `(243,235,237)` / `(238,219,220)` / `(235,211,212)` / `(233,204,206)` |
| 复用次数 | 同一份文档 24 个 `w:drawing` 中 **15 个**都指向这同一张 183B 图（62.5%） |

**这就是您看到的 `_|`**：一个几乎全透明、只有 4 个浅色像素、显示尺寸不到一个标点宽的 3×3 占位图。

- **WPS 看不到**：按 2.2pt 原始尺寸渲染，透明 + 浅粉灰在白底上几乎不可见；
- **百度网盘在线预览看得到**：预览器把 `.doc` 转 HTML/PDF 时，会给这类极小内联对象补占位边框／底色／描边，于是显成一个小角标。

所以**不是您看错，也不是我们「凭空插了一张图」**：那里确实有一个对象，但它**不是题目配图**。
更值得警惕的是：**不同渲染器对同一文档的可见性不一致，而我们的解析链路直接信任了 LO 转出的 XML，等于把「渲染器差异」翻译成「题干里的图」**。

> 说明：放大图呈现为左上角 2×2 浅色块，与您截图的 `_|` 形状不完全一致；可能是同一占位符在不同预览器下的描边差异，也可能是相邻的另一个小对象。无论哪一种，**它都不是可下发的题目图**，不影响本节结论。

## 4. 这是系统性现象，不是个例

对复核清单涉及的 **20 份唯一文档**逐份只读重转并 dump 全部 `w:drawing`/`w:object`（`20/20 ok`，`health=200`）：

| 指标 | 实测 |
|---|---:|
| 文档数 | 20 |
| 对象总数 | **860** |
| 显示尺寸任一边 < 0.5 cm | **276（32.1%）** |
| 全部为 `wp:inline` / 带 `pic:pic` | 是（本样本未见 anchor 浮动、未见 OLE、未见文本框） |

部分文档举例（对象总数 / 极小对象数）：

| 文档 | 对象 | 极小 |
|---|---:|---:|
| `2013-2014…第6单元 碳和碳的氧化物`（#26 所属） | 24 | **15** |
| `（人教版）九年级下册：第11单元 盐、化肥` | 22 | **13** |
| `专题24 科学探究实例（练）` | 45 | **24** |
| `专题 身边的化学物质--酸、碱、盐、化肥 课后练习及详解` | 37 | **21** |
| `2015面试原作` | 42 | 4 |
| `人教版初中历史常考专题突破…` | 6 | 0 |

⇒ 极小占位图在部分文档里占对象总量**一半以上**，且分布很不均匀。这解释了为什么「原文此处没有图」会成片出现。

**候选生成的机制**：`netdisk-inline-crop.py::parse_docx()` 用
```python
xml2 = re.sub(r'<w:drawing[ >]|<w:object[ >]', put, xml)
```
把**每一个**节点都打成一个「图标记」；随后 F2 按 `char_start` 把标记映射进题干，F5/F5b 只看 `stem` 文字邻域做语义判定。
⇒ **F0/F1 保证的是「文字流同源」，不是「这个对象是题目配图」**。P-018 在 docx 原件上能成立，是因为原件里 `w:drawing` 大多是顺序一致的行内真图；老 `.doc` 经 LO 重转后，排版占位符被实体化，`w:drawing` 的语义被稀释了。

## 5. 为什么「继续加文字规则」解决不了

| 复核发现 | F5/F5b 能否处理 | 原因 |
|---|---|---|
| 13 条「此处无图」（含水印、图中文字、图在别处） | ❌ | 规则只看 `stem` 文字 + `char_offset` 邻域，**观测不到对象** |
| 3 条题干末尾长数字残串 | ❌ | F5b 窗口只覆盖插点附近，残串在 stem 尾部 |
| 6 条题干缺字 / 公式丢失 | ❌ | 属 P-023 的 `m:oMath`/`w:object` 定性，F5 管「图插哪」管不了「题干有没有字」 |
| 3 条「答案区/解析区」被插点 | ❌ | 邻域文字完全正常，没有可写的文字特征 |

**观测点选错，不是阈值不够。** F5b 本轮已把阈值调到「换行+≥6 位纯数字」这种具体形态，同 seed 重跑后 4 条边界候选前 3 拦第 4 放行、16/16 `offset_zero` 全拦、9 个已知残串 0 漏网（D-033），**但人工复核仍判 18 条不通过**——这就是「局部指标全绿 ≠ 结果可用」的实证。

⇒ 参照既有「已证伪 ⛔ 别重走」纪律（P-013 只改召回选词 ⇒ exact 仍全 0），本轮把**「靠文字邻域规则达到放行标准」**记为已证伪，不再追加 F5c。

## 6. 对象级准入：分层设计与本样本测算

把闸门前移到对象侧，判据只看对象自身属性（不清洗原文、不重映射 `char_offset`、不碰 `text_content` / `text_sha256`，因此不破坏 F0 同源铁律）：

| 层 | 判据 | 拦的对象 |
|---|---|---|
| A | `min(w_cm, h_cm) < 0.30`（显示尺寸过小） | 3×3 透明占位、被缩小到 0.05 cm 的装饰件 |
| B | `h_cm < 0.60 且 w_cm/h_cm > 2`（宽扁条状） | 下划线／填空线／横式装饰条 |
| C（待设计，不进入本轮） | 渲染后非透明像素占比、纯色/单色判空、整页水印尺寸与位置、`wp:anchor` 浮动对象、`w:object` OLE 分类 | 内容级误判 |

**阈值敏感性（纯 A 层，仅这 40 条）**：

| 阈值 | 拦下不通过 | 误伤通过 |
|---|---:|---:|
| 0.10 / 0.15 / 0.20 / 0.30 cm | **15/18** | **0/22** |
| 0.50 cm | 16/18 | 1/22（#35） |
| 0.80 cm | 18/18 | 1/22（#35） |

**A+B 组合**：`18/18` 拦下、`0/22` 误伤。

尺寸分布存在明显断层，这是上述结果的原因：

- 不通过集：15 条 `≤0.079 cm`；另 3 条为宽扁条 `1.191×0.503`、`2.776×0.556`、`1.085×0.45 cm`
- 通过集：最小边 **0.423 cm**（#35），其余从 **2.134 cm** 起

🔴 **四条必须写死的边界**：

1. **这是在同一份复核结果上事后拟合的阈值**。A+B 的 `18/18 / 0/22` **只能叫「样本内可分离」，不能叫准确率、不能叫验证通过**。用于生产前必须**换一批独立样本做盲测 + 人工复核**，且盲测样本不得参与阈值选取。
2. **`media bytes` / `no_media` 本轮不可作为判据**。探测脚本解析 `word/_rels/document.xml.rels` 时假设 `Id` 在 `Target` 之前，部分文档属性顺序相反导致 `media: []`；#35（0.423×0.67 cm、`has_imagedata=true`、media 空）就是一个例子，它很可能是 `SO₄²⁻` 被图片化的上下标，**属于 P-023 公式定性，不是垃圾**。
3. **拦掉错图 ≠ 题目可读**。03/04/10/17/18 的「缺字」、03/04/31 的题干尾部残串依然在；对象闸只保证「不下发错图」，不解决 P-023 的题干完整性。
4. **#35 提示尺寸不能一刀切**：0.4 cm 量级可能是有效公式碎片。C 层的「渲染后内容判空」比单看尺寸更可靠，但需独立提案与压测。

| 路线 | 做法 | 能解决 | 代价 / 风险 | 建议 |

🔴 即便 ①③ 全部落地，**「检索时能给出正确匹配的题目及解析」这道关卡仍未过**：判定层 `question-match.ts` 六道硬闸未动、第二层准入未全绿、`0021 review_events` 仍 0 行。不得把本报告结论表述为「用户可以用了」。
