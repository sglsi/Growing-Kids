## 1. 本轮分段证据给每个方向的「收益上界」

阶段 B 只读实测（`geo-fixed` 稳态档，详见配套报告）：

| 段 | 耗时 | 可优化上界（**理论**，非承诺） |
|---|---|---|
| L0 通道 A `name/path ilike` 多 OR（284 行） | 892 ms | ≈0.9 s |
| L0 通道 B `text_flat ilike` DB（1,133 行 / 9.29M 字符） | 462 ms | ≈0.5 s |
| 通道 B 经 PostgREST（9,626,831 B） | 769 ms（含上面 462） | 传输/序列化增量 ≈0.3 s |
| JS `flatText` 归一化 1,133 行 | 39 ms | ≈0.04 s |
| L0 打分/合并/组装（残差） | ≈0.4 s | 未直测，**不给上界** |
| 深挖 8 份 + 判定 + 同源例题 + 附件装配 | ≈0.19 s | ≤0.19 s |
| 客户端 − 服务端 | 4 ms | ≈0 |

🔴 上界是「该段全部消失」的理想值，**不是收益预测**；且段间可能重叠（通道 B 的 462ms 已含在 769ms 内）。**不宣称**任何优化后 P95 达标，也不做「3.5s − 1.7s」式的确定性推算。

## 2. 六方向逐项评审

### ① 预热候选池 / 连接

| 项 | 内容 |
|---|---|
| 阶段 B 证据 | **否证收益**：三轮首轮 P95 2405 / 2312 / 4069ms，warm P95 3498 / 3462 / 3488ms；长尾在稳态而非首轮尖峰 |
| 收益上界 | ≈0（本轮甚至出现首轮更慢） |
| 代价 | 生产变更（预热任务/常驻缓存）、内存占用、可能引入新的稳态负载 |
| 红线 | `P-021` §2 ④ X 禁止「预热」；`§2 ⑥` 不实施任何生产变更 |
| 证据依赖 | 无需更多证据，三轮复采已足够 |
| 建议 | **不做**；若将来换协议复采出现「首轮显著慢于 warm」，再单独提 |

### ② 粗筛池前置（先按 `text_flat` trigram 缩到 N 份再深挖）

| 项 | 内容 |
|---|---|
| 阶段 B 证据 | 候选池本来就是耗时主段，前置粗筛**不减少**通道 A/B 的扫描；收益与「减少深挖份数」绑定，而深挖段仅 ≈0.19s |
| 收益上界 | ≤0.19 s，且以改召回口径为代价 |
| 代价 | 改变候选集合 ⇒ 影响召回与共现计数，**必须重新证明 P0 六条硬闸不被绕过** |
| 红线 | 🔴 **最高红线**：P0 六闸串联否决、举证责任倒置、第二层准入未全绿；「库变大 ≠ 放行变宽」 |
| 证据依赖 | 需要新的准入证据（误判归零 + 召回 ≥90% + 定位 100%），`0021` 仍 0 行 |
| 建议 | **不做**。性能理由不构成放宽准入口径的依据 |

### ③ `SELECT` 列裁剪 / 共现计数下推（不拉 `text_flat` 大字段）

| 项 | 内容 |
|---|---|
| 阶段 B 证据 | **支持「传输量大」的观察**：通道 B 1,133 行 / 9.63 MB，PostgREST 端到端 769ms，pg 直连 462ms ⇒ 传输/序列化 ≈0.3s；JS 归一化仅 39ms |
| 收益上界 | ≈0.3–0.8 s（取决于能否在 SQL 侧完成共现计数而不回传全文） |
| 代价 | 改 `netdisk-search.service.ts` 的查询结构；`flatText()` 是 `text_flat` 唯一真相源，若改为 SQL 侧 `ilike` 计数，**归一化口径必须与 `question-match.ts::normalizeForMatch()` 逐字一致**，否则共现数漂移（P-008 正文 0 命中的老根因） |
| 红线 | 触碰「前后端/判定层同源口径」；需独立提案 + 前后对照；`P-021` §2 ② 不变量 C（契约）与 §4 阶段 D 明令本提案不实施 |
| 证据依赖 | 先做**只读可行性验证**：在只读副本上比对「SQL 侧共现计数」与「JS `flatText` 计数」是否逐题逐字相等；不相等即放弃 |
| 建议 | **六项中唯一值得进入下一步只读评估**的方向，但仍须独立提案；本轮不动代码 |

### ④ 加索引 / 物化视图

| 项 | 内容 |
|---|---|
| 阶段 B 证据 | 通道 A `name/path ilike '%k%'` 多 OR **892ms**；现有索引清单只有 `netdisk_files_text_flat_trgm_idx`（D-029 `EXPLAIN`），`name/path` 无 trigram 索引时 `%k%` 只能顺序扫 |
| 收益上界 | ≈0.9 s（通道 A 全消的理想值） |
| 代价 | 迁移 = **生产写入**（建索引锁表 / 磁盘 / 回填），需备份、独立提案、灰度与回滚预案；L3 4C/3.7G 资源紧 |
| 红线 | `P-021` §2 ② L2「加索引或改表结构」明令不做；`§4` 阶段 D 不预授权；`GK-OPS-22` 先提案后实施 |
| 证据依赖 | 先用只读 `EXPLAIN` 在**副本**上验证 trigram 索引的收益，不在生产直接建 |
| 建议 | 排在 ③ 之后；即便证据充分也须独立提案，**本轮不做** |

### ⑤ 调 `MAX_DEEP_FILES` / 8s 预算

| 项 | 内容 |
|---|---|
| 阶段 B 证据 | **否证收益**：深挖 8 份的配对差分仅 ≈0.19s；生产 `NETDISK_ONLINE_EXTRACT` 未开，`ensureText()` 在下载分支前返回（`netdisk-search.service.ts:981–988`），本来就不做网盘下载 |
| 收益上界 | ≤0.19 s（且以损失覆盖为代价） |
| 代价 | 改判定层预算＝改准入口径；可能减少同源例题与定位机会 |
| 红线 | 🔴 `§4 P0-3` 硬闸、`P-021` §2 ② 不变量 B 明令不动；`§5` 已标「本提案明令不动」 |
| 建议 | **不做**。阶段 B 已说明这不是主因段 |

### ⑥ 只报暖机后数据 / 换 P95 算法 / 换 query 集合

| 项 | 内容 |
|---|---|
| 阶段 B 证据 | 三轮全量 P95 均 ≥3s；warm P95 3498 / 3462 / 3488ms **同样 ≥3s** ⇒ 换子集也凑不出达标 |
| 收益上界 | 0（不改变任何真实耗时） |
| 代价 | 破坏跨轮可比性、使历史数据失效 |
| 红线 | 🔴 `P-021` §2 ② 不变量 B「不改测量口径去凑达标」；`docs/design/method/检索链路P95测量协议.md` §5 禁止事项；等同放宽硬闸 |
| 建议 | **明令禁止**，不接受任何以达标为目的的口径修订 |
