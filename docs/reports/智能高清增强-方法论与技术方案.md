## 一、问题定义：把主观感受翻译成技术缺失

用户的两句反馈，指向的是**两个不同层次**的问题，必须分开处理，否则容易"头痛医脚"。

| 用户感受 | 真实技术含义 | 根因定位 |
|---|---|---|
| ① 对比度不明显、和原图差别不大 | 文字与背景的**灰阶间距**没有被拉开 | 管线中**没有**光照归一化、**没有**局部自适应对比增强 |
| ② 文字模糊、看不清 | 边缘**陡峭度/高频信息**不足 | 仅靠插值+轻度 USM；**超分本身不能恢复已丢失的高频**，且 ESPCN 能力有限 |

### 1.1 现状管线诊断（已核查代码）

当前 `enhanceImage`（`server/src/image/image-superres.ts`）实际执行：

```
RGB → YCbCr → [Y 通道: Lanczos3 升采样 + 轻度 sharpen  或  ESPCN 超分]
              → [Cb/Cr: 双三次升采样] → 重组 RGB
```

**缺失的关键环节**（这正是"和原图差别不大"的直接原因）：

| 缺失环节 | 后果 |
|---|---|
| ❌ 光照/背景归一化 | 阴影、渐变光照被原样保留 → 背景不平，视觉上"没修过" |
| ❌ 局部自适应对比增强 | 文字灰阶与背景灰阶接近（如 180 vs 210）→ 对比不明显 |
| ❌ 自适应二值化（扫描观感核心） | 没有"文字纯黑、背景纯白"的扫描件质感 |
| ⚠️ 锐化仅 `sharpen(sigma=1.4, m2≈2.7)` | 强度保守，且不恢复真实高频 |
| ⚠️ 超分模型为 ESPCN（2016 轻量） | 实测 x2 仅 **+1.1~1.8 dB**，对"清晰度"贡献有限 |

### 1.2 一个必须纠正的认知

> **扫描类 App 的"清晰"，视觉上主要来自"背景拉平 + 局部对比/二值化"，而不是分辨率提升。**

把一张 180/210 灰阶的模糊文字，通过局部自适应阈值拉成 20/250，人眼会立刻判定"清晰、修过"——即使像素总数没变。
这就是为什么当前做了 x2 超分、用户仍觉得"和原图相关不大"：**我们提升了分辨率，却没有提升区分度。**

## 二、业界方案解剖：扫描全能王 / 夸克在做什么

### 2.1 扫描全能王「增强」的技术本质

多方逆向与公开资料表明，其"增强/锐化"核心是**自适应二值化的变体**：

```python
# 局部均值 × 系数 β 作为阈值（β≈0.9）
means = correlate2d(img, kernel) / counts
img = np.where(img < means * beta, 0, 255)
```

关键工程细节（很有价值）：
- **为什么要乘 β**：背景是渐变的，若直接以局部均值为阈值，会有大量背景像素落在阈值下 → "背景变花"。乘 0.9 把背景整体推到阈值之上，同时文字像素值很小、不受影响。
- **窗口 win≈9**：约 2~3 倍字符高度。

其「智能高清滤镜」（2023）进一步升级为**场景化决策**：
1. **图像感知**：深度学习感知光照/阴影/颜色/倾斜，判断过暗或过亮
2. **场景化决策**：判定文档种类（试卷 vs 发票），自动选择处理组合
3. **一键处理**：模糊、阴影、手指遮挡、摩尔纹（屏幕纹）、曲面矫正

其「图像美化算法」（已备案）用于**去手写/去水印**，技术栈为：
- 基础：CGAN（条件生成对抗网络）
- 手写擦除：U 型分割网络训出手写 mask → 膨胀 → 通用擦除模型（inpainting）修复背景
- 水印擦除：U-Net 分割 mask → 水印去除网络
- 文字擦除：端到端网络，同时学习擦除结果与文字 mask

### 2.2 可借鉴的设计思想（按优先级）

| 思想 | 说明 | 对我们的价值 |
|---|---|---|
| ① **效果优先于保真** | 文档场景用户要"看得清"，不是"像素级还原原稿" | ⭐⭐⭐ 决定产品取向 |
| ② **多模式输出 + 预览自选** | 原图 / 增强并锐化 / 黑白 / 增亮 / 灰度，并列预览让用户挑最满意的结果 | ⭐⭐⭐ 直接提升满意度与粘性 |
| ③ **局部自适应而非全局** | 一切以局部窗口统计为准，抗不均匀光照 | ⭐⭐⭐ 核心技术路线 |
| ④ **场景化自动决策** | 先感知（是否模糊/过暗/有阴影）再选处理组合 | ⭐⭐ 中期目标 |
| ⑤ **去手写 = 分割 + 修复（inpainting）** | 而非"擦成白块" | ⭐⭐ 已有 erase 功能可对齐 |

> **实测校正（v5 本轮新增）**：本次与扫描王的对比图中，扫描王那张实际是**「黑白」模式**输出。对纯黑白打印件（如本次小学试卷），其背景经二值化后色度恒为 0，故"无任何色块、绝对中性"——这并非扫描王把彩色增强做到了极致，而是它**丢弃了颜色**。我们此前以该图为基准去追"背景色差 σ→0"方向没错，但应理解为：**对黑白源，正确答案是提供「黑白」模式让用户选，而非在彩色模式里死磕色偏**；彩色模式的色偏消除（方案 A 逐通道阴影校正）仅对**彩色源**（带彩色图示的卷子、照片）有意义。

## 三、方法论对比

### 3.1 光照 / 背景归一化（解决"背景不平、没修过感"）

| 方法 | 原理 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| 全局直方图均衡化 | 全局灰度重映射 | 极简 | 放大噪声、破坏局部细节，文档场景基本不可用 | ✗ |
| **CLAHE** | 分块局部直方图均衡 + 限幅裁剪 | 提升局部对比、抑制噪声放大 | 不真正去除光照梯度；可能放大背景纹理、有块状 | △ 可作辅助 |
| **形态学背景估计（Top-Hat）** | **暗字亮底用闭运算 closing**（膨胀→腐蚀）填掉黑字 → 估计背景 → 原图减背景 + 均值 | **真正去除低频光照梯度**，保留文字；经典、可控 | 结构元须大于**字符整体尺寸**；单结构元在复杂光照下有块效应 | ✅ **主推** |
| ⚠️ 算子极性（v2 修正） | 暗字亮底 → **closing**；亮字暗底 → **opening** | 用反会把字一起削掉 | 常见错误：一律用 opening | 必读 |
| 多方向 SE + 开闭重建（Wang 2014, PLoS ONE） | 多方向结构元 + 重建，融合去块效应 | 无块效应、复杂光照表现好 | 计算量较大 | ✅ 高质量备选 |
| 同态滤波 | 频域分离照度/反射分量 | 理论完备 | 频域变换开销大、局部性差 | △ |
| Retinex（SSR/MSR） | 照度-反射分解 | 颜色保真较好 | 参数敏感、易光晕 | △ |
| 深度学习光照估计 | 端到端 | 上限高 | 需数据 + GPU，部署重 | ✗ 当前阶段 |

**推荐**：形态学背景估计（主）+ CLAHE（辅，`clipLimit≈1.0~2.0`，仅作温和补强）。
理由：文档图像的光照不均是**低频**现象，形态学/背景估计是"对症"解法；CLAHE 是对比度工具，不解决渐变。

### 3.2 局部自适应二值化 / 对比增强（解决"文字背景对比不明显"）⭐ 核心

| 方法 | 阈值公式 | 优点 | 缺点 |
|---|---|---|---|
| Otsu（全局） | 最大化类间方差 | 简单快速 | 不均匀光照下直接失效 |
| Niblack | `T = μ + kσ`（k≈−0.2） | 引入局部方差 | 背景区噪声多 |
| **Sauvola** | `T = μ·(1 + k·(σ/R − 1))` | 低对比区表现好，文档界事实标准 | k / 窗口敏感，需调参 |
| Wolf | 在 Sauvola 基础上引入全局最小灰度 | 极暗 / 低对比区域更优，历史文档受认可 | 更复杂 |
| Bradley | 积分图 O(1) 求局部均值 × (1−t) | 极快，与窗口大小无关，适合实时 | 不含方差，低对比区差 |
| 深度学习二值化（U-Net / SBB） | 逐像素分割 | DIBCO 上 F-measure > 95%，抗水印/污渍/透印 | 需训练数据 + GPU，推理成本高 |
| **扫描全能王式（局部均值 × β）** | `img < mean·β ? 0 : 255` | 极简、工程稳定、观感"干净" | 需 β 调参（≈0.9），强渐变背景须先做光照归一化 |

**关键设计决策：软映射 vs 硬二值化**

- **硬二值化**（0/255）：对比最强、最"扫描件"，但**丢失全部灰阶**——对照片、图表、彩色插图是破坏性的。
- **软映射**（推荐作为默认"增强"）：以 Sauvola 的局部 `μ, σ` 构造**对比拉伸曲线**，把文字推向黑、背景推向白，但**保留中间灰阶过渡**。观感接近二值化，却不破坏非文字内容。

> 建议：默认走软映射；"黑白/扫描件"模式才用硬二值化。这与扫描全能王的多模式一致。

### 3.3 超分辨率（解决"分辨率"，但对"清晰度"贡献有限）

| 方法 | 特点 | 体量 | 适用性 |
|---|---|---|---|
| 双三次 / Lanczos3 | 纯插值 | — | 基线（当前 classical 模式） |
| SRCNN / **ESPCN** | 浅层 CNN，极快 | ~100 KB | **当前所用**；实测 x2 仅 +1.1~1.8 dB |
| EDSR / RCAN / RDN | 残差 + 通道注意力，PSNR 高 | 数 MB ~ 数十 MB | 通用强但重，CPU 推理慢 |
| Real-ESRGAN（含 tiny/ncnn） | 真实退化建模，感知质量好、边缘锐利 | 4.7 MB+（tiny 更小） | 观感提升明显，需防 GAN 伪影 |
| SwinIR | Transformer，SOTA | 较重 | 上限高，CPU 慢 |
| **TSRN** | 文本专用（序列 + 语义注意力），TextZoom 数据集 | 中 | 文本识别率显著优于通用 SR |
| **TPGSR** | 文本识别先验（CRNN/ASTER）引导，多阶段 | 重（需 teacher 识别模型） | 识别率 SOTA，但部署成本高 |

**TPGSR 论文实测（TextZoom，ASTER 平均识别率）**，可直观看到上限与差距：

| 方法 | easy | medium | hard | **average** |
|---|---|---|---|---|
| Bicubic | 64.7% | 42.4% | 31.2% | **47.2%** |
| SRCNN | 69.4% | 43.4% | 33.0% | 49.5% |
| SRResNet | 69.6% | 47.6% | 34.3% | 51.3% |
| **TSRN** | 75.1% | 56.3% | 40.1% | **58.3%** |
| **TPGSR-TSRN** | 78.9% | 62.7% | 44.5% | **62.8%** |
| HR（上界） | 94.2% | 87.7% | 76.2% | **86.4%** |

**结论**：即便 SOTA 文本 SR（62.8%）距 HR 上界（86.4%）仍有巨大差距 → **超分不能单独承担"清晰"的期望**。它应作为辅助，观感主力交给 §3.2。

### 3.4 去模糊（解决"真的糊了"）

| 方法 | 特点 | 适用性 |
|---|---|---|
| USM / 非锐化掩膜 | 高通叠加，"看起来"锐 | **当前所用**；不恢复真实信息，过量会过冲/白边 |
| 维纳滤波 | 频域正则化逆滤波，噪声下稳定 | 需已知 PSF；可作为受控补救 |
| 盲去卷积（RL / 稀疏先验） | 交替估核 + 复原，无需 PSF | 慢、易振铃（ringing） |
| DeblurGAN / v2 | 端到端 GAN，真实模糊表现好 | 需 GPU，有伪影风险 |
| Restormer | Transformer，上限高 | 重，CPU 不现实 |

**重要判断**：应先做**模糊检测**（如拉普拉斯方差 / 梯度能量），**仅在判定为模糊时**才启用去模糊，避免对清晰图做无谓处理导致画质损失。

### 3.5 去噪（配套，宜轻不宜重）

文档场景首选**保边**滤波：中值（当前可选，`median(3)`）、双边滤波、非局部均值（NLM）、BM3D、DnCNN。
**注意**：去噪必须在对比增强**之前**，否则会被对比增强放大噪声。

## 四、推荐技术方案（分阶段落地）

### 总体管线（目标形态）

```
几何校正(自动调正)
   ↓
① 光照/背景归一化        ← 新增（P0，主推形态学背景估计）
   ↓
② 轻度保边去噪           ← 新增/强化（P0，可选但建议）
   ↓
③ 超分辨率（可选，按倍率） ← 保留现有 ESPCN，后续再升级
   ↓
④ 去模糊 / 锐化           ← 强化（P0 受控 USM；P3 条件式去模糊）
   ↓
⑤ 局部自适应对比增强      ← 新增（P0 核心，Sauvola 风格软映射）
   ↓
⑥ [模式] 硬二值化         ← 新增（P1，"黑白"模式）
   ↓
输出（原图 / 增强 / 黑白 三选一）
```

**顺序理由**：
- 光照归一化必须最先（它削的是低频背景，先做才不会干扰后续高频处理）
- 去噪在对比增强之前（否则噪声被放大）
- 超分在对比增强之前（二值化/硬映射会永久损失灰阶信息，之后再超分没有意义）
- 对比增强放最后（它决定最终观感，是"临门一脚"）

### P0 · 立竿见影（纯算法、无模型、低风险）— **优先做这一批**

| 项 | 方案 | 预期收益 |
|---|---|---|
| **P0-1 背景归一化** | **闭运算 closing**（暗字亮底）大核估计背景，或大半径模糊/中值近似 → `out = (src − bg) · α + mean(bg)`。SE ≈ **1.5~3 × 字高**（⚠️ 非笔画宽） | 消除阴影与渐变，"修过感"立刻出现 |
| **P0-2 局部对比软增强** | Sauvola 风格：按局部 `μ, σ` 做对比拉伸（非硬二值化），窗口 ≈ **2~3 × 字高** | ⭐ 直接解决"对比度不明显" |
| **P0-3 积分图加速**（v2 新增） | 局部均值/方差用**积分图 O(1)** 查询，避免逐像素 O(win²) 滑窗 | 让窗口 30~50 在 Node 单线程下可行 |
| **P0-4 自适应窗口** | 复用 `detectTextRows`（`image-perspective.ts`）估计**字高** → 自动定窗口 | 避免不同字号/分辨率下窗口失配 |
| **P0-5 版面感知（新增·v3，跨功能复用导出）** ⚠️ | 增强**不可整图无差别施加**。必须先做版面区域判别，**仅在【文字区】施加 Sauvola 对比增强 / 二值化；【图片区】【表格区】保持原样或仅走温和对比拉伸**。依据：Sauvola/二值化对**连续色调区域具有破坏性**（会把灰度插图、几何图形压成纯黑白块、丢失中间调）——与去手写"图形被误擦"是**同一类根因（不认识图片区）**。可行的最小实现：先用已有 `detectTextRows` 的行结构 + 连通域特征**粗判非文字区并排除**（P0 阶段无模型）；P1 起与去手写**共用同一个版面分割模型** | 防止增强破坏试卷里的图形/插图/照片 |
| **P0-前置改造** ⚠️ | `detectTextRows` 当前**未导出字高**（内部 `medH` 不外露）→ 需扩展返回值或新增 `estimateCharMetrics()`，导出 `{medH, strokeWidth, rowPitch}` | 自适应参数的唯一数据来源，必须先做。**⚠️ 与去手写 P0-7 是同一阻塞，应作为全项目级一次改造** |

> P0 的价值：**不需要任何新模型、不需要 GPU**，纯算法即可解决用户反馈的第①个（对比度），并大幅改善第②个（观感清晰度）。

### 跨功能复用（v3 新增）：与去手写 / 自动调正的共用基座

> 详细论证见《去手写功能-方法论与技术方案.md》§5.1。此处仅记录与**本方案直接相关**的复用点：

| 复用项 | 说明 |
|---|---|
| **medH 前置改造** | 本方案 P0-4 与去手写 P0-7 依赖同一数据 → **合并为一次改造**，不要各做一遍 |
| **光照归一化** | 本方案 P0-1（closing + Top-Hat）**同时就是去手写 P0-8 的预处理**，共用一套实现 |
| **版面分割模型** | 本方案 P0-5 / P1 与去手写 P1「图片区独立类别」**共用同一模型**，一次训练两功能受益 |
| **频率差异化降采样** | 本方案 §7.1 原则（低频可降采样、高频必须原尺度）**同样适用于去手写**，已推广为全项目规范 |
| **积分图 + libvips** | 共用加速基座（libvips 为 C/C++ 原生扩展，**非 WASM**） |
| **统��质量护栏** | `compareRecognized()`（OCR 一致性 0.75）+ `unmodifiedRegionSimilarity`（0.95）+ 覆盖率护栏 → **"宁可不处理，不能处理坏"上升为全项目红线** |

### P0.5 · 自适应锐化（v2：从 P0 拆出）

**拆分理由**：锐化与对比增强**正交**——对比增强管**灰阶间距**，锐化管**边缘陡峭度**；且锐化参数需匹配"对比增强之后"的图像，不能独立调参。

| 项 | 方案 | 备注 |
|---|---|---|
| 自适应 sigma | `sigma ≈ 笔画宽度 / 2`（以字高推导，实测微调） | sigma 过小只锐噪声，过大产生光晕 |
| 边缘软门控 | 用**局部梯度幅值**软门控（比 Canny 更廉价、无双阈值调参） | 避免放大背景噪声 |
| 防光晕 | 限制总 amount；多尺度（sigma 1px + 3px）谨慎启用并做 A/B | 多尺度会叠加光晕风险 |

### P1 · 多模式输出 + 预览自选（对标扫描全能王）

**核心设计思想（用户提议，本轮确立）**：不再由算法替用户"定一个最好结果"，而是**并列产出多种模式、渲染缩略图、让用户自己挑最满意的那张**。这直接服务于产品目标——提升用户满意度与使用粘性，也比"程序替用户决策"更稳。扫描全能王即采用此范式：原图 / 增强并锐化 / 黑白 / 增亮 / 灰度，点击即看效果、随时切换。

**模式 taxonomy（对齐扫描王实际功能）**

| 模式 | 本程序对应处理 | 适用 |
|---|---|---|
| **原图** | 仅几何校正（调正/裁剪），不做像素增强 | 想保留原始观感 |
| **增强并锐化**（默认，彩色） | 光照归一化(除法) + 软对比增强 + 自适应锐化；**彩色源叠加方案 A 逐通道阴影校正消去色偏** | 通用、彩色源、带图示卷子 |
| **黑白 / 文档** | 亮度归一化前置 + 灰度 + 自适应阈值(Otsu/Sauvola) 映射近二值 | **纯黑白打印件（本次试卷即此类）** |
| **增亮** | 更轻的 flatten / 更高白点，整体偏亮 | 拍摄偏暗、阴影重 |
| **灰度** | 去色 + 增强（比黑白温和，保留灰阶、无色偏） | 想去掉颜色但保留层次 |

**关键结论（实测支撑）**：对纯黑白打印件，"黑白"模式是**最优解**——灰度图色度恒为 0，背景蓝色块由构造性消失。实测本次试卷：增强彩色模式背景有色偏格子占 **28.2%**、σ(B−G)=**3.40**；转「黑白」后两项均归 **0**，与扫描王基准一致。→ **彩色模式的色偏消除（方案 A）只对彩色源有价值；对黑白源应直接走「黑白」模式。**

**预览自选 UX（落地要点）**
- **后端**：同一张输入并行产出各模式结果（或按需懒生成），输出结构化 `modes: { original, enhance, bw, brighten, gray }`。
- **前端**：结果页并列渲染 5 张缩略图 + 模式名标签，点击放大/切换。
- **智能默认档**：轻量检测判断源图是否"基本单色"（色度低、Otsu 分明）→ 是则**默认选中「黑白」**，否则默认「增强并锐化」；用户不满意可一键切换，不剥夺选择权。
- **强度档位**（弱/中/强）作为各模式二级微调，避免"算法觉得好、用户觉得过头"。

> ⚠️ 前端涉及新增"多模式预览/选择"交互组件，属本阶段**仅标注、不改代码**；后端各模式处理函数多数已具备（归一化、锐化、灰度、阈值），主要工作是**编排成可并列输出的模式入口** + 单色源检测。方案 A 的逐通道色彩阴影校正暂挂起，待「增强并锐化」彩色模式实施时一并落地。

### P2 · 超分模型升级（中期）

> **「高清扩展」定位**（本轮确立）：X2/X3/X4 超分即"高清扩展"——与基础增强（背景归一化 + 局部对比增强）正交的**可选清晰度增强**。
> · 默认彩色增强（enhance/brighten/gray）开启 X2；黑白模式强制原生分辨率（§10.8），不启用高清扩展。
> · 它在管线中位于对比增强**之前**（硬映射会永久损失灰阶，之后超分无意义）；引擎经 `runSREngine` 统一分发，按权重 `family` 选择（当前 `espcn`/`classic`，`tatt`/`real-esrgan` 为中期接入点）。
> · 并发成本：`sr-gate` 已把 `scale>=3 || mode==='espcn'` 划入 heavy lane，仅 x2-classical 走轻量 lane。

1. **短期**：保留已验证的 ESPCN 权重（已与 TF 冻结图逐位对齐），但**置于对比增强之前**（管线顺序修正）。
2. **中期**：评估替换一个更强的轻量模型——
   - 候选 A：**文本专用**（TSRN / **TATT**）——文字边缘更锐，对识别率增益更直接
   - 候选 B：Real-ESRGAN `tiny` / ncnn 版——通用性更好，但需注意 GAN 伪影
   - 决策依据：CPU 推理耗时 + 主观 A/B + OCR 一致性增益
   - **只选一个模型**；纳入 `sr-gate`（`sr-gate.ts`）的 **heavy lane** 控并发
3. **注意**：不要让超分喧宾夺主——按 §3.3 数据，它的边际收益低于对比增强。

> ⚠️ **v2 明确否决：双模型区域混合（文字区 TextSR + 背景区 Real-ESRGAN）**
> 理由：① 文字 mask 若复用 `handwriting-segmenter`，其主入口是 `segmentByVlm()`——**每张图一次 VLM 大模型调用**，成本严重错配，且它分割的是**手写**而非印刷文字，语义不匹配；② mask 边界必然产生接缝伪影，需羽化/多尺度融合，复杂度陡增；③ 单核 CPU 跑两个超分模型耗时翻倍，与 `sr-gate` 冲突。降级为"未来可选探索"，不作为 P2 目标。

### P3 · 条件式去模糊（可选，按需）

- 前置**模糊检测**（拉普拉斯方差阈值）；仅在模糊时启用
- 轻量方案优先：小核盲去卷积 + 振铃抑制；确有需求再评估 DeblurGAN-lite

### P4 · 场景化自动决策（长期，对标"智能高清滤镜"）

感知 → 决策 → 组合执行：
- 感知：是否模糊、是否过暗/过亮、是否有阴影、文档类型（试卷/发票/笔记）
- 决策：自动选择 P0~P3 中哪些环节启用及强度

## 五、关键参数建议（后续实现时的起点值）

| 环节 | 参数 | 建议起点 | 说明 |
|---|---|---|---|
| 背景估计 | 结构元/核尺寸 | ≥ 2× 字符高度（建议取字高的 3~5 倍） | 太小会把文字吃掉，太大跟不上光照变化 |
| Sauvola | 窗口 | 2~3× 字符高度（可用 `detectTextRows` 估） | 文献常用 21~51（视分辨率） |
| Sauvola | `k` | 0.1 ~ 0.35（相机拍摄偏 0.2~0.34） | k 越大越"去背景"，但过大伤笔画 |
| Sauvola | `R`（动态范围） | 128（8bit） | 标准值 |
| 扫描式 β | `β` | 0.85 ~ 0.95 | 解决渐变背景"发花"的关键 |
| CLAHE | `clipLimit` | 1.0 ~ 2.0（仅作温和补强） | 过大放大噪声 |
| 锐化 | `sigma` / `amount` | sigma 1.0~1.5，amount 受边缘掩膜约束 | 防白边过冲 |

> 相机拍摄（CAM）与扫描件（DOC）应**分开取参**：文献显示 Sauvola 在 CAM 域表现更优（不均匀光照主导），全局 Otsu 在 DOC 域更干净。

## 六、效果评估方法（避免"自我感觉良好"）

| 层次 | 指标 | 说明 |
|---|---|---|
| **快速筛选** | **文字边缘陡峭度**、文字 vs 背景**灰阶差 Δ**、局部 Michelson 对比度 | 无需标注，每轮迭代可跑；分别对应反馈②① |
| **任务指标** ⭐ | **OCR 一致性** —— 复用 `image-quality.ts` **已有的** `compareRecognized()`（`OCR_CONSISTENCY_THRESHOLD = 0.75`） | ⭐ 增强前后识别结果自比对，**无需人工标注 GT**，直接对应"看得清=认得出" |
| **保真（参考）** | PSNR / SSIM | 仅对合成退化有意义；**不可单独作为验收标准** |
| **终裁** | 主观 A/B（文字特写对比图） | 用户判定"像不像修过" |

**分层用法**：每轮迭代跑「边缘陡峭度 + OCR 一致性」自动筛选 → 关键版本出主观 A/B 终裁 → 人工标注样本集仅用于 P3 与里程碑验收。

> ❌ **明确不用 NIQE / BRISQUE**（v2 修正）
> 二者是基于**自然场景统计（NSS）**的无参考质量指标，标定于自然照片。文档图像是极端非自然分布（大片纯白 + 稀疏黑笔画）：一张**完美的干净文档会被判为低质量**，而加噪/加纹理反而可能得分更高 → 用它筛选会**系统性误导调参方向**。文档领域应使用 DIBCO 体系的 F-measure/PSNR/NRM/DRD（需 GT），或本方案采用的边缘陡峭度 + OCR 一致性。

## 七、风险与开放问题

| 风险 | 说明 | 缓解 |
|---|---|---|
| 硬二值化损失灰阶 | 对照片、图表、彩色插图破坏性 | 默认软映射；硬二值化仅作独立模式 |
| 过增强放大噪声/纸纹 | 低质量拍照底子差 | 先去噪；CLAHE 限幅；强度可调 |
| CPU 性能预算 | 形态学大核 + 局部窗口统计在 Node/1 核虚机上可能很慢 | **分阶段差异化**（见下）；局部统计用**积分图**；加速靠 **libvips 原生算子**（C/C++ 扩展，**非 WASM**） |
| 文档类型差异 | 试卷（密集小字）vs 发票（表格线）vs 笔记（手写）参数不同 | P1 阶段做模式/档位；P4 做自动场景识别 |
| 用户期望管理 | 超分不能凭空创造细节，极模糊原图上限受限 | 明确"增强"而非"复原"；提供强度档位让用户把控 |

### 7.1 性能约束细则（v2 修订）

不同环节的频率特性不同，**不能一刀切降采样**：

| 阶段 | 频率特性 | 可否降采样 | 说明 |
|---|---|---|---|
| 背景 / 光照归一化 | **低频**（光照梯度变化缓慢） | ✅ **可以且应该** | 降采样后估计背景 → 升采样回原尺度相减，提速显著且几乎无损 |
| 局部对比增强（Sauvola） | **高频**（笔画级） | ❌ **必须原尺度** | 降采样会削掉待增强的笔画细节，与目标直接冲突 |
| 锐化 | **高频** | ❌ **必须原尺度** | 同上 |

其他约束：

- **加速手段**：局部统计一律走**积分图**；重算子尽量落到 **libvips 原生算子**——注意它是 **C/C++ 原生扩展（node-gyp addon），不是 WebAssembly**，libvips 内部已有线程池与 tile 流式处理，不要误选 WASM 方案。
- **大图**：采用 **tile 分块**控内存峰值，但局部窗口算子分块**必须带重叠（halo ≥ 窗口半径）**，否则块边界出现统计不连续的接缝。
- **并发**：重模型走 `sr-gate` 的 **heavy lane**，避免与 light lane 抢单核算力。

## 九、结论与建议优先级

1. **根因确认**：用户反馈的两个问题，主因**不是超分不够强**，而是管线缺失**背景归一化**与**局部自适应对比增强**——这两步才是扫描类 App 观感的来源。
2. **建议先做 P0**（背景归一化 + Sauvola 风格软对比增强 + 自适应窗口 + 受控锐化）：纯算法、无模型依赖、低风险，预计能直接解决反馈①并大幅改善反馈②。
3. **超分升级（P2）放在第二位**：按公开数据，其边际收益低于对比增强，且成本更高。
4. **评估以 OCR 一致性 + 主观 A/B 为主**，不要只看 PSNR，也不要用 NIQE/BRISQUE。

## 十、P0 → P0.5 → P1 实施结果与验证（v4 新增）

### 10.1 实施范围

| 阶段 | 落地项 | 位置 |
|---|---|---|
| **P0-前置** | 抽公共版面度量基座，导出 `medH / strokeWidth / rowPitch / inkIsDark / confidence` | `image-layout.ts`（新建） |
| **P0-1** | 形态学 **closing** 估背景 + 自动色阶（降采样做，遵循 §7.1 低频可降采样） | `image-doc-enhance.ts` `normalizeBackgroundLuma()` |
| **P0-2** | Sauvola 软映射（**默认保留灰阶**），`softWidth = max(16, σ×1.6)` | `localContrastEnhance()` |
| **P0-3** | 双积分图 O(1) 求局部 μ/σ + **带 halo 的 tile 分块** | `mapLocalStats()` |
| **P0-4** | 窗口/SE/锐化 sigma 全部由字符度量驱动，窗口 = **2.5 × 字高** | `enhanceDocumentLuma()` |
| **P0-5** | 连通域五判据（bbox 面积 / 实心 / 长横线 / 长竖线 / 中间调密集）生成保护掩膜 | `buildProtectMask()` |
| **P0.5** | 自适应锐化：`sigma ≈ 笔画宽/2` + 梯度 p90 软门控 + amount 限幅 | `adaptiveSharpen()` |
| **P1** | 三模式（原图 / 增强 / 黑白）× 三强度（弱 / 中 / 强） | `image-superres.ts` + `image.service.ts` + `image.types.ts` |

管线顺序按 §五落地：**① 背景归一化 → ② 超分 → ③ 版面感知 → ④ 对比增强 → ⑤ 锐化 → ⑥（黑白）二值化**。
注意**超分在对比增强之前**——硬映射会永久损失灰阶，之后再超分没有意义。

### 10.2 实测结果（真试卷 1279×1706，`scale=2` → 2558×3412）

量化口径按 §六：**Δ = Otsu 分割后背景/前景均值差**（对应反馈①"对比度不明显"），**edgeP90 = 梯度幅值 p90**（对应反馈②"文字模糊"）。

| 档位 | Δ | vs 原图 | edgeP90 | 耗时 |
|---|---|---|---|---|
| 原图 | 60.2 | — | 17 | — |
| **legacy（旧行为）** | **60.9** | **+0.7** | 18 | 2448ms |
| 增强 / 弱 | 140.7 | +80.5 | 42 | 2558ms |
| **增强 / 中（默认）** | **177.7** | **+117.5** | **51** | 2630ms |
| 增强 / 强 | 194.7 | +134.5 | 55 | 2595ms |
| 黑白 / 中 | 204.6 | +144.4 | 58 | 2612ms |

**关键结论：旧行为 Δ 仅比原图高 0.7** —— 用数据复现了用户"和原图差别不大"的判断。新管线把 Δ 提到 **2.95 倍**、edgeP90 提到 **3 倍**，"修过感"从数值上成立。

非文档样本（App 截图 1080×2504，含大量 UI 色块）同步验证：Δ 126.1 → 172.8，**346 个 UI 块被判为图形区并保守保护**，未出现色块被压黑。

### 10.3 版面感知有效性（P0-5）

精确跟踪「原图灰度 110~165 的几何图灰填充像素」在结果中的归宿：

| 版本 | 灰填充被推黑比例 |
|---|---|
| 判据①修正前（用 ink 像素数） | 几何图**漏检**，灰填充几乎全被压成黑块 |
| 修正后（改判 **bbox 面积** + 新增判据⑤**中间调密集**） | **13.9%**（增强/中）、18.6%（黑白/中） |

### 10.7 黑白模式二值化修订（v6，2026-09-29，对照扫描王黑白输出实测）

**动机**：与全能扫描王黑白输出逐区域对齐对比（AKAZE 特征匹配 + 仿射对齐到同一坐标系，手写区剔除——手写由去手写模块专门处理，不在本模式范围内）发现两处差距：

| 指标（印刷内容，对齐后） | 扫描王 | 旧版 Sauvola(k=0.2) | 新版 全局Otsu+温和去噪 |
|---|---|---|---|
| 图形区中间调残留%（斑驳灰底） | 4.5 | **37.2** | **2.6** |
| 噪点（≤6px 连通域数） | 244 | 127 | **8** |
| 全页 ink% | 4.58 | 7.32 | 6.58 |

**根因**：Sauvola 的价值是抗阴影，但管线①的除法归一化已把背景精确拉到 255——抗阴影优势归零，短板暴露：平坦背景局部 σ≈0 → T = μ(1−k) ≈ 204，把灰度 100~204 的抗锯齿过渡像素**全部判黑**（笔画加粗粘连）；且保护区豁免二值化，把纸纹灰底原样留在图形周围（斑驳）。

**修订**（`binarizeBwPage()`，bw 分支专用；enhance/gray/brighten 不受影响，输出字节级一致）：

1. **Sauvola → 全局 Otsu**：归一化后双峰（纸白/墨黑）清晰，T 落谷底（实测 144）。前提是背景归一化在前——**若跳过归一化（legacy 路径），全局 Otsu 会因阴影失效**，故 bw 二值化依赖管线顺序。
2. **保护区不再豁免**：P0-5 保护的意义是"不在保留灰阶的模式里破坏灰阶"，对只剩 0/255 的黑白模式不成立；对齐扫描王行为（全页二值化、图形背景拉白、线条保留）。连续色调照片被二值化是用户显式选择黑白模式的预期代价。
3. **温和去噪**：⚠️ 实测教训——面积阈值 0.5·strokeWidth²（≈27px）会把 5×7px 的**逗号/句点一起删掉**（正文区 29 处标点消失）；扫描王本身保留 ~244 个小噪点，说明其去噪极轻。最终取 `max(3, 0.15·strokeWidth²)`（≈8px），标点面积 ≈0.5·strokeWidth² 留 3 倍余量。

**遗留**：笔画宽度（对齐后 2.74px vs 扫描王 1.91px）在修订前后不变——加粗来自二值化**之前**的预处理锐度（超分/锐化残留的宽过渡带），与二值化方法无关，属 P2/P3（文本专用超分/去模糊）范畴。手写铅笔字在全局 Otsu 下自然变浅，不做任何特殊处理（手写由去手写模块专门处理）。

### 10.8 黑白模式固定原分辨率输出（v7，2026-09-29）

**动机**：用户确认黑白图小尺寸预览「尺寸又小效果又好，可将其作为黑白的最终效果」。工程上成立——**黑白二值图做超分无意义**：二值化后仅剩 0/255 两值，超分只是对其插值，产生不了新细节，徒增体积（69KB→182KB）与耗时；且扫描王自身黑白输出（1050×1409）本就低于原图（1279×1706）。

**修订**（`image-superres.ts`）：

1. `EnhanceCtx` 新增 `lumaBase`（超分前的原分辨率归一化亮度）与 `metrics0`（原分辨率字符度量）。
2. `renderPreset`：`bw` 且 `scale>1` 时改用 `lumaBase + W×H + metrics0` 渲染。⚠️ metrics 必须用原分辨率版本——若误传 scale 后的 `metricsUp`，自适应膨胀/去噪阈值会被等比放大；另 `neutral=true` 时 `recombineToPng` 不读 `cbUp/crUp`，故原分辨率亮度与 2x 色度缓冲无尺寸冲突。
3. `enhanceImage`（单模式）preset=bw 时强制 `scale=1`，省去超分算力。
4. `enhanceImageModes({scale:2})` 下彩色类照常超分（enhance ≈6.6MB），bw 固定回落原分辨率（≈69KB，↓62%）。

**验证**：固定原分辨率后对齐复核与 scale=2 二值化版本指标完全一致（图形区斑驳 2.6%、噪点 4、ink% 6.60）——**质量零退化，纯赚体积与速度**。

### 10.9 高清扩展命名 + P2 引擎可插拔地基（v8，2026-09-29）

**「高清扩展」正式命名**：把 X2/X3/X4 超分从"默认核心超分"重新定位为**可选清晰度增强（高清扩展）**，与基础增强（背景归一化 + 对比增强）正交。黑白模式已固定原生分辨率（§10.8），故高清扩展只对彩色类模式生效——正契合"扫描全能王增强并锐化"的清晰度扩展语义。

**引擎可插拔地基**（P2 中期"换更强模型"的前提，`image-superres.ts`）：

1. `SRWeights` 新增 `family?: 'espcn' | 'classic' | 'tatt' | 'real-esrgan'` 字段，解除对 ESPCN 三层卷积的结构锁定（此前该结构直接阻塞 TATT/Real-ESRGAN 接入）。
2. 新增 `runSREngine(w, luma, W, H)` 统一分发入口：按 `family` 选前向；`espcn`/`classic` 正常分发，`tatt`/`real-esrgan` 未接入时**抛明确错误**（而非静默退化）。验证：`buildAnalyticESPCN.family='classic'` 正常、`espcn` 正常分发、`tatt` 接入点正确拦截。
3. `prepareEnhanceContext` 改用 `runSREngine`，调用点不变、向后兼容。

**量化增益与 P2 中期选型依据**（彩色增强模式，对齐后统一 900 宽）：

| 处理 | 输出尺寸 | Sobel RMS | 强边缘% |
|---|---|---|---|
| 原图 | 1279×1706 | 29.46 | 14.99 |
| 增强 s1（无高清扩展） | 1279×1706 | 75.64 | 27.28 |
| 增强 s2（高清扩展 classical） | 2558×3412 | 78.46 | 27.52 |

- **本质收益 = 输出分辨率 4×**（1279→2558），便于大屏/打印/后续 OCR 在更高分辨率下工作；
- **同尺寸清晰度增益仅 +3.7% RMS**——印证 §3.3「超分对清晰度贡献有限」。当前 `classical`（Lanczos+libvips 锐化）作为高清扩展已够用（提供分辨率提升），但**文字同尺寸锐度无法本质跃升**。
- **P2 中期方向**：要真正让文字"更锐"而非仅"更大"，应评估 **TATT / TSRN 文本专用超分**（候选项 A）——其文本边缘专门锐化，是 §3.3 所缺的那部分高频来源；Real-ESRGAN tiny（候选 B）通用但 GAN 伪影需警惕。两模型的接入点（`family` 分支 + 权重加载）已在 `runSREngine` 就位，待真·权重到位即可落地。

### 10.10 黑白成果反哺去手写：能复用的是「能力」不是「产物」（v9，2026-09-29）

> 用户提问：黑白模式（§10.7/§10.8）出图效果明显变好，拿这张"效果好的图"给去手写用会不会有帮助？
> 完整论证与落地见《去手写功能-方法论与技术方案》§5.2；此处只记**对智能高清自身的结论**。

**结论：有帮助，但复用对象是管线中间的"光照归一化能力"，不是末端的黑白图。**

实测（真实试卷 1279×1706，同一检测器只换输入 `detectBuf`）：

| detectBuf | 色域法（抓彩色笔） | 彩度 mean/max | 灰阶层次数 |
|---|---|---|---|
| (a) 原图无归一化 | 0.005% | 19.96 / 47 | 140 |
| (b) 归一化图【生产 P0-8】 | 0.011% | 24 / 54 | 103 |
| **(c) 黑白二值图** | **0.000%** ❌ | **0 / 0** ❌ | **2** ❌ |

- **彩度归零 → 蓝/红笔 100% 漏检**；**灰阶 103→2 级 → 深浅笔迹无从区分**。
- 深色法 6.568% > 5.656% 看似召回更高，实为二值化**拉粗笔画**导致的**过度检出**（笔画宽 2.74 vs 1.91px），是误报源而非增益。

**对高清自身的启示（与 §10.8 同源）**：黑白模式的"清晰"是**对人眼**的（对比度高、背景干净），但它是**为终端观感做过有损优化**的产物。任何"拿它当中转格式喂给下游算法"的想法都要先做上面这张表——**看判据还剩几个台阶**。二值图只剩 0/255，正如 §10.8 所说"额外处理都是在噪声上做文章"。

**复用落地（在去手写侧，见 §5.2）**：把 `normalizeIlluminationForDetection` 用到**修复侧**做局部底色（`buildLocalBackgroundMap`），真实试卷填充色距 **↓79.6% ~ ↓82.5%**，合成图 **↓86.7% ~ ↓87.4%**，非 mask 区一致性 99.92%~100.00%。并顺带修掉一个既有缺陷：彩色笔抗锯齿最外圈被误判为印刷体而搬运（蓝笔残留 2.30% → **0.00%**）。

**遗留 P1 候选**：结构延拓搬来的邻域像素带着邻域光照，跨光照梯度搬移仍有色差——可按 `(局部底色 / 邻域底色)` 做比例校正。
