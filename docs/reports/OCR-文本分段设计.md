# OCR 文本分段设计（阅读顺序 + 行→段落合并）

> 立项：思傅 2026-10-20 反馈「对 OCR 文字的识别分段当前不合理」。
> 原则：**能用引擎现成的成熟能力，就绝不自己造**；只有当引擎确实没有时才自研，且自研也要用业界成熟算法。
> 落地代码：`server/src/ocr/ocr-segment.ts`（分段核心）、`server/src/image/image.service.ts`（ocrPage 接线）、
> `ocr-engine/main3.py`（侧车契约）、`src/pages/recognize/index.tsx`（前端流程）。

---

## 1. 问题：一段就是一行

改造前，页面文本栏的数据源是**行级** `text_regions`，排序逻辑是自研的
「x 区间聚类分栏 → 栏内按 y 再按 x」：

```
toReadingOrderSegments(regions, cols)   // 每个 region 直接吐成一段
```

后果（用户视角）：

| 现象 | 原因 |
|---|---|
| 一道题的 4 行文字被拆成 4 段，勾选要点 4 次 | 段落 = 检测行，没有行→段合并 |
| 试卷有标题/正文/表格，全都一个样 | 版面语义（label）没用上，只用了行 |
| 多栏页交错（左1 右1 左2 右2） | 分栏依赖图像投影，漏检即退化成「按 y 再按 x」 |

同时，**必须先整页识别再人工挑段**的流程本身也在制造这个问题——详见 §5。

## 2. 既有成熟能力盘点（调研结论）

### 2.1 精准通道：PaddleOCR PP-StructureV3 —— **分段能力是现成的**

官方文档（[PP-StructureV3 Pipeline](https://www.paddleocr.ai/main/en/version3.x/pipeline_usage/PP-StructureV3.html)、
[PaddleX 3.5 教程](https://paddlepaddle.github.io/PaddleX/3.5/pipeline_usage/tutorials/ocr_pipelines/PP-StructureV3.html)）
明确说明 `parsing_res_list`：

- **列表顺序即解析后的阅读顺序**（"The order of the list is the reading order after parsing"）；
- 每个元素含 `block_label`（版面区域标签：`doc_title` / `paragraph_title` / `text` / `table` / `image` / `figure_title` …）、
  `block_bbox`（区域框）、`block_content`（**区内文本，多行整体**）、`block_id`、`block_order`（阅读序，非排序部分为 null）。

也就是说，**PP-StructureV3 一条管线就已经完成了：版面区域检测 → 区内行合并成段 → 阅读序排序**。
这三个环节恰恰是我们要做的一切。

> 项目侧车 `ocr-engine/main3.py` 早已把 `parsing_res_list` 取出来放进响应 `blocks`
> （`{label, bbox, order, num_lines, content}`），但 Node 侧只把它塞进 `layout` 字段当摆设，
> 文本栏却去用了行级 `text_regions` —— **成熟能力一直躺在响应里没被使用**，这才是「分段不合理」的根因。

**改造：直接用 `blocks` 作为段落。**（代码：`segmentsFromLayoutBlocks`）

### 2.2 快速通道：RapidOCR —— **确实没有分段能力**

RapidOCR 是纯 OCR（检测 + 识别）引擎，输出 `{text, box, score, quad}`，没有版面/段落概念：

- RapidAI 的版面分析是**独立包** `rapid_layout`（[文档](https://rapidai.github.io/RapidLayout/main/install_usage/how_to_use_other_engine)），
  本项目未引入，且会再加一路 onnx 模型（与「快速 = 1~3s」的定位冲突）；
- 社区通行做法就是自己在坐标上做：行聚类 → 行→段合并 → 阅读序（见
  [基于 RapidOCR 的 HTML 结构化实践](https://blog.csdn.net/weixin_31240035/article/details/164742089)：
  行归组阈值取行高中位数 ×0.6、段归组行间距阈值取行高中位数 ×1.5、块归组取段间距 ×2）。

**结论：快速通道必须自研，但要用业界成熟算法——Recursive XY-Cut。**

### 2.3 阅读序：Recursive XY-Cut（递归 XY 切分）

业界成熟且是**多栏阅读序的标准解法**：

- 递归地在 X / Y 投影的**最宽空白谷**处切分：竖切分栏 → 横切分段 → 叶子内排序；
- 等价于「先读完左栏再读右栏」的人工阅读顺序；
- 生产采用者：OpenDataLoader PDF（[XY-Cut++](https://opendataloader.org/docs/reading-order)，论文 arXiv:2504.10258）、
  pdf.oxide（[Reading Order & XY-Cut](https://pdf.oxide.fyi/docs/guides/reading-order)）、
  及各类文档解析管线（[工程实现参考：阈值与步骤](https://deepwiki.com/nathanfhh/nbp-web-gen/5.2-recursive-xy-cut-layout-analysis)）。

## 3. 采用的分段机制（两条路径，一个出口）

```
                 ┌─ 精准（PP-StructureV3）：blocks 非空 ──→ ① 版面块直通
buildSegments ───┤                                          （引擎已完成阅读序 + 行→段）
                 └─ 快速（RapidOCR）/ 块缺失 ─────────────→ ② 递归 XY-Cut + 行聚类
```

### 路径 ① 版面块直通（精准，`segmentsFromLayoutBlocks`）

1. 过滤空内容与不可读块（label ∈ {image, seal, chart, figure, background}）；
2. 按 `order` 排序（缺失时回退原始下标——引擎给出的列表顺序本身就是阅读序）；
3. **块内按题号细分**：块内容里若有 ≥2 行以题号开头（`1.`／`1、`／`(1)`／`一、`），
   按题号行切开——试卷常把多道题并成一个 text 块，不切开用户勾不了单题；
4. label → 段落语义类型（title / text / table / formula / other），连同 `lines`（段内行数）一起下发；
5. 题号细分可能打乱顺序，最后再按「栏 → 上 → 左」几何兜底排一次。

### 路径 ② 递归 XY-Cut + 行聚类（快速，`segmentsFromTextRegions`）

```
行级 regions
   │  ① 行合并：y 中心差 ≤ 0.6×行高中位数 → 同一物理行（空格拼接）
   ▼
物理行
   │  ② 递归 XY-Cut 定阅读序
   │     ├ 竖切：X 投影最宽空白谷 > 1.5×行高 → 先左栏后右栏
   │     ├ 横切：Y 投影最高空白区 > 0.6×行高 → 先上后下
   │     └ 叶子（切不动 / 深度 ≥6）：按 y 再按 x 排序
   ▼
阅读序行序列
   │  ③ 行→段：相邻行间隙 > 1.5×行高，或左边界跳变 > 2×行高，或行首是题号 → 断段
   ▼
段落（段内保留换行）
```

**关键阈值（全部是「行高中位数」的倍数 → 尺度无关，720p 与 4K、大字与小字结论一致）**

| 阈值 | 取值 | 用途 | 出处 |
|---|---|---|---|
| 行高中位数 | 所有行高取**中位数**（非均值，抗标题/脚注异常值） | 一切阈值的基准 | 社区实践 + XY-Cut 实现 |
| 同行判定 | y 中心差 ≤ 0.6 × 行高 **且** 水平间隙 ≤ 1.0 × 行高 | 被切断的同一行先合回来 | 社区实践（0.5~0.7）+ 本项目修正 |
| 行合并的水平相邻 | 水平间隙 ≤ 1.0 × 行高 | ⚠️ 缺它必错：两栏页左栏首行与右栏首行 y 常常完全对齐，只按 y 判同**行**会把左右两栏粘成一行，XY-Cut 还没切栏行就先跨栏粘死了 | 本项目实测发现并修正 |
| 竖切（分栏） | 空白列宽 > 1.5 × 行高 | 识别栏间沟 | XY-Cut 通行值 |
| 横切（分段） | 空白行高 > 0.6 × 行高 | 段间/块间空行；比常见的 0.3 保守，中文行内字距不会被误判成段间 | 本项目按中文排版实测上调 |
| 行→段间隙 | > 1.5 × 行高 | 间距突增即新段 | 社区实践（行间距 ×1.5） |
| 行→段缩进 | 左边界跳变 > 2 × 行高 | 缩进换段 / 右收尾 | 本项目实测 |
| 题号断段 | 行首 `1.` `1、` `1)` `一、`（**只认大题**） | 试卷「一题一段」 | 本项目场景定制 |
| 题号正则刻意排除 | `(1)` `（1）` 这类**括号小问**不算新题 | 否则一道大题的小问会被切成一堆碎段 | 本项目实测发现并修正 |
| 递归深度 | ≤ 6 | 防病态输入爆栈 | 工程护栏 |

## 4. 接口契约

`POST /api/image/ocr-page`

请求：

| 字段 | 类型 | 说明 |
|---|---|---|
| `image_url` | string | 页面图 / **裁剪出的题目图** |
| `mode` | `'fast' \| 'precise'` | 快速（RapidOCR）/ 精准（PP-StructureV3） |
| `rectify` | boolean（默认 true） | 是否先几何摆正；**传裁剪图时前端必须传 `false`**（见 §5.2） |

响应 `page_text[]`：

| 字段 | 说明 |
|---|---|
| `text` | 段落文本（段内保留 `\n`） |
| `box` | 段落包围盒 `{x0,y0,x1,y1}` |
| `col` | 阅读栏索引（单栏恒 0） |
| `kind` | `text` / `title` / `table` / `formula` / `other` |
| `lines` | 段内行数（1 = 单行） |
| `source` | `layout`（引擎版面块）/ `xycut`（行级 XY-Cut） |

## 5. 配套：错题提取改为「先裁剪，再识别」

分段再准，也救不了「整页流水账里挑段落」的流程。思傅 2026-10-20 拍板的流程：

```
选来源页 → 在题目卡片「＋裁剪题目」框出本题区域 → 对裁剪图 OCR → 勾选段落 → 「加入题干」
```

| 环节 | 实现 |
|---|---|
| ① 裁剪 | 题目卡片内「＋裁剪题目」→ 全屏裁剪器（`cropOnly`），目标题号全程显示在顶部（`🎯 图片将存入：第 N 题`） |
| ② 上传 | `purpose='save'` 正式归档（不用 temp，避免 24h 后被 GC 回收导致图片裂掉） |
| ③ 识别 | 裁完**自动对这张裁剪图跑一次快速 OCR**（1~3s）；也可手动点「识别本题（快速/精准）」 |
| ④ 归位 | 段落直接挂在该题卡片内，「加入题干」一步写入本题题干——不再经剪贴板、不再弹题号选择器 |

**为什么更合理**：文本与图片从一开始就同属一题（物理隔离代替人工辨亲）；
小图版面简单、字更大，识别本身也更准；用户勾的每一段都必然属于本题。

### 5.2 `rectify=false` 的必要性

ocrPage 原本无条件跑 `buildLayoutContext`（几何摆正：dewarp/纠偏）。
对**已经从摆正页图上切下来的正矩形小图**再摆一次，不但零收益，还会二次透视把小图拉塌
（历史故障：识别后图变成 37×39 裂图）。

故 ocrPage 增加 `rectify` 开关：裁剪图 OCR 一律 `rectify=false`，且不重新暂存对象（原 URL 直接用，省一次 IO）。
整页识别仍 `rectify=true`（并把页面图换成摆正图，用户后续裁剪即基于摆正图）。

## 6. 验证与后续

### 6.1 已验证（`dynamic-tests/probe-segmentation.ts`，2026-10-20 实测通过）

合成输入 = 两栏试卷：左栏「第 1 题（3 行）+ 第 2 题（2 行）」、右栏「第 3 题（2 行）」，
且右栏首行与左栏首行 **y 完全对齐**（最易诱发跨栏粘连的布局）。

| 通道 | 实测输出 | 结论 |
|---|---|---|
| 快速（XY-Cut） | 3 段：`题1(3行合并)` → `题2(2行合并)` → `题3(col=1)` | ✅ 顺序正确、行已合并成段 |
| 精准（版面块） | 3 段：`题1(大题+小问合并)` → `题2` → `题3`；`image` 块被剔除 | ✅ 小问未被误切、非文本块已排除 |
| 统一入口 | 有 blocks → `source=layout`；无 blocks → `source=xycut` | ✅ 分流正确 |

验证过程中暴露并修掉的两个真实缺陷（都是纸面推演看不出来的）：

1. **跨栏同行粘连**：左栏首行与右栏首行 y 对齐 → 被并成一行 → 顺序崩；修法：行合并加水平相邻约束。
2. **小问被当成新题**：`（1）25 × 4 ÷ 5` 命中括号题号 → 第 1 题的小问被切成独立段；
   修法：题号正则只认大题。

- 单元级：对已知「两栏 + 三道题」的合成图，断言 XY-Cut 输出顺序为「左栏题1→题2 → 右栏题3」，非交错；
- 端到端：手机拍一页卷子 → 裁第 2 题 → 卡片内应出现 1~3 段（该题的几行合成一段），不是十几行；
- 后续可选项：
  1. 快速通道若要更强的版面能力，可引入 `rapid_layout`（代价：多一路模型，不再 1~3s）；
  2. 竖排/古籍场景需把 XY-Cut 的切分轴顺序改为「先横切后竖切」；
  3. 题号细分目前只看行首，跨行的「题干 + 选项」结构尚未做层级归并（大题/小题）。
