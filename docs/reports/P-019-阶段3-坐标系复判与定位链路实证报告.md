## 1. 为什么必须复判

D-025 的专项验证用 **`identical` / `common_prefix` 逐字比对**判定「`parse_docx` 的 `plain` 流与 `text_content` 流不同源」，结论 14/24 不安全。

但 P-018 抠图主链路（`netdisk-inline-crop.py::main`）**从来不依赖逐字对齐**：

```python
ns_idx = [i for i, c in enumerate(clean) if not c.isspace()]
ns = ''.join(clean[i] for i in ns_idx)          # 全文去空白
...
ns_stem = norm(stem)                             # norm = re.sub(r"\s+", "", s)
q = ns.find(ns_stem)                             # 锚点重定位
p = ns_idx[q]; end = ns_idx[q + len(ns_stem) - 1] + 1
pre_ns = len(norm(clean[p:pp]))                  # 题内非空白字符数
off = offset_in_stem(stem, pre_ns)               # 映射回 stem 自身坐标
```

D-025 已确认的差异**全部是空白折叠**（`\n\n\n` vs `\n\n`、双空格 vs 单空格），而 `norm()` 会把所有空白抹掉。⇒ **逐字流比对是错误参照系**，它证伪的是一个 P-018 从不使用的不变量。

本轮改用链路真实口径做实证：直接 `import` 两个真相源（不复刻、不推断），拿**生产已写库的 28 份 `.doc` + 1,250 个真实 `question_objects`** 跑完整定位链路。

## 3. 六组判据实测

### 3.1 文字流同源（复判核心）

| 判据 | 结果 | 说明 |
|---|---|---|
| `raw_identical`（逐字） | **9 / 28** | 与 D-025 一致：逐字确实不同 |
| `norm_identical`（去空白逐字） | **15 / 28** | 看似只有一半，但见下 |
| `hf_chars > 0` 的文档 | **13 份** | 13 份**全部** `norm` 不一致 |
| `hf_chars = 0` 的文档 | **15 份** | **15/15 全部 `norm_identical=true`** |
| 13 份不一致的 `norm_prefix == nb_len` | **13 / 13** | `norm(clean)` 是 `norm(extract_docx)` 的**严格前缀** |
| `stemInHeaderFooter` | **0** | 无任何 stem 落到页眉页脚区 |

**结论**：document 正文部分的非空白字符流 **28/28 完全一致**；13 份的「不一致」纯粹是 `extract_docx` 把页眉页脚**追加在末尾**（逐字证据：`right635PAGE5PAGE`、`center635PAGE10PAG`、`www.youyi100.com`、`https://shop2078…`），首差异位置恒等于 `len(norm(clean))`。空白折叠差异 100% 被 `norm()` 抹掉。

⇒ **D-025 的「14 份明确错位」是判据错误，不是坐标系错位。** 需同步修正判据（补 `b_len>0 && max_offset>0`，见 §5 F1）。

### 3.2 重转稳定性（阶段 1 的 docx 产物用完即删，阶段 3 必须重转）

| 判据 | 结果 |
|---|---|
| 重转产物图对象数 == `doc_convert_done.drawing_count + object_count` | **28 / 28** |
| 重转 `extract_docx` 去空白流 == 写入 `text_content` 去空白流 | **27 / 28** |
| 写入 `text_content` 的 sha256 == `doc_convert_done.text_sha256` | ✅（异常样本单验 `db_matches_recorded=true`） |
| 异常样本两次独立转换文字流一致 | ✅ `two_passes_same=true` ⇒ **排除转换非确定性** |

**唯一异常 i=10**（`中考语文复习必考文言文解读全集（二）`，82,430 字，495 个 stem）根因已定位，不是猜：

- `db_matches_recorded=true` ⇒ 写库内容正确、记账钉子正确；
- `two_passes_same=true` ⇒ 两次重转逐字一致，LO 转换确定；
- 差异仅一处：写入流把「而不**知**人之乐」的「知」写成了 **2 个 `U+FFFD`**（`0xfffd 0xfffd` vs `0x77e5`），长度 82430 vs 82429；
- 即**阶段 1 CLI 文本序列化层的编码瑕疵**（记忆里「OCR 中文无 U+FFFD 才对」的同类问题），与坐标系无关；且该文档 `hit=495/495`、`miss=0`，链路未受影响。

⇒ 但它给出一道可自动拦截的闸门：**F0 同源闸门**（见 §5）。

### 3.4 🔴 新发现的真实风险：多重匹配会串题

`ns.count(ns_stem) > 1` 的 stem 共 **65 个**，集中在 5 份文档（i=8 有 29 个、i=9 有 18 个）。P-018 用 `ns.find()` 只取**首次**命中，若同一题干在试卷与答案卷重复出现，图会被插到错误位置。

**F2 消歧实证**（5 份重转，244 个对象）：

| 判据 | 结果 |
|---|---|
| `q_exp = len(norm(text_content[:char_start]))` 处逐字等于 stem | **244 / 244** |
| 存在与 `q_exp` 距离 0 的匹配 | **243 / 244**（1 个 stem 无匹配） |
| 唯一最近匹配 | **243 / 244** |
| 🔴 `ns.find()` 首次命中**不是**期望位置 | **3 个**（实证抓到会选错的位置） |
| 消歧后题干内图标记 | 100 |

⇒ `char_start` 消歧**可用且必要**：它把 3 个潜在错位纠正回来，且不改判定层、不改前端、不改 `question-match.ts`。

## 4. 结论：从「不通过」修正为「判据错 + 链路可用但需闸门」

🔴 **D-025 历史行保留不涂改**，本条作为新证据追加：其「阶段 3 硬门不通过」结论的**判据**（逐字同源）不适用于 P-018 真实链路。按真实口径复判，document 正文非空白流 28/28 同源、1,160/1,169 个有效 stem 命中、`offset` 越界 0。

🔴 **但抠图仍不放行**，因为暴露了 4 个必须闸门化的真问题：

1. 1 份写入流 `U+FFFD` 编码瑕疵（F0 可自动拦）；
2. 65 个 stem 多重匹配，`ns.find()` 实证选错 3 处（F2 可修）；
3. 28 个 `w:object` 被标 `formula` 但**性质未定**（F3 未做定性专项，**不得当公式**）；
4. `netdisk-inline-build.mjs` 候选 SQL 写死 `nf.ext='docx'`，扩到 `.doc` 属 L1 改动且触碰 P-018 现网链路（F4 需单独批准）。

⇒ 修法与逐题确认清单见独立专项提案 **`P-020`**，台账 **D-026**。**本轮未实现任何闸门、未写 `question_inline_figures`、未下发图。**
