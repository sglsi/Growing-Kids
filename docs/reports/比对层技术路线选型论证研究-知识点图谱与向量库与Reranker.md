## 0. 结论摘要

1. **前提成立，且已在代码中落地**：「给出适配度最高的 1~3 个选项」不是待调整的新目标，`server/src/shared/question-reference.ts` 的 `MAX_REFERENCES = 3` 就是它；`P-015`（D-018，2026-11-07 批准、11-08 实施完）已把目标从「原题 exact 命中」重锚为「给思路相近的例题 + 事先声明」。
2. **上一轮「明确排除」的作用域需要修正**：`P-025 §2` 与 `D-036` 把向量库 / Reranker / 知识点图谱写进「⛔ 明确排除」，其论证核心是**判定层**的目标函数（举证倒置、误判归零、来源唯一）。`P-015 §5` 的红线原文已修正为「**已授权对比参照与改设计方法；本期经评估仍不上向量库……后续可另立提案**」，且 §4 明列「向量 / 稠密召回、Reranker、知识点元数据与图谱……各需独立提案」。⇒ **判定层永久排除；参考例题层是「登记为后续独立提案方向」，不是禁止**。上一轮把它讲成全局结论，作用域讲宽了，本轮据台账修正。
3. **三者不是三选一，是同一条链路的三段**：向量库作用于「候选召回」，Reranker 作用于「Top-3 排序」，知识点图谱作用于「讲解组织」。所以「选一条」实际是「**先修哪一段**」。
4. **推荐：本地向量语义召回为唯一第一条落地路线**，且**度量闭环必须先于算法**。理由是代码与数据双重实证的瓶颈定位：当前参考例题只从「字面锚点命中的 ≤8 份文档」里挑，属「没看到」而非「排不好」；向量是三者中唯一扩池的，且作用域纯召回层、与判定层六闸零冲突。
5. **必须同时说清三条「不能」**：向量库**不**解决「讲通知识点 / 方法论 / 基本原理」（那是内容层，只有图谱对口）；**不**能证明自己变好（无 query 日志表、`review_events` 0 行）；**不**能碰判定层。
6. **大厂最值得借鉴的不是这三件里的某一件，而是「点击日志回流」这一环**——恰恰是我们没有的。算法可以借，闭环借不来，因此度量缺口比选型更优先。
7. 落地须另立 `P-026` + 台账 D 号 + 逐题拍板；本轮只给论证，给不出「有效」结论，也不宣称任何收益。

## 3. 三条技术在新目标函数下的重新评估

### 3.1 原理与落点（简要，详见上一轮口述与 `P-015 §1` / `P-025 §3③` 的行业资料）

| 技术 | 原理 | 在本链路的落点 | 产出形态 |
|---|---|---|---|
| **向量库** | 题干 / 对象编码为稠密向量，ANN（HNSW / IVF）召回语义近邻 Top-K，绕开字面差异 | **候选召回** | 一组候选 + 相似度 |
| **Reranker** | Cross-Encoder 对 (query, candidate) 逐对打分，把召回池重排 | **Top-3 排序** | 更靠前的 Top-K |
| **知识点图谱** | 题目 / 知识点 / 方法 / 原理构造成图（节点 + 属于 / 前置 / 同考点 边），按概念层级扩展与推理 | **讲解组织 / 标注** | 考什么、用什么方法、前置知识、可迁移到哪类题 |

行业可证实做法（`P-015 §1`、`P-025 §3③`）：作业帮 2020 Techo Park 四层检索架构；猿题库 QCon 2015 `Prepare→Split→CNN→NLP 纠错→分词/倒排/LTR(GBRT)→SIFT 插图匹配`；专利 `CN113505786A`（语义检索解决「题意一样文字不同」）、`CN111666474A`（整页按坐标拆题 + 题目向量化）、`CN119990146A`（稀疏 + 稠密向量召回 → Reranker 精排 → LLM 参考相似题生成讲解）、`CN121031565B` / 教育 RAG 综述（BM25 + 向量 + 知识图谱 + RRF + Reranker，元数据硬过滤）；阿里云《开放搜索教育搜题能力和实践》（AND + 向量召回，厂商自述准确性反超 OR 3–5%、召回文档减 40 倍、延迟降 10 倍）；夸克「检索刹车」。⚠️ 上述数字均为**厂商公开口径，非本项目实测，不作效果证据**；三家排序特征、阈值、模型版本均不公开。

### 3.2 逐条论证

#### 向量库 —— 推荐首选

- **对症度（最高）**：§2.1 的瓶颈是「没看到」，§2.2 的失配是字面层。语义召回同时解决两者：把「4 个字面锚点命中 ≤8 份文档」变成「全库语义近邻 Top-K 对象」。行业专利 `CN113505786A` 的存在本身就说明「题意一样文字不同」是通用解法对象。
- **作用域最干净**：只作用于参考例题层的召回通道，**不产生、不改写 `answer` / `verified` / `canAdopt`**；`question-match.ts` 六闸与 `judgeWithStore()` 主链路零改动。这与现行红线「召回变宽 ≠ 放行变宽」不冲突——因为参考例题层本来就不做放行。
- **可用候选池比想象小**：只需 embed `has_solution=true` 且解析去空白 ≥60 字、`link_status='ok'` 的对象，**上界 144,316 行（21.97%）**，不是 65.7 万。精确值需只读复测，本轮不外推。384 维 float32 向量本体 ≈ 144,316 × 384 × 4 B ≈ **211 MiB**；768 维约 423 MiB；加 HNSW 图开销，常驻量级约 **0.2–0.5 GB**（纯算术估算，**未实测**，不含模型常驻与查询开销，须实测 `MemAvailable` 后定）。
- **合规可控但为硬约束**：题干属未成年人作业内容。必须**本地 embedding 推理**，禁止把题干外发云端 embedding API、禁止引第三方 SDK（否则触发 `P-025 F4` 隐私否决，涉 PIPL §28/29 与政策 r8）。离线批量建索引须遵守 L3 批量铁律（worker ≤2、批 ≤2、`ionice -c3 nice -n19`、`systemd-run` 限 `MemoryMax` / `CPUQuota`、每批查 `MemAvailable`），或**在别处算好只投索引文件**。
- **P95 可控的前提是架构**：当前 P95 已 3.44s 且主段在 L0 候选池，绝不能把 embedding 推理加进在线主链路。必须**离线预计算 + 在线仅一次 query embedding + ANN 查询**，且走**旁路独立通道**喂 `referencePools`，与主深挖链路并行或异步，带超时预算与降级（查不到回退现行共现召回）。
- **不解决什么**：见 §4.2。

#### Reranker —— 条件性后续，不宜第一条

- **依赖上游池**：它不产生新候选，只重排。当前池是「≤8 份文档的 rows」、`MIN_SHARED_SIGNALS=3` 后才剩少量，重排天花板极低。**先给一个没看到对题的池子精排，是典型的次序颠倒**。
- **成本**：每候选一次交叉编码推理，L3 4C4G 单机、P95 已超标，在线延迟压力大；本地化与隐私要求同向量。
- **训练 / 校准无燃料**：行业 Reranker 靠点击日志训 LTR（`P-025 §1`）。我们无 query 日志表、`answer_cache` 0、`review_events` 0 ⇒ 只能上预训练通用模型，无法针对本项目校准，也**无法证明它比现行 `sharedSignals.length` 排序更好**。
- **定位**：向量召回跑通、形成稳定候选池并有独立盲测样本之后，作为阶段 3 单独提案。

#### 知识点图谱 —— 最贴「讲通」，但最重，不宜第一条

- **唯一对口 B 层**：思傅要的「知识点、方法论、基本原理、融会贯通」，本质是结构化讲解内容，只有图谱 / 结构化标注能直接表达「考什么、用什么方法、前置是什么、能迁移到哪」。
- **但表结构零支撑**：`migrations/0026_question_objects.sql` 的字段只有 `stem_text` / `solution_text` / `has_solution` / `label` / `char_start|end` / 指纹 / `source_revision` / `link_status` / `engine_version`，**没有任何知识点、题型、难度、学科、年级字段**；`label` 是切题题号标签，且 Top 重复组 `"10"`×1273 说明题干切分本身还有噪声。
- **成本结构不同**：图谱不是「接一个算法」，而是「建本体 + 给 65.7 万对象打标 + 持续维护」；且 `has_solution` 仅 21.97%，自动打标在不规范题源上噪声大，人工标注面更小。
- **治理最重**：「同考点推荐 / 该练什么 / 知识路径」会触及学习行为，须过 `GK-SRS-20a §5.1` 三问（Q1 量级 ≥0.3 / Q2 覆盖 / Q3 可测）与 §6.2 M 系列准则；按 M10 / §5.5，若 Q3 不可测必须诚实降级为「不宣称、不做指标」。`P-015` 明确「本轮不改任何学习行为，故不过 §5.1 三问的新增项」——**图谱会打破这个前提**。
- **定位**：阶段 4 长期内容层；且必须先有 A 层（选对题），否则等于给错的题配更完整的讲解。

### 3.3 决策矩阵

| 维度 | 向量库 | Reranker | 知识点图谱 |
|---|---|---|---|
| 解决的目标层 | A · 选对（扩池） | A · 选对（排序） | **B · 讲通** |

## 4. 为什么选向量库，以及它不能解决什么

### 4.1 五条理由（按证据强度排序）

1. **瓶颈定位是代码事实，不是推测**：§2.1 的 `referencePools` 只来自 ≤8 份文档。三者中只有向量扩池。
2. **题源不规范是数据事实，且字面方案已自认到顶**：§2.2 的 8.05% / 10.69% / `U+FFFD` 与 `P-015 §6` 的「精确滑窗几乎命不中」互相印证；58 词手写表是权宜之计，语义表征是它的自然升级，不是换赛道。
3. **作用域与现行红线完全兼容**：判定层六闸、举证倒置、`answer:''` / `verified:false` / 无采纳 / 事先声明四条不变量都可原样保持；「召回变宽 ≠ 放行变宽」这条红线在参考例题层根本不构成约束。
4. **已有合法入口**：`P-015 §4 / §5` 明确登记为「后续独立提案方向」，`P-025 §2` 写的是「各需独立提案」而非「永久禁止」。⇒ 重开路径清晰，不需要推翻任何既有决策。
5. **是另外两条的必要上游**：先有稳定候选池，Reranker 才有意义；先能选对题，图谱的讲解才有落点。选它不会堵死后续路线。

### 4.2 三条「不能」（必须写进任何后续提案）

1. **不能解决「讲通」**：向量只改变「给哪 3 道」，卡片内容仍是「另一道题的题干 + 解析」。要实现思傅说的「知识点、方法论、基本原理、融会贯通」，需另立讲解层（图谱 / 结构化标注 / 讲解模板），且须过 20a 三问。**别把 A 层改善写成 B 层达成**。
2. **不能证明自己变好**：无 query 日志表、`answer_cache` 0、`review_events` 0 行且 D-036 已实证「0 行是出数条件问题、不是代码缺失」。按 20a §5.5，代理指标不得作成功证据；`P-025 F5` 把「计算召回率 / 准确率、把行业命中率当误判归零」定为结论作废。⇒ **度量闭环必须先于算法**，见 §6。
3. **不能碰判定层**：`question-match.ts` 一行不动、`strict=1`、第二层上线准入、P0 六闸串联否决、`CACHE_VERSION v14` 契约——全部不动（`P-025 F6/F7`）。

### 4.3 大厂真正值得借鉴的一条：闭环，不是算法

`P-025 §1` 已把行业链路概括为「高召回 → 多路召回 → 两阶段排序 → **TOP3–5 给用户自确认 → 点击日志回流训练**」。思傅「完全匹配对头部大厂也艰巨」的判断，与 `P-015 §1` 引用的专利 `CN119990146A` 论断一致：「试题库规模必然是可穷尽的，其时效性、准确性都不能完全保证」⇒ `exact=0` 是行业常态，不是本项目独有缺陷。

但大厂链路的**燃料**是日志回流：点击 / 采纳 / 停留 / 后续作答持续校准词权重与排序模型。我们目前三样都没有。⇒ **照搬算法容易，复制闭环不可能**；所以最该先补的是「怎么知道变好了」，这正对应 `P-025` 的 J2 / Q3 与前后对照协议 v1.0。这也解释了为什么 `P-025 Q1` 推荐「数据侧优先」——与本轮结论同源。
