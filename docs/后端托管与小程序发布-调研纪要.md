## 1. 扣子时代「没备案也能跑」的真实机制（2026-10-19 实证）

用户此前的印象是"自托管 NestJS 且未备案也能运行"。考证仓库证据后澄清——**当时并非自托管，也没有任何绕过手段**：

### 1.1 后端跑在扣子平台基础设施上

仓库根目录 `.coze`（扣子项目清单文件）：

```toml
project_type = "miniprogram"
template = "taro"

[deploy]
build = [ "bash", ".cozeproj/scripts/deploy_build.sh" ]
run   = [ "bash", ".cozeproj/scripts/deploy_run.sh" ]
```

NestJS 由扣子平台构建、运行、提供对外域名（`COZE_PROJECT_DOMAIN_DEFAULT`，构建时注入前端 `PROJECT_DOMAIN`）。服务器与域名均为扣子所有，平台域名由平台方备案——**用户侧无需备案任何东西**。

### 1.2 小程序全程只有开发版

旧 `project.config.json`（合并前基线）：

```json
{ "appid": "touristappid", "setting": { "urlCheck": false } }
```

微信官方规则：开发者工具关闭域名校验后，模拟器可请求任意 http/https 地址，**合法域名白名单与备案规则不生效**——这是开发阶段的正式豁免。用户已确认扣子侧仅到「开发版」，从未发布体验版/正式版。

### 1.3 扣子预览通道不是微信客户端

扣子 IDE 预览为扣子自建 WebView 容器，不走微信域名策略；扣子作为第三方平台服务商（曾占"小程序开发与数据分析"授权）代管上传。

> **借鉴**：判断一个"当年怎么跑起来的"问题，先分清「平台托管 / 自托管」与「开发版 / 体验版 / 正式版」两个维度，多数"豁免"只是未进入受限场景。

## 2. WorkBuddy 域名为何不能当小程序 API 后端（2026-10-19 线上实证）

### 2.1 现象

小程序（DevTools 与真机同）请求 `https://growing-kids.app.workbuddy.host/api/*` 一律 **403**；`curl` 同地址全部 **200**。

### 2.2 定位过程（全部可复现）

| 测试 | 结果 |
|---|---|
| 无特殊头 curl | 200 |
| `Referer: https://servicewechat.com/...` | 200 |
| `User-Agent: Mozilla/5.0 wechat miniprogram` | 200 |
| **`User-Agent` 含 `MicroMessenger`** | **403**（3/3 确定性，非限流） |
| 空 UA | 200 |

403 响应体标题为「**请在浏览器中打开**」，带腾讯网关头 `Acp-Connection-Id`。后端源码 0 处 `ForbiddenException`、无全局 guard/限流（`app.module.ts` 仅中间件）。

### 2.2b 2026-10-20 换新域名后复测（同一结论，排除偶发）

迁移到 `d02753307b5b4364b073bee6f42a4e70.app.workbuddy.host` 后重跑，四组对照：

| UA | http_code |
|---|---|
| iPhone 真机完整 UA（含 `MicroMessenger/8.0.49` + `MiniProgramEnv/iPhone`） | **403** |
| `GrowingKidsSmoke/1.0`（普通 UA） | 200 |
| 仅 `MicroMessenger/8.0.49` | **403** |
| 不带 UA | 200 |

⇒ 拦截判据就是 **UA 是否含 `MicroMessenger` 子串**，与域名、路径、Referer 无关。403 体为「请在浏览器中打开」HTML，非后端产生。

### 2.3 结论

`app.workbuddy.host` 是 **WorkBuddy「应用发布」的浏览器分享链接通道**，边缘网关拦截微信 UA。微信 `wx.request` 固定携带 MicroMessenger UA 且基本不可覆盖 → **小程序无法连接部署在该域名的后端**。

叠加约束：即便无 UA 拦截，正式小程序后端域名必须进 MP 后台「request 合法域名」（要求 HTTPS + 域名所有者可验证 = 需 ICP 备案），平台子域无法验证所有权 → **本来就不能当生产小程序后端**。

> **借鉴**：小程序后端选型先过两关：① 目标域名是否拦截微信 UA；② 能否进入合法域名白名单（备案 or 腾讯官方域名 or callContainer）。

## 3. 三个后端托管方案对比（2026-10-19 官方资费）

### 3.1 Supabase（现状：数据库在用，新加坡区）

| 维度 | 结论 |
|---|---|
| 数据库（Postgres） | ✅ 可用，后端经 `@supabase/supabase-js` 直连，服务端密钥走 `.env` |
| API 层（NestJS） | ❌ **不可行**：Edge Functions 为 Deno 短函数，无长驻进程；本项目后端 63 个 ts / 21 模块，含 `@nestjs/schedule` 定时任务、`multer` 上传、`pdf-lib`/`docx` 生成，均依赖长驻/重 CPU |
| 域名/备案 | ❌ `supabase.co` 境外域名无 ICP 备案，进不了白名单（自定义域名也需自有备案） |
| 延迟 | ⚠️ 新加坡区→国内 100ms+，适合数据库、不适合 API 入口 |

### 3.2 微信云托管（CloudRun）——推荐

**计费（官方刊例，按量付费，先用后付）**：

| 计费项 | 单价 | 首个环境免费额度（3 个月） |
|---|---|---|
| CPU | 0.055 元/核·小时 | 720 核·小时 |
| 内存 | 0.032 元/GB·小时 | 1440 GB·小时 |
| 构建时长 | 0.05 元/分钟 | 600 分钟 |
| 公网出流量 | 0.8 元/GB | 5 GB |

**本项目估算**：NestJS 容器 0.5 核 / 0.5G 常驻（最小副本 1 防冷启动）≈ CPU ¥20/月 + 内存 ¥12/月 + 构建/流量 ≈ **¥30-40/月**；最小副本设 0 时按量计费，月费几元~十几元。

**适配性**（官方定位"传统后台服务平滑迁移、无需改造"）：
- ✅ 任意语言/容器/Dockerfile，NestJS 编译 `dist/main` + 读 `PORT` 即可（本项目已具备）
- ✅ 只支持 HTTP 域名调用、不跑有状态服务 → 与"NestJS 容器 + 外部 Postgres"架构完全匹配
- ⚠️ 容器无持久化存储 → 文件必须走对象存储
- ⚠️ CallContainer 超时 ≤15s、请求体 ≤100K（不带图片）

**⚠️ 「3 个月免费」怎么找 / 两个易混淆点（2026-10-25 复核，活动仍有效）**：
- 它**不是营销活动页**，没有领券入口——是「首个环境」自动赠送的额度，**建好第一个环境后**在
  「微信云托管控制台 → 费用中心 → 充值与账单」里才能看到余量。官方定价页（developers.weixin.qq.com
  → 微信云托管 → 产品计费 → 产品定价）有刊例表。
- **三个产品别走错门**：本额度属于**微信云托管 CloudRun**（cloud.weixin.qq.com，容器平台）；
  隔壁**微信云开发 CloudBase**（同域 /cloudbase）是另一套 BaaS，其新用户优惠是「免费云环境
  40,000 资源点/月、可体验 6 个月」；**腾讯云**（cloud.tencent.com）又是第三个 console，三者不通用。
- **额度账要算清**：720 核·小时 ÷ (24h×90天) ≈ **常驻只能开 0.33 核**。0.5 核常驻 3 个月需
  1080 核·小时，超 360 核·小时 ≈ 超支 ¥19.8；0.25–0.3 核常驻可零费用跑满 3 个月（内存 0.5G
  常驻 1080 GB·小时 < 1440 额度 ✅）。且**仅首个环境赠送**，开生产/预发第二个环境即按刊例计价。

### 3.3 WorkBuddy cloud-service（BaaS）

**费用**（无独立价目，消耗 WorkBuddy 订阅套餐「单应用资源额度」）：

| 套餐 | 月费 | 连续包月 | 单应用资源额度 | 可托管应用 |
|---|---|---|---|---|
| 体验版 | 免费 | — | 5,000 | 10 |
| 标准版 | ¥99 | ¥70 | 25,000 | 30 |
| 高级版 | ¥199 | ¥140 | 50,000 | 50 |
| 旗舰版 | ¥999 | ¥700 | 150,000 | 99 |

**能力边界**（与 Supabase 同类的 BaaS，非容器平台）：
- 四模块：数据库（文档型 CRUD）/ Auth / Storage / LLM API（免密钥大模型）
- ❌ 无容器/云函数/长驻运行时 → **NestJS 无法部署，"迁移"= 将后端业务重写成前端直连 BaaS**
- ❌ 文档型数据库 ≠ Postgres（drizzle schema 需重设计）
- ⚠️ 数据平面绑 WorkBuddy 应用发布域（endpoint + Origin 校验）→ 发布命脉绑死 WorkBuddy 小程序通道（2026-10 时该通道沙箱仍报"依赖安装失败"）
- ✅ 独有优势：LLM API 免密钥（可补后端 AI 三件套在扣子外不可用的坑）

### 3.4 三方横评

| | Supabase | 微信云托管 | WorkBuddy cloud-service |
|---|---|---|---|
| 月费 | 库已用 | ¥0(3 月免费)→~¥35 | ¥0 体验→¥70-99 |
| 后端代码 | 不可部署 | **原样 ~90%** | **重写** |
| 备案/域名 | 不可 | 免（callContainer） | 免 |
| 发布通道 | — | 微信官方自主 | 绑 WorkBuddy |
| 数据 | Postgres 现成 | 外连 Supabase 即可 | 文档型重设计 |

### 3.5 WorkBuddy 云服务的小程序专用通道（2026-10-20 新发现）

读官方 `cloud-service` 技能 `references/mini-program/routing.md`（C2 节）得到两条此前未知的事实：

1. **小程序不用应用自己的域名，而是固定网关**
   `publicConfig.endpoint` = `mp-api.app.workbuddy.host`（生产）/ `mp-api.app-staging.workbuddy.host`（staging）。
   原因：微信 request 合法域名不支持通配、且有条数上限，按应用分配域名无法规模化，故所有小程序共用这一个已备案网关。
2. **发布流程自动注册白名单**（关键）
   原文：「The same host is registered **idempotently** in WeChat's request / upload / download allowlist **by the publish flow before the code is uploaded**, so a release needs no manual domain setup.」
   ⇒ 这解释了 MP 后台显示的「服务器域名已托管给第三方」——本项目的第三方平台正是 **WorkBuddy 小程序三方服务商**，域名管理权在它手里，用户无需、也无法在 MP 后台手动改。

**但能力边界没变**：云服务只有 Database / Auth / Storage / LLM 四模块，**没有容器、没有云函数、没有长驻运行时**。
本项目后端 63 个 ts / 21 模块（NestJS + `@nestjs/schedule` + multer + pdf-lib/docx + Python OCR 侧车）**无法部署上去**，
「迁过去」实质等于把后端业务重写成前端直连 BaaS，且文档型库要重设计 drizzle schema。

> 文档同时警告：不要直接 curl 探测该网关、不要据直连结果改写 `endpoint`——网关只转发带 `publishableKey` + `Referer: https://servicewechat.com/{appid}/...` 的签名请求，
> 裸请求回落到「链接已失效 / 该应用尚未发布」是**预期行为**，不是域名错误。

### 3.6 腾讯云轻量应用服务器（VPS）路线（2026-10-25 思傅撞见 1.4 折活动，评估后补记）

**是什么**：腾讯云轻量应用服务器（Lighthouse）= 管理型 VPS，开箱即用、自带快照与一键升配。
思傅看到的的活动页规格：**4核4G3M / 上海 / 1 年 / ¥109**（1.4 折，新用户**首单限 1 个**，日常价 ¥780/年；
官方活动页同页声明「国内套餐实例**续费低至 5.5 折**」≈ ¥429/年）。

**与本项目的匹配度**：

| 维度 | 结论 |
|---|---|
| 跑 NestJS | ✅ 原样跑（有 root）；且 **Docker Compose 可用** ⇒ OCR 侧车可独立容器（云托管必须打同一个 1.5-2GB 镜像，见 §5.6） |
| 性能 | ✅ 4核4G 跑 NestJS+PaddleOCR 余量很大；持久化磁盘，文件可落本地 |
| 长期自主 | ✅ 后期可把 Supabase 也搬上来自建 Postgres，基础设施全自持 |
| **备案** | ❌ **硬门槛**：小程序生产环境 `wx.request` 合法域名要求域名 ICP 备案（大陆服务器），个人备案 **7-20 个工作日**且部分省份受限 ⇒ **买了也不能立刻上线**，必须先启动「域名注册 + 备案」长链路 |
| 运维 | ❌ 全自管：Node/Python/OCR/证书/备份/安全更新；无自动扩缩容；VPS 常驻计费，做不到云托管那样缩容到 0 |
| 流量 | ⚠️ 月流量包有限（以套餐页为准）；日后图片若也从服务器出，3M 带宽是瓶颈（当前图片在 Supabase，不受影响） |

**三年成本对比**（4核4G3M VPS vs 云托管 0.5 核常驻）：

| | 轻量服务器 | 微信云托管 |
|---|---|---|
| 第 1 年 | ¥109（另加域名 ~¥55/年） | ¥0（3 个月免费额度） |
| 第 2-3 年 | ~¥429/年 × 2 | ~¥35/月 × 24 ≈ ¥840 |
| 三年合计 | ≈ ¥1,130 | ≈ ¥1,155 |
| 备案 | **必须**（7-20 工作日） | 免（callContainer） |
| 运维负担 | 全自管 | 平台托管 |
| 架构灵活性 | Compose/持久盘/可自建 DB | 单端口单镜像/无持久盘 |

**结论**：两者**成本同量级**，差别是「备案 + 自运维」换「完全自主 + Compose 灵活」。
- 想**最快上线给真实用户** → 云托管，服务器不买；
- 愿意运维、接受备案周期、想长期自持基础设施 → ¥109 这台**可以买**（首单折扣一次性，服务器本就是将来要用的，不算浪费），但**买完第一件事 = 注册域名 + 提交备案**（最长链路先启动），第二件 = 按 §5 清单评估 Compose 部署；
- ⚠️ 唯独不要「因为 1.4 折便宜」而买——它不解决当前任何 blocker，备案没走完之前上不了生产。
- 附：同活动页有境外（首尔）¥199/年套餐可免备案，但延迟与稳定性不适合生产，仅适合试验。

### 3.7 结论（2026-10-20 定稿，2026-10-25 增补 VPS 路线）

| 需求 | WorkBuddy 云服务 BaaS | WorkBuddy 站点托管（现状） | 微信云托管 | 腾讯云轻量服务器（VPS） |
|---|---|---|---|---|
| 跑 NestJS + Python OCR | ❌ 无计算运行时 | ✅ 能跑 | ✅ 能跑 | ✅ 能跑（Compose 更灵活） |
| 域名进白名单 | ✅ 发布自动注册（免配置） | ❌ 未备案，加不进 | ✅ callContainer 免域名 | ⚠️ 需域名 + **域名 ICP 备案**（7-20 工作日，⚠️ 与已通过的小程序备案**无关**，见 §8.1） |
| 微信客户端可达 | ✅ 固定网关 | ❌ **UA 含 MicroMessenger → 403（实测）** | ✅ 微信私有链路 | ⚠️ 备案完成后可（wx.request 走白名单） |
| 运维负担 | 平台托管 | 平台托管 | 平台托管 | **全自管** |
| 定位 | 只能替代局部（DB/Auth/存储/LLM） | 浏览器联调后端 | **免备案全量方案（首选）** | 备案后的全量自主方案（见 §3.6） |

## 4. 免备案上真机的正规路：云托管 + `wx.cloud.callContainer`

官方文档（developers.weixin.qq.com/minigame/dev/wxcloudrun）原文要点：

- 「小程序/公众号可使用 CallContainer，**无需域名，因此不需要在 mp 管理后台配置服务器域名，从而一开始就无需申请域名，也无需备案**。」
- CallContainer 请求自动携带 openid 等登录态（后端匿名身份/微信登录逻辑可简化）
- ⚠️ 注意区分：普通 `wx.request` 打云托管默认公网域名**仍受 request 合法域名限制**（官方明示默认公网域名仅限接口测试、不能配进小程序后台）。2025 年真实踩坑文结论一致：**必须把请求层改成 callContainer 才能真正摆脱白名单。**

## 5. 云托管迁移清单（待实施）

1. **前端请求层**（`src/network.ts`）：增加 callContainer 通道 + wx.request 降级（能力探测 + 环境 ID/服务名配置）
2. **文件上传**：`multer` 收容器不可行 → 图片改对象存储直传（后端 upload/image 模块改造）
3. **定时任务**：`@nestjs/schedule` 在实例缩容到 0 时不触发 → 常驻实例或挪云函数 cron
4. **数据库**：暂留 Supabase（容器走公网连，出流量 0.8 元/GB，可忽略）；后期要降延迟再迁腾讯云。
   **⚠️ 2026-10-25 复核补记——Supabase 跨境延迟的完整解法（按推荐序）**：
   - **云托管不限定数据库位置**（容器无持久盘，但网络可达即可；`@supabase/supabase-js` 只是 HTTP 客户端，连接串指向哪都行），所以不存在「必须外连」：
   - **① 轻量服务器自建 Postgres（成本最低，推荐给家庭级应用）**：那台 4核4G 的机器就能跑；
     云托管服务设置里配 **VPC 私有网络**（官方文档《服务设置》§7：启用后可通过 VPC 内网 IP/内网域名访问
     「数据库、Redis 等」腾讯云私有网络资源）→ 同地域同 VPC 内网互通，RTT 从跨境 100ms+（实测高峰
     可达 1.5s）降到 <1ms。代价 = 自己管备份（pg_dump 定时 + 异地副本）与故障恢复。
   - **② TencentDB for PostgreSQL 托管版（零运维，约百元/月量级）**：同样走 VPC 内网互联
     （官方《内网调用腾讯云其它数据库资源》文档）；Postgres→Postgres 迁移无损（pg_dump/pg_restore，
     schema 原样）。这就是《迁移到腾讯云-方案与步骤.md》里既定的第二步，云托管 + 云数据库同地域部署即可。
   - **③ 微信云托管自带 MySQL**：计价表里有，但 Postgres→MySQL 是伤筋动骨的迁移（JSONB/57 处查询），**不选**。
   - **④ 继续 Supabase + 缓解**：Supavisor 连接池（6543）+ 现有 mem-cache/SWR 能挡住一部分，
     但跨境链路本身不稳定（晚高峰丢包），治标不治本。
   - 备注：VPC 配置入口 = 云托管控制台 → 服务 → 服务设置 → 私有网络设置；若环境版本看不到该入口，
     需确认账号/环境是否支持（早期社区反馈个人版环境受限，以控制台实际为准）。
5. **后端打包**：Dockerfile / 代码包部署，端口读 `PORT`（已支持）
6. **容器要同时装 Node + Python**（2026-10-20 补充）：云托管**不支持 Docker Compose、一个服务只能开一个端口**，
   而本项目后端依赖 Python OCR 侧车（`ocr-engine/`，已有自己的 `Dockerfile`，依赖含 paddleocr/rapidocr + onnxruntime）。
   ⇒ 需把 NestJS 与 OCR 侧车打进**同一个镜像**（启动脚本拉起两个进程），镜像预计 1.5–2 GB，冷启动会明显变慢。
7. **图片链路改造**（官方推荐模式）：`callContainer` 请求体文本 ≤100 KiB（二进制 ≤20 MiB）、返回 ≤1000 KiB、超时 15s，

## 7. 多云适配度评估（2026-10-25，微信云 / 阿里云 / 百度云 / 运营商云）

本项目选型的约束按重要性排序：**① 微信小程序后端免备案通道（callContainer 只有微信云托管有）→ ② NestJS 长驻 + OCR 重 CPU + 定时任务（容器平台）→ ③ 国内延迟 → ④ Postgres 内网可达 → ⑤ 成本（¥0-50/月）**。

| | 微信云托管 | 阿里云 | 百度云 | 运营商云（天翼/移动/联通） |
|---|---|---|---|---|
| callContainer 免备案 | ✅ **独占** | ❌ | ❌ | ❌ |
| 微信生态协同（openid 透传/服务通知） | ✅ 原生 | 手动 | 手动 | 手动 |
| 容器产品成熟度 | 中（单端口/单镜像限制） | **高**（ACK/ASK 全家族） | 中（CCE 可用） | 中低 |
| 国内节点与延迟 | ✅ | ✅ | ✅ | ✅ |
| 数据库内网可达（PG） | ✅（VPC 配置，见 §5.4） | ✅（RDS PG） | ✅ | ✅ |
| 与混元生态协同 | ✅ 同生态 | 跨云调用 | 跨云 | 跨云 |
| 开发者生态（文档/SDK/社区） | 微信场景强 | **最强** | 弱 | 弱 |
| 结论 | **首选**（约束①只有它满足） | 愿意备案后的第二选择 | 无差异化优势 | 仅政企合规/特殊价格时考虑 |

**结论**：不是因为技术最强，而是**约束①（免备案 + 微信生态原生）只有微信云托管满足**；若未来愿意备案且要更强基础设施能力（多产品线、可观测性、编排），阿里云是合理的第二选择（届时 callContainer 优势消失，拼产品成熟度）。百度云与运营商云对本项目无差异化优势。
**计费拆细的逻辑**（答"为什么分这么多种计费项"）：每类资源成本结构不同——CPU/内存是时间资源（实例活着就烧钱，与忙闲无关）按核·小时；流量是带宽资源按 GB；构建是 CI 机器时间按分钟（防滥用 + 引导用户自管镜像）；存储是空间×时间按 GB·天；操作次数有固定机器开销（数据量为 0 也花钱）按万次。拆得越细，**用户越只为真实消耗付费、能逐项优化，平台越能精确覆盖成本、提高多租户资源周转**（也是敢送 3 个月免费额度的底气——多数试用者根本用不完）。代价是账单复杂度，需盯费用中心。

## 8. 2026-10-29 增补：小程序 ICP 备案通过后的状态更新与最新建议

### 8.1 一条必须先分清的事：两条备案，两把不同的锁

2026-10-29 小程序 ICP 备案通过（**陕ICP备2026030931号-1X**），最容易误读成"备案搞定了，后端也能上了"。**不是。** 这是两条完全独立的链，锁的是两件不同的事：

| | 小程序 ICP 备案 | 域名 ICP 备案 |
|---|---|---|
| 备案对象 | 小程序本身（名称、服务内容、主体信息） | 域名 + 其接入的大陆服务器 |
| 提交入口 | mp 后台（备案专项入口） | 域名接入服务商（腾讯云/阿里云等）→ 管局终审 |
| **解锁什么** | **能否提交代码审核、能否发布上线**（平台侧前置） | **正式版 `wx.request` 能否访问该域名**（request 合法域名白名单前置） |
| 本项目状态 | ✅ **已通过**（2026-10-29） | ❌ **未办**（无域名、无大陆服务器；后端仍是 `http://192.168.3.242:3001`） |
| 用户侧可见 | 备案号自动展示在小程序「更多资料」页 | 无（网站侧才需展示） |
| 周期 | 已走完 | 7-20 工作日（个人主体，部分省份受限） |

> **⇒ 由此定一条用词规矩**：本文与 GK 文档此后凡提"备案"，必须带定语（小程序备案 / 域名备案）。
> 笼统的"备案已通过"会让下一个读文档的人直接踩坑——以为可以配白名单了。

### 8.2 备案通过实际改变了什么、没改变什么

**真正改变了三件事（都写进发布清单）：**

1. **「提审」这条前置条件满足了。** 此前即便代码全好，没有备案号也提交不了审核；现在可以走「体验版 → 提审 → 发布」全流程，只剩后端可达性这一关。
2. **备案时填报的服务类目成为约束。** 备案信息与实际运营需一致——后续若扩类目（例如将来升企业主体、加 AI 类目），**备案要一起变更**，不是只改 mp 后台。
3. **隐私政策里"运营者与备案信息"从空承诺变成事实。** 该节此前写不出编号，现在可写；且备案号在「更多资料」页自动可见，前后一致。

**没改变的三件事（选型结论一个字都不用改）：**

1. 后端域名仍进不了正式版白名单 ⇒ 路线仍是 **A 局域网 / B 云托管 / C VPS** 三选一。
2. `app.workbuddy.host` 依旧不能当后端（UA 拦截 + 平台子域无备案）——§2 结论继续有效。
3. `wx.cloud.callContainer` 仍是唯一"完全绕开域名"的通道——它省的是**域名备案**，与小程序备案无关。

### 8.3 最新建议（按 2026-10-29 事实重排）

**前提变了两个，推荐顺序不变：**

- 变：首发不再被"小程序没备案"卡住 ⇒ 现在**唯一**剩余的时间型风险就是**域名备案的 7-20 工作日**。因此**任何能把首次上线提前到"本周内"的路线，优先级都高于任何需要备案的路线**。
- 变：主体确定为**个人** ⇒ 不得含课程售卖/付费/直播，类目走「教育 → 教育信息服务」；这条对后端选型无影响，只影响审核材料（详见验收报告 §3.1）。

| 顺序 | 动作 | 判定 | 若成功 | 若失败 |
|---|---|---|---|---|
| **①（今天）** | 建微信云托管环境，验证 **B2**：关联小程序后，云托管公网域名是否自动进 mp 后台 request 合法域名 | 后台「开发管理 → 服务器域名」里能看到该域名 | 走 B2：只改 `PROJECT_DOMAIN`，**当天可用正式版**，月费 ¥0（免费额度内）～¥43 | 回落 ② |
| ②（B2 失败时） | 走 **B1** `callContainer` | 需改图片链路（`wx.cloud.uploadFile` 换 fileID） | 免域名、免备案，改动 3-5 天 | 回落 ③ |
| ③（仅在①②都不可行时） | VPS + 域名备案（§3.6） | 备案 7-20 工作日 | 完全自主，OCR 可独立容器 | 首发顺延 2-4 周 |

**三条明确建议：**

1. **不要"先买服务器等备案"当首发路径。** 备案通过只解了小程序侧；服务器的域名备案仍是 7-20 个工作日。先走 ①，把"能不能上线"变成"今天就能验"的问题。
2. **VPS 的定位下调为"第二阶段 + OCR 分担"。** 若 ① 成立，云托管的真实短板只有一个：OCR 是 CPU 密集，0.25 核带不动、单镜像让冷启动变慢。届时把 OCR 侧车放到 VPS（Compose 独立容器）、NestJS 留云托管，是最省钱的组合——这也是那台 ¥109 机器的正确用途，而不是"当首发后端"。
3. **域名备案可以并行办、不必等结论。** 域名本身 ~¥55/年，备案免费，只是要时间。若本来就打算长期自持，今天就可以启动备案（与 ① 不冲突）；但**首发不依赖它**。

**成本/时间对比（2026-10-29 口径）**

| | B2（推荐先验） | B1 | C · VPS + 域名 |
|---|---|---|---|
| 首次可用耗时 | **几小时** | 3-5 天 | **7-20 工作日备案** + 1-2 天部署 |

| 运维 | 平台托管 | 平台托管 | 全自管 |
