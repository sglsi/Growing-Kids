> 无决策点的结构规则 + 事后客观审计」完成三级升级，并用**实际命令日志审计**验证了有效性。

## 一、结论先说

**跨 3 天共 21 次「出错停止」中断，100% 是同一个根因**（另有 2 次为 429 平台限流，
非代码问题，见 §七）：

> **把 JavaScript 表达式写进了内联 shell 命令**，导致 zsh 在**解析命令阶段**就失败。
> 平台外层包装成 `Failed to run function tools: Error:`，内层错误签名永远只有一个：
> `Bad substitution: <JS表达式>`（冒号后全是 `.方法(` 或 JS 内置对象——这就是指纹）。

分段时间表（会话日志取证，`/root/.codebuddy/logs/<日期>/`）：

| 时间段 | 次数 | 触发词 |
|---|---|---|
| 9/24 19:47 | 1 | `name.replace` |
| 9/25 | 2 | （同形态） |
| 9/26 10:55–13:20 | 7 | `JSON.stringify`、`spec.ratio.toFixed`、`Date.now`、`typeof`、`r.printRatio.toFixed`、`ratios.map`、`Math.max` |
| 9/26 19:06–19:16 | 6 | 空、`p.x.toFixed`×3、`px.toFixed`、`h0.toFixed` |
| 9/26 20:48–20:52 | 2 | `${}` ×2（**写下教训后**连踩） |
| 9/26 22:07–22:08 | 2 | 空、`c.name.padEnd`（**拦截工具建成后**连踩） |

## 二、机制（已在本机用 zsh 精确复现，不是推测）

工具的 shell 是 **zsh**（报错前缀 `(eval):1` / `zsh:1` 是铁证）。
zsh 在**解析命令**阶段做变量/命令替换，而 JS 表达式长得像替换语法：

| 命令形态 | zsh 实际反应 | 判定 |
|---|---|---|
| `${p.x.toFixed(2)}` | `zsh: bad substitution` | ❌ 致命 |
| `$(o.x.toFixed(2))` | `zsh: unknown file attribute: 2` | ❌ 致命 |
| `${}`（空） | `zsh: bad substitution` | ❌ 致命 |
| 双引号内未转义反引号 | 反引号内 `${}` 被替换 → 炸 | ❌ 致命 |
| `<<EOF`（heredoc 分隔符**未加引号**） | 内容被替换 → 含 `${}` 就炸 | ❌ 致命 |
| `obj.method(2)` 但**无** `${}` / `$()` | 正常执行 | ✅ 安全 |
| `${X}` / `${pipestatus[1]:-$?}` / `${f#src/}` | 正常（合法参数展开） | ✅ 安全 |
| `$(date)` / `$(find ...)` | 正常（真命令替换） | ✅ 安全 |
| `<<'EOF'`（**加引号**）、单引号区间、`\`` 转义 | 内容原样 | ✅ 安全 |

**一句话**：shell 根本没在跑我的 JS，而是**在解析命令时就死了**。

## 三、为什么前几次"解决了"还会再犯（关键认知）

三次铁证：

1. **20:40 写下教训 → 20:48、20:52 连踩 2 次**（知道原因 ≠ 不再犯）
2. **21:03 拦截工具建成 → 22:07、22:08 又连踩 2 次**（有了工具 ≠ 不再犯）
3. 两次踩雷都发生在"**就快速验证/计算一下**"的瞬间——那一刻根本不会想起要先扫一遍。

> **结论**：凡是"需要想起来才做"的防护，都会在任务压力下失效。
> 唯一出路是**让危险写法在结构上不可能出现**，外加**事后客观审计**验证遵守情况。

## 四、最终协议：「Bash 无码原则」（2026-09-26 22:20 起强制，零例外）

**Bash 工具只用来「调用已有程序」，永远不用来「编写代码」。**

机械判定（无例外、无需判断）：

| Bash command 内容 | 判定 |
|---|---|
| `node 文件.cjs` / `npx tsc --noEmit` / `git status` / `ls` / `grep ...` | ✅ 允许（纯程序调用） |
| 命令中出现 **`${`**（纯变量 `${VAR}` 除外） | ❌ 禁止 |
| 命令中出现 **`$(`**（真命令替换除外） | ❌ 禁止 |
| 命令中出现 **反引号** | ❌ 禁止 |
| `node -e "..."` | ❌ 禁止 |
| `node -e '...'`（单引号、无 `$` 无反引号） | ⚠️ 不炸但不鼓励 |
| heredoc `<<'EOF'` 喂 stdin | ⚠️ 允许但首选仍是 Write+node |

**执行方式（永远是这三步）：**

1. 任何计算 / 转换 / 探针 / 格式化输出 → **Write 工具**写进 `.cjs`（内容不受任何限制，因为不经过 shell）
2. `node /path/to/xxx.cjs`（命令里只有程序和路径）
3. 一次性探针写到沙箱临时目录，避免污染工作区

**为什么这次会有效**：以前失败都发生在"懒得建文件"的瞬间。现在**没有"小代码可以
内联"这个选项了**——不是"小代码要先扫一遍"，而是"**代码没有大小之分，一律进文件**"。
决策点被彻底消除。

## 八（续）· 第二轮复发与钩子化根治（2026-09-29）

> ⚠️ **本节推翻 §五~§七 的乐观结论**。
> 那套方案让 9/26 立规当晚降到 0 违规，但**没有扛住时间**。

### 8.1 取证：它确实复发过

### 8.2 为什么 §五 那套会失效

§三 已经把机制说透了：

> 凡是"需要想起来才做"的防护，都会在任务压力下失效。

但 §五 交付的**仍然是可选项** —— `tools/lint-shell.cjs` 要我"提交前扫一遍"才生效。
它没有解决那个被自己点名的问题。**协议漂移（protocol drift）是必然的，只是时间问题。**

> 教训： diagnosing 出"自律会失效" ≠ 解决了它。只要还存在"是否检查"这个决策点，就会漂移。

### 8.3 根治：把检查搬进工具链路（取消决策点）

平台原生支持 `PreToolUse` / `PostToolUse` 钩子（审计证实：PreToolUse 调用了 4646 次、
PostToolUse 4518 次），配置在 `/root/.codebuddy/settings.json`：

| 钩子 | 时机 | 守卫 | 作用 |
|---|---|---|---|
| `PreToolUse` → Bash | 交给 shell **之前** | `tools/hook-bash-guard.cjs` | 复用 `lint-shell.cjs` 判据；命中即 `decision:block`，**命令不会执行** |
| `PostToolUse` → Write/Edit | 文件落盘**之后** | `tools/hook-write-check.cjs` | `node --check` 语法自检，把编译错误在**当轮**报出来 |

端到端实测（`echo $(p.x.toFixed(2))`）：

```
Error: 【Bash 危险写法已拦截】这条命令含 zsh 会在**解析阶段**就炸掉的写法…
```

命令未执行、未炸、会话未中断 —— 这才是我们要的效果。

**设计原则：fail-open。** 守卫自身的任何异常（畸形 stdin / 子进程失败 / 未捕获异常）
都一律放行并记入 `guard-failopen.log`。宁可漏拦，也不能让守卫崩掉而挂起全部工具调用。

### 8.4 第二类本地中断：Edit 失败（5 次）

| 现象 | 次数 |
|---|---|
| `String to replace not found in file` | 4 |
| `File has been modified since read` | 1 |

成因链条是：**写出带语法错误的脚本 → 运行才发现 → 回头 Edit 修复 → Edit 匹配失败 → 还要再 Read**。
本会话就实实在在走了两遍（`const node bin = ...`、`const bomb truths = ...`）。

`PostToolUse` 写后语法自检把这个链条掐在第一环。**并且它立刻证明了自己** —— 守卫自身
第一版就带着语法错误（模板串里嵌了未转义反引号 `` `node` ``），钩子一开就被审计日志抓住。

### 8.5 不可控类（平台侧，本地无法根除）

| 类型 | 次数 | 说明 |
|---|---|---|
| 429 限流 | 6 | 配额，`15:48:42 UTC+8` 重置过一次 |
| 网络 `status=undefined` | 5 | 连接层抖动 |
| SIGTERM | 2 | **会话进程本身**被终止（两个不同 pid），休眠/回收所致 |
| 插件安装失败 | 25 | `MarketplaceRegistryChangedError`，不影响任务 |

**合计：本地可根治的中断 12 次（7 + 5），已全部有结构性防护；其余均为平台侧。**

### 8.6 本轮最有价值的方法论收获

**观测工具本身也会制造假信号** —— 本轮踩了三次，每次都差点导致错误结论：

| # | 假信号 | 差点得出的错判 | 纠正方式 |
|---|---|---|---|
| 1 | 审计器按 JSONL 解析纯文本行日志，命中 0 | "没有任何中断" | 抽样看真实格式，改文本行解析 |
| 2 | 拿**日志截断词**当完整表达式写测试用例，得 3 例"漏报" | 错怪检测器、误改判据 | 用 `probe-zsh-truth.cjs` 对 15 种写法跑**真实 zsh** 取 ground truth |
| 3 | 自己下 `--grep="Bad substitution"` 的审计命令，其**命令文本**含关键词被匹配回来 | "守卫有漏洞" | 改用 `Interruption` 签名 + 排除 BashTool 行 |

> **规则（此后强制）：先验证观测手段，再相信观测结论。**
> 检测器要自测、测试用例要有独立 ground truth、审计要排除自指噪声。
> 这正是 §五 说过「检测器本身也需要被审计检验」的再一次印证 —— 现在它连**测试用例**也覆盖了。

顺带修正前期报告一处：**`${}`（空）在当前 zsh 下实际安全**（实测 `echo ${}` 正常返回），
判据把它列为危险属**有意的过度保守**，保持不变。
