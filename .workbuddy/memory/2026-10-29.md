## 60s 超时天花板：三条慢链路异步化（思傅指令「60s 天花板现在修」）

### 做了什么
- **迁移 `migrations/0020_async_jobs.sql`**：`async_jobs` 表（id/user_id/type/status/dedupe_key/params/result/error/stage/时间戳/expires_at），含幂等索引、清理索引、status 约束。
- **后端 `server/src/jobs/`**（types / service / controller / module）：
  - `POST /api/jobs` → **202 回 ticket**（HTTP 202 但 body.code 仍写 200——全项目 unwrap 按 code 判断，写 202 会让所有调用方抛错）；`GET /api/jobs/:id` 轮询；`GET /api/jobs` 未完成列表；`DELETE /api/jobs/:id`。
  - 三种任务：`ocr-page` / `answer-search` / `search-solve`，TTL 分别 180/260/150s。
  - 内存并发闸门：全局 3、单用户 2（精准 OCR 是 CPU 密集、搜答案要花钱，没闸门时连点几下会把机器拖死，表现为「全部超时」）。
  - 幂等 `dedupe_key = sha256(userId|type|canonical(params))`，只对 pending/running 生效。
  - 超时看门狗（轮询时判 + setTimeout 兜底）、启动回收（进程不认识任何 pending/running ⇒ 统一标 failed「服务已重启」）、每 6h 清理过期行。
- **前端 `src/services/jobs.ts`**：提交 + 轮询，**整个文件没有 timeout 大于 15s**（这是设计约束，不是懒）。`api.ts` 三条链路改走异步；recognize 与 answer-editor 加等待反馈（「已等待 Ns」，节流 10s 更新一次避免闪烁）。
- **M17 异步任务（12 条用例）**，不进 CI（需 OCR 侧车）。

### 关键判断（值得留档）
- **⚠️ 闸门必须拦在提交阶段**：任务在后台执行时**没有 req**。若把 `requireAiEnabled`（R-合规-02）放进执行器，异步化就等于给 AI 外发开关开后门——用户关了开关，只要能提交任务，内容照样外发。M17 用两条 🔴 用例守住，且用例里**先显式 `PUT /settings/ai false` 再断言 403**，不写「403 或 202 都算过」那种恒真断言。
- **任务只在提交它的进程内存里跑**，不引队列中间件（单机部署，加 Redis 是把小问题换成一套运维）。代价明确接受：重启即失效，启动时统一标 failed 并写明原因——不做假装还在跑。
- **不给假进度**：后端无法知道 OCR 走到第几步，所以只返回 stage 文案 + `waited_ms`，由前端显示「已等待 Ns」。编一个百分比比不显示更糟。
- **uploadFile 没有前端解法**：超时不可调、上传不可异步化 ⇒ 只能压缩减体积；失败提示应说「换张小图」而不是「网络不好」（后者是把硬限制说成偶发故障，用户会一直重试）。timeout 已改为真实生效的 60000。
- 前端 fast 模式保持同步（1~3s），timeout 55000（必须小于 60s，写再大不生效）。

## 晚间二轮：故障依旧 → 真因是 `__usePrivacyCheck__` 自锁（订正上一轮判断）

### 现象（思傅复测）
三处点击仍无反应；工具报 `[wxapplib] backgroundfetch privacy fail {"errno":101}`；登录后头像空、昵称「微信用户」。

### 关键推理链
1. 先排除「没编译」：`dist` 18:37 晚于 `src` 18:36，且 `grep guardPrivacy dist/pages/*/index.js` 命中 2~3 处 ⇒ 代码已进包。**不是构建问题。**
2. 那条 `backgroundfetch` 报错是我的突破口：`grep backgroundFetch src/ server/src/` **零命中** ⇒ 非本项目调用，是**基础库内部预检**。它出现说明：**隐私校验已启用，但授权未放行**。
3. 于是回到 `src/app.config.ts`：`__usePrivacyCheck__: true` + **平台侧隐私指引未代配**（托管状态）。这个组合的语义不是「弹隐私弹窗」，而是「**启用隐私协议机制**」⇒ 基础库**拦截/挂起所有隐私接口**。

Taro 4.1.9 运行时缺隐私 API 只是次因（连自行 resolve 的机会都没有），保留原生 `wx` 取值即够。

## 21:10 首页内容一直不显示 —— silent 把 loading 钉死 + 统计拖累列表

### 第二因（修好 loading 也还是会慢得以为没显示）
`Promise.all([fetchOverview, fetchTimeline, fetchSubjects])` 把列表绑在最慢的聚合统计上。
日志实测：`/api/timeline/overview` **5777 / 8107 / 6678 ms**，`/api/timeline` 只要 1~3 s。
绑在一起 ⇒ 内容要等 8 秒才出。

### 修法
1. 解除骨架与 silent **脱钩**：缓存命中立即 `setLoading(false)`；请求结束（成功/失败）
   由**最后一个在途请求**解除——`pendingLoadsRef` 计数，**别用布尔**（并发时先返回的会提前放行）。
2. 列表+学科先 await 渲染；`overview` 改 `void fetchOverview().then(...)` 不 await
   （await 会让 finally 迟迟不执行、计数不归零）。
3. 统计未到显示 `—` 而非 `0`（有 23 条题却写「0」，用户以为数据丢了）；
   `overview` 到位前学科区不喊「暂无分类数据」。
4. 同源修正：资料库/文档/记忆三页同样是 `if (!opts.silent) setLoading(false)`，
   一并改无条件解除（它们首次加载恰好非 silent 所以没爆）。

## 21:40 记忆页按钮点不动 + 插符号丢焦点（两处都是组件内部尺寸/焦点状态）

### ① 记忆页「图片/录音/视频」点了没反应，光标跑进内容栏
**不是布局重叠，是 `ui/textarea` 组件内部尺寸脱节**：
- 外壳写死 `h-20`（80px）；
- 但 `style` 混在 `{...props}` 里透传给了里面**原生** textarea；
- 记忆页传 `height:160px` ⇒ 原生层 160、外壳 80；
- 外壳默认 `overflow:visible` + 内层 `bg-transparent` ⇒ 多出的 80px **透明但可点**，正好压住三个按钮。

**为什么排查方向一开始错了**：上一轮我以为是「Textarea 原生组件层级高」，去改调用方的 height，
改完没用——因为 height 本来就生效了，只是它生效在**错的层**。视觉上框还是 80px 高，
按钮清清楚楚，只有触摸命中被抢走。

修：`style` 只落外壳；外壳 `h-20`→`min-h-20`；内层用同一份 height/minHeight + `self-stretch`。
影响面逐个验算：recognize(3)、detail(2)、answer-solution-editor、answer-editor、memory —— 高度与改前一致。

### ② 插一个数学符号就退出输入态
点 chip 必然让原生 textarea 失焦，键盘收起；上一版只 `request(cursor)`，
但微信的 `cursor` **只在聚焦中才被采信**，不负责把焦点拿回来。
修：`useCaret` 增受控 `focus` + `refocus()`（先 false、30ms 后 true——微信 focus 是**边沿触发**，
值一直 true 再设 true 什么都不发生）+ `blur()` 让受控态跟原生一致。
覆盖：题干两分支、答案与解题过程、独立答案编辑器。

### ③ 隐私限制会不会在其他用户身上重现（思傅提问）
- 当前 `PRIVACY_CHECK='0'` ⇒ 包内 `__usePrivacyCheck__:false` ⇒ 基础库**根本不进隐私校验流程**，
  接口直接弹原生选择器；与账号/机型/首次使用**无关**。
- 唯一重现组合：**开关 true + 平台侧《用户隐私保护指引》未代配**（托管状态下的真实风险）。
- 三层保障：`ensurePrivacyAuthorized` 2s 看门狗 + `probeBroken` 永久放行 / `release-check` 发布态 block /
  7 处调用点全前置 `guardPrivacy`。
- 排障判据：Console 有 `[privacy]` → 隐私链路；没有 → 触摸命中问题（今天 ⑥ 就是）。
