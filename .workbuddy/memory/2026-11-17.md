## D-079：OCR 侧车唤起 + 跨栏跨页补裁图 + 裁剪卡死（思傅真机三报）
- **根因（生产日志实证）**：侧车空闲15min回收，冷启动 systemctl 1s + **探针预热 14975ms**（`/healthz`200≠模型就绪）。这 16s 以前算在识别请求里 ⇒ 叠摆正/推理顶微信 60s 硬上限 ⇒ 报失败，而侧车刚起来（换入口再点又成）。潜伏缺陷：`start()` 开头 `if (isRunning()) return`，unit 模式只信 `unitActive` ⇒ 单元被后台停掉后永不重启。
- **修**：新增 `POST /api/image/ocr-warmup`（`ocrService.warmupSidecar()`→`ensureReady(45s)`，永不抛错）+ 前端 `warmupOcr()`（10min TTL、失败清缓存）/`warmupQuiet()`；识别页**进页面 fire-and-forget 预热**，各 OCR 入口（识别文字/文档/整页快速·精准/单题/补图/改框重切/详情页）统一 `await warmupQuiet()`；`start()` 改「认为在跑也先探活」探不通强制重建（unit 置 false 走 systemctl；spawn 先 SIGKILL）。
- **跨栏/跨页**：`SeqRow.extra` + 题目行「＋补一块」+ `kind:'extra'` 裁剪器（整页起框、提示「补充块（跨栏/跨页）」），入库 `images:[stem,...extra]`，与主图合计受 MAX_ENTRY_IMAGES 约束。
- **裁剪卡死**：手势改**同步起手**（旧实现只在 SelectorQuery 回调里设 dragRef ⇒ 快速拖动丢手 + 查询堆积）+ 触摸层矩形缓存 + 拖动 16ms 节流 + 新增 `handleForceExit`（先 hideLoading 再复位忙态）+ 裁剪导出 `mask:false` 反馈不挡退出。
