## 09:10 后端托管选型调研（Supabase vs 微信云托管，含 2026-10 官方资费）
- **Q1 Supabase 托管结论**：分层看——数据库可继续留 Supabase（新加坡库已在用）；但 NestJS API 层不能放 Supabase：① Edge Functions 是 Deno 短函数，跑不了 NestJS 长驻进程，且本后端 63 个 ts/21 模块 + @nestjs/schedule + multer + pdf-lib/docx 均依赖长驻/重 CPU；② supabase.co 境外域名无 ICP 备案，进不了小程序 request 合法域名白名单（自定义域名也需自己备案）；③ 新加坡区到国内延迟高。
- **Q2 微信云托管资费（官方 2026-10 现行）**：云托管按量付费——CPU 0.055 元/核*小时、内存 0.032 元/GB*小时、构建 0.05 元/分钟、公网出流量 0.8 元/GB；首个环境 3 个月免费额度（720 核时 CPU + 1440 GB时 内存 + 600 分钟构建 + 5GB 流量）。本场景 0.5 核/0.5G 常驻 ≈ ¥32/月，最小副本 0 则按量几分到十几元。云开发套餐另计：免费 4 万资源点/月（体验 6 个月），基础套餐 ¥19.9/月。
- **免备案正路（关键）**：官方文档——小程序用 `wx.cloud.callContainer` 调用云托管「无需域名、无需在 mp 后台配服务器域名、无需备案」，且自动带 openid；而 wx.request 打云托管默认公网域名仍受 request 合法域名限制（默认公网域名官方明示仅接口测试用、不能配进小程序后台）。真实踩坑文佐证：必须 callContainer 才能摆脱白名单。
- 迁移工作量：云托管官方定位「传统后台服务平滑迁移、无需改造」，NestJS 加 Dockerfile/代码包即可；需改三处——① 前端 network.ts 增加 callContainer 通道 + wx.request 降级；② 文件上传（multer）换对象存储（容器无持久化 + callContainer 100K 限制）；③ @nestjs/schedule 在最小副本 0 时可能不触发。数据库可暂留 Supabase（容器走公网连，出流量 0.8 元/GB）。

## 09:20 调研：WorkBuddy cloud-service（BaaS）成本与能力边界
- **费用结构**（workbuddy.cn/pricing，2026-07 新版个人版）：cloud-service 无独立价目，消耗套餐内「单应用资源额度」——体验版免费（500 积分/月、单应用额度 5000、可托管 10 应用）；标准版 ¥99/月（连续包月 ¥70、单应用 25000）；高级版 ¥199/月（¥140、单应用 50000）；旗舰版 ¥999/月（¥700、单应用 150000）。→ BaaS 成本=订阅费，非按量账单；超单应用额度需升套餐。
- **能力边界（关键，与 Supabase 同类）**：cloud-service 仅四模块——数据库（文档型 CRUD）、Auth、Storage、LLM API；**无容器/云函数/长驻运行时 → 跑不了 NestJS**。"迁移"实为把后端 63 个 ts/21 模块重写成前端直连 BaaS，且文档型数据库≠Postgres（drizzle schema 需重设计）。数据平面绑 WorkBuddy 应用发布域（endpoint+Origin 校验）→ 发布命脉绑死 WorkBuddy 小程序通道（当前沙箱仍卡"依赖安装失败"）。独有优势：LLM API 免密钥（可接后端 AI 三件套死刑痛点）。
- 三方费用结论：云托管 ¥0(3 个月免费)→~¥32-40/月、NestJS 原样、免备案(callContainer)，最省；cloud-service ¥0 体验→¥70-99/月但需重写+绑 WorkBuddy 通道；Supabase 仅能留数据库。
