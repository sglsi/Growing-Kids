## 三项改造（思傅 2026-10-20 晚）：智能高清入口 / 错题提取流程 / OCR 分段

**① 「…」→ 智能高清 直跑高清放大 → 改为弹「模式选择面板」**
- 根因：首页「最近题目 · …」与拍照识别页的「智能高清」按钮传 `autoAction='enhance'`，
  image-editor 的 autoAction effect 直接 `handleAi('enhance')` → 后端默认 x2 超分；
  而编辑器内点同一个按钮是「先弹模式面板」。同一功能两条路径行为不一致。
- 修：autoAction='enhance' 时改走 `dispatchAi('enhance')`（原图/增强并锐化/增亮/灰度/黑白/高清扩展）。
  高清放大从此只作为面板里的「高清扩展」一项存在。

**② 错题提取改为「先裁剪题目 → 再对裁剪图 OCR」**
- 新布局：来源页卡（图 260 高 + 页切换 + 整页识别次要入口 + 诊断）；
  题目卡（图组 +「＋裁剪题目」→ 识别本题（快速/精准）→ 本题文字面板 → 题干）。
- 裁剪确认后**自动对该图跑快速 OCR**（1~3s），段落直接挂在这道题上，「加入题干」一步写入。
- 后端 `ocr-page` 新增 `rectify` 开关：裁图 OCR 传 false，跳过几何摆正（避免二次透视把
  小图拉塌——37×39 裂图教训），且不再重新暂存对象（直接用原 URL）。
- 整页识别降级为次要入口，保留"摆正后页面图替换 url"的既有行为。

**③ OCR 分段：改用成熟机制（`server/src/ocr/ocr-segment.ts`）**
- 调研结论：精准通道 PP-StructureV3 的 `parsing_res_list` **自带阅读序 + 区内行合并成段**
  （列表顺序即阅读序，block_label/block_bbox/block_content），项目侧车早已取出 blocks
  却只塞进 layout 当摆设，文本栏却用行级 regions → 一行一段。根因在此。
- 快速通道 RapidOCR 无版面能力（RapidLayout 是独立包，未引入）→ 自研但用成熟算法：
  行聚类 → **递归 XY-Cut**（竖切分栏 1.5×行高 / 横切分段 0.6×行高 / 叶子按 y+x）
  → 间隙(1.5×行高)/缩进(2×行高)/题号 断段。全部阈值 = 行高中位数倍数（尺度无关）。
- 验证脚本 `dynamic-tests/probe-segmentation.ts`（两栏三题，右栏首行与左栏首行 y 对齐）
  实测通过，并抓出两个真缺陷：
  1) 跨栏同行粘连 → 行合并加「水平间隙 ≤1.0×行高」约束；
  2) `（1）` 小问被当新题 → 题号正则只认大题（去掉括号分支）。
- 契约：`page_text[]` 增 kind/lines/source；文档 `OCR-文本分段设计.md`（含出处链接）。
