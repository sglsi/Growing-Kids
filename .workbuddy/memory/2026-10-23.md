### 2.1 后端：搜题接口按 mode 彻底拆分（`5064e35`）
- **根因**：旧实现把「检索」和「推理」混在一条降级链里（检索成功→AI 基于检索提炼，失败→AI 纯推理兜底），所以按钮叫联网搜答案、结果却可能是 AI 编的，用户无法区分。
- **拆分**：`POST /api/answer-search/:id` 增加 `mode`：
  - `mode=search`（联网搜题）：**只检索，不喂 AI**。直接返回最相关来源摘要 + refs 链接，用户点链接看原文；检索不到就如实说，**绝不拿 AI 答案冒充搜索结果** → `source=search/verified=true`
  - `mode=ai`（AI 解题）：**只推理，不检索**，明确标注「AI 推理结果，未联网核实」 → `source=llm/verified=false`

- 验证（真机后端；**Supabase 已恢复**，HTTP 307/1.2s，10-22 晚的全段封锁已解除）：
  - ai 17.6s → `source=llm/verified=false/refs=0`
  - search 83s → `source=search/verified=true/refs=5`（真实百度教育/文库）/conf=0.86
  - 缓存隔离：search 后跑 ai → `source=llm/cached=false`（没吃检索缓存）；两模式各自 `cached=true`

## 3. LaTeX 可读化双向转换 + 编辑态改造（commits `43bfebe` + `6cee502`）

思傅：「对所有的用户来说，源码是看不懂也直接编辑不了的，用户只能对他们认识的数学符号及认识的文字内容进行编辑，不可能编辑去源码，请解决此问题」。

### 3.1 设计：编辑态显示可读形式，库存永远是标准 LaTeX
- `latexToReadable(src)`：库存 LaTeX → 人类可读形式（`1/2`、`√3`、`x²`、`∠ABC`、`→a`、`C(5,2)`、`∑_(i=1)ⁿ`）。覆盖 `$...$`/`$$...$$`/`\[...\]`/`\(...\)` 包裹段、**没有 $ 包裹的裸 LaTeX 段**（符号面板插入的就是这种）、纯文字段原样保留。
- `readableToLatex(src)`：保存时转回标准 LaTeX 入库（渲染效果不变）。三段式：分词成原子 → 合并前缀运算（`√X`/`→X`/`←X`/`C(a,b)`）→ 组装。**认不出的模式原样保留，绝不猜测**。
- `text` state 始终是库里的 LaTeX（唯一真相）；`editing` 才是编辑中的可读文本；进入编辑才转换，保存才转回。

### 3.2 本轮修的真 bug（66/66 往返用例 + 28/28 符号面板模板用例全过）
1. **takeLastAtom 正则漏 `^`/`_` 标记**（最严重）：旧正则第二分支写的是 `base{...}`，但真实形态是 `base^{...}`/`base_{...}` → `x^{2}` 只能取回末字符 `}` → `\frac{x^2}{y_1}` 回转成 `x^{2\frac{}}{y}_{1}`（渲染失败）。此前 37 用例能过是**偶然**——多数场景 `rest+atom` 恰好拼回原串，一旦原子被整体包裹（frac/binom/deco）就暴露。修复：正则补 `(?:[\^_](?:\{[^{}]*\}|[0-9a-zA-Z]))*` 上下标组，第一分支（命令+花括号）也允许后跟上下标（`\sqrt{x}^{2}`），另加 `∛\([^]*\)` 分支。
2. **分数分母漏吞上下标**：`a/b₁` → `\frac{a}{b}_{1}`（₁ 挂到整个分数上，语义错误）。修复：`/` 分支消费分母原子后，继续吞紧随的 unicode 上下标和 `_(X)`/`^(X)` 显式形式。
3. **`→` 空参 bug**：`n → ∞` 里 `→` 后跟非字母原子，生成 `\vec{}`。修复：arg 为空原样保留箭头。
4. **上下标可读顺序**：改先下标后上标（`x₁²`、`∑_(i=1)ⁿ`），符合书写习惯；两种顺序都能被回转。
5. **`\sqrt[3]{x}` 可读形式**：此前输出 `3√x`，回转错位成系数 `3\sqrt{x}`；改为 `∛` 字形（字面保留，渲染正确）。n 次根退化为 `n√x` 字面形式（渲染视觉正确但不规范）。

### 3.3 UI 接线（answer-editor + detail 两个分支 + 符号面板）
