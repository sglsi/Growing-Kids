## 真机残留故障：连删 / 打标点时跳光标（第二轮定性）

思傅复现两条：①按住删除键连删，光标突然跳末尾；②不选候选直接上屏标点（中英文都中），
光标跳末尾。要求先检索同类现象，再用本机开发者工具测、再改。

### 检索到的事实（不是猜）
- 这是**微信小程序 textarea 的普遍坑**，多篇实践都写「真机复现概率高、开发者工具里极低」；
  根因讲法一致：`bindinput` 里 setData 回写 value，双线程异步 ⇒ 渲染层重设 value ⇒ 光标复位。
- Taro 侧给的做法：`onInput` 里同时维护 `value` 和 `cursor`（`e.detail.cursor`）；
  中文组合态期间不要改值。

### 本地读源码得到的硬事实
`@tarojs/react/dist/react.esm.js: getUpdatePayload`
```js
for (i in oldProps) if (!(i in newProps)) payload.push(i, null)          // ← 删键 = 下发 null
for (i in newProps) if (oldProps[i] !== newProps[i] || (isFormElement && i === 'value')) payload.push(i, newProps[i])
```
⇒ 只要这个节点 commit，`value` **一定**会被重发；"不下发"唯一办法是"不 commit"。

### 先做的错误尝试（被实测否掉）
把 `onInput` 延迟 120ms 上抛（想让打字期间不 commit）。模拟器打「甲乙丙」→ 实际「甲丙」，
DOM setter 记录到 `b:"甲" v:""`、`b:"乙" v:"甲"`：**延迟让 state 更旧，commit 照样发生，
反而写回更旧的文本**。⇒ 记进教训：延迟不是解法，只会把光标问题变成丢字问题。

### 最终改法
`ui/textarea.tsx`：`latestRef` 在 onInput 里立刻写入（比 setState 早一拍），
渲染时 `displayValue = latestRef ?? value`；页面主动改值靠
`trustPage = !focusRef.current || cursorProp !== null` 判定（插符号/回填/清空带 cursor）。
即"下发的值永远是已知最新的文本"，而不是上一拍 setState 的旧值。

### 验证（模拟器）
- 连打 16 字（15ms）：下发 16 次，**不一致 0**；
- 连删 15 次（18ms，起点 20）：下发 15 次，**不一致 0**，长度 25 / 光标 5（正确）；
- 回归：detail 两框 L1–L8 全过、基础光标 6 项全过、插「×」后光标 4 且能续打；memory/edit 全过；
- tsc/lint 干净；`build:weapp` 过；`verify:gate` **37/37**（M12 改钉新契约：值来源 latestRef、
  禁延迟上抛、禁删 value）。

**提交**：`714a853`（未 push）。**待真机确认**：模拟器造不出"事件还在路上"的时序，
这两条的最终判定只能由真机给。

### 工具
- `ide-caret-ime.mjs`：DOM 层给 value setter 打桩，逐次记录「下发值 vs 原生文本」+ 光标前后；
- `ide-value-writes.mjs`：单次打字的写入明细（定性和排查用）；

## 第十三轮：英文输入光标仍跳 → 病根是「Taro 恢复受控值的时机」

思傅复测：中文好了，**英文逐字符输入时光标照旧跳到末尾**。

### 定性（读源码 + 模拟器稳定复现，不再靠猜）
- `@tarojs/react` 的事件收尾：`finishEventHandler()` → `TaroReconciler.flushSync()` →
  `restoreStateIfNeeded()`；恢复走 `updateWrapper` → `setNodeValue(node, event.detail.value, props.value)`，
  判据是 **`props.value != null && event.detail.value !== props.value` 就把原生文本改回去**。
- React 18 对事件回调里的 setState 是**批处理**的，`props.value` 往往还停在上一拍
  ⇒ 刚打的字符被改回、光标甩到末尾、偶尔丢字。中文一次上屏只发一次 input，两拍隔得远，所以侥幸没事。
- 模拟器复现：16 个字母 / 15ms 间隔 → 下发的值 13/16 次比原生短，最终只剩 13 字。

### 改法（两处）
1. `ui/textarea.tsx`：`handleInput` 里 `emit()` 之后立刻 `flushSync()`，把这次 setState **同步刷出去**，
   让 fiber 上的 `props.value` 等于本次事件文本 ⇒ 恢复逻辑判定"不需要恢复"。
2. `pnpm patch @tarojs/react@4.1.9`：去掉 `|| (isFormElement && i === 'value')`
   （表单元素无条件重发 value），下发次数从 29 次降到与 input 1:1。
   补丁落在 `patches/@tarojs__react@4.1.9.patch` + `package.json` 的 `pnpm.patchedDependencies`。

### 被实测否掉的（别再走）
- 延迟上抛（"打字期间不 commit"）：属性停旧串，恢复逻辑照样改回旧串 ⇒ 连打 16 字只剩 1~2 个；
- 完全不传 value：Taro 的 textarea 直接**打不进字**；传 `undefined` = 下发空串，清空内容；
- `defaultValue`：被折叠回 value，仍滞后（29 次下发 / 13 次不一致）；
- 运行时改 `FormElement[Symbol.hasInstance]`：连带打断 Babel `_classCallCheck`，整个小程序白屏。

### 验证（模拟器，修后）
- 连打 16 字（15ms）：下发 16 次，**不一致 0**，光标 16；
- 连删 15 次（18ms，起点 20）：**不一致 0**，长度 25 / 光标 5；
- 标点：英文 `Hello, world! How are you?`、中文 `甲乙丙，丁戊。己庚？`、中英混排 —— 长度与光标全对；
- detail 双框（242 字题）：中间连打 10 字、连删 6 次、中间打中文标点、答案框独立输入 —— 全 OK；
- 插符号：`Ω 数学符号` → `√` 插在光标处、光标 61、**插入后继续打 Q 落在符号后**（历史故障点）；
- 长文本（17035 字）：末尾追加 10 字只进去 7 个 —— 模拟器里同步渲染 + 17KB setData 太慢，
  真机是原生 textarea、不重排 DOM，应好于模拟器，待真机确认。
- `verify:gate` 37/37（M12 改钉 flushSync 契约、禁延迟上抛、cursor 按"变化"判定）；tsc/lint 干净。

### 新增脚本
- `ide-caret-punct.mjs`：中英文标点连打（长度 + 光标双判据）；
- `ide-detail-caret.mjs`：detail 双框（含长文本分支、视口外滚动、点击聚焦断言）；
- `ide-insert-symbol.mjs`：插符号 → 光标位置 → 续打。

## 第十四轮（同日）：英文输入依旧坏 —— 真因是 setData 时序，flushSync 只治了一半

### 怎么重新定性的
- 模拟器复现：连打 16 字只剩 11~14，`value 下发 30 次 / 不一致 14 次`。
- 先在组件里埋点（`__tdiag`/`__rdiag` 走 `wx.setStorageSync` 读回来）：每次 input 结束时
  `props.value` **确实同步**变成了本次文本（`a → ab → abc`），`threw: null` ⇒ **flushSync 是生效的**，
  第十三轮方向没错，坏在别处。
- 再在原生 textarea 的 value setter 里记调用栈（`ide-write-stack.mjs`）：坏写入全部来自
  `WAWebview.defaultValueChange → updateValue → doUpdates`，即**视图层应用 setData**，不是 restore。
- 再给 `setNodeValue` 打点：restore 拿到的 `props.value` 曾经是 `""`，于是把整段文本写成空串 ——
  这是后来"跳过下发"方案引入的新坑（payload 变 null ⇒ `commitUpdate` 提前返回）。

### 三处改动（最终形态）
1. `patches/@tarojs__react@4.1.9.patch`：`getUpdatePayload` 里把「与元素当前值相同的 value」
   从 payload 摘掉（`splice`），**但 payload 必须返回非 null**（空数组也可以）。
2. `patches/@tarojs__runtime@4.1.9.patch`：`FormElement.dispatchEvent` 的 INPUT 分支
   `this.value = val` → `this.props.value = val`，只同步内部状态，不再 setAttribute（省掉一次 setData）。
3. `src/components/ui/textarea.tsx`：`if (typeof next !== 'string') return` ——
   丢掉视图层应用 value 后回抛的空 detail input（否则页面 `setContent('')` 清空）。

### 被否掉的（这次实测）
- **在 `getUpdatePayload` 里 `continue` 掉 value（payload 可能为 null）**：`commitUpdate` 提前返回
  ⇒ 元素 `__reactProps$` 不更新 ⇒ restore 读旧值 ⇒ 连打 16 字**最终长度 0**。
- 反过来把 restore 关掉也不行：它就是"受控"的定义，关掉等于放弃程序化回填。

### 验证（最终构建）
- `ide-caret-ime.mjs all`：连打 16/16、0 不一致、光标 16；连删 15/15、0 不一致。
- `ide-caret-punct.mjs`：英文 26、中文 36、中英混排 43，光标全对。
- `ide-caret-stress.mjs`：中文/混输/快速连打/连退/全选替换/插后继续打字 6 项全过。
- `ide-extended-cases.mjs`：长文本/换行/粘贴/maxlength 边界/撤销/重做 8 项全过。
- `tsc`/`lint` 干净；`verify:gate` **37/37**（M12 新增两补丁 + 空 detail 守卫的断言）。

### 环境坑（花了很久）
- 开发者工具启动后模拟器不编译：`WeappCache`/`WeappSimulator` 缓存坏了，**清掉再启动**即可；
  还会出现"模拟器长时间没有响应"的模态框，且**CDP 的点按/键盘事件打不进这个模态框**。
- **不要在 IDE 运行中 `build:weapp`**：它会读到半成品 dist，报
  `getFileInfoError ... dist/pages/xxx.js`，然后整页白屏（重启 IDE 才恢复）。

## 第十五轮（同日）：成长记忆页面四项体验问题

思傅反馈四条：①「新增」不明显；②新记录加完不刷新，必须切页再回来；③录音点了不能播；
④视频看不到；⑤最好列表里就有图片/视频/音频缩略图。

### 逐条根因
1. **不刷新**：列表页/详情页留在页面栈里，`navigateBack` 回来**不重新 mount** ⇒ `useEffect` 不重跑。
   缓存已被 `invalidateDomain('mem')` 清了，只差这一次调用。
2. **录音点不动**：详情页用的是原生 `<audio controls autoPlay>`。Taro 把小写标签当自定义元素下发，
   小程序渲染层没有音频组件 ⇒ 点击**零反应**。视频同理（`<video>`）。
3. **视频看不到**：同上；即使换成 `<Video>` 也**必须给确定高度**，`width:100%` 无高度 = 0 高。
4. **没有缩略图**：`normalizeMemory` 里**根本没映射** `cover_url`，而列表接口只给 `cover_key`
   （对象存储 key）⇒ `thumbUrl || coverUrl` 恒空。`<Image>` 又不发请求头，前端拼不出可用地址。
5. **「新增」不显眼**：原来只是搜索框右边一个 `h-9` 小按钮。

### 改法
- 前端
  - `memory/index.tsx`：`useDidShow` + `firstShowRef` 跳过首帧，`load({silent:true})` 静默刷新；
    主行动改成整条品牌色卡片「记录此刻」（图标 + 标题 + 副标题 + 箭头）。
  - `memory/detail.tsx`：同样补 `useDidShow`；音频改 `Taro.createInnerAudioContext()`，
    自绘播放/暂停 + 「播放中 0:02 / 0:07」，`useDidHide` 与卸载时 `stop()+destroy()`；
    视频改 `@tarojs/components` 的 `<Video>`，高度按宽高比算（夹 160~440）。
  - `memory-card.tsx`：图片/视频/音频各一格缩略图，右下角叠数量或时长；老后端只有
    `audio_duration` 时也画音频格。
  - `services/memory.ts`：补 `coverUrl/thumbUrl/mediaKinds/mediaCounts/videoDuration/videoThumbUrl`
    映射；新增 `storageFileUrl(key)` 兜底。
  - `edit.tsx`：视频取 `chooseMedia` 的 `thumbTempFilePath` 一起上传，写进 `thumb_key`。
- 后端
  - `memory.service.ts` 列表：一次 `.in('memory_id', ids)` 取全部媒体聚合，**不逐条查**；
    给 `cover_url / cover_thumb_url / media_kinds / media_counts / video_thumb_url / video_duration`。
  - `storage.controller.ts`：MIME 表补 mp4/mov/webm/mp3/m4a/aac/wav（原来全落 octet-stream）。

### 实测（模拟器）
- 列表：图片缩略图**真载**（`wx-image` 内层 `background-image` = `/api/storage/files/blobs/...`，72×72）；
  音频格显示 `0:07`。
- 详情：点播放 → 文案变「播放中 0:02 / 0:07」（`InnerAudioContext` 真的出声）。
- 视频：`wx-video` 渲染为 296×191 且带 src（不再是 0 高的未知标签）。
- 刷新：从列表进编辑页 → 期间用 API 新增一条 → `navigateBack` 回来，**1 条变 2 条**，没切页。
- `tsc`/`lint`/`nest build` 干净；`verify:gate` **37/37**。

### 环境事故（花了很久）

  只剩空壳目录、`@nestjs/schedule` 只剩半解压的 `*_tmp_39948`。
  修法：从 npmmirror 拉 tarball 补回、`schedule_tmp_*` 直接改名、用脚本按 pnpm 规则重建 `.bin`
