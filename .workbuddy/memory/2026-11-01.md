## B 任务：扩展用例（长文本 / 换行 / 粘贴 / 撤销重做 / maxlength）

**新增** `server/scripts/ide-extended-cases.mjs`（8 组）与 `ide-enter-diag.mjs`（回车诊断）。

| 框 | 结果 |
| --- | --- |
| detail 题干框（maxlength=-1） | ✅ 13 项通过 |
| detail 答案框（maxlength=-1） | ✅ 13 项通过 |
| chat/admin 话术框（maxlength=500） | ✅ 15 项通过（含截断边界 4 项） |
| recognize 题目框（maxlength=-1） | ✅ 13 项通过 |

**三条实测结论（都已写进提交信息）**
1. 🔴 **CDP 敲 Enter 不产生换行，不是组件缺陷**：`dispatchKeyEvent(keyDown/char)` 只到
   `keydown`/`keypress`，**没有 beforeinput** ⇒ 文本不变。只有 `insertText('\n')` 会产出
   `beforeinput + input(inputType=insertLineBreak)`，与真实回车同路径。⚠️ 以后写输入类
   自动化一律用 insertText，别用 dispatchKeyEvent 敲字符键。
2. ✅ **受控输入框下撤销/重做有效**（原以为会被页面 state 盖回）：Ctrl+Z → ABC，Ctrl+Y → ABCDEF。
3. ✅ **maxlength 截断不留后患**：499 写到 500 截断，光标在末尾，中间再插字仍 500
   ⇒ onInput 拿到的是已截断值，页面 state 与原生始终一致。

## A 任务：识别页「题干 + 答案」双框分支（最后一块空白）

**问题**：这两框只在 `drafts.length > 0` 时渲染，drafts 只能由真实 OCR 产生；
模拟器点「选择图片」弹的是**系统文件选择框**，CDP 点不动 ⇒ 该分支一直没被测过。

**解法**：顶掉 `wx.chooseMedia`，返回一张用 `wx.getFileSystemManager().writeFile`
写进 `wx.env.USER_DATA_PATH` 的图。裁剪编辑器 / 上传 / OCR / 切题全走真实链路。
配套 `ocr-seed-image.py` 按随机编号造图（后端按 file_hash 去重）。

### 🔴 四个坑（都写进脚本注释了）
1. **CDP 鼠标事件必须带 `buttons:1`** —— 缺省 0 时 Chromium 不当成一次有效按下，
   页面收不到 tap。同一个坐标带上就能点开 tab，不带上就「没反应」，极易误判成页面 bug。
2. **业务同意会静默拦在选图前**：`gk_policy_agreed_v1` 没写时 `guardPolicy` 返回 false，
   而它用 `wx.showModal`（原生弹窗，**不在页面 DOM 里**）⇒ 查 DOM 只能看到「什么也没发生」。
   这轮是查 storage keys 才确认的。同理：页面无反应时先查闸门状态，别先怀疑渲染。
3. **Taro 4 调 `chooseMedia` 不带 success 回调**，走 Promise 形态；只写回调版 mock
   会抛 `opts.success is not a function`。
4. **编辑器里两个"保存"不是一回事**：「保存图片」= 直接存进最近题目（不回传），
   底部「保存并替换原图」才是 `onConfirm` 出口。点错页面拿不到图。

### 结果
OCR 真跑通：一张 4 题作业图 → 切成 4 题，题干列与「答：xx」都识别到
（`1.计算 13 + 27 =\n答：40` …）；双框共 8 个 textarea。
L1–L8 全过（maxlength=-1 故 L6 跳过）：300 字插入 / 中间插 5 字 / 连退 10 次 /
中间插换行 / Ctrl+V 贴 110 字 / Ctrl+Z / Ctrl+Y，光标位置逐项核对。
全程 `console.error` 与 `wx.onError` **零条**。

**提交**：`5bbfadb`。**未 push。**

## E 任务：按思傅答复落地的两处改动 + 编辑器「多个保存」结论

### 1) 识别页选图后的编辑器：只留一个出口
`enableSaveToInbox={false}` + `confirmText="用这张图"`。关键发现：底部主按钮
**根本不是保存** —— `handleEditorConfirm` 只把图回填到 paper/question/answer 三个 slot，
不落库、也没有「原图」可替换，文案却写着「保存并替换原图」。
页面上另有「以图片形式直接保存到最近题目」（`handleSaveImageDirect`），不依赖编辑器那只。
其余 7 个调用点早就传了 false，只有 `recognize/index.tsx:2121` 这处漏了。
模拟器核实：编辑器正文只剩「用这张图」，`保存图片`/`保存并替换原图` 均为 0。

### 2) 标题守卫补第 3 条（base62 随机串）
`server/src/upload/upload-name.ts`（新文件，从控制器里挪出来才能被测到）。
判据 = 相邻字符类别切换密度 ≥ 0.5：随机串 0.61~0.94 / 正常名 0.24~0.37。
M13 加断言（4 机器名判 true、4 正常名判 false）。门禁 37/37。
老数据那条已改标题为正文首行，复查 answer(624)/question(57)/solution/status 与
file_key/thumb 全在；首页已显示新标题、随机串消失。
⚠️ **PUT 只传 title 不会动 content，但我的复查脚本拿 `.stem` 比较导致误报「正文被改」**
—— 该条用的是 `question` 字段，改用整段对比才对。

### 3) 结论：不需要多个「保存」
三个"保存"语义：①工具栏「保存图片」= 存进最近题目、停在编辑器；②底部主按钮 =
回传并关闭（文案随调用点）；③智能高清面板「确定」= 只应用增强、不落库。
②③都不该叫「保存」。判断依据不只是"看起来重复"：**我在 A 任务里真的点错过**。
