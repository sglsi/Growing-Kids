### 2. 🔴 录音播放失败的真因：存储读端点没有 Content-Length、不支持 Range
`GET /api/storage/files/*` 返回 `Transfer-Encoding: chunked`，无 `Content-Length`、
无 `Accept-Ranges`；带 `Range` 请求仍回 200（不是 206）。

- 根因：`fs.createReadStream(abs).pipe(res)` —— pipe 不算长度、不处理分段。
- 为什么长期没暴露：图片/封面走 `<Image>`，对这两个头不敏感；只有 `InnerAudioContext` 在乎。
- 修法：改 `res.sendFile(abs, { headers: {...} })`（基于 send，自动 Content-Length /
  Accept-Ranges / 206）。实测修完：`200 → Content-Length: 44496`、
  `206 → Content-Range: bytes 0-1023/44496`。
- 前端同时改两处：`obeyMuteSwitch = false`（默认 true ⇒ iOS 静音键下完全不发声，
  是录音类最常见的假故障）、`onError` 打出 `errCode`（否则下次还得从头猜）。
- 判据写进 QA-16 **§6.4**（v1.23）。
