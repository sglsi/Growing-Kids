## 上午 10 点：云托管计费项对账 + 多云适配评估（思傅问定价页）

逐项核对官方定价页（含「计费参数说明」的产生用量条件），结论：
- 本项目只用 **CPU/内存**（0.25核0.5G ≈ ¥21.6/月；0.5核1G ≈ ¥42.8/月，官方规格表固定搭配）+ 趋近 0 的公网流量；
  MySQL/对象存储/固定 IP 全不用。**两个零成本技巧**：①官方注明「只通过 callcontainer 访问不产生流量」；
  ②「镜像拉取」方式部署不收构建费（OCR 大镜像本地 build + push 正好走这条）。
- 免费额度账：0.25核0.5G 常驻 90 天 = 540 核·h + 1080 GB·h ≤ 720/1440 **全免**；0.5核1G 超支 ≈¥43。
- ⚠️ OCR 与 NestJS 打同一容器时 0.25 核带不动 → 要么拆开（NestJS 上云托管、OCR 留 VPS）要么上 0.5 核。
- 多云结论（写入 §7）：免备案 + 微信生态协同是**独占约束** ⇒ 微信云托管首选；愿意备案后阿里云是第二选择（产品成熟度最高）；百度云/运营商云无差异化优势。
- 「计费为何拆这么细」：CPU/内存=时间资源（活着就烧钱）、流量=带宽、构建=CI 机器时间（防滥用+引导自管镜像）、存储=空间×时间、操作次数=固定机器开销（数据量为 0 也花钱）。拆细=用户只为真实消耗付费+可逐项归因优化，平台=精确覆盖成本+多租户周转（也是敢送 3 个月额度的底气）。
