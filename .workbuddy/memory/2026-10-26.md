## 详情页输入三修（commit 99f7475 / 1c42f3a / 4d28cb0，push 等指示）

思傅报的三个现象：①编辑识别文字时光标跳到最末尾（回车/段末输入/段末插符号位置不对）
②正确答案是否有字数限制、希望答案与解题过程合并 ③两处输入点「保存修改」后存不上。

**根因（三条互相独立）**
1. **光标跳末尾**：每次 `onInput` 都把位置写进 state 再绑回 `cursor` 属性。微信原生 textarea
   收到 cursor 变化会按该值重定位；输入法组词/回车等场景事件给的位置与真实光标不一致，
   事件不带 cursor 时退化成 -1（≈定位到末尾）⇒ 光标被拽走。符号插入位置错位同源（读的是被污染的 state）。
2. **字数限制**：`ui/textarea.tsx` 没兜底 maxlength，**微信 textarea 默认 140 字**，答案框静默截断。
3. **存不上**：真正被编辑的内容在子组件内部（AnswerEditor 的 `editing`）和页面另一个 state
   （`solutionEditing`）里，只有点各自的「保存/完成」才回写父级；直接点底部「保存修改」写的是旧值。
   另：附件增删时 `persist(next, text)` 把组件里的旧 text 一起写回，刚改的答案被随后加的图片覆盖。

**改动**
- `utils/use-caret.ts`（新增）：光标只记 ref（不重渲染、不逐帧改 cursor 属性），仅程序化插入时
  `request(pos)` 一次性定位，用户继续输入即撤销；越界退化文本末尾。详情页题干/答案、AnswerEditor 全改走它。
- `ui/textarea.tsx`：默认 `maxlength={-1}`（置于 `{...props}` 之前，调用方可覆盖）。
- `utils/answer-merge.ts` + `components/answer-solution-editor.tsx`（新增）：答案与解题过程合并成**一个**
  编辑框（页面持有唯一草案 answerDraft），保存时按行首【解析】/解析：/解题过程：等小标题切回
  answer/solution 两字段；正文里出现「解析」二字不误切；无标记则整段当答案。附可折叠数学式预览。
- 详情页 handleSave 一次提交题干+答案+解析+学科+掌握；**未改动的段落沿用库里原 LaTeX**，
  不做可读↔LaTeX 回转（cases/aligned 回转只能近似成纯文本），保存两次幂等。
- SWR 加脏标记 dirtyRef：用户动过输入框时网络回包只更新条目元数据，不覆盖正在编辑的文本。
- AnswerEditor 新增 hideTextBox / onAdopt；附件写库**只提交附件**，不再带 answer。

**验证**
- `tsc --noEmit` 全绿；eslint 零新增（既有 8 条：no-shadow + px-1.5，HEAD 上同样存在）。
- 合并/切分 9 个用例（纯答案/解析标记/方括号/仅解析/正文含解析字样/占位/往返/改一段/幂等）全 PASS；
  LaTeX 往返 `(1/2)、√3、x²` 一致。
- 后端实测：answer 1263 字 + solution 2562 字 PUT→GET 完整一致（服务端无长度限制，截断纯在客户端）。
- `pnpm build:weapp` 通过；dist 校验 detail 有 3 处 `maxlength:-1`、cursor 全部来自 caret（无 state 直连）。
