### 6.5 检索最新信息：智能客服≠智能体；小程序调扣子走后端代理（思傅问「小程序如何调用扣子 LLM」）

- **两类产品别搞混**：
  - 智能客服（发布渠道多为 Chat SDK / 悬浮窗）= 知识库 FAQ 问答，能力受限（思傅现在这个）。
  - 智能体 Agent = 可选大模型（豆包/通义/GLM…）+人设+插件/知识库/工作流；**发布时勾「API 渠道 / Agent As API」**才能力全开，调 `/v3/chat`。
- **小程序调扣子 LLM 的正确姿势 = 后端代理**，绝不前端直连：
  - 前端直连三大坑：① PAT 写小程序会被反编译扒走、被盗刷计费；② 扣子校验来源，`wx.request` 注入的小程序 UA/Referer 常被拒（403）；③ 域名白名单+密钥管理不适配第三方密钥。
  - 正确链路：**小程序 → 自己的 Growing-Kids 后端 → 扣子 OpenAPI**；PAT 只放后端 `.env.secrets`。
  - 后端 route A 的 `cozeChatSync`（`/v3/chat`）+ 降级链已就绪，只差一个「真智能体 bot_id」；answer-search 已走该链，若要通用对话可加 `POST /api/chat`。
- **令牌选型**（docs.coze.cn/developer_guides_authentication）：PAT=短效(1~30 天)、仅测试、绝不进前端；生产用 SAT（长效服务身份）或 OAuth（按用户隔离对话历史）。
