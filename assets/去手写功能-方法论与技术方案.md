# 去手写功能（文档图像手写擦除）技术方案 · 方法论对比与拟制

> 阶段：**方法论对比 + 方案拟制**（尚未进入程序设计）
> 输入：用户实测反馈
>   ① 会把图片中的**图形内容**当作手写内容处理掉；
>   ② 给出的建议不可操作（字比印刷字大/小、手动裁掉手写区域、用红/蓝彩色笔迹），
>      这类「改变用户习惯 / 增加复杂度」的操作等于把用户推向竞争对手。
>   ③ **实测对比图（v2 新增）**：一张含几何图形 + 铅笔手写的数学试卷，处理后
>      **图形区域变成水平条纹伪影、印刷文字大面积模糊、整页分辨率减半（1279×1706 → 640×854）、背景发灰**——
>      问题不止「误擦局部」，而是**整页结构性破坏**（详见 §2.4）。
> 用户核心洞察：许多**彩印书为强调会用红/蓝等彩色印刷体、大小不同的字体**印制，
>   所以「靠颜色 / 字号区分手写与印刷」这条路本身就站不住脚。
> 对标：夸克扫描王、扫描全能王（CamScanner）「图像美化算法」；学术论文 SOTA。
>
> ⚠️ 本阶段**只做方法论与技术方案对比、拟制，不写实现代码**。

---

## 一、问题定义：两个痛点的共同根因是「判别范式错了」

| 用户痛点 | 表面现象 | 深层根因 |
|---|---|---|
| ① 图形被当手写擦掉 | 试卷里的几何图、函数图像、插画、印章、图标、表格线消失 | 分割环节**不认识「图形」这个概念**，把任何非文字墨迹都当成手写 |
| ② 建议不可操作 | 提示「字写得比印刷字大一些」「改用红/蓝笔重拍」「用编辑裁剪」 | 分割环节**靠颜色 / 几何启发式**，失败时只能把责任甩给用户去改变书写习惯 |
| ③ 整页被处理坏（v2 实测） | 图形变条纹、文字模糊、分辨率减半、背景发灰 | **mask 失控（过大/含印刷）+ 修复算法对大 mask 无能力 + 管线降采样后直接输出**——三个环节同时失效 |

**两个痛点的同一根源**：现有方案用「颜色 / 字号 / 行高 / 基线」等**几何-颜色启发式**去近似「什么是手写」。而用户指出的事实——**印刷体本身就红蓝并存、字号大小不一**——意味着这套启发式在彩印书、教材、试卷上必然崩。

> 一句话：**用颜色大小去区分手写与印刷，是方向上的错误；正确方向是让模型理解「手写」这个语义概念。**

## 二、现状管线诊断（已核查代码）

当前去手写（`eraseV2` → `buildHandwritingMask` → `inpaint`）实际有两条分割路径：

```
buildHandwritingMask
   ├─ [主] segmentByVlm        → 多模态大模型返回手写区域 bbox（整块 + 外扩）
   └─ [降级] 色域阈值 + 深色墨迹  → 不依赖外部 AI 的本地兜底
            ├─ maskFromColorThreshold  (chroma ≥ 22 抓彩色笔迹)
            └─ maskFromDarkInk         (行高 ≥ 字高×1.5 且 基线众数低 → 判手写行)
   ↓
inpaint(adaptive)  → 分块判「空白区/压字区」→ 底色填充 / 结构延拓
   ↓
blendWithMask  → 只替换 mask 区域（非 mask 原样保留）✅ 这一步是对的
```

### 2.1 三条导致「图形误擦」的具体路径

| 路径 | 缺陷 | 为什么擦掉图形 |
|---|---|---|
| **色域法** `maskFromColorThreshold` | 判据 `chroma≥22` 即「有色偏=手写」 | 彩印书的**红/蓝印刷重点字、彩色插画**色度同样高 → 被当成「彩色手写笔」纳入 mask 擦掉 |
| **行级法** `maskFromDarkInk` | 只区分「印刷文字行 vs 手写行」，**完全没有「图形」类别** | 任何非文字墨迹（线稿插画、几何图、印章、图标、公式图）经 Otsu 后是墨迹 → 行高够大、无基线对齐、密度不过高 → 被当「手写行」整块擦掉 |
| **VLM 主路径** `segmentByVlm` | prompt 已写「不要框选印刷图片」，但零样本 VLM 不可靠 | 仍可能把插画/图形误判为手写；且返回的是**整块 bbox + 外扩**，adaptive inpaint 把图形区域判为「空白区」→ 底色填充 → 图形被纯色覆盖消失 |

### 2.2 痛点②的实锤证据

代码里确实存在用户痛恨的引导文案：

- `image.service.ts:66-68`：`· 把答案写在题目之间的空白处，字写得比印刷字大一些；· 改用蓝色/红色笔书写后重新拍照；· 或用「编辑裁剪」把含手写的区域裁掉。`
- `image.service.ts:92-94`：把「蓝/红笔」当成可自动识别的特征来宣传——与用户「彩印书就用红蓝印刷」的反驳直接冲突。

这正是「判别范式错了」的必然产物：既然靠颜色/字号判断，失败时就只能教用户「按我的规则改笔色、改字号、手动裁剪」。

### 2.3 现状里**正确的部分**（应保留）

- `blendWithMask` 的「非 mask 区域原样保留」铁律（`output = inpainted·mask + original·(1-mask)`）——从机制上保证版面不被重排。
- 软 mask（羽化）、紧种子（源排除区）避免「拿墨迹补墨迹」等精细设计。
- `unmodifiedRegionSimilarity` / `compareRecognized` 等可复用的验收手段。

### 2.4 实测失败案例分析（v2 新增，基于用户对比图）

样本：数学试卷照片（原图 1279×1706），铅笔手写答案散布全页（部分压在印刷文字/填空线上），印刷内容含**带灰色阴影填充的几何图形** ×4。对比处理后结果图，观察到 4 类破坏：

| # | 实测现象 | 证据 | 归因（对应管线环节） |
|---|---|---|---|
| 1 | **几何图形区变水平条纹拖影**，4 个图形全部不可辨认 | 图形区域出现规律性水平拉伸纹理 | 分割把灰色阴影图形判入手写 mask（行级法不认识图形 / VLM bbox 整块外扩）→ 修复阶段 `structuralExtend`/adaptive inpaint 对大块 mask 做**行方向延拓**，把左右像素水平拉伸填充 → 条纹伪影。**这是确定性修复对大 mask 的能力边界实锤** |
| 2 | **印刷文字大面积模糊/拖影**，题目不可读 | 未被手写覆盖的印刷行也被涂抹 | ① 手写压字区 mask + **膨胀/外扩过度**，波及相邻印刷文字；② VLM 返回整块 bbox，整块区域（含印刷）全部入 mask；③ 修复在印刷区产生拖影 |
| 3 | **输出分辨率 640×854 = 原图 1279×1706 的恰好一半** | 两图 EXIF/像素尺寸对比 | 管线中途**降采样处理**（性能优化）后**直接以降采样分辨率输出**，未回填原尺寸；即使内容正确，文字清晰度也先损失一半 |
| 4 | **背景整体发灰、对比度下降** | 结果图纸面呈灰暗色 | 底色填充的「背景色」取样可能取到了阴影/灰区；且低分辨率输出进一步降低观感 |

**三个环节同时失效，缺一都不会这么惨**：

```
分割失控（图形+印刷入 mask，mask 占比过高）
   ↓
修复无能（大 mask → 行延拓 → 条纹；印刷区拖影）
   ↓
输出降级（分辨率减半 + 背景发灰）
```

**由此得出的三条硬结论**：

1. **mask 必须有总量护栏**：mask 面积占比超过阈值（建议 20~25%）或出现「大块连通 mask」，说明分割已失控——此时**正确行为是放弃擦除、原图返回**，绝不能硬着头皮修（现状正是硬修导致整页条纹）。「宁可不擦，不能擦坏」是失败兜底的最高优先级。
2. **大 mask 修复必须生成式**：手写散布全页是真实场景常态，mask 连通成大块不可避免。确定性延拓在 >中等尺寸 mask 上必然产生结构性伪影（本例条纹），P2 的 LaMa 升级**从「更好」变为「必需」**；且 LaMa 训练时必须含**大 mask 策略**（论文默认即支持）。
3. **分辨率是铁律**：任何降采样只允许发生在**中间计算**，最终输出必须回填原图分辨率；「输出分辨率 = 输入分辨率」应作为回归断言项。此结论与《智能高清增强方案》§7.1 性能约束一致，两条管线应共用同一规范。

## 三、业界解剖：扫描全能王 / 夸克在做什么

### 3.1 扫描全能王「图像美化算法」（已工信部深度合成算法备案）

其手写擦除技术栈（官方备案描述）：

> 手写擦除算法中同样使用 **U 型分割网络**在内部构造的**手写分割数据集**上训练手写分割网络，通过训练好的手写分割网络获得手写文字 mask，对手写文字 mask 进行**膨胀**并且与原图一起送入**通用擦除模型**中，获得最终的手写擦除结果。

关键设计思想：

1. **手写 mask 由专门的分割模型生成**，学的是「手写」这一语义概念——不是颜色、不是字号。
2. 分割（得到 mask）→ 膨胀（盖住抗锯齿边）→ **通用擦除模型（CGAN inpainting）**修复背景。
3. 水印/文字擦除同理，都是先**语义分割出待擦区域**再修复。

### 3.2 夸克扫描王（产品形态标杆）

- 功能定位：**「试卷去手写，拍照自动去除手写笔迹，一键还原空白试卷重练」**。
- 核心技术：自研 AI 大模型 + 多模算法；印刷体识别精度 99.99%、手写体识别 98.5%+。
- 离线端侧：模型量化压缩（体积缩小约 100 倍）部署到手机，**端到端约 2 秒**。
- **产品形态要点**：强调「**自动**」「**一键**」——全程**不要求用户改变书写习惯、不要求手动裁剪**。这正是用户要的「便利性、满意度、粘性」。

### 3.3 学术 SOTA（实测可落地的三段式）

业界比赛/工程普遍采用**检测 → 分割 → 修复**三段式：

| 环节 | 常用模型 | 选型理由 |
|---|---|---|
| 检测 | YOLOv8 / DBNet / CRAFT | 先粗定位手写区域 |
| 分割 | **U²-Net / U-Net / SegFormer** | U²-Net 源自显著性检测，对手写这种「显著前景、细长笔画」特别友好，IoU 优于 DeepLabV3+ |
| 修复 | **LaMa** | 大/不规则 mask 修复 SOTA，无需边缘先验 |

> **为什么三段式天然规避「印刷误擦 + 手写残留」**：端到端生成模型（image-to-image）很难区分手写与印刷（颜色接近、笔画交错时，常把印刷一并抹掉或残留手写）；而显式分割阶段是**语义级**的，把「擦除」拆成「找手写 + 恢复底层」，每一步产物可检验。

**SignaTR6K（ICCV 2023）四分类语义分割**——直接对应本需求的核心：

> 把每个像素分成 **手写 HT / 印刷 PT / 背景 BG / 重叠 OV** 四类，用 U-Net + 融合损失做像素级标注。

它的价值在于：**「手写」和「印刷」是模型学出来的不同语义类**，所以红蓝印刷体、彩色插画、大小不一的字体都能被正确归到 PT/BG，而不是 HT——**正好治本**，从源头上消除「靠颜色/字号区分」的两个痛点。

### 3.4 修复阶段：LaMa 为什么压过传统方案

| 方案 | 大面积 mask | 复杂纹理 | 说明 |
|---|---|---|---|
| OpenCV `inpaint`（Telea/FMM） | 差 | 一般 | 大块文字区会糊 |
| EdgeConnect | 一般 | 一般 | 需先生成边缘先验，手写周围有印章/底纹时边缘图不可靠，误差传导 |
| DeepFillv2 | 较好 | 较好 | 效果不错但模型重 |
| **LaMa (FFC)** | **很好** | **好** | 快速傅里叶卷积给全图感受野，对长条/不规则 mask 稳定，不需边缘先验，泛化到高分辨率 |

LaMa 的 FFT 全图感受野特别适合修复被手写覆盖的**印刷周期结构（表格线、网格、公式线）**——这正是当前 `structuralExtend` 想做但确定性算法做不完美的部分。

### 3.5 数据范式：合成数据是护城河

手写擦除的像素级标注人工极贵（一张十几分钟）。业界通行做法：

- **合成数据打底**：取真实印刷体图像（扫描书、试卷 PDF、毕业论文）作背景，把**手写笔迹随机叠加**上去，mask 天然对齐。
- 渲染参数随机化：旋转 ±5°、字间距/行距随机、墨色在黑~蓝黑间波动、透明度 0.7~1.0、字号抖动。
- **关键**：叠加位置要**同时覆盖「印刷文字区域」和「空白区域」各约一半**——否则模型学不会「擦后恢复印刷体」。
- 增强：弹性形变（模拟纸张皱褶）、亮度/对比度扰动（模拟不同拍摄曝光）。

## 四、方法论对比

### 4.1 「手写 vs 非手写」判别范式对比（核心）

| 判别范式 | 原理 | 图形误擦 | 彩印红蓝误擦 | 黑笔同字大误擦 | 用户负担 |
|---|---|---|---|---|---|
| **颜色法**（现·色域阈值） | chroma≥阈值=手写 | ❌ 彩色插画误擦 | ❌ 红蓝印刷误擦 | ✅ 黑笔有效 | 高（教改笔色） |
| **行高/基线法**（现·行级） | 高行+无基线=手写 | ❌ 图形当高行擦 | ⚠️ 部分误判 | ❌ 同字大失效 | 高（教改字号） |
| **几何连通域法**（改良启发式） | 封闭/实心/规则形状排除 | △ 可缓解但仍有边界 | △ | △ | 中 |
| **VLM 零样本**（现·主路径） | 提示词约束返回 bbox | △ 不可靠，仍需护栏 | △ | ✅ 语义较好 | 低 |
| **专用分割模型**（U-Net/U²-Net/SegFormer） | 学「手写」语义 | ✅ 图形属 BG/PT 不擦 | ✅ 红蓝印刷属 PT 不擦 | ✅ 语义区分 | **低（全自动）** |
| **四分类 HT/PT/BG/OV**（SignaTR6K） | 像素级区分手写/印刷/背景/重叠 | ✅ 原生支持 | ✅ 原生支持 | ✅ 原生支持 | **低（全自动）** |

> 结论：**唯一能同时根治两个痛点的是「语义分割」**。启发式再多修补（连通域过滤、形状排除）也只是缓解，且必然有边界 case；模型学语义才能一劳永逸。

### 4.2 修复（inpainting）方法对比

| 方法 | 类型 | 大面积/压字区表现 | 是否引入新内容 |
|---|---|---|---|
| 中值/高斯（现） | 确定性 | 实心块无效，留笔迹色 | 否 |
| 线段/结构延拓（现·structuralExtend） | 确定性 | 能接表格线，但复杂汉字笔画重建差 | 否 |
| Telea / FMM（经典） | 经典扩散 | 大块糊 | 否（插值） |
| DeepFillv2 / EdgeConnect（GAN） | 生成式 | 较好 | 是（可能编造） |
| **LaMa（FFC）** | 生成式 | **优**，周期性结构好 | 是（受控） |
| CGAN 通用擦除（扫描全能王） | 生成式 | 优（专用训练） | 是（受控） |

> 建议修复阶段从「确定性」升级到「受控生成式（LaMa 或专用 CGAN）」，但对**非 mask 区域仍强制原样保留**，杜绝版面破坏。
>
> **实测注记（v2）**：结果图图形区出现的水平条纹，正是「大块 mask + 确定性延拓」的典型伪影——验证了上表「中值/结构延拓在大面积 mask 下失效」的判断，也验证了 LaMa 论文以**大/不规则 mask** 为核心训练目标的必要性。

### 4.3 产品形态对比

| 形态 | 代表 | 用户负担 | 粘性 |
|---|---|---|---|
| 全自动一键 | 夸克 / 扫描全能王 | **零** | 高 |
| 半自动（手动涂抹/框选） | 部分旧工具 | 中（需操作） | 中 |
| 不可操作引导（教改笔色/字号/裁剪） | **当前失败分支** | 高（改变习惯） | **负（赶客）** |

## 五、推荐技术方案（分阶段落地）

### 总体原则

1. **治本**：用「语义分割」替代「颜色/几何启发式」来区分手写——这是消除两个痛点的唯一根本路径。
2. **修复升级**：确定性修复 → 受控生成式 inpainting（LaMa / 专用 CGAN）。
3. **产品零负担**：全自动一键 + 失败自动降级 + 可撤销对比；**绝不输出「改用红蓝笔/改字号/手动裁剪」类建议**。

### P0 · 止血（纯护栏、无模型，低风险，优先做）

| 项 | 方案 | 解决 |
|---|---|---|
| **P0-1 色域法去误判** | `chroma≥22` 不再直接当手写；识别「连续大面积彩色区域 / 规则形状」为**彩色印刷体或彩色插画**并排除 | 彩印红蓝印刷体、彩色插画误擦 |
| **P0-2 图形连通域过滤** | `maskFromDarkInk` 增加**图形/非文字连通域剔除**：封闭区域、实心色块（含灰色阴影填充——实测图形正是灰色填充被误判）、极端长宽比、含规则形状（圆/方/三角）的墨迹从 mask 移除 | 几何图、插画、印章、图标误擦 |
| **P0-3 VLM prompt 加固 + bbox 收紧** | 明确「图形/插画/图表/表格/印章/彩色印刷体（无论红蓝）/**灰色阴影填充**一律保留，只擦手写体笔迹」；输出带 label 与置信度；**bbox 不做整块大外扩**，宁可漏、不可滥 | 主路径图形误框、mask 波及印刷文字 |
| **P0-4 失败文案重写**（关键体验） | 删除「字写大一些 / 改用红蓝笔重拍 / 编辑裁剪」类文案；改为：自动降级保留原图 + 可选「局部涂抹」（默认不需要）+ 明确「已保留原图，未改动」 | 痛点② 不可操作建议 |
| **P0-5 mask 总量护栏**（v2 新增，实测教训） | mask 面积占比 >20~25% 或出现大块连通 mask → **判定分割失控，放弃擦除、原图返回**；膨胀半径设上限。原则：**宁可不擦，不能擦坏** | 实测「整页条纹/文字涂抹」的触发条件——现状正是 mask 失控后硬修导致灾难 |
| **P0-6 分辨率与底色铁律**（v2 新增，实测教训） | ① 降采样只允许在中间计算，**输出必须回填原图分辨率**（回归断言项）；② 底色填充的背景色取样需排除阴影/灰区（如取局部亮分位数而非均值） | 实测「分辨率减半」「背景发灰」 |

> P0 不解决「黑笔同字大写在印刷上」这类硬边界 case（那是 P1 语义模型的活），但按实测案例归因，**P0-5/P0-6 + P0-2 能把「整页灾难」降级为「局部小瑕疵或干脆不处理」**——这是用户可接受的底线。

### P1 · 语义分割替代（治本，中期）

| 项 | 方案 |
|---|---|
| 分割模型 | 训练/接入专用手写分割模型（U-Net / **U²-Net** / SegFormer），采用 **四分类 HT/PT/BG/OV** 思路，从源头区分手写与印刷/背景/图形 |
| 数据 | **合成数据打底**：印刷体背景 + 叠加手写笔迹，参数随机化；叠加位置覆盖「印刷文字区」与「空白处」各约一半（否则学不会恢复印刷体） |
| 压字区(OV) | 手写压在印刷上时，以**保留印刷体为优先**（恢复被截断的线/字，而非填底色缺口） |
| 落地约束 | 需 GPU/云端推理；重模型归 `sr-gate` 的 **heavy lane**（已有，可复用）控并发 |

### P2 · 修复升级（中期，配合 P1）

| 项 | 方案 |
|---|---|
| inpainting 模型 | 引入 **LaMa 类生成式**修复替代确定性 median/structuralExtend，对大面积 mask、压字区、周期性结构（表格线/网格）恢复更好 |
| **大 mask 定位提升为必需**（v2） | 实测证明：手写散布全页 → mask 连通成大块 → 确定性延拓必然产生条纹伪影。生成式修复不是「锦上添花」而是「大 mask 场景的唯一可行解」；LaMa 训练/选型必须覆盖**大 mask 策略** |
| 超大 mask 兜底 | mask 区域过大且位于空白纸面时，**纯背景底色填充优于任何延拓/修复**（试卷空白处本就是白纸）；仅压字/压图形区才走生成式修复 |
| 铁律保留 | 仍走 `blendWithMask`「非 mask 区域原样保留」；修复只作用于 mask |
| 兜底 | 无 GPU/离线场景回退到确定性修复（P0 现行策略），且受 P0-5 总量护栏约束 |

### P3 · 全自动产品体验（对标夸克，提升粘性）

| 项 | 方案 | 对应诉求 |
|---|---|---|
| 一键去除 | 拍照即自动去手写，全程零手动 | 便利性 |
| 失败兜底 | 检测失败/低置信 → 自动保留原图并温和提示，绝不报错、绝不教改习惯 | 满意度 |
| 对比/撤销 | 原图 vs 结果**滑杆对比** + 一键撤销/重做 | 粘性 |
| 场景化 | 「试卷还原（去手写留空白）」默认场景；不推「手写保留」给用户增加选择负担 | 便利性 |

## 七、效果评估方法（针对两个痛点设指标）

| 指标 | 说明 | 针对痛点 |
|---|---|---|
| **图形保留率** ⭐ | 含图形/插画/表格/印章的测试图，统计图形区域**未被 mask 覆盖**的比例 | 痛点① |
| **彩印红蓝保留率** ⭐ | 红/蓝印刷重点字、彩色印刷插画是否完好 | 痛点①（用户特别指出） |
| **印刷文字完好率** ⭐（v2 新增） | 未被手写覆盖的印刷区域 OCR 一致性**不得低于原图**（复用 `compareRecognized()`）；任何「处理前能认出、处理后认不出」即失败 | 实测文字涂抹 |
| **输出分辨率一致性** ⭐（v2 新增） | 回归断言：输出尺寸 = 输入尺寸 | 实测分辨率减半 |
| **灾难失败率** ⭐（v2 新增） | 结果图出现条纹/拖影/整页发灰等结构性伪影的比例；目标为 **0**——做不到就触发 P0-5 原图返回 | 实测整页破坏 |
| 手写擦除率（零残留） | 手写区是否被清干净、无残笔 | 基础能力 |
| 非 mask 区域一致性 | 复用现有 `unmodifiedRegionSimilarity`（应≈1） | 防版面破坏 |
| 主观 A/B | 原图 vs 结果特写对比 | 终裁 |

> 指标优先级（v2 明确）：**「不擦坏」类指标（图形/彩印/印刷文字/分辨率/灾难）全部为一票否决项，「擦得干净」为加分项**——先保底，再求好。
>
> ❌ 仍**不用 NIQE/BRISQUE**（自然图像指标，文档场景失效，同智能高清方案结论）。
> **本次实测的对比图对直接纳入回归样本集**（含几何图形 + 铅笔手写 + 压字区，正是最难的场景）；首期样本集建议 10~20 张：试卷 / 教材彩印页 / 含图形页 × 黑笔/铅笔/彩笔手写。

## 八、风险与开放问题

| 风险 | 缓解 |
|---|---|
| 语义模型 CPU 推理成本 | 端侧量化（夸克经验：压缩 ~100×，端到端 ~2s）；重模型归 `sr-gate` heavy lane |
| 合成数据质量决定上限 | 真实数据补充（纸张老化/折痕/印章），避免过拟合纯合成分布 |
| 压字区(OV)修复仍是难题 | 以保留印刷为优先；LaMa 比确定性延拓更稳，但仍需回归 |
| 启发式护栏的边界 case | P0 只止血，根治靠 P1；不追求 P0 完美 |
| **用户习惯红线** | 任何分支都不把负担推给用户；失败即自动降级保留原图 |

## 十、结论与优先级（v2 按实测案例修订）

1. **根因确认**：两个痛点的共同根源是「靠颜色/几何启发式近似手写」，而**印刷本身就红蓝并存、字号不一**——启发式必然崩。治本是让模型学「手写」语义。
2. **实测对比图证实问题严重度远超「误擦局部」**：分割失控（图形+印刷入 mask）→ 修复无能（大 mask 行延拓成条纹）→ 输出降级（分辨率减半、背景发灰），**三个环节同时失效导致整页灾难**。这直接改变方案重心：**「宁可不擦，不能擦坏」成为第一原则**。
3. **P0 止血范围扩大**：在图形/彩印护栏 + 文案重写之外，新增 **P0-5 mask 总量护栏**（失控即原图返回）与 **P0-6 分辨率/底色铁律**（输出=输入分辨率、底色取样排除阴影）。这两项是实测灾难的直接解药，纯护栏无模型。
4. **P1 语义分割治本**：四分类（HT/PT/BG/OV）分割模型 + 合成数据，从源头区分手写与印刷/图形，杜绝红蓝印刷体/图形误擦。
5. **P2 生成式修复从「更好」变为「必需」**：大 mask 场景确定性延拓必出条纹（已实测）；LaMa 需覆盖大 mask 策略，超大 mask 且位于空白纸面时退化为纯底色填充。
6. **评估原则反转**：「不擦坏」（图形/彩印/印刷文字/分辨率/灾难五项）为一票否决，「擦得干净」为加分项；本实测对比图直接纳入回归样本集。
7. **产品红线**：绝不输出「改用红蓝笔/改字号/手动裁剪」类引导；失败即自动降级保留原图。

> 下一步待确认：① 是否按 **P0 → P1 → P2 → P3** 推进（建议先 P0，且 P0 验收标准就用本实测图：图形完好 + 印刷文字 OCR 不降 + 输出分辨率不变，三者任一不达标即视为 P0 未完成）？② 语义分割模型（P1）的落地形态倾向**云端专用模型**（质量高、对接 `sr-gate` heavy lane）还是**端侧轻量量化模型**（零延迟、离线）？③ 是否建 10~20 张真实样本集（含彩印页/图形页，含本次实测图）用于 P0 验收？
